# 코드정리 가이드 (새로 시작)

모든 차수 프롬프트와 함께 준다. 코드를 새로 쓸 때도, 기능을 더할 때도 이 기준을 지킨다.

## 0. 목표

- 기능 하나를 더할 때 **관련 파일 3~4개만** 보면 되게.
- 수치를 고칠 때는 **데이터 파일만** 고치면 되게.
- 화면(그래픽 스타일)을 **통째로 갈아 끼울 수 있게.**
- 규칙을 **브라우저 없이** 테스트하고, 봇으로 **밸런스를 잴 수 있게.**
- 나중에 **다섯 명 파티**가 붙어도 구조를 바꾸지 않게.

## 1. 폴더

```
index.html          화면 틀, CSS, importmap(Three.js CDN), app.js 불러오기
js/
  app.js            시작, 모드 전환(제목·던전·정착지), 루프, 모듈 연결
  util/             난수(씨앗), 수학, 칸 좌표, 조사 함수 jo()
  data/             표만. 적·무기·장비·아이템·역할·지형·층·대사·건설·방문자·밸런스 수치
  sim/              규칙. 던전 한 판의 세계
    world.js        틱·시간·유닛 목록·사건
    unit.js         유닛 만들기(등불지기·동료·적 공통)
    space.js        충돌·길찾기·시야
    combat.js       자동 공격·피해 계산
    ai/             적 원형별 두뇌, 동료 두뇌
    status.js       상태 이상(초 단위)
    elements.js     원소 반응·지형 변화
    dungeon/        지도 생성·층·계단·숨은 방
    items.js        소모품·던지기
    gear.js         장비·강화·확인
    torch.js        횃불·등잔
    party.js        파티 명령·위협
    roles.js        역할 스킬
  town/             정착지 규칙(sim과 같은 규칙: 화면 모름)
    settlement.js   땅·건설·방 인식·프리셋
    residents.js    주민·필요·일·관계
    story.js        모닥불 밝기·방문자·등불지기 잇기·결말·달력
    meta.js         저장(판을 넘어 남는 것)
  render/           화면. 어댑터 하나 뒤에 스타일 하나
    adapter.js      모든 스타일이 구현할 인터페이스
    diorama/        지금 스타일(디오라마)의 구현
  ui/               DOM: HUD·조이스틱·창·로그·정보 카드
tests/
  sim/*.test.mjs    node --test, 브라우저 없음
  town/*.test.mjs
  smoke.mjs         playwright, 화면이 뜨고 한 판이 도는가
tools/
  measure.mjs       봇 측정(전투 시간·피해·사망률)
docs/               설계 문서
```

- **파일 하나 400줄 이하.** 넘으면 역할별로 나눈다.
- 새 폴더를 만들기 전에 위 구조 안에 들어갈 곳이 있는지 먼저 본다.

## 2. 의존 방향

```
util ← data ← sim, town ← app → render, ui
                  │ 사건(events)          ↑
                  └──────────────────────┘ (읽기만)
```

| 폴더 | 불러와도 되는 것 | 불러오면 안 되는 것 |
| --- | --- | --- |
| `util/` | 없음 | 전부 |
| `data/` | `util/`, 다른 `data/` | `sim/`·`town/`·`render/`·`ui/` |
| `sim/`, `town/` | `util/`, `data/`, 같은 폴더 | `render/`, `ui/`, THREE, `window`, `document` |
| `render/` | `util/`, `data/`, THREE. `sim`·`town` 상태는 **읽기만** | `ui/`, 규칙 함수 호출 |
| `ui/` | 전부(상태는 `sim`·`town`의 공개 함수로만 바꾼다) | — |
| `app.js` | 전부 | — |

- 규칙이 화면을 부르지 않는다. 화면에 알릴 일은 **사건**으로 남긴다(§4).
- 순환 import가 생기면 공통 부분을 한 단계 아래(`util`·`data`)로 내린다.
- 이 규칙을 검사하는 import 점검 스크립트(`npm run lint`)를 두고 CI에서 돌린다.

## 3. 시간 (슈퍼핫)

- 세계는 **고정 틱 1/20초**로만 나아간다. `world.step()` 한 번이 한 틱.
- `world.flowing`이 거짓이면 `step()`은 아무것도 바꾸지 않는다. 흐름은 입력 층이 정한다(조이스틱·이동 키·Space·자동 걷기·시전 중).
- 루프(`app.js`)는 실제 흐른 시간만큼 틱을 돌리되 **프레임당 최대 3틱**. 화면은 틱 사이를 보간해서 그린다.
- 모든 지속·간격·쿨타임은 **초**(틱 수로 바꿔 쓰지 않는다). 걸음 수는 횃불처럼 거리 경제에만.
- 규칙 안에 `setTimeout`·`requestAnimationFrame`·`Date.now()`·`Math.random()` 금지. 시간은 `world.time`, 난수는 `world.rng`.
- **연출을 기다리는 규칙은 없다.** 피해·사망·폭발은 그 틱에 확정되고, 화면은 사건을 보고 나중에 그린다.

## 4. 사건

- 규칙은 화면에 알릴 일을 `world.emit(type, data)`로 남긴다. `world.events`에 `{ t, type, ... }`로 쌓인다.
- 화면은 매 프레임 `world.drainEvents()`로 가져가 연출한다(번쩍임·피해 숫자·궤적·폭발·로그).
- 사건 이름은 과거형 동사 한 단어: `hit`, `miss`, `whiff`, `killed`, `telegraphed`, `burst`, `picked`, `leveled`, `heroDied`.
- 로그 문구는 사건에서 화면(ui)이 만든다. 규칙 안에 한국어 문장을 쓰지 않는다(§8).

## 5. 유닛

- 등불지기·동료·적·소환수는 **모두 같은 `Unit`** 이다. 다른 것은 `team`(`party`·`foe`·`neutral`)과 `ctrl`(`player`·`ai`)뿐.
- 유닛에 들어가는 것: 위치·반지름·속도·방향, 체력, 상태 이상(맵), 쿨타임(맵, 초), 무기·장비에서 나온 최종 수치, 역할, 두뇌 상태.
- 규칙 함수는 "등불지기만"을 가정하지 않는다. `hero`를 특별 취급해야 하면 `ctrl === 'player'`로 판단하고, 그런 곳은 최소로.
- 적 AI는 **원형**(근접·원거리·시전·돌진·치유·잠복)으로 나누고, 적 종류는 데이터(원형 + 수치 + 고유 기믹)로 만든다. 적 종류마다 코드 파일을 늘리지 않는다.

## 6. 데이터

- 수치와 표는 모두 `data/`에. 규칙 코드 안에 숫자를 박지 않는다(0·1·2 같은 뻔한 값 제외).
- 밸런스 수치(적 체력·공격 간격·예고 시간·전투 목표 등)는 `data/balance.js` 한곳에 모은다. 봇 측정 뒤 고치는 곳이 여기다.
- 표 항목에는 사람이 읽을 이름과 한 줄 설명을 함께 둔다(`name`, `line`).
- 데이터는 순수 객체. 함수는 간단한 조회만.

## 7. 상태와 저장

- 던전 한 판의 상태는 `world` 하나, 판을 넘어 남는 것(정착지·주민·기억한 이름·창고)은 `meta` 하나. 모듈 안에 다른 전역 변수를 두지 않는다.
- 저장은 `meta`만 `localStorage`에. 저장 형식에 `version`을 두고, 올릴 때마다 옮기는 함수를 `town/meta.js`에 추가한다.
- 화면의 캐시(메시·텍스처)는 `render/` 안에만. `world`·`meta`에 넣지 않는다.

## 8. 문구

- 게임 안 문구는 설명하지 않는다. 로그는 일어난 일만 짧게, 규칙을 풀어 쓰는 안내는 없다. 시간은 "N초". 조사 얼버무림(`이(가)`) 대신 `jo()`.
- 문장은 `data/`(대사·이름·설명)와 `ui/`(로그·버튼)에만. 규칙(`sim`·`town`)에는 한국어 문장이 없다.

## 9. 화면 어댑터

- 스타일은 `render/adapter.js`의 인터페이스를 구현한다:
  - `mount(el)`, `resize()`, `setDungeon(world)`, `setTown(town)`
  - `frame(state, alpha, dt)`: 상태를 읽어 그린다
  - `onEvents(events)`: 연출
  - `setFrozen(bool)`: 멈춤 표현
  - `pick(x, y)`: 화면 좌표 → 칸 또는 유닛 id
- 스타일을 바꿀 때는 `render/새스타일/`을 만들고 `app.js`의 한 줄만 바꾼다. 규칙과 UI는 건드리지 않는다.
- 예고(`world.telegraphs`), 힘 모으기, 멈춤 상태는 **어떤 스타일에서도** 가장 먼저 눈에 들어와야 한다.

## 10. 테스트와 측정

- **규칙 테스트**(`tests/sim`, `tests/town`, `node --test`): 브라우저 없이, 씨앗 고정. 기능마다 "무엇이 되어야 하는가"를 한 줄 이름으로.
  - 예: "손을 떼면 시간이 멈춘다", "힘 모으기 중 빠지면 헛친다", "젖은 무리에 번개가 번진다".
- **스모크**(`tests/smoke.mjs`, playwright): 화면이 뜨고, 새 게임 → 던전 → 몇 초 플레이 → 귀환이 콘솔 오류 없이 된다. 스크린샷을 `test-results/`에.
- **측정**(`tools/measure.mjs`): 봇이 여러 씨앗으로 한 구역을 돌고 전투 시간·받는 피해·사망률·층당 시간을 표로 낸다. 목표에서 벗어나면 `data/balance.js`를 고친다.
- `npm test`(규칙 + 스모크), `npm run lint`(import·의존 규칙), `npm run measure`. CI는 lint + 규칙 테스트 + 스모크.
- 테스트가 문구에 기대지 않게 한다(사건과 상태로 검사).

## 11. 기능을 더할 때

| 더할 것 | 고치는 곳 |
| --- | --- |
| 적 | `data/enemies.js`(원형·수치·기믹), 새 원형이면 `sim/ai/`, 모양은 `render/…/` |
| 무기·장비 | `data/weapons.js`·`data/gear.js`, 새 모양이면 `sim/combat.js` |
| 소모품 | `data/items.js`, `sim/items.js` |
| 원소 반응·지형 | `sim/elements.js`, 연출은 `render/` |
| 역할·스킬 | `data/roles.js`, `sim/roles.js` |
| 정착지 건물·가구 | `data/build.js`, `town/settlement.js` |
| 주민 사건·대사 | `town/story.js`·`town/residents.js`, `data/lines.js` |
| HUD·창 | `ui/` |
| 수치 조정 | `data/balance.js`만 |

## 12. 작업 방식

- 한 번에 한 작업. 작업 하나 = 커밋 하나 이상, 메시지는 무엇을 왜 바꿨는지 한 줄 + 필요하면 몇 줄.
- 작업이 끝나면 보고: 만든 것·바꾼 것, 테스트와 측정 결과, 문서와 다르게 정한 것, 남은 문제.
- 설계 문서를 바꾸는 결정을 했으면 해당 문서의 상태 줄과 적용 기록을 같이 고친다.
- 쓰지 않게 된 코드는 바로 지운다(꺼 두고 남기지 않는다). 되살릴 일이 있으면 git 기록에서 꺼낸다.
