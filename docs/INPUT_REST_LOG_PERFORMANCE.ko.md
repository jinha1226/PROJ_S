# 포션·휴식·로그·입력 지연 후속 점검

기준 commit: `918761c`. 2026-09-10. 기존 사용자 파일/세이브를 유지하며 로컬 수정한다. 이번 요청에는 푸시가 포함되지 않았다.

## 발견과 변경

- 전투 후 검증 오류: 독립 NPC의 `INDEPENDENT/` 공격은 순차 처리인데 과거 위치 검증이 같은 시간의 앞선 이동을 되감아 `canonical_melee_batch_frozen_position_invalid`를 반환했다. 실제 이동·전투·귀환 흐름에서 재현했다. 이후 포션/회복/저장처럼 전체 검증을 하는 작업이 막힐 수 있다. `FIELD_ACTOR/`와 마찬가지로 해당 공격 이벤트 시점의 위치를 사용하도록 수정한다. 공격 거리 검증을 제거하거나 이벤트를 삭제하는 것이 아니다.
- 포션: 지난 수정의 회복 선적용은 version 4 새 게임에만 적용됐다. 이제 기존 필드 저장에서 새로 사용하는 물약에도 선적용한다. version 3 이하의 새 사용 기록에는 `heal_before_time: true`를 기록하고, 이 필드가 없는 과거 기록은 원래 순서로 재생한다. version 4 기록 형식은 그대로다. 포션 거절 사유는 가려진 HUD 대신 열린 아이템 팝업 안에 표시한다.
- 휴식: 고정 300시간 제한은 코드에 없으며 300은 회복 맥박 간격이다. 이전 테스트는 반복 함수를 직접 불렀지만, 이제 실제 프레임 루프로 연속 회복·종료를 검사한다. 누적 휴식 시간을 표시하고 적 발견/피해/굶주림/진행 불가로 멈출 때 이유를 사건 영역에 표시한다. 실제 전투 후 위 NPC 위치 오류로 회복이 거절되는 흐름을 재현했고 수정 뒤 HP 완전 회복까지 통과했다. 다만 사용자 저장과 기기 조건은 아직 없어 모든 중단이 이 원인이라고 단정하지 않는다.
- 로그: 사건 영역 48→66px, 본문 최소 높이 54px로 3줄 공간을 확보한다. 마을에서도 사건 영역을 보여 대화에 따른 관계 변화를 읽을 수 있게 한다. 관계 원장을 표시용으로 증분 재생해 상태창과 같은 0~100 호감도의 실제 차이를 출력한다. 증가·감소·상한에 걸려 +0인 경우를 구분한다. 관계의 방향(누가 누구를 좋아하는지)도 출력한다. 시뮬레이션 관계 규칙/이벤트는 바꾸지 않는다.
- 채집: 제품 하단 상황 버튼의 채집 표시와 실행 연결을 제거한다. 자원 데이터·저장·거점 생산 로직을 삭제한 것은 아니다.
- NPC: 매 actor tick마다 모든 타일을 훑던 안전 경로 장애물 목록을 고정 물 지형 목록 + 기존 환경 변화 타일 인덱스로 만든다. 지형 변경/로드/롤백은 기존 캐시 무효화 경로를 사용한다. 탐험 목표·이동 속도·시뮬레이션 결과를 바꾸는 최적화는 아니다.
- 경로 탐색: 한 번의 동기식 탐색 안에서 같은 셀의 지형/점유 조회를 재사용한다. 호출을 벗어나면 캐시를 사용하지 않아 새 점유 상태를 반영한다. A* 우선순위와 동률 판정은 유지한다.
- 회복 시 검증: HP/MP 회복이 발생할 때마다 전체 과거 전투 이력을 다시 검증하던 경로를 기존 런타임 변경분 검증으로 통일한다. HP 이력 일치/MP 범위/이벤트 인과/파티 상태 검사는 유지하고, 로드/스냅샷의 전체 검증은 유지한다. 위 NPC 위치 오류 수정과 별개이며, 검증 오류를 무시하는 처리가 아니다.
- 사건 로그: 매 표시마다 전체 이벤트 이력을 재탐색하지 않고 새 이벤트만 분류한다. 최근 줄/턴 제한만 역방향으로 읽는다. 월드 교체와 롤백 꼬리 교체 시 인덱스를 다시 만든다.

## 외부 소스에서 참고한 구조

- [Shattered Pixel Dungeon Actor.java](https://github.com/00-Evan/shattered-pixel-dungeon/blob/master/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/actors/Actor.java): 각 actor의 다음 행동 시각과 동률 우선순위로 처리 대상을 선택하며 입력 대기 때 진행을 멈춘다. 우리 `field_turn_system`도 이미 다음 행동 시각 기반이므로 스케줄러를 통째로 교체하는 것보다 tick 안의 전체 순회를 줄이는 쪽을 먼저 적용했다.
- [DCSS view.cc](https://github.com/crawl/crawl/blob/master/crawl-ref/source/view.cc): 셀 단위 갱신/다시 그리기 표시, 시야 범위 작업, 턴 갱신 여부와 표시 갱신의 분리가 있다. 우리도 “변화가 없는 전체 상태를 계속 계산하지 않는다”는 방향으로 환경 인덱스와 로그 인덱스를 사용한다.

위 파일의 코드를 복사/번역하거나 라이브러리로 연결하지 않았다. 일반적인 스케줄링·변경분 갱신 개념만 참고해 기존 프로젝트 구조 안에서 작성했다.
