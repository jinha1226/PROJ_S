# 그래픽 컨셉 · 결정과 규격

작성일: 2026-09-22 · 상태: 방향 결정. 환경 에셋 v1(`environment-v1.md`)의 제작 방식을 기준으로 전 자산으로 확장한다.

## 0. 결정

- **스타일: 픽셀 감성의 탑뷰 다크 판타지.** "픽셀처럼 읽히는" AI 생성 이미지를 고해상도 시트로 보존하고 논리 32px로 표시한다. 네이티브 도트 시트를 손으로 찍지 않는다. 림월드식 평면 회화는 채택하지 않는다 — 이미 생성된 환경 v1의 품질과 톤이 기준을 충족하고, 이 톤이 다크 판타지에 더 맞는다.
- **공급: 전부 AI 생성(built-in imagegen), 기존 에셋 팩·타사 타일은 쓰지 않는다.** 참조 이미지는 우리가 만든 것만 쓴다(석조 벽·바닥 v1/v2, 환경 v1).
- **제작자 역할 분담**: 이미지 생성과 프롬프트는 사람(또는 Codex)이, 규격·검사·아틀라스 카탈로그·임포트·팔레트 통일·화면 합성 검증은 코드가 한다. 코드로 그림을 만들지 않는다.
- **일관성 원칙**: 시트마다 프롬프트 원문을 `docs/art/*-prompts.json`에 남기고, 참조 파일을 명시한다(환경 v1 방식). 새 시트는 반드시 이전 시트를 참조로 첨부한다.

## 1. 규격

| 항목 | 값 |
| --- | --- |
| 논리 타일 | 32×32 px. 모바일 세로(390px)에서 6칸 시야 = 칸당 64px 표시(2배) |
| 시트 해상도 | 1024~1254px 정사각, 4×4 또는 8×8 등분. 셀 안 12% 투명 여백, 접지선 셀 높이 82% (환경 v1과 동일) |
| 시점 | 정사영 탑뷰에 약간의 정면(front face). 아이소메트릭 금지. 바닥은 완전 탑뷰, 벽은 윗면+정면 |
| 조명 | 좌상단 고정 광원, 따뜻한 회색 외곽선, 저채도 재질, 불·마법만 채도 허용 |
| 캐릭터 크기 | 1타일. 큰 몬스터는 2×2 허용(놀·오크 대장급). 초상화 별도 |
| 초상화 | 256×256, 상반신, 정면 3/4, 동일 프레임(어두운 배경·상단 비네트) |
| UI 텍스처 | 9-slice 패널·버튼 3종(기본/강조/위험), 게이지, 프레임 — 코드로 만드는 것이 아니라 생성 시트에서 잘라 쓴다 |
| 알파 | 실제 투명. 체커보드·배경 타일 금지 |

## 3. 캐릭터: 완성 변형 시트 + 코드 차분 추출

부위 손상·장비를 화면에 내기 위한 레이어는 필요하지만, **레이어를 AI에 직접 생성시키지 않는다.** 이미지 생성기는 레이어 간 픽셀 정렬(앵커), 부분 투명(갑옷만), 시트 간 비율 일관성을 지키지 못한다. 대신 AI가 잘하는 "완성된 한 장"만 시키고 레이어는 코드가 뽑는다.

1. **한 시트에 같은 몸 템플릿의 완성 변형을 나열해 생성**한다: 기본복 / 가죽갑옷 / 사슬갑옷 / 판금 / 투구 A·B / 검 / 도끼 / 활 / 방패 / 왼팔 늘어짐 / 절뚝 포즈. 같은 시트·같은 참조라 비율이 유지된다.
2. **코드가 기본복 셀과의 픽셀 차분으로 오버레이를 추출**하고 앵커(접지선·중심축)를 맞춘다. 차분이 몸까지 번진 셀(모델이 체형을 바꾼 경우)은 검사에서 탈락시켜 그 셀만 재생성한다.
3. 합성은 런타임: `body(pose) + armor + helm + weapon + shield (+ 손상 오버레이)`.

| 레이어(추출물) | 출처 | 수 |
| --- | --- | --- |
| body | 기본복 셀 + 포즈 변형(팔 늘어짐·절뚝) | 3 |
| armor / helm | 장비 변형 셀 − 기본복 | 3~4 / 2 |
| weapon / shield | 무기·방패 변형 셀 − 기본복 | 3 / 1 |
| 손상 오버레이 | 붕대·피 등 작은 스프라이트(별도 소품 시트) | 3~4 |

부위 손상은 레이어 8종 교체가 아니라 **포즈 변형 2장 + 작은 오버레이**로 표현한다. 표시 크기가 64px라 그 이상의 세부는 보이지 않는다. 방향은 남향 1종으로 시작하고, 애니메이션은 정적 스프라이트 + 코드 연출(흔들림·플래시)로 대신한다. 몬스터는 페이퍼돌 없이 단일 스프라이트이며, 역할(근접/궁수/술사)이 실루엣으로 구별되게 무기·자세를 프롬프트에 고정한다.

## 4. 생성 워크플로

1. **캐릭터 바이블 시트 먼저**: 주인공 기본복 1장 + 완성 변형(§3의 장비·포즈) 12~15셀을 한 시트로. 이 시트가 이후 모든 캐릭터·장비 생성의 참조가 되고, 차분 추출의 기준 셀이 된다.
2. 시트마다 프롬프트 템플릿을 쓴다: `Use case: stylized-concept. Asset type: production game sprite atlas … Reference is style only … transparent alpha … equal cells with 12% margin, grounded at 82% … orthographic top-down with a little front face … crisp chunky pixel art at logical 32x32 … warm grey outlines, dark low saturation …` (환경 v1 원문을 기준으로 대상 목록만 바꾼다).
3. 생성 → §5 후처리 → `catalog.json` 등록 → 미리보기 장면(`tools/art/*_preview.tscn`)에서 확인 → 게임 연결.
4. 실패 기준: 셀 밖 침범, 배경 페인트, 스타일 이탈(매끈한 벡터·굵은 만화선·과한 불 광채), 참조와 재질 톤 불일치. 실패한 셀만 재생성한다.

## 5. 코드가 하는 후처리와 검사 (`tools/art/`)

- 알파 검증: 셀 가장자리 12% 안에 불투명 픽셀 없음, 배경 잔여(체커보드·검정 사각) 검출.
- 팔레트 근사: 각 셀의 색을 §2 팔레트 ± 허용 거리로 양자화, 강조색 예외 목록. 이탈률을 리포트.
- 접지·중심: 접지선 높이와 무게중심을 셀별로 계산해 82% 기준에서 벗어난 셀 표시.
- 실루엣 대비: 바닥 타일 위에 합성했을 때 실루엣 대비가 기준 이하이면 표시(작은 화면 식별성).
- 차분 추출: 변형 셀 − 기본복 셀 → 오버레이 PNG + 앵커. 차분 면적이 예상 부위(상체·머리·손) 밖으로 번지면 실패로 표시.
- 카탈로그 생성: 셀 좌표·기준점·레이어 종류를 `catalog.json`으로 출력, `AtlasTexture`가 그대로 읽음.
- 화면 합성 테스트: 실제 층 위에 캐릭터·몬스터·소품을 놓은 미리보기 장면. 캡처는 가상 디스플레이에서만(창을 띄우지 않음).

## 6. 1층 파일럿 제작 목록 (우선순위 순)

1. 캐릭터 바이블: 주인공 기본복 + 장비·포즈 변형 12~15셀(§3), 차분 추출로 시작 장비 3종 오버레이 확보.
2. 몬스터 8종: 쥐·목도리 도마뱀·코볼트·고블린·홉고블린·오크·놀·강쥐. 역할 변형은 무기로(궁수 활, 술사 지팡이) — 종족당 1시트 4셀.
3. 지형: 환경 v1 재사용 + 문·통로 바닥·유물 단상·관문 4종.
4. 소품: 환경 v1 재사용 + 잠긴 상자·흙더미·봉인된 유물·야영 모닥불(기존 화로와 구분).
5. UI: 9-slice 패널 3종, 버튼 3종, 게이지 2종, 초상화 프레임.
6. 초상화: 주인공 1(성격 탭용 표정 변형은 후순위).

## 7. 범위 밖

애니메이션 프레임, 북향·측면 방향, 2층 이후 테마 시트, 컷신·일러스트. 이 문서는 톤과 규격을 정하며 개별 프롬프트 원문은 시트별 `*-prompts.json`이 갖는다.
