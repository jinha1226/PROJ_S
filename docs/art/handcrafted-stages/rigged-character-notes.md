# 공통 뼈대 캐릭터 HTML

`character-lab.html`을 직접 열면 된다. 로컬 서버나 Godot 실행이 필요 없다. HTML과 같은 폴더의 JS, `rigged-hero` 폴더를 함께 유지해야 한다.

## 이번 구현

- Blender에서 직접 작성한 몸체와 16개 뼈, 강체 가중치 기반 Armature 변형.
- 같은 모델·카메라·포즈에 장비 메시만 켜고 끄는 기본/장비 비교.
- 검은 `hand.R`, 방패는 `forearm.L`, 갑옷은 몸통과 어깨뼈에 연결.
- 4방향 × (정지 1 + 보행 4 + 공격 4) × 2복장 = 72 PNG.
- 64×64 직접 렌더, 재질별 3단계 명암, 투명 배경, HTML 최근접 확대.
- 실제 뼈 좌표를 카메라에 투영한 관절 표시. 임의로 그린 장식 뼈가 아니다.
- 재생·정지·단계 이동·속도·방향 선택. 이전 이미지 생성 시안은 `character-generated-lab.html`에 보존.
- 새 몸체는 이미지 생성 없이 코드로 작성한 저폴리곤 초안이다. 외형 일관성 검증이 우선이며 손으로 마감한 픽셀 아트 완성품은 아니다.

## 파일

- `rigged-hero/hero-rig.blend`: 모델·실제 뼈대·36개 포즈의 키프레임.
- `rigged-hero/manifest.json`, `manifest.js`: 프레임·카메라 기준점·관절·장비 연결 정보. JS는 file://에서도 읽기 위한 동등한 사본.
- `tools/art/build_rigged_pixel_hero.py`: 재현 가능한 제작·렌더 스크립트.
- `rigged-character-art.js`: 프레임 재생과 실제 뼈 표시.

## 검사와 한계

- `node tests/rigged_hero_assets.mjs` PASS: 72 RGBA64 파일, 방향/포즈별 실제 이미지 차이, 두 복장의 관절 일치, JSON/JS 일치.
- `tests/rigged_hero_acceptance.py`: 실제 Blender 파일의 뼈·가중치·장비 연결·장비 토글 시 기본 몸체 불변성을 검사한다. 이전 렌더 단계에서 PASS; 마지막 재출력 뒤 재실행은 사용자 중단으로 완료 확인을 하지 못했다.
- HTML의 재생·정지·관절 표시·모바일 폭은 브라우저에서 확인했다. 이후 발견한 렌더 프레임 시간 문제를 수정하고, 최종 PNG의 실제 포즈 차이는 파일 검사로 확인했다. 마지막 브라우저 재확인은 사용자 중단으로 완료 확인을 하지 못했다.
- 보행은 단순 FK다. 발 접지/미끄러짐·갑옷 간섭·타격 자세의 자연스러움은 후속 다듬기 대상이다.
- 현재 장비 UI는 기본/장비 세트 선택이며 개별 장비 조합 UI는 아직 아니다.
- 게임 엔진·전투 판정·진행 데이터는 변경하지 않았다.
