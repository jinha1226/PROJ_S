# 빌드를 아는 동료 AI

작성일: 2026-09-26 · 상태: **구현됨 · 초기 가중치 검증**
전제: ②(`stone_effects.json`, 효과 `keywords`), ③(빌드군 12개, 효과별 빌드군 번호), ④(부위 영혼석, `enemy.part_kind`, 적 정보 창의 부위 줄)
근거: [③ 빌드군과 부위 효과](2026-09-26-build-families-part-effects-design.md) · [공격 형태·부위 영혼석](2026-09-26-damage-forms-part-stones-design.md)
기존 코드: `expedition/ai/utility.gd`(후보마다 Σ 가중치 × 곡선(입력), 상위 3개 항으로 설명), `expedition/ai/stances.gd`(`party_target`, 태세별 후보 생성: 돌격·치고 빠지기·수호), `data/content/tactics_profiles.json`(고려 항목 목록, 태세×후보 종류 가중치, 성격 보정), `expedition/ai/tactic_rules.gd`(파츠 규칙), `expedition/ui/companion_intent_ui.gd`(의도·이유 코드)

## 0. 목표와 결정

영혼석으로 빌드를 맞춰 줘도 동료가 빌드를 모르면 "출혈 빌드 동료가 멀쩡한 적만 친다" 같은 일이 생긴다. 이 설계는 **동료가 자기 빌드에 맞게 목표·자리·마무리를 고르게** 한다.

1. **플레이어 설정은 늘리지 않는다.** 빌드는 끼운 영혼석에서 자동으로 읽는다. 단순 명령은 이미 전술 버튼에 있다.
2. **새 AI를 만들지 않는다.** 기존 점수 AI에 고려 항목 몇 개와 후보 몇 개를 더한다. 태세·성격·파츠 규칙은 그대로 우선한다.
3. **"할 수 있는 공격을 버리고 멀리 쫓지 않는다"는 기존 원칙을 지킨다.** 빌드 선호는 지금 닿는 후보 사이의 순서를 바꿀 뿐이다.
4. **이유를 보여 준다.** 빌드 때문에 고른 행동은 의도 표시에 짧은 이유가 붙는다("출혈 대상 우선", "창으로 마무리").
5. **몬스터 AI는 바꾸지 않는다.**

## 1. 빌드 읽기

- 효과 데이터(`stone_effects.json`)의 각 효과에 `families: [빌드군 번호…]`를 둔다(③ §3 표의 마지막 열).
- `BuildSense.profile(actor) -> Dictionary`: 끼운 부위 효과의 빌드군을 세어 비율로(`{1: 0.5, 4: 0.3, …}`). 장비 효과(아이템 설계)도 같은 방식으로 더한다.
- **주 빌드군**: 전체 빌드군 기여를 합계 1로 정규화한 비율 0.3 이상 중 상위 2개(동률은 번호순). 없으면 빌드 선호 없음(지금과 같게 동작).
- 장착 효과·봉인·장비를 읽어 판단마다 계산한다. 변경 시 오래된 전투 캐시를 사용하지 않는다.

## 2. 새 고려 항목

`tactics_profiles.json`의 고려 항목 목록에 넷을 더한다. `finish_form`은 양보 감점 때문에 −1..1(`signed`), 나머지는 0..1(`linear`)이다.

| id | 입력 | 뜻 |
| --- | --- | --- |
| `build_target` | 후보의 목표가 주 빌드군에 얼마나 맞는지(§3 표, 여럿이면 최댓값) | 목표 고르기 |
| `build_setup` | 후보가 동료의 빌드를 도와주는지(§4) | 파티 연계 |
| `build_hold` | 제자리에 있을 가치(사수 조준 쌓임, 수호 인접) | 자리 잡기 |
| `finish_form` | 후보가 처치하고, 그 형태가 파티가 원하는 부위와 맞는지(§5) | 마무리 양보 |

- 가중치는 태세 × 후보 종류마다 둔다. 첫 값: `build_target` 공격 30·파츠 25, `build_setup` 20, `build_hold` 대기 25·이동 −(신호형 아님, 이동 후보에는 입력 0), `finish_form` 공격 35·파츠 35.
- 기존 가장 큰 항(피해·처치·위험 회피)을 넘지 않게 잡는다. 빌드 점수는 비치명 후보들 사이에서만 비교한다. 실제 치명 피해가 예측되고 피할 수 있는 후보가 있으면 위험 후보를 먼저 제외한다. 성격의 기존 실수·후퇴 단계는 유지한다.

## 4. 파티 연계(`build_setup`)

동료의 주 빌드군을 보고, 내 후보가 그것을 준비해 주면 점수를 준다.

| 동료 빌드군 | 내 후보가 이러면 1.0 |
| --- | --- |
| 1 출혈 | 내 공격이 베기이고 대상이 아직 출혈 없음 |
| 2 분쇄 | 내 공격이 타격이고 대상이 아직 골절 없음 |
| 3 급소 | 내 공격이 찌르기이고 대상이 아직 급소 노출 없음 |
| 7 원소 | 내 행동이 대상을 젖게 하거나 동료 원소와 반응할 상태를 검 |
| 8 저주 | 내 행동이 대상에게 해로운 상태를 하나 더 검 |

- 여러 동료면 가장 큰 값. 자기 자신의 빌드는 `build_target`이 맡는다. 모든 평가는 빌드군뿐 아니라 후보가 실제 부여 가능한 형태·원소·상태 및 실제 사거리와 합법성을 확인한다.

## 5. 마무리 양보(`finish_form`)

부위 영혼석(④)은 마무리 형태로 부위가 갈린다. 파티가 원하는 부위를 노리게 한다.

- **원하는 부위**: `s.part_wishes = {종족 id: [부위…]}`. 기본값은 자동: 파티가 아직 없는 부위 중, 파티원이 끼운 빌드군과 효과 빌드군이 겹치는 부위.
- 전술 버튼 메뉴에 **"부위 노리기"** 켜기/끄기(파티 공용, 기본 켜짐). 끄면 `finish_form`은 0.
- 후보가 대상을 처치하고 그 형태가 원하는 부위의 형태면 1.0. 원하는 부위가 있는데 형태가 다르고, 다음 적 행동 전에 맞는 형태의 동료가 합법적으로 공격하고 보수적 피해 예상으로 처치할 수 있으면 **처치 후보 점수에서 `finish_form` 가중치만큼 뺀다**(양보).
- 양보는 대상의 예고·접촉 위협이 없을 때만 한다. 대상당 한 번만 양보할 수 있고 실제 실행 성공 시 기록한다. 기본 드롭 확률 50/25/25를 보조하는 선호이지 확정 수집이 아니다.

## 6. 자리(`build_hold`)

| 빌드군 | 1.0 |
| --- | --- |
| 6 사수(조준 쌓임 효과를 가짐) | 대기·제자리 공격 후보이고, 사거리 안에 적이 있음 |
| 5 수호 | 후보 칸이 동료(가장 약한 동료 우선)와 인접 |

| 10 소환 | 후보 칸이 내 소환수보다 적에게서 멀다 |

## 7. 후보 생성

- 지금 태세 생성기는 공용 목표(`party_target`)와 인접한 적만 공격 후보로 낸다.
- **더한다**: 주 빌드군이 있으면, **지금 닿는**(이동 없이 공격·파츠 사거리 안) 적 중 `build_target`이 가장 높은 적 하나를 공격 후보로 추가한다. 이동해서 쫓는 후보는 만들지 않는다(원칙 3). 액티브는 기존 `PartsCandidates`의 합법 후보를 점수화한다. 사수 조준 효과를 가진 경우 제자리 공격과 대기 후보를 명시적으로 생성하되 공격 가능하면 공격을 우선한다.
- 공용 목표는 바꾸지 않는다. "공격 명령"(`ATTACK_TARGET`)이 있으면 빌드 후보를 만들지 않는다(명령이 이긴다).

## 8. 의도 표시

- 새 이유 코드: `BUILD_TARGET`, `BUILD_SETUP`, `BUILD_HOLD`, `FINISH_FORM`, `FINISH_YIELD`.
- 빌드 점수를 뺀 기존 점수의 최선 후보와 실제 선택이 달라졌을 때만 관련 이유 코드를 단다. 양보 감점은 선택된 후보가 아닌 포기한 처치 후보에서 원인을 읽는다.
- 문구(`companion_intent_ui.gd`): "출혈 대상 우선", "골절 대상 우선", "급소 노리기", "마무리 노림", "동료 준비(출혈)", "조준 유지", "곁을 지킴", "창으로 마무리(심장)", "마무리 양보".

## 11. 검토할 결정

1. 주 빌드군 문턱 0.3.
2. 새 가중치 첫 값(§2) — 위험 회피를 절대 넘지 않게.
3. 마무리 양보를 켜 두는 것이 기본이어도 되는지(효율이 조금 떨어질 수 있음).
4. 원하는 부위를 자동으로만 둘지, 적 정보 창에서 부위를 눌러 직접 찍게 할지.

## 구현 확인 (2026-09-26)

`build_sense.gd`가 실제 장착 효과를 정규화하고 후보·입력을 만든다. `Utility`와 기존 선택기가 점수를 계산한다. 장비·부위를 바꾼 다음 조회부터 새 빌드를 읽는다.

- 거리형의 근접 회피는 조준 유지보다 먼저다. 파츠 규칙 조건이 맞지 않는 후보에는 빌드 보너스를 더하지 않는다.
- 생존 필터는 안전 후보가 존재할 때 치명상 후보를 먼저 제외한다. 안전 후보가 없는 경우 기존 후보 안에서 최선을 고른다.
- 마무리 양보는 대상·층별 한 번, 실행 성공 시에만 소비한다. 동료가 적보다 먼저 행동해야 하며, 방어·피해 감소·비치명타 대가·보호막·대신 맞기·부활을 반영한 보수적 피해로 처치 가능성을 판단한다. 다른 동료가 치명상 위기에 있어도 양보하지 않는다.
- 빌드 항을 뺀 선택과 달라진 경우에만 `BUILD_*`·`FINISH_*` 이유를 만든다. 말풍선은 기존 전환·재표시 간격을 따른다.
- 전술 메뉴의 `부위 노리기`로 파티 전체의 수집 선호를 켜고 끈다. 직접 공격 명령은 빌드 선호를 건너뛴다.
