# 읽히게 만들기 (최소판)

작성일: 2026-09-26 · 상태: **구현 완료(최소 범위)**

후속 사용자 결정: [6개 영구 흡수와 간결한 영혼석 효과 요약](../../soulstones.ko.md). 아래 범위 밖의 빌드 요약 제한은 현재 영혼석 탭의 실제 효과 요약에는 적용하지 않는다.
앞: [도감](2026-09-26-codex-design.md)
전제: ②(발동 엔진, 효과 `name`·`text`·`keywords`), ④(부위 영혼석), ①(무기 형태)
기존 코드: `expedition/progression/effect_engine.gd`(`fire`), `expedition/run/session.gd`(`after_damage`), `expedition/progression/stone_effects.gd`(`heal`), `expedition/run/run_result.gd`(`battle_stats` 멤버 행), `expedition/ui/battle_hud.gd`(`BattleReport`), `expedition/ui/screens/character_folio.gd`, `essence_tab.gd`, `codex_screen.gd`

## 0. 결정

Path of Achra처럼 **다 보여주고 스스로 파악하게** 한다. Achra의 장치는 셋이다: 맵 위 발동 이름(우리는 이미 `PROC` 알림이 있다), 키워드 툴팁, 자세한 로그. 안내형 장치(빌드 경고, 다음 부위 추천, 처음 안내, 쉰 영혼석 표시)는 **만들지 않는다.**

만드는 것은 셋뿐이다.

1. **전투 리포트 한 줄**: 멤버마다 발동한 영혼석과 그 피해·회복. (모바일 로그는 작아서 Achra의 로그 역할을 대신한다.)
2. **키워드 팝업**: 영혼석·장비·도감의 키워드 칩을 누르면 뜻. (모바일에는 마우스 올리기가 없어 누르는 팝업.)
3. **상태창 연계 설명**: 끼운 영혼석(과 무기 형태)을 같은 키워드끼리 묶고, 거는 쪽 → 쓰는 쪽 순서로 효과 문구를 보여 줘 어떻게 맞물리는지 읽히게 한다. 경고·추천 없이 끼운 것만.

## 1. 전투 리포트 한 줄

- 기록: `battle_stats.members[id].effects[효과 id] = {"procs": n, "damage": n, "heal": n}`.
  - `procs`: 효과의 발동 규칙(`do`·`code`)이 실행될 때 +1.
  - `damage`: 그 효과가 실행되는 동안 난 피해(추가 피해·폭발·전이·반격·반사).
  - `heal`: 그 효과가 실행되는 동안의 회복.
- 상시 % 효과(공격력 +% 등)는 발동이 없으므로 리포트에 나오지 않는다. 몫 나누기는 하지 않는다.
- 파티 멤버만 기록한다.
- 화면: 전투 리포트 카드의 멤버 줄 아래 한 줄, 기여(피해+회복) 순 최대 5개. "피 냄새 ×12 · 피해 84   포식 ×2 · 회복 30".

## 2. 키워드 팝업

- 새 데이터 `data/content/keywords.json`: 효과 데이터에 나오는 모든 키워드의 뜻 한두 줄.
- 칩: 영혼석 카드(`essence_tab.gd`), 도감의 모은 영혼석(`codex_screen.gd`), 장비 카드의 효과 아래.
- 팝업: 키워드, 뜻, 닫기. (관련 부품 목록·도감 이동은 넣지 않는다 — 연계는 상태창에서 본다.)

## 3. 상태창 연계 설명

- 캐릭터 화면 상태 탭에 "영혼석 연계" 카드. 끼운 영혼석이 **어떻게 맞물리는지를 효과 문구로 설명**한다. 경고·추천은 없고, 끼운 것만 다룬다.
- 끼운 효과들(과 무기 형태)을 **둘 이상이 나누는 키워드**로 묶고, 묶음마다 제목 + 줄:

```
출혈 연계
  거는 쪽 · 장검(베기) — 명중하면 출혈 (피부가 무를수록 잘 걸림)
  거는 쪽 · 쥐 앞니 — 베기·찌르기 공격의 출혈 확률 +10%p
  쓰는 쪽 · 피 냄새 — 출혈 중인 대상에게 주는 피해 +20%
  쓰는 쪽 · 사냥 본능 — 출혈 대상을 처치하면 반경 1에 출혈 전이
```

- 순서: 거는 쪽 → 둘 다 → 쓰는 쪽. 같은 쪽 안에서는 슬롯 순서, 무기는 거는 쪽 맨 앞.
- 거는 쪽·쓰는 쪽을 가르지 않는 키워드(소환, 지원 등)는 "함께 · 이름 — 문구"로.
- **데이터**: 효과마다 `"roles": {"<키워드>": "setup"|"payoff"|"both"}`. 규칙에서 초안을 뽑는 도구(`tools/fill_effect_roles.py`)로 채우고 사람이 검토한다.
  - `apply_status`·`spread_status`로 그 상태를 걸거나 `wound_chance`를 올림 → setup
  - 조건 `target_has`·`victim_had`·`status_is`가 그 상태 → payoff
- **무기 형태 문구**: 베기 "명중하면 출혈 (피부가 무를수록 잘 걸림)", 타격 "명중하면 골절 (뼈가 약할수록 잘 걸림)", 찌르기 "명중하면 급소 노출".
- 나누는 키워드가 없으면 "연계 없음".

## 4. 테스트

| 스위트 | 검사 |
| --- | --- |
| `tests/effect_report.gd` (새) | 발동·피해·회복 기록, 중첩 효과는 안쪽 효과 몫, 파티 밖은 기록 없음, 리포트 문구, 상위 5개 |
| `tests/keywords.gd` (새) | 효과 데이터의 모든 키워드가 `keywords.json`에 있음, 칩을 누르면 팝업 |

## 5. 범위 밖 (하지 않음)

빌드 요약 카드와 경고, 다음 부위 추천, 처음 한 번 안내, 쉰 영혼석 표시, 원정 결과 요약, 상시 % 효과의 몫 나누기. 플레이 뒤 필요하면 그때 하나씩 더한다.

지연 폭발·효과가 건 지속 피해는 소유자와 효과 ID를 보존해 기여를 집계한다. 키워드 설명은 원래 카드를 유지하는 자식 팝업이며, 전투 리포트는 화면에 맞춘 스크롤 카드다.
