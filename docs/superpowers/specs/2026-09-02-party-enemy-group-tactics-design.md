# P2 — 적 무리 전술 설계

작성일 2026-09-02. 4인 파티 단체전투 시리즈의 2/4.

## 목표

적이 주인공 한 명만 추적하는 현재 규칙을 없애고, 배치된 파티 전원을 인지한 뒤
적 무리 단위의 파생 타깃 정보를 사용하도록 한다. 판단용 보드는 저장하지 않으며,
같은 월드에서 반복 계산해도 스냅샷·이벤트·RNG가 변하지 않아야 한다.

## 순차 범위

1. **P2-1 인지와 보드:** 모든 `DEPLOYED` 파티원을 시야 후보로 삼고,
   `EnemySquadBlackboard`가 가시 대상·압박·focus·claim을 순수 계산한다.
2. **P2-2 타깃 선택:** `forecast_enemy_action()`이 분대 claim을 사용하되, 죽거나
   배치 해제된 대상에는 즉시 결정론적으로 재계획한다. `ALERT/HUNTING`이며
   활성 전투 거리 안인 적만 claim을 받아, 먼 적이 분배 슬롯을 선점하지 않는다.
3. **P2-3 이동 예약:** 같은 칸으로 몰리는 적 이동을 id 순 예약과 대체 경로/HOLD로
   해소하여 적 배치 전체가 원자적으로 거부되는 일을 막는다.
4. **P2-4 관찰·매트릭스:** 적 focus/claim 설명 DTO와 다중 적 시드 매트릭스로
   집중 공격 편향, 행동 정지, 저장·재생 회귀를 검증한다.

## P2-1 계약

- 인지 후보는 `active_party_member_ids` 중 멤버 상태가 `DEPLOYED`이고 살아 있는
  엔티티다. 거리 오름차순, HP 비율 오름차순, entity id 오름차순으로 관측 대상을
  고른다.
- 인접한 배치 파티원은 즉시 `HUNTING`; 시야 안 파티원은 기존 suspicion 공식을
  그대로 사용한다. 아무도 보이지 않을 때의 SEARCHING/RETURNING 전이는 유지한다.
- 전투 활성 거리와 적 배치 참여 여부는 주인공 거리가 아니라 가장 가까운 배치
  파티원 거리로 판정한다.
- `EnemySquadBlackboard.build(world)`의 정확한 키는
  `schema_version`, `active_enemy_ids`, `deployed_party_ids`, `visible_targets`,
  `target_pressure`, `focus_target_id`, `claims`다.
- focus는 인접 적 수 내림차순, HP 비율 오름차순, 가시 적 수 내림차순,
  roster slot/id 오름차순이다. claim은 적 id 순서로 배정하며 대상이 둘 이상이면
  한 대상에 최대 2명까지만 우선 배정한다.
- 보드, 가시 목록, claim은 파생 데이터다. 스냅샷·스키마·저널에 넣지 않는다.

## P2-3 계약

- 한 적 배치의 MOVE를 entity id 오름차순으로 예약한다. 먼저 예약한 적은 원래
  목적지를 유지하며, 같은 목적지 또는 대각선 flank와 충돌하는 뒤 적만 재계획한다.
- 대체 칸은 현재 타깃까지의 Chebyshev 거리를 반드시 줄이는 인접 통과 가능 칸이다.
  거리, 8방향 고정 순서, y/x 순으로 결정하며 모든 전진 칸이 막히면 HOLD한다.
- 예약 계산은 월드·이벤트·RNG를 바꾸지 않는다. 실제 MOVE/HOLD는 기존 canonical
  leaf만 사용하며, 한 적의 목적지 충돌 때문에 배치 전체를 롤백하지 않는다.

## 비범위

- 사기·공포 전염과 지속 모드(P3), 화면 밖 축약 전투(P4).
- 새 공격·이동 행동 타입, RNG 기반 전술, 텔레파시로 아직 아무 적도 보지 못한
  파티원을 추적하는 규칙.
- 이번 P2-1에서 `forecast_enemy_action()`의 실제 타깃을 claim으로 바꾸는 것.
  보드 계약을 먼저 고정한 뒤 P2-2에서 연결한다.
