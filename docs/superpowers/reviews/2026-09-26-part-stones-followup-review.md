# 부위 영혼석 후속 설계 검토

검토일: 2026-09-26. 대상은 현재 로컬에 추가된 초안 세 개다.

- [② 발동 엔진](../specs/2026-09-26-trigger-engine-design.md)
- [③ 빌드군과 부위 효과](../specs/2026-09-26-build-families-part-effects-design.md)
- [④ 부위 영혼석 구현](../specs/2026-09-26-part-stones-implementation-design.md)

① 공격 형태·부상의 구현과 별개인 후속 범위다. 기존 30종의 90개 부위를 먼저 완성하고 새 8종을 나중에 붙이는 순서는 유지할 만하다. 아래 문제를 후속 구현 계획에 반영해야 한다.

## 1. 조건이 거짓이어도 발동 기회를 소모함

② §4.1은 `Reactions.once`를 조건 검사 전에 호출한다. 도끼의 첫 대상이 조건을 만족하지 않으면 다음 대상이 만족해도 발동하지 않는다. 같은 효과에 같은 `when` 규칙이 두 개 있으면 첫 규칙이 두 번째를 막기도 한다.

효과·사건 단위로 조건을 만족한 규칙을 모으고, 실제로 실행할 규칙이 있을 때 한 번 표식을 예약한 다음 해당 규칙들을 실행한다. 예약은 결과 실행보다 먼저 해서 재진입은 차단한다. 조건이 거짓인 첫 대상 뒤에 참인 대상이 오는 검사와 동일 효과의 두 규칙을 함께 실행하는 검사가 필요하다.

## 2. 주변 동료의 상시 효과를 발견할 경로가 없음

② §4.2의 `modifier`는 요청된 인물의 장착 효과만 순회한다. `owner_adjacent_to_target` 조건을 추가해도 옆 동료가 가진 해골 병사의 피해 감소를 발견하지 못한다. 기존 동작 보존 요구와 충돌한다.

자기 효과와 주변 동료의 오라를 구분해 효과 소유자를 모으는 규칙이 필요하다. 엄호가 있을 때는 실제 피해 대상 주변을 기준으로 계산하고, 소유자 id로 중복을 제거한다. 기존 `stone_effects`의 인접 동료 피해 감소 검사를 그대로 유지한다.

## 3. 치명상 대신 맞기가 사후 위기 사건에 연결됨

②의 `ALLY_CRISIS`는 HP가 25% 이하로 처음 떨어진 **뒤**의 사건이다. ③의 `ACOLYTE_BONE`은 쓰러질 피해를 **받기 전** 대신 맞아야 한다. 사후 사건으로는 이미 들어간 치명상을 막을 수 없다.

사전 사건 `ALLY_LETHAL`을 따로 두고 예상 피해·원래 대상·보호 후보를 전달한다. 회복 효과 `ACOLYTE_HEART`는 기존 사후 위기 사건에 둔다. 엄호 체인과 상호 엄호의 순환 처리도 현재 `protection_recipient` 규칙을 따른다.

## 4. 정규 ID의 별칭만으로 기존 테스트를 보존할 수 없음

④는 맨 ID를 별칭으로 남겨 대부분의 테스트가 그대로 통과한다고 적었다. 하지만 기존 코드는 `parts_bag["RAT_GNAW"]`, `hero.essences.FIRE_CALLER`, `equipped_abilities`와 규칙 배열을 직접 읽기도 한다. 저장 키를 `BASE/part`로 바꾸면 `canonical()` 조회 별칭만으로 이 직접 조회는 호환되지 않는다.

공개 조회 API를 통한 접근은 별칭을 허용하되 저장은 정규 ID 하나로 한다. 직접 조회 호출부와 테스트를 목록으로 만들고 의도를 유지하며 정규형에 맞춰 옮긴다. 같은 종족의 두 부위가 한 액티브를 공유하므로 규칙·재사용 대기·UI 선택·AI 조회에서도 액티브 ID와 영혼석 ID를 분리해야 한다.

## 5. 형태와 사건의 의미를 현재 피해 경로에 맞춰야 함

현재 실제 공격 형태는 `s.blow_form`이며 `CombatRules.damage`의 `element`/`hit_form`과 다르다. 예를 들어 창 기본 공격의 원소는 `physical`, 파츠가 전달하는 옛 표기는 `IMPACT`여도 실제 부위 형태는 `PIERCE`일 수 있다. 엔진의 `context.form`은 `Forms`의 실제 형태를 전달하고, 원소·주문 여부·1차/2차 여부는 별도 필드로 둔다.

또한 `Session.after_damage(..., received)`는 실제 피해 대상을 반환한다. `HIT`·`STRUCK`·부상은 이 대상으로, 처치 시 상태와 치명타 여부는 피해 처리 당시의 스냅샷으로 전달한다. 사건을 뒤늦게 재구성하면 엄호·연사·반사로 바뀐 상태를 읽을 수 있다.

## 6. 보스 제외 종족 수 표가 38종과 맞지 않음

③ §2의 역할 수는 7+7+6+7+6+8=41이다. 현재 `essences.json`의 33개 행(일반 종족 30개와 보스 3개)에 새 8개를 더한 수와 일치하며, 문서의 "보스 제외"와 충돌한다. 부위 효과 114개를 생성할 때는 일반 종족 38개만 대상으로 삼고 보스 3개는 별도 단일 영혼석으로 검증한다. 역할 수 표도 이 범위로 다시 산출해야 한다.

## 구현 순서

②의 사건·효과 소유자·정규 ID 계약부터 확정하고 기존 30개 효과 보존 검사를 통과시킨다. 그 뒤 ④-a의 정규화와 드롭을 연결하고, 출혈·분쇄·급소 등 빌드군별로 새 효과를 추가한다. ③의 역할 조합 수치는 효과 조합이 작동한 뒤 동일 시드 난이도 게이트로 검증한다. 새 종족 이미지와 아이콘은 기존 합의대로 사용자 검토 후 적용한다.

## 반영 현황

2026-09-26: ② 발동 엔진과 기존 30개 효과 이식에 1·2·3·5의 수정 사항을 반영했다. ③의 일반 종족 역할 수는 38종으로 바로잡았고, ④에는 직접 저장 키·액티브 ID 전환 요구를 명시했다. 실제 부위별 ID와 60개 새 효과는 다음 ④-a 단계다. 이미지 승인 전에는 기존 그림을 쓰도록 수정했다.
