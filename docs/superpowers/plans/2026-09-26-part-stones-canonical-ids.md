# 부위 영혼석 ④-a1: 정규 ID와 호환성

2026-09-26. 발동 엔진 다음 단계인 ④-a1을 구현한다. 실제 세 부위 드롭과 화면 묶음은 ④-a2, 새 효과 60개는 ④-a3이다.

## 반영

- [x] 일반 30종에 `cut`·`broken`·`pierced`를 정의한다. 90개 부위와 보스 영혼석 3개가 있다.
- [x] `BASE/part[@element]`를 보유·장착·가방·드롭 집계 키로 쓴다. 맨 `BASE`는 대표 부위 별칭이며 API 조회와 입력에 계속 쓸 수 있다.
- [x] 부위 이름과 역할·스탯·학파 상속을 연결한다. 대표 부위에만 기존 효과를 두고 나머지 부위는 새 효과 단계까지 빈 효과로 둔다.
- [x] 몬스터는 같은 종족 대표 효과 하나를 유지한다. 보스 영혼석은 부위로 나누지 않는다.
- [x] 같은 종족의 여러 부위를 장착해도 액티브·규칙·재사용 대기는 하나다. 역할·속성 세트는 부위마다 센다.
- [x] 마지막 해당 종족 부위가 빠질 때만 그 액티브 규칙을 지운다. 일부 부위를 해제해도 설정한 조건과 활성 여부를 유지한다.
- [x] 같은 종족의 주문 선택을 공유한다. 여러 부위를 흡수하거나 장착해도 같은 주문이 중복으로 들어가지 않는다.
- [x] NPC 초기 장비·사냥·선택, 시작 키트, 아레나·시뮬레이터, UI·기존 아이콘 조회를 정규 키에 맞춘다.
- [x] 검사에 사용하던 맨 ID 입력은 유지하고, 딕셔너리와 장착 배열을 직접 읽는 검사는 정규 ID를 기대하도록 옮긴다.

## 구현 중 확정한 규칙

속성이 다른 같은 종족 부위를 끼우면 **첫 번째 봉인되지 않은 슬롯의 속성**으로 액티브가 동작한다. 액티브 ID는 `BASE@element`이고 재사용 대기의 키는 `BASE`다. 슬롯 교체·봉인으로 속성이 바뀌어도 대기를 우회할 수 없다. AI·스킬 목록에는 종족당 하나만 표시한다.

이 공유 규칙은 부위를 장착하는 플레이어·NPC에게 적용한다. 몬스터의 고유 기술과 보스가 훔친 기술은 기존 `BASE@element` 재사용 키를 유지해, 몬스터 턴 처리의 대기 감소와 기술 흡수 동작을 바꾸지 않는다.

이전 런 상태의 별칭 키는 `Essences.normalize_actor`와 `normalize_run`으로 옮긴다. 가방과 드롭 수량은 합하고, 흡수 여부는 한 번으로 합친다. 동일 영혼석의 별칭 슬롯이 중복되면 뒤의 슬롯만 비운다. 봉인 만료와 재사용 대기는 가장 긴 값을 유지한다. 명시된 정규 주문 선택을 별칭 선택보다 우선하며, 같은 종족의 선택이 충돌하면 첫 장착 부위의 유효한 선택을 유지한다. 종족별 첫 처치 기록인 `essence_seen`은 부위 키로 바꾸지 않는다.

현재 프로젝트에는 런을 파일에 저장·복원하는 기능이 없다. 이번 호환성 검사는 런 딕셔너리와 JSON 상태 왕복을 다룬다. 파일 저장 기능을 추가할 때는 복원 직후 `normalize_run`을 호출해야 한다.

일반 처치와 NPC 사냥은 아직 대표 부위를 준다. 기록 중인 `enemy.part_kind`를 실제 드롭에 적용하는 작업은 ④-a2에서 한다. 테스트 로드아웃은 전체 93개를 제공하므로 나머지 부위도 흡수·장착·스킬을 검증할 수 있다. 획득 메시지는 기존처럼 이름만 로그에 남긴다. 새 그래픽은 추가하지 않았다.
