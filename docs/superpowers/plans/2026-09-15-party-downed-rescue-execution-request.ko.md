## 질문과 완료 목표

현재 기본 게임 런타임에서 주인공과 동료의 HP 0 이후 구조 기회를 제공하고, 부축 도주 결과가 실제 기억·휴식 대화·이후 동료 판단까지 일관되게 연결되는가?

사용자는 계획서 작성 이후 구현을 지시했다. 계획의 A~D 전체를 구현·검증·문서화·커밋한다. 이번 지시는 계획만 보완하거나 A단계만 구현한 상태로 끝내는 요청이 아니다.

## 실행 계약

1. 기본 런타임은 `playtest/party_encounter_sandbox.tscn` 및 기존 sim/field turn 경로다. prototype/rebuilt 데모에 별도로 구현하지 않는다.
2. 10턴은 별도 답변이 없는 현재 계획의 기본안을 채택한다: 기본 행동 100 ×10 = 1000 world_time, DOWNED 발생 T에서 정확히 T+1000 마감. 이는 사용자가 시간제 단위를 별도 답변으로 확정했다는 뜻은 아니다. 이 요청에서 채택한 구현 기본값이다.
3. 신규 파티 주인공/동료 HP 0 → DOWNED. 추가 타격으로 10턴을 단축하지 않는다. 적 이탈 시 HP 1로 회복하며, 위험 지형에서는 회복을 보류한다. 마감 시 사망, 주인공 실제 사망 시 회차 종료.
4. 카메라 범위가 아닌 시뮬레이션 공유 시야를 사용한다. 전원 DOWNED로 시야가 비는 자동 회복을 막고, 위기 시간 진행 입력을 제공한다.
5. ASSIST/RELEASE 기본 100시간, 부축 이동은 정상 이동 시간 150% 올림. helper 목적지 이동 + target의 helper 출발칸 이동을 원자적으로 수행한다. 대상의 deadline은 계속 감소한다.
6. 부축 중단/교대/사망/층 이동/귀환/조작 전환/자동 이동의 예외를 계획대로 처리한다. helper가 busy인 경우와 전원 DOWNED 입력 막힘을 반드시 검증한다.
7. 구조의 원본 downed/assist 사건 ID를 기록한다. 실제 구조 완료만 RESCUED_BY 기억과 관계 반영에 연결한다. 자연 회복을 타인의 구조로 기록하지 않는다.
8. 안전한 휴식 때 사실에 근거한 짧은 성격별 구조 대화, 응답/닫기, 사건당 소비 기록 및 상호 구조 약속을 구현한다. 기존 appraisal의 크기를 고려한 제한적 구조 우선순위에 연결한다. 생성형 AI 대화는 사용하지 않는다.
9. 몬스터·독립 원정 NPC·옛 ruleset/save/journal의 규칙은 보존한다. 기존 이능 관련 작업과 schema/journal 변경이 겹치면 최신 상태에 맞춰 통합하고 사용자 변경을 덮어쓰지 않는다.
