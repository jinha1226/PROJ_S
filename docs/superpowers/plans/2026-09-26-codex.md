# 도감 구현 계획

작성일: 2026-09-26 · 상태: 구현 완료 · 93개 회귀 스위트 및 웹 패키지 검증 통과

스펙: [도감](../specs/2026-09-26-codex-design.md). 실제 원정의 몬스터·부위 영혼석·고정 아티팩트 기록을 원정 사이에 유지한다. 수집 보상과 원정 중단·재개 저장은 이번 범위에 포함하지 않는다.

## 수정한 계약

- 파일은 `user://codex.json`. 기록 사건은 메모리만 바꾸며, 층 이동·야영 진입·결과 화면·앱 일시정지 및 종료에서 dirty인 경우에만 저장한다.
- 완성된 `.tmp` 파일을 교체한다. 쓰기에 실패하면 dirty를 유지한다. 파일이 없으면 생성하지 않고 빈 기록을 반환한다. 깨진 JSON은 `.bad.json`으로 옮기고, 알려진 필드의 잘못된 구조를 정규화하되 확장 필드는 보존한다.
- 시작 화면의 실제 새 탐험 버튼은 기록을 켜고 현재 시야도 관찰한다. 직접 호출하는 `main.new_run()`과 `Session.new_run()`은 기본적으로 기록하지 않는다. 실제 시작 버튼을 누르는 UI 테스트는 임시 도감 경로를 사용한다.
- `grant_test_loadout`이 새로 넣은 영혼석은 획득·흡수 기록에서 제외한다. 이후 같은 영혼석을 실제로 얻으면 그 획득과 이후 흡수는 정상 기록한다.
- 일반 몬스터의 키는 `species_id`, 보스는 `boss:<boss_kind>`. 영혼석은 정규 ID에서 변종 속성만 뺀 `BASE/part`, 보스 영혼석은 맨 ID다.
- 타락한 모험가는 `enemy=false`인 보스 NPC다. 발견은 일반 적과 보스 NPC를 모두 검사하고, 처치 기록도 NPC 보스 경로에 연결한다.
- 아티팩트는 실제 `unrands.json.rows` 배열의 대문자 ID를 사용한다. `unrands` 사전을 가정하지 않는다. `Gear.grant_gear`가 실제 획득을 기록한다.
- 원정 끝 기록은 세션에서 한 번만 센다. 결과 화면을 다시 그려도 원정 수가 늘지 않는다.
- 그림은 기존 에셋을 사용한다. 모르는 몬스터는 실루엣이며, 모르는 종족의 부위 이름과 미획득 아티팩트의 이름·효과는 숨긴다.

## 구현 순서와 파일

### 1. 파일과 기록

- [x] `expedition/progression/codex.gd`: `empty`, `read`, `write`, `monster_key`, `stone_key`, `note_*`, `flush`.
- [x] `expedition/run/session.gd`: `codex`, `records_codex`, `codex_dirty`, `codex_run_ended`, `codex_test_stones`.
- [x] `tests/codex.gd`: 첫 실행, 저장 왕복, 깨진 파일 복구, 확장 필드 보존, 비기록 세션, 실패한 저장의 dirty 유지.

`read()`는 빈 파일을 새로 만들지 않는다. `note_seen`은 이미 본 종족과 변종을 다시 관찰해도 dirty를 다시 켜지 않는다. 테스트는 `Codex.path`를 임시 경로로 바꾸고 파일을 정리한다.

### 2. 실제 원정에 연결

- [x] `continuous_floor.gd`: 시야 계산 뒤 일반 적과 보스 NPC 발견.
- [x] `session.gd`: 파티가 참여한 처치와 마지막 NPC 보스 처치.
- [x] `gear.gd`: 실제 부위 드롭, 보스 부위, 아티팩트 획득.
- [x] `essences.gd`: 성공한 흡수만 기록.
- [x] `descent.gd`, `camp.gd`, `result_card.gd`, `main.gd`: 저장 시점.
- [x] `start_screen.gd`: 실제 시작과 시험 세션을 구분.

기록 모듈은 전투·경험치·드롭 확률을 변경하지 않는다. 순환 참조를 피하기 위해 원정 모듈은 세션의 `Codex` 상수를 통해 기록을 호출한다.

### 3. 화면 항목과 완성률

- [x] `monster_list`, `monster_entry`: 구역별 일반 종족과 보스 4종, 이름·몸 특성·대표 효과·액티브·부위·변종·처치 수.
- [x] `stone_list`, `stone_entry`: 종족별 세 부위와 보스 영혼석, 획득·흡수·마무리 형태·키워드·빌드군.
- [x] `unrand_ids`, `unrand_entry`: 아티팩트 12종의 칸, 한글 이름, 효과와 대가.
- [x] `completion`: 현재 카탈로그로 분모를 계산하며, 시작 버튼에 전체 완성률을 표시.

현재 분모는 몬스터 34종, 영혼석 93종, 아티팩트 12종이다. 빌드군 번호는 JSON을 읽은 뒤 정수로 변환해 필터의 타입 차이로 항목이 빠지지 않게 한다.

### 4. 화면과 진입점

- [x] `expedition/ui/screens/codex_screen.gd`: 몬스터·영혼석·장비 탭, 상세, 빌드군 필터.
- [x] 시작 화면, 야영, 전술 메뉴, 적 정보 창에 진입점.
- [x] 영혼석은 종족 × 세 부위 격자. 몬스터는 구역별 격자와 보스 묶음.
- [x] 세 탭 모두 세로 스크롤을 사용하고 가로 스크롤은 막는다. 높이는 실제 화면에 맞춘다.
- [x] 자동 줄바꿈이 끝난 뒤 PopupPanel의 실제 크기를 다시 맞춘다. 이전 측정으로 창이 넓어진 채 남는 현상을 방지한다.
- [x] 팝업을 열면 자동 이동을 중지한다. 자동 전투도 팝업이 열린 동안 진행되지 않는다.

안정된 노드 이름은 `CodexScreen`, `CodexCompletion`, `CodexTab_<tab>`, `CodexEntry_<key>`, `CodexDetail`, `CodexFilter_<family>`다. 키의 `/`와 `:`는 `_`로 바꾼다.

## 검증

`tests/codex.gd`는 51개 검사를 통과했다. `tests/codex_ui.gd`는 28개 검사를 통과했다. UI 검사는 세 탭을 320×568, 360×640, 390×844에서 열고 화면 경계를 검사하며, 실제 자동 전투 타이머도 진행되지 않는지 확인한다.

CI 스위트 목록에 `codex`, `codex_ui`를 추가했다. 기존 88개와 효과 설명 UI 3개를 합한 전체 93개 스위트를 통과했다. Godot 4.6.2의 웹 내보내기와 소스 폴더 밖에서의 패키지 실행을 오류 없이 완료했다.
