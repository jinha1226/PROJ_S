# 후속 영혼석 구현: 발동 엔진 이식

2026-09-26. 이번 구현 단위는 ②와 기존 30개 효과 이식이다. ④-a와 ④-b는 아래 순서대로 이어간다.

## 반영한 설계 수정

조건이 참인 규칙을 모은 후 발동 표식을 예약하고 여러 규칙을 함께 실행한다. 소유자 탐색에 인접 아군 오라와 소환자를 포함한다. 사전 `ALLY_LETHAL`과 사후 `ALLY_CRISIS`를 분리한다. 피해 형태·원소·주문 여부·실제 엄호 대상·치명타·처치 상태 스냅샷을 분리해 전달한다. 기존 저장 키가 별칭만으로 호환된다는 주장을 고치고 액티브 ID를 따로 관리하도록 ④를 수정했다. ③의 일반 종족은 38종이며 보스 3종은 별도다.

## 이번 구현

- [x] 효과 JSON, 조건·결과·코드 처리기·쌓임·발동 엔진을 추가한다.
- [x] 기존 30개 효과를 데이터로 옮기고 공개 API와 수치·롤 레인·발동 빈도를 유지한다. 역할 조합은 기존 코드에 남긴다.
- [x] 피해·상태·부상·이동·주문·소환·처치·회복 사건을 연결한다.
- [x] 추가 피해로 처치했을 때 보상과 처치 효과가 중복 실행되지 않게 한다.
- [x] 기본 발동은 행동당 한 번, 연쇄는 깊이 2, 추가 피해는 2차 피해로 제한한다.
- [x] 데이터 검사와 엔진 통합 검사를 CI에 넣는다. 기존 `stone_effects` 검사는 변경하지 않는다.

새 코드는 `effect_engine.gd`, `effect_conditions.gd`, `effect_actions.gd`, `effect_code.gd`, `stacks.gd`이며 정의는 `data/content/stone_effects.json`이다. 코드 처리기는 기존 반격·반사·연사·탈피·부활·기습·거머리·분노·원혼 처치처럼 순서나 특수 상태가 필요한 동작만 맡는다.
