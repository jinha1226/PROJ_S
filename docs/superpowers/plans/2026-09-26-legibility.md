# 효과 설명 UI 구현 계획

작성일: 2026-09-26 · 상태: 구현 완료 · 93개 회귀 스위트 및 웹 패키지 검증 통과

스펙: [읽히게 만들기](../specs/2026-09-26-legibility-design.md). 전투에서 발동한 효과의 기여, 눌러 읽는 키워드 설명, 장착 효과 사이의 연계를 표시한다. 추천·경고·처음 안내를 추가하지 않는다.

## 수정한 계약

- 효과 규칙을 실행할 때 `s.effect_source = {owner, effect}`를 설정한다. 중첩 발동은 안쪽 소유자를 쓰고, 실행이 끝나면 바깥 문맥을 복원한다.
- 집계는 실제 파티 멤버만 한다. 발동 수와 실제 HP 손실·회복을 기록한다. 상시 수치의 피해 몫을 추정하지 않는다.
- 예약 폭발에는 효과 소유자와 ID도 저장한다. 효과가 건 지속 피해에도 집계 문맥을 보존한다. 집계 정보가 전투의 피해량·경험치·처치 소유권을 바꾸지 않는다.
- 기본 부상과 영혼석이 직접 건 상태를 구분한다. 기본 공격으로 생긴 출혈을 모든 출혈 관련 영혼석의 피해로 나누지 않는다.
- 키워드는 원래 카드 위의 별도 자식 팝업에서 설명한다. 닫으면 카드·선택·스크롤 위치가 유지된다. 장비 상세 위에서 누르면 장비 상세 창의 자식으로 열린다.
- 기존 빌드군 키워드와 실제 상태 키워드를 구분한다. 예를 들어 같은 대상 연속 공격은 출혈을 거는 효과로 표시하지 않는다.
- 연계는 두 줄 이상이 공유하는 키워드만 묶는다. 거는 쪽 → 둘 다 → 쓰는 쪽 → 함께 순이며, 같은 쪽에서는 장착 순서를 따른다.
- 왼손의 추가 부상은 절반 확률임을 별도로 표시한다. 무기 형태와 효과 메타데이터를 추가해도 실제 전투 규칙은 변경하지 않는다.

## 1. 효과 기록과 전투 리포트

- [x] `expedition/progression/effect_report.gd`: `note`, `top`, `line`.
- [x] `effect_engine.gd`: 규칙 실행 문맥 설정·복원과 발동 수 기록.
- [x] `session.gd`, `stone_effects.gd`: 실제 피해·회복 기록.
- [x] `effect_code.gd`, `statuses.gd`: 지연 효과와 지속 피해의 집계 문맥 보존.
- [x] `run_result.gd`: 멤버 행의 `effects` 초기화.
- [x] `battle_hud.gd`: 멤버별 기여 상위 5개, 화면에 맞춘 스크롤 리포트.

행은 `battle_stats.members[id].effects[effect] = {procs, damage, heal}`다. 정렬은 피해+회복, 발동 수, 효과 ID 순이다. 0인 피해·회복 부분은 문구에서 생략하고 활동이 없는 행도 제외한다. 직접 HP를 바꾸는 부활은 실제 회복된 양만 센다.

노드 이름은 `ReportEffects_<member_id>`와 `ReportScroll`이다. 3인 파티의 각 멤버가 효과 다섯 개를 표시해도 작은 화면 안에 들어가며 긴 내용만 스크롤된다.

## 2. 키워드 설명

- [x] `data/content/keywords.json`: 현재 효과 데이터의 모든 키워드 설명.
- [x] `expedition/ui/screens/keyword_popup.gd`: `chips`, `show`.
- [x] `essence_tab.gd`: 흡수한 영혼석과 장착 슬롯 상세.
- [x] `codex_screen.gd`: 수집한 영혼석.
- [x] `popups.gd`: 가방의 영혼석과 장비 효과.

설명에는 상태의 기본 효과와 조건을 쓴다. 상태 지속·피해량이 효과마다 다르면 이를 명시한다. 골절은 모든 행동을 느리게 한다고 쓰지 않고 이동·자리 교환·물리 공격을 설명하며, 급소 노출은 다음 물리 공격의 치명타 판정과 소모를 설명한다.

노드 이름은 `KeywordChip_<keyword>`, `KeywordPopupWindow`, `KeywordPopup`, `KeywordClose`다. 새 팝업을 여는 데 원래 `modal_content`를 지우지 않는다.

## 3. 상태창 연계

- [x] `tools/fill_effect_roles.py`: 기존 키워드에 대해 setup/payoff/both 초안을 만들고 이미 있는 roles는 보존한다. `--check`는 파일을 수정하지 않는다.
- [x] `stone_effects.json`: 규칙과 코드 처리기를 대조한 키워드·roles 메타데이터.
- [x] `expedition/progression/effect_links.gd`: 무기와 장착 효과를 키워드별로 묶는 `groups`.
- [x] `character_folio.gd`: 상태 탭의 `EffectLinks` 카드.

`apply_status`, `spread_status`, 부상 확률 증가, 관련 코드 처리기는 거는 쪽으로 분류한다. 대상 상태 조건과 지속 피해 증가는 쓰는 쪽이다. 구분이 없는 소환·지원·수호 등은 함께로 읽는다. 연결이 없으면 `연계 없음`을 표시한다.

빌드군 칩과 상태 칩은 서로 다른 의미다. `families`와 전투 규칙·수치는 유지하고, 읽는 데 필요한 keywords/roles만 보완했다.

## 검증

- `tests/effect_report.gd`: 15개 검사, 반사·실제 중첩 발동·지연 폭발·효과가 건 지속 피해·문맥 복원·파티 밖 제외.
- `tests/keywords.gd`: 193개 검사, 전체 키워드 사전, 팝업 표시, 원래 카드 보존, 실제 장비 상세의 선택과 복귀.
- `tests/effect_links.gd`: 46개 검사, 적용과 활용의 순서, 무기 형태 포함, 단독 키워드 제외, 상태 키워드의 roles.
- `tests/codex_ui.gd`: 최대 3인 기여 리포트가 320×568 화면에 들어가는지 추가 확인.

CI에 세 스위트를 추가했다. 도감의 두 스위트와 기존 88개를 포함한 총 93개 스위트가 통과했다. Godot 4.6.2의 웹 내보내기와 소스 폴더 밖에서의 패키지 실행을 오류 없이 완료했다.
