# 동료 의도·스킬·판단 전환 표시 구현계획

작성일: 2026-09-24 · 상태: 구현 대기 · 실행 담당: Sol 또는 Luna

## 1. 목표와 승인된 화면

동료를 선택하지 않아도 모든 살아 있는 동료의 현재 계획을 맵에서 읽을 수 있게 한다.

- 공격: 동료에서 표적까지 반투명 실선, 표적에 작은 조준 표시.
- 이동·후퇴: 실행 예정 경로에 반투명 점선과 끝 화살표.
- 스킬: 실제 발동 시 캐릭터 머리 위에 아이콘과 짧은 스킬명.
- 주요 판단 전환: 짧은 말풍선. 같은 판단을 매 행동 반복하지 않는다.
- 새로운 설명창·상시 판단 문장·Utility 점수·전체 판단 로그를 추가하지 않는다.

AI 선택기, 가중치, 파츠 수치, 전투 속도는 변경하지 않는다. 기존 전투 연출 타이밍은 유지한다. 이번 작업은 UI와 표시용 데이터 연결이다.

관련 AI 명세는 `../specs/2026-09-24-utility-lookahead-design.md`(v2)다. 이전 `utility-ai-refactor-design.md`의 동치 보존 지침을 따르지 않는다. AI 구현은 Claude가 담당한다.

## 2. 확인한 현재 구조

- `expedition/main.gd`의 refresh 경로가 선택한 멤버에 대해서만 `command_choice → Tactics.choose`를 호출하고 `board.next_action`에 저장한다.
- `expedition/board.gd::paint_decision()`은 그 한 명의 선과 reason 문장을 foreground에 그린다. 재생 중에는 호출하지 않는다.
- board의 actor visual은 z=1, foreground는 z=2다. 카메라·피격 확대 변환과 `cell_center()`가 존재한다.
- `expedition/battle_presentation.gd`는 행동 전후 snapshot, effects, actor id만 기록한다. 현재 frame만으로 실제 스킬·판단 근거를 확실하게 복원할 수 없다.
- 전투 계산을 먼저 끝내고 snapshot을 재생하므로, 재생 중 최신 session을 읽으면 화면보다 미래의 정보를 표시할 수 있다.

구현 시작 시 위 내용과 실제 checkout을 다시 비교한다. Claude 작업으로 인터페이스가 생겼다면 기존 구현을 재사용한다.

## 3. 소유권과 작업 분리

| 파일 | 작업 |
| --- | --- |
| `expedition/companion_intent_ui.gd` 신규 | 순수 표시 모델, 판단 전환 감지, 말풍선 상태 |
| `expedition/companion_intent_overlay.gd` 신규 | 실선·점선·화살표·목표 마커 렌더링 |
| `expedition/board.gd` | overlay 연결, 스킬 배지·말풍선 렌더링, 구 표시 제거 |
| `expedition/battle_presentation.gd` | 전달받은 표시 데이터를 frame에 복사, 재생 시점 보존 |
| `tests/companion_intent_ui.gd` 신규 | 표시 모델·재생·순수성 계약 검사 |
| `expedition/main.gd` 공유 | 선택 동료 전용 preview를 전원 데이터 연결로 교체하는 최소 수정 |
| `expedition/session.gd` 공유 | 실제 선택·실행 결과를 전달하는 최소 hook, AI 담당과 통합 시 반영 |
| `.github/workflows/deploy-pages.yml` 공유 | 새 검사 한 항목 추가, 다른 변경 보존 |

금지: `utility.gd`, `lookahead.gd`, `parts_candidates.gd`, `stances.gd`, `tactical_action_selector.gd`, 프로필 JSON 수정. UI 편의를 위해 AI 동작을 변경하지 않는다.

독립 작업은 새 표시 모듈과 fixture 테스트부터 진행한다. 공유 파일의 연결은 AI 작업과 함께 확인하여 마지막에 적용한다. session hook이 아직 없다면 가짜 데이터를 실제 판단처럼 표시하지 않는다. fixture로 확인한 부분과 실제 연결이 끝난 부분을 완료 보고에서 구분한다.

## 4. AI ↔ UI 데이터 계약

다음은 **신규 협의 인터페이스**이며 현재 존재하는 필드라고 가정하지 않는다. AI의 choice를 UI용 DTO로 변환하는 adapter를 한 곳에 둔다.

```gdscript
{
    "actor_id": 1,
    "decision_id": 17,       # 행동 선택 단위의 단조 증가 id; round만으로 중복 판단 금지
    "kind": "ATTACK",      # MOVE, WAIT, GUARD 또는 실제 파츠 id
    "from": Vector2i(3, 4),
    "cell": Vector2i(4, 4),
    "target_id": 9,         # 대상이 없으면 -1; 위치로 동일성 판단하지 않음
    "path": [],             # 선택기가 확정한 경로만. MOVE는 없으면 [from, cell]
    "intent": "ATTACK",    # ATTACK, APPROACH, RETREAT, EVADE, PROTECT, HOLD, SKILL
    "reason_code": "",     # 확실한 원인이 있을 때만
    "skill_id": "",        # 실제 능력 정의 id
    "explain": []           # 진단용; 원문을 화면에 출력하지 않음
}
```

- 안정된 actor id를 사용한다. 파티 index/선택 index에 의존하지 않는다.
- 계획 preview와 성공한 실제 실행 이벤트를 별도로 전달한다. preview는 확정된 미래가 아니다.
- `command_choice`의 명령도 동일 계약으로 전달한다. 강제 후퇴·실수 등 Utility 밖의 선택도 누락하지 않는다.
- 실제 실행 frame에는 실행 전 선택 DTO와 성공 여부를 복사한다. 실행 실패·WAIT fallback을 원래 스킬 발동으로 표시하지 않는다.
- Utility explain의 기여도 1위가 곧 행동 전환 원인이라고 단정하지 않는다. 명시된 태그/이유 코드를 우선하며, 근거가 없으면 말풍선을 생략한다.
- preview 호출은 RNG·commitment·last_action·통계·AP를 바꾸지 않아야 한다. 순수 조회 API가 확인되지 않으면 UI에서 choose를 매 프레임 호출하지 않는다. AI 담당이 제공하는 안전한 preview 또는 캐시를 사용한다.
- 세 멤버의 preview는 같은 현재 상태에 대한 각각의 잠정 계획이다. 앞선 멤버의 행동 후에는 다음 멤버 계획이 바뀔 수 있다.

## 5. 계획 갱신과 재생

1. 전투 시작·행동 완료·명령 변경·장비/태세 변경 시 필요한 preview를 갱신한다. `_draw`, `_process`에서 AI 평가 금지.
2. pause 상태에서도 살아 있는 전원의 계획을 표시한다. AP가 없는 멤버의 다음 라운드를 임의로 시뮬레이션하지 않으며, 유효한 preview가 없으면 생략한다.
3. presentation frame에는 그 시점에 유효한 `intents_before`/`intents_after`와 실행 이벤트를 담는다. 실시간 session의 최종 상태를 재생 도중 참조하지 않는다.
4. frame 전반에는 before 계획을 표시하고, 행동 적용 시 after 계획으로 전환한다. 아직 유효성 확인이 안 된 계획은 숨긴다. 표시를 유지하기 위해 미래 선택을 미리 노출하지 않는다.
5. 대상 사망·소실·시야 이탈 시 선을 제거한다. 다음 판단이 있으면 그 판단으로 교체한다.
6. 전투 종료·거점 복귀·원정 초기화·board 재생성 시 계획과 말풍선 상태를 비운다.

## 6. 시각 명세

### 6.1 상시 의도 선

- 살아 있고 화면/시야에 보이는 모든 동료 대상. 동료 선택 여부와 무관.
- 기본 alpha 0.30, 두께 1.5px를 시작값으로 사용한다. 동료별 고정된 청록/금색/연보라 계열을 순환 배정한다.
- 색 외에도 선 종류·조준점·방패·화살표로 의미를 구분한다. 현재 실행 중 동료만 alpha 0.55로 강화 가능.
- 공격은 발밑에서 표적 발밑으로 잇고 중심에서 약간 잘라 캐릭터를 덮지 않는다. 공격 선은 사격 궤적/사거리 보장이 아니라 표적 연결이다.
- MOVE는 실제 path의 각 칸 중심을 잇는 점선. 경로가 없으면 다음 한 칸만. UI에서 표적까지 새 경로 탐색 금지.
- 후퇴는 점선 끝에 바깥 방향 화살표, 호위는 보호 대상에 방패 마커. WAIT는 선 없음.
- 지형 위·actor sprite 아래의 전용 overlay로 렌더링한다. mouse_filter=IGNORE 등으로 입력을 가로채지 않는다.
- board와 동일한 camera/impact transform을 **한 번만** 적용한다. 줌·팬·피격 확대에서 정렬을 유지한다.
- 화면 밖 대상은 별도 경계 화살표 없이 생략한다. 경로 중 보이지 않는 구간/미탐색 칸은 그리지 않는다. 숨겨진 적 위치 누출 금지.

### 6.2 스킬 표시

- 실제 성공 실행 이벤트에서만 생성. 기본 ATTACK, MOVE, WAIT에는 표시하지 않는다.
- 기존 `Abilities`의 이름/배지와 이미 있는 아이콘을 우선 재사용. 아이콘이 없으면 짧은 텍스트 배지 사용. 신규 이미지 생성 불필요.
- 캐릭터 머리 위에 스킬 아이콘 + 이름 1줄. 긴 이름은 영역에 맞춰 생략, 설명문 없음.
- 실행 frame의 시작부터 표시하고 0.6초를 기본 지속시간으로 한다. 배속에 동기화하되 최소 실시간 0.3초는 읽히게 한다. pause는 표시 수명을 정지한다.
- 피해 숫자·HP·다른 캐릭터 배지와 충돌을 피하도록 화면 좌표에서 위쪽 배치/경계 clamp. actor sprite의 확대된 머리 영역을 고려한다.
- 같은 actor에게 연속 발동하면 오래된 배지를 교체한다. 무제한 queue 금지.

### 6.3 판단 전환 말풍선

실제로 실행된 판단끼리 비교한다. 첫 판단과 preview 재평가에는 말풍선을 만들지 않는다.

| 전환/근거 | 문구 예시 |
| --- | --- |
| 공격/접근 → 저체력 후퇴 | `물러날게!` |
| 위험 예고·불 회피로 전환 | `위험해!` |
| 아군 구조/보호로 전환 | `엄호할게!` |
| 명시적 우선 표적 변경, 궁수임이 확인됨 | `궁수부터!` |
| 그 외 명시적 우선 표적 변경 | `저쪽부터!` |

- 기존 표적이 죽어서 다음 적을 공격하는 일반 전환은 생략한다.
- 같은 의미의 지속 행동, MOVE 좌표만 변경, 기본 공격↔평범한 공격 파츠 변경은 생략한다.
- 동료당 기본 4초 cooldown, 같은 문구는 다른 주요 판단을 거치기 전까지 반복 금지. 시간은 실제 화면 재생 중 흐른 시간 기준이며 pause에는 정지한다.
- 한 번에 말풍선 최대 2개. 위험/구조를 표적 변경보다 우선하며 오래된 대사를 queue로 뒤늦게 재생하지 않는다.
- 지속 1.2초를 시작값으로 설정. 같은 actor의 스킬 배지와 겹치면 스킬 표시 우선, 낮은 우선순위 대사는 생략한다.
- 문자열 파싱으로 행동 원인을 추론하지 않는다. 확인되지 않은 이유는 말하지 않는다.

## 7. 구현 순서와 단계별 완료 기준

### Task A — DTO adapter와 순수 표시 모델

새 `companion_intent_ui.gd`와 fixture 테스트 작성. 입력 DTO → 선/경로/배지/말풍선 descriptor를 생성한다. actor별 직전 실행 의미와 cooldown을 관리한다. 게임 객체를 수정하지 않는다.

완료: 3명 표시, 다음 한 칸 fallback, 첫 행동 무대사, 주요 전환만 대사 생성이 테스트로 확인됨.

### Task B — 맵 렌더러

새 overlay와 board 연결. 기존 `paint_decision`의 선택 동료 전용 선·설명 상자를 대체한다. HUD나 동료 선택 조작은 재설계하지 않는다.

완료: 선택 없이 전원 descriptor가 그려지고 좌표 변환·시야 필터·입력 통과가 확인됨.

### Task C — 실제 전투 연결

Claude의 최신 choice/preview API를 확인하고 adapter를 맞춘다. main의 refresh 연결과 presentation snapshot 확장을 최소 수정으로 적용한다. 실제 선택 저장 hook이 필요하면 session AI 작업과 함께 통합한다.

완료: AI와 같은 대상/스킬을 표시하고, 재생 중 미래 상태를 읽지 않으며 실패 행동을 발동으로 표시하지 않음.

### Task D — 회귀 검사와 인계

새 테스트를 CI에 추가하고 기존 `battle_presentation`, `autobattle` 및 변경된 연결부 관련 스위트를 실행한다. 테스트 파일명·실행 방식은 현재 프로젝트에 맞춰 확인한다. 공유 파일은 최신 diff를 재확인한 뒤 커밋 범위를 정한다. 다른 작업자의 변경을 되돌리거나 통째로 포함하지 않는다.

## 8. 필수 검증

- 서로 다른 적을 겨냥한 동료 3명: 선택 캐릭터 변경 없이 세 선 존재.
- 후퇴/우회: 전달받은 실제 경로만 표시, 미탐색 구간·숨은 적 미노출.
- 표적 사망: 해당 재생 frame에서 선 제거. 나중 frame의 사망을 미리 적용하지 않음.
- 스킬: 성공 시 1회 표시, 실패·평타·preview에는 없음. 상태 변화가 없는 성공 스킬도 이벤트가 누락되지 않음.
- 말풍선: 첫 행동 없음, 공격→저체력 후퇴 1회, 후퇴 반복 없음, 일반 처치 후 표적 변경 없음.
- 배속·pause·resize·camera/impact transform·board 재생성에서 시간/위치/상태 유효.
- 표시 ON/OFF로 동일 seed 전투 결과, RNG 상태, AP, last_action/commitment, 전투 통계가 같음.
- 테스트용 future session을 frame 이후 상태로 바꿔도 재생 표시가 frame 데이터와 일치함.
- 데이터 미제공·빈 explain·없는 target id에도 오류 없이 생략.
- 기존 선택 동료 설명 상자와 신규 표시가 중복되지 않음.

헤드리스 테스트를 기본으로 한다. 사용자가 요청하지 않은 캡처는 만들지 않는다. 시각 가독성을 직접 확인하지 못했다면 확인했다고 보고하지 않는다. 렌더링 데이터/좌표 검사와 실제 화면 평가는 구분한다.

## 9. 완료 보고

변경 파일, AI 데이터 연결 상태, 통과한 검사, 남은 실제 화면 확인 항목을 짧게 보고한다. mock 데이터만 붙인 상태를 인게임 완료로 보고하지 않는다. 이번 계획 작성 요청에는 메인 푸시가 포함되지 않으며, 실행 담당은 이후 사용자의 커밋·푸시 지시 범위를 따른다.
