# 모바일 전투 단순화 구현 계획

작성일: 2026-09-27 · 상태: 제안 / 구현 전

목표는 근접·원거리·마법 모두에서 **짧게 이해하고, 적은 터치로 행동하며, 빌드의 차이를 전투 중 확인하는 것**이다. 기존 조건 엔진을 활용한다. 이 문서 작성은 아래 변경의 구현 완료를 뜻하지 않는다.

현재 규칙: [영혼석 6개 영구 흡수](../../soulstones.ko.md), [영혼석 마법 연결](../../soulstone-spells.ko.md). 밸런스 측정: [밸런스 방법론](../../balance-method.ko.md).

## 1. 현재 문제와 유지할 기반

현재는 영혼석의 기본 스탯·부위별 패시브·종족 공통 액티브·선택 주문·역할 조합·속성 조합이 함께 적용된다. 예시 빌드의 설명을 이해해도 실제 기술 목록은 다른 방향으로 늘어난다. 출혈 빌드에는 물세례·방패벽이, 저격 빌드에는 투석·도끼 투척이 함께 들어온다.

조건 자체는 이미 구현되어 있다.

| 기존 조건·효과 | 구현 근거 | 사용할 방향 |
| --- | --- | --- |
| 이동하지 않은 라운드에 조준 +1, 최대 3. 이동하면 초기화 | `KOBOLD_HEART`, `not_moved_last_round`, `aim` | 집중 사격의 준비 상태 |
| 이동한 뒤 첫 공격 피해 +20% | `VAMPIRE_WING`, `moved_since_attack` | 기동 공격의 보조 효과 |
| 거리 4칸 이상에서 피해 +20% | `ARCHER_EYE`, `target_distance_at_least` | 원거리 위치 선택 |
| 전투 첫 공격 확정 치명타 | `GOBLIN_EAR`, `first_attack` | 첫 공격의 명확한 보상 |
| 원거리 명중 뒤 확률 추가 사격 | `ORC_THROW`, `second_shot` | 속사 구성의 재료 |
| 공격·적중·처치·회피·막기·피격 등 이벤트 | `EffectEngine.EVENTS` | 효과 연결과 발동 표시 |

이 효과들을 모두 새로 만들지 않는다. 기존 효과 중 무엇을 대표 규칙으로 사용할지 고르고, 준비 상태·발동 결과·중복 적용을 정리한다.

유지하는 계약:

- 전통 턴제. 주인공은 직접 행동하고, 동료·NPC·몬스터는 기존 준비 시각과 AI에 따라 행동한다.
- 영혼석은 레벨당 1칸, 최대 6칸. 흡수 즉시 적용, 교체·해제 불가, 가득 차면 추가 흡수 불가.
- 캐릭터 레벨 최대 10. 능력치·장비·신체·성격·관계·적대·구조 시스템은 이번 작업에서 전면 재작성하지 않는다.
- 동료·몬스터는 시야 밖에서도 기존 자율 행동을 계속한다. UI 단순화를 위해 시야 밖 AI를 멈추지 않는다.
- 대각선 이동·공격, 기본 공격의 접근 이동, 탐색 중지 같은 기본 조작은 우선 정상 동작해야 한다.

## 2. 큰 분류와 전투 방식

큰 분류는 **방어 / 근접 / 원거리 / 마법 / 지원** 다섯 개만 기본 화면에 표시한다. 기존 내부 ID `TANK / MELEE / RANGED / MAGIC / SUPPORT`는 유지하고 `TANK`의 표시 이름을 방어로 바꾼다.

| 큰 분류 | 전투 방식 | 대표 행동 또는 효과 |
| --- | --- | --- |
| 방어 | 회피 · 방어 · 재생 | 위치를 바꿔 피하기 / 공격을 버티기 / 회복하며 버티기 |
| 근접 | 연타 · 강타 | 같은 적을 여러 번 공격 / 한 번에 강하게 공격하고 밀치기 |
| 원거리 | 속사 · 집중 | 빠른 연속 사격 / 이동하지 않고 조준을 쌓아 사격 |
| 마법 | 폭발 · 제어 · 소환 | 범위 공격 / 이동·행동 방해 / 소환수가 함께 공격 |
| 지원 | 치유 · 강화 | 자신·동료 회복 / 아군 강화·적 약화 |

- 회피·재생처럼 자동으로 적용하기 좋은 효과는 패시브로 둔다. 모든 전투 방식에 버튼을 만들지 않는다.
- 소환·사령은 마법의 소환 방식으로 유지한다. 해골 소환과 실제 소환수 행동을 버리지 않는다.
- 기존 세부 유형 17개는 내부 효과·AI 호환용으로 남길 수 있다. 기본 화면에 17개 비율·분류를 모두 설명하지 않는다.
- 분류는 탐색과 설명에 사용한다. 분류 이름만으로 숨은 효과나 새로운 세트 보너스를 만들지 않는다.
- 시작 무기·현재 기술에서 전투 방식을 안내한다. 별도의 직업 → 방식 → 속성 선택 절차를 추가하지 않는다.

### 먼저 시험할 세 가지 구성

첫 실험에서는 근접·원거리·마법을 하나씩 만든다. 방어·지원과 나머지 방식은 이 셋의 조작·체감 검증 후 확장한다.

| 구성 | 전투 중 판단 | 기존 구현 재사용 | 최소 추가 작업 |
| --- | --- | --- | --- |
| 근접 강타 | 적을 어디로 밀어낼지, 언제 강타할지 | `PUSH`, 물리 피해·밀치기·충돌 처리 | 강타와 이동 후 강화의 연결, 피해 피드백 |
| 원거리 집중 | 자리를 유지할지, 조준을 버리고 이동할지 | `KOBOLD_HEART`, `aim`, `GOBLIN_AIM` | 조준 표시와 집중 사격 소비 규칙 |
| 마법 폭발 | 어느 위치에 적을 모아 공격할지 | 기존 `burst` 주문, 시야·사거리·범위·VFX | 고정 기술 연결과 모바일 대상 선택 |

세 구성의 차이를 먼저 확인한다. 기존 대표 효과 90개·마법 50개를 한꺼번에 다시 배분하지 않는다.

## 3. 기술·조건·속성의 단순화

### 3.1 기본 공격 + 주력 기술 + 보조 기술

기본 플레이에서는 기본 공격과 **기술 바로가기 두 개**를 사용한다. 바로가기는 주력 기술 1개, 방어·이동·치유·소환 등의 보조 기술 1개다. 기본 공격은 기존 공격 버튼으로 사용한다.

- 대표 행동은 시작 무기·시작 구성에서도 하나를 제공한다. 영혼석 여섯 개를 모은 뒤에야 빌드가 작동하도록 만들지 않는다.
- 최근 추가한 영혼석별 주문 목록 선택은 새 모바일 구성에서 **고정 기술 또는 고정 행동 강화**로 바꾼다. 영혼석을 흡수한 뒤 주문 목록을 다시 골라야 하는 단계를 없앤다.
- 부위에 붙은 효과와 함께 쓰는 기술을 명시한다. 종족이 같다는 이유만으로 모든 부위에 동일한 액티브를 자동 부여하지 않는다.
- 새 영혼석은 주로 주력 행동을 강화하거나 변형한다. 흡수할 때마다 새로운 조작 버튼이 늘어나는 것을 기본 보상으로 삼지 않는다.
- 다른 역할의 영혼석도 흡수할 수 있다. 혼합 구성을 강제로 금지하지 않는다.

**바로가기 두 개는 사용 가능 기술의 상한이 아니다.** 이미 얻은 추가 기술은 기술 목록에서 확인·사용할 수 있다. 세 번째 기술을 얻었다고 기존 기술을 지우거나 영혼석 효과를 정지하지 않는다. 바로가기 변경은 안전한 지역·야영에서 하며, 영혼석 교체와는 별개다.

기술 획득 시 빈 바로가기에 자동 배치한다. 둘 다 차 있으면 새 기술은 목록에 추가하고 기존 배치를 유지한다. 자주 쓰는 기술이 임의로 바뀌지 않게 한다.

### 3.2 조건은 대표 규칙 하나부터

각 대표 구성은 **핵심 조건 하나**로 이해할 수 있게 설계한다. 추가 영혼석은 그 조건의 보상이나 적용 범위를 바꾼다. 새로운 조건을 덧붙이는 콘텐츠는 첫 검증에서 제외한다.

예: 집중 구성은 ‘이동하지 않으면 조준이 쌓인다’가 핵심이다. 거리 조건·표식 조건·추가 사격 확률·속성 개수 조건을 동시에 갖춰야 작동하는 완성 빌드를 첫 시험 대상으로 삼지 않는다.

집중 사격의 실험 계약:

- 이동하지 않은 완료 라운드에 조준 +1, 최대 3. 기존 라운드 판정과 이동 시 초기화를 사용한다.
- 기본 원거리 공격은 기존 조준 피해 보정을 받으며 조준을 소비하지 않는다.
- 대표 집중 사격은 현재 조준의 보정을 한 번 적용하고, 유효한 사격 행동을 확정하면 조준을 소비한다.
- 대상 없음·시야 밖·사거리 초과 등 거부된 입력은 조준·MP·시간·재사용을 소비하지 않는다.
- 합법적인 공격이 빗나간 경우에는 조준과 행동 시간을 소비한다.
- 조준 보정을 기존 효과와 새 기술에서 두 번 더하지 않는다. 기존 예고·피해 계산 경로를 사용한다.

속사는 처음부터 확률 효과만으로 정체성을 표현하지 않는다. 확정 두 발 기술처럼 결과를 예측할 수 있는 대표 행동을 먼저 시험한다. 추가 사격이 적중 이벤트를 무한히 다시 부르거나 출혈·독을 과도하게 중첩하지 않도록 기존 2차 피해·행동당 발동 제한을 명시적으로 적용한다.

### 3.3 출혈·독·불은 보조 속성

처음에는 **출혈 / 독 / 불** 세 가지를 사용해 대표 구성의 변형을 시험한다. 속성은 공격 방식과 별개이며 흡수한 영혼석 데이터에서 자동으로 결정된다. 별도 속성 장착·선택 메뉴는 만들지 않는다.

| 속성 | 첫 실험에서 보여 줄 차이 |
| --- | --- |
| 출혈 | 공격 후에도 HP가 줄어들며, 지속 중인 대상이 분명히 표시됨 |
| 독 | 지속 피해를 준 뒤 다른 적을 상대하거나 거리를 벌리는 선택이 가능함 |
| 불 | 화상과 범위 공격을 통해 모여 있는 적을 상대하는 변형 |

첫 실험에서는 구성당 보조 속성 하나를 붙인다. 이것은 시험 범위 제한이며, 여러 속성 영혼석을 흡수했을 때 일부를 몰래 비활성화하는 규칙이 아니다. 실제로 흡수한 효과는 모두 적용한다.

냉기·번개·젖음·저주·소환 효과와 기존 반응 코드는 보존한다. 첫 시험에서 속성 조합 전체를 확장하거나 복합 반응의 새 레시피를 만들지 않는다. 제어 기술의 빙결·속박은 기존 상태 규칙을 사용할 수 있다.

### 3.4 역할·속성 개수 보너스는 별도 비교

현재 역할 2·4·6개, 속성 2·3개 보너스는 이해해야 할 규칙을 늘리고 대표 효과와 보상이 겹친다. **새 모바일 시험 구성에서는 이 개수 보너스를 끄는 안을 우선 비교한다.** 영혼석 자체의 기본 스탯·고정 효과는 유지한다.

기존 보너스를 설명 없이 숨겨서 계속 적용하지 않는다. 시험 프로필은 보너스 없음, 기존 프로필은 현재 보너스 적용으로 분리한다. 플레이 체감과 전투 수치가 확인된 뒤 새 원정의 기본 규칙을 결정한다.

## 4. 모바일 화면과 터치 흐름

기본 화면의 아래 영역은 다음 순서로 구성한다.

```text
로그: 최대 4줄
주력 기술 [강타]       보조 기술 [엄호]
인물 카드: 이름 / HP·MP / 필요한 상태 표시
공격 | 대기 | 탐색 | 전술 | 가방
```

기존 미니맵·현재 위치·턴수·식량·메뉴 HUD와 맵 중심의 화면은 유지한다. 기술 바로가기 다섯 칸을 두 칸으로 교체하고, 빈 기술 칸 때문에 큰 영역을 남기지 않는다.

터치 계약:

- 기본 공격은 한 번 눌러 현재 적에게 공격하거나 한 칸 접근하는 기존 조작을 사용한다. 기본 공격마다 범위 선택 창을 띄우지 않는다.
- 대상 기술은 ‘기술 누르기 → 대상 누르기’ 두 번으로 실행한다. 대상 범위를 보여 주고 필요하면 다른 기술 선택·빈 공간 터치로 취소할 수 있게 한다.
- 자기 방어·자기 강화·인접 빈칸 소환은 한 번 누르면 실행한다. 조준할 필요가 없는 기술에 대상 선택을 요구하지 않는다.
- 치유는 자신·살아 있는 아군만 선택한다. 솔로에서도 자기 치유가 가능하다.
- 드래그·길게 누르기를 필수 입력으로 사용하지 않는다. 길게 누르기는 설명 확인에만 쓴다.
- 행동 버튼의 터치 영역은 최소 44 논리 픽셀을 목표로 한다. 맵의 인접 타일 선택 영역을 무조건 확대해 서로 겹치게 만들지 않는다.
- MP·재사용·대상 조건 때문에 사용할 수 없는 기술은 상태를 표시한다. 입력 거부를 아무 반응 없이 삼키지 않는다.
- 기술 비용 확인을 위해 상태창·가방을 매번 열 필요가 없게 한다. 버튼에는 MP 또는 남은 재사용만 짧게 표시한다.
- 기술 선택 시 자동탐색·장거리 이동을 먼저 멈춘다. 취소 후 터치 이동이 정상 작동해야 한다.

상태창 영혼석 탭은 기존 여섯 칸과 실제 효과 요약을 유지한다. 각 영혼석의 기본 상세는 이름, 주력 행동에 주는 변화 한 문장, 고정 기술·비용 순서다. 정확한 수치·복합 조건은 상세에서 펼쳐 볼 수 있게 한다. 가방의 흡수 전 상세에서도 같은 정보를 제공한다.

도감 기본 필터는 큰 분류 다섯 개다. 세부 유형 비율·복잡한 빌드 분포는 기본 화면에서 제외한다. 대표 구성에는 실제 부위·기술과 일치하는 짧은 전투 흐름을 표시한다.

## 5. 조건 준비 상태와 발동 결과

준비 상태는 아이콘과 짧은 표시를 사용한다.

| 상태 | 전투 중 표시 |
| --- | --- |
| 조준 | 인물 카드 또는 기술 버튼의 조준 아이콘 + `1 / 2 / 3` |
| 이동 후 첫 공격 강화 | 해당 공격 버튼의 테두리 강조, 공격 후 해제 |
| 대표 기술 재사용 | 해당 버튼의 남은 재사용 수치 |
| 적의 출혈·독·화상 | 적 상태 아이콘과 남은 지속값 |

- 화면에 ‘이동하지 않았으므로 피해가 증가합니다’ 같은 설명 문장을 계속 띄우지 않는다.
- 준비 상태는 실제 효과가 적용 가능한 때만 보여 준다. 봉인·사망·전투 종료·이동·공격으로 상태가 바뀌면 같은 판정 결과를 읽어 갱신한다.
- UI용 조건 판정을 별도로 복제하지 않는다. 표시를 읽는 것만으로 RNG·시간·스택·HP·MP가 바뀌면 안 된다.
- 대표 강타는 짧은 충격·밀치기, 속사는 구분되는 두 발, 화상·독·출혈은 서로 다른 기존 VFX와 아이콘을 사용한다.
- 이동·카메라는 부드럽게 유지한다. 큰 화면 흔들림·매 타격 팝업·반복 말풍선으로 효과를 강조하지 않는다.
- 새 이미지가 필요하면 먼저 검토용으로 제출한다. 이번 계획의 첫 구현은 기존 에셋을 사용한다.

## 6. 데이터·코드 적용 위치

처음에는 아레나에 **세션별 시험 프로필**을 추가한다. 기존 구성과 같은 조우를 비교할 수 있어야 한다. 전역 static 데이터를 덮어써서 다른 세션까지 바꾸지 않는다.

새 바인딩의 권장 필드:

```json
{
  "simple_binding": {
    "style": "FOCUS",
    "grant_skill": "FOCUS_SHOT",
    "enhance_skill": "",
    "effect_ids": ["KOBOLD_HEART"],
    "attributes": [],
    "summary": "제자리를 유지하면 조준이 쌓인다"
  }
}
```

필드는 설계 예시이며 현재 스키마에 이미 존재하는 것으로 취급하지 않는다. 기술 부여와 기존 기술 강화는 명시적으로 구분한다. `style`이나 설명 문자열만 읽어 효과를 추론하지 않는다. 첫 버전은 기존 `rules`와 효과 ID를 최대한 재사용한다.

| 위치 | 구현 작업 |
| --- | --- |
| `data/content/essences.json` | 시험 대상 영혼석에 명시적 고정 기술·행동 강화 바인딩 추가 |
| `data/content/stone_effects.json` | 기존 조건 재사용, 중복 피해·확률·다중 발동 계약 정리 |
| `data/content/example_builds.json` | 세 가지 단순 구성 추가. 실제 구성에서 발생하지 않는 흐름 설명 제거 |
| `expedition/progression/essences.gd` | 영구 흡수·봉인 계약 유지, 새 프로필의 기술 연결·복원 |
| `expedition/progression/tag_sets.gd` | 세션 프로필에 따른 개수 보너스 판정. 기본 스탯과 별도로 제어 |
| `expedition/items/abilities.gd`, `expedition/spells/spells.gd` | 고정 기술 실행·비용·대상 판정, 기존 피해·소환·회복 경로 재사용 |
| `effect_conditions.gd`, `effect_engine.gd`, `stacks.gd` | 기존 조건·발동 제한 사용. 집중 사격 소비와 표시용 읽기 계약 보강 |
| `expedition/run/session.gd` | 시험 프로필, 바로가기 배치, 합법적인 행동 확정·취소 계약 |
| `expedition/ai/parts_candidates.gd`, `expedition/ai/tactical_action_selector.gd` | 새 고정 기술의 후보 연결. UI와 동일한 합법성·비용·대상 사용 |
| `expedition/ui/screens/floor_hud.gd` | 기술 두 개 바로가기·조건 표시·대상 선택·추가 기술 접근 |
| `essence_tab.gd`, `essence_summary.gd`, `popups.gd`, `character_folio.gd` | 영혼석 효과·준비 상태·흡수 전 정보·추가 기술 상세 |

짧은 파일명은 각각 `expedition/progression/` 또는 `expedition/ui/screens/`의 기존 파일을 가리킨다.

호환성 계약:

- 기존 원정은 기존 프로필로 계속 실행한다. 프로필 필드가 없는 기존 데이터도 기존 규칙으로 처리한다.
- 새 시험 프로필은 처음에 아레나에서만 사용한다. 새 원정의 기본값 변경은 아래 검증 후 별도 단계다.
- 기존 `active / spells / rules`를 바로 삭제하지 않고 새 바인딩과 함께 보관한다. 기존에 고른 주문·흡수한 영혼석을 자동으로 잃게 하지 않는다.
- NPC·동료도 자기 세션의 같은 효과 규칙을 읽는다. 사용자 화면에서 감춘다고 실제 능력이 사라지거나 별도 수치가 적용되지 않게 한다.

## 7. 구현 순서와 완료 조건

### 단계 1 — 기준선과 작은 시험 구성

현재 커밋·장비·레벨·종족·파티 인원·조우·시드를 기록한다. 근접 강타 / 원거리 집중 / 마법 폭발의 고정 아레나를 만든다. 영혼석 0개와 1개에서도 기본 전투가 성립하는지 확인한다.

완료 조건: 기존·시험 세션을 동시에 생성해도 서로 영향을 주지 않는다. 비교 결과에 조건과 실제 획득 기술이 기록된다.

### 단계 2 — 대표 행동과 조건 연결

세 구성의 주력 기술을 고정한다. 각 구성의 핵심 조건은 하나부터 사용한다. 집중 소비·이동 초기화·기술 취소·중복 보정·2차 공격 제한을 검사한다. 마법은 기존 실패율을 일단 유지하며 바로가기에 실패 가능성을 확인할 수 있게 한다. 확정 시전 비교는 별도 실험으로 기록하고 몰래 면제하지 않는다.

완료 조건: 동일 조우에서 세 구성의 유효한 위치·공격 순서가 다르다. 강화된 공격과 일반 공격의 차이가 준비 상태 및 실제 결과로 확인된다.

### 단계 3 — 두 개 바로가기와 모바일 상세

기존 다섯 칸 기술 바를 두 칸으로 바꾼다. 추가 기술의 목록 접근, 흡수 전 설명, 스크롤 상세를 연결한다. `320×568 / 390×844 / 430×932`에서 가로·세로 범위와 실제 캔버스 확대를 확인한다.

완료 조건: 주력 대상 기술은 최대 두 번, 자기 기술은 한 번의 터치로 사용한다. 바로가기에 없는 획득 기술도 사용할 수 있다. 긴 이름·비용·6개 영혼석 상세 때문에 화면이 늘어나지 않는다.

### 단계 4 — 속성 하나씩과 체감 확인

각 구성에 출혈·독·불 중 하나를 붙인 변형을 시험한다. 역할·속성 개수 보너스 유무는 다른 조건을 고정한 별도 비교로 기록한다. 조준 유지를 위해 대기만 반복하거나 스킬 하나만 반복하는 지배 전략을 확인한다.

완료 조건: 설명을 읽지 않아도 어떤 상태가 준비됐고 무엇이 발동했는지 구분할 수 있다. 단순히 피해 숫자만 커진 것인지, 위치·타이밍·대상 선택도 바뀌었는지 기록한다.

### 단계 5 — 방어·지원·소환과 NPC

앞 단계가 통과하면 방어·지원과 소환을 같은 조작 체계에 넣는다. 자기 치유·인접 아군 보호·빈칸 소환·영입한 동료의 기술 사용을 확인한다. NPC의 새 기술 후보가 없어서 기술을 보유하고도 못 쓰는 상태를 허용하지 않는다.

완료 조건: 솔로에서 지원 기술이 불필요한 버튼이 되지 않는다. 동료가 합류해도 별도 복잡한 기술 편집을 요구하지 않는다. 시야 밖 행동·성격·관계·적대·구조 동작이 유지된다.

### 단계 6 — 새 원정에 적용

사람이 세 구성의 차이와 조작을 확인한 뒤 새 원정의 기본 프로필을 결정한다. 선택된 영혼석부터 바인딩을 옮기고 도감 설명을 갱신한다. 기존 원정과 카탈로그 전체를 한 번에 강제 변환하지 않는다.

완료 조건: 같은 레벨·장비의 기준 전투, 1인 및 최대 3인 조우, 원정 누적 자원을 각각 검증한다. 확정할 규칙을 [영혼석 문서](../../soulstones.ko.md)에 반영하고 본 계획의 단계별 결과를 기록한다.

## 8. 검증과 수집할 자료

자동 검사는 기존 `part_effects / effect_engine / effect_data / part_stones / role_combos / essence_spells / stone_magic / build_actives / mobile_hud / essence_ui / npc_essences / companion_tactics`를 변경된 프로필 계약에 맞춰 유지한다. 새 회귀 검사는 다음 실제 실패 가능성에 집중한다.

- 취소·거부된 입력으로 조준·MP·시간을 잃음.
- 이동·자리 교환·전투 종료·봉인 후 준비 상태가 남거나 UI만 사라짐.
- 두 발 공격·추가 사격이 무한 재발동하거나 속성을 잘못 중첩함.
- 기술 세 개 이상 획득 후 기존 기술·효과가 누락됨.
- UI를 갱신하는 것만으로 RNG·스택·피해 상태가 변함.
- 프로필이 다른 두 세션·NPC에 효과 또는 설정이 누출됨.

측정은 다음을 분리한다.

| 항목 | 확인할 내용 |
| --- | --- |
| 조작 | 공격·기술당 터치 수, 취소·오입력, 기술 사용을 위한 메뉴 진입 수 |
| 조건 | 조준 최대 단계 도달·소비·이동 초기화, 이동 후 강화 발동, 준비 후 미사용 |
| 전투 | 접근·대기·기본 공격·기술 행동 수, 경과 tick, 받은 피해·유효 회복·MP 비용 |
| 구성 차이 | 위치 변경, 사거리 활용, 밀치기·광역의 실제 기여, 한 행동만 반복하는 비율 |
| 원정 | 층 도달·후퇴·사망 위치, 남은 HP·MP·식량, 야영·소모품 사용 |

초기 사람 확인은 같은 조건의 짧은 조우를 구성별로 반복해서 진행한다. ‘핵심 규칙을 한 문장으로 설명할 수 있는가’, ‘다음 행동의 결과를 예상할 수 있는가’, ‘같은 적을 다른 방식으로 상대했는가’를 기록한다. 막히는 부분을 설명을 더 붙여 해결하기보다 행동과 표시를 먼저 수정한다.

회귀 검사 통과·자동 승률 개선은 재미의 통과 조건을 대신하지 않는다. 전투 수치의 목표 범위는 기준선 실측 후 정하고, 모바일 조작 및 구성 차이를 사람에게서 확인한 기록과 함께 판단한다.
