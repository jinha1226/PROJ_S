# 원정 UI 안내와 상황 튜토리얼 구현 계획

- 작성: 2026-09-16
- 조사 기준: `c912a85`
- 상태: **계획만 작성. 구현·배포는 후속 지시 시 진행한다.**
- 사용자 결정: UI 설명과 상황 튜토리얼을 함께 제공한다. 상단 소음 표시는 숨기지 않는다.

## 1. 목표와 범위

첫 플레이에서 화면을 읽는 방법과 핵심 행동을 이해하도록 돕는다. 별도 연습장이나 고정 동선은 만들지 않는다. 기존 절차적 맵과 쓰러진 NPC의 랜덤 위치를 유지한다.

초기 범위는 UI 세 구역 안내, 이동, 첫 전투, NPC 구조, 특수부위 결속, 동료 전투불능, 층 이동이다. 튜토리얼 때문에 아이템·기술·동료를 지급하거나 전투 및 은신 규칙을 변경하지 않는다. 기존 길드 의뢰 튜토리얼과 보상 체계는 분리한다.

## 2. 첫 원정의 UI 안내

캐릭터 생성과 시작 화면이 닫히고 실제 던전 화면이 준비되면 시작한다. 한 장에 한 구역만 강조한다. 확인과 건너뛰기를 제공하며 전 화면의 모든 버튼을 하나씩 강제로 누르게 하지 않는다.

| 순서 | 강조 영역 | 설명 |
|---|---|---|
| 1 | 상단 | 미니맵 터치로 전체 지도, 실제 층·지역명, 조작 인물의 식량 개수, 은신·경계·발각, 소음 표시, 메뉴 |
| 2 | 초상화와 기술 줄 | 조작 인물 변경, HP·MP, 선택 인물의 기술 상시 표시, 빈 슬롯의 의미 |
| 3 | 최하단 | 공격 → 휴식/대기 → 탐험 → 전술 → 가방. 적 유무에 따른 휴식/대기 전환 |

### 오해를 막는 문구

- 은신: 현재 보이는 적의 인식 상태를 표시한다. 보이지 않는 적까지 안전하다는 뜻은 아니다. 은신 성공 확률로 설명하지 않는다.
- 식량: 개수와 포만도는 다른 정보다. 현재 상단 개수는 조작 인물의 소지 식량이며, 포만도는 기존 상세 정보에 따른다.
- 소음: `—`를 유지한다. 현재 수치가 연결되지 않은 상태라는 짧은 설명을 제공한다. 임의 게이지나 가짜 소음 수치를 만들지 않는다.
- 기술: 빈 슬롯은 아직 기술이 없는 자리다. 안내를 위해 가짜 시작 기술을 넣지 않는다.

## 3. 상황별 안내

| ID | 발동 조건 | 안내할 행동 | 중복·노출 제한 |
|---|---|---|---|
| move | 첫 UI 안내 종료 후 조작 가능한 원정 화면 | 지도 터치 이동, 자동 탐험과 중지 | 최초 한 번 |
| combat | 현재 시야에 살아 있는 적이 처음 들어옴 | 직접 대상 선택, 공격, 사거리 밖 접근, 기술 선택 후 대상 지정, 대기 | 화면 밖 적으로 발동하지 않음 |
| rescue | 첫 쓰러진 NPC와 실제 상호작용 가능 | 물약 확인·주기, 돕지 않기 선택 | NPC 좌표·발견 시점은 바꾸지 않음. 물약 없는 경우도 설명 |
| part | 첫 결속 가능한 특수부위가 파티 인벤토리에 들어옴 | 인물의 숙련·이능 화면에서 부위 결속 후 기술 사용 | 획득 표시와 실제 결속 완료를 구별. 기존 저장도 조건 충족 시 안내 가능 |
| downed | 현재 파티원이 실제 전투불능 상태가 됨 | 10턴 유예, 남은 턴 확인, 회복·부축·도주 | 이야기용 쓰러진 NPC와 구별. 구현된 구조 조건을 확인하고 문구 확정 |
| stairs | 실제 다음 층 진입 평가가 허용됨 | 층 진입 버튼, 적을 모두 처치할 필요 없음 | 단순 계단 이미지나 숨겨진 포탈 좌표로 발동하지 않음 |

안내 확인은 행동 성공과 다르다. 1차 구현에서는 강제 과제나 완료 보상을 넣지 않는다. 결속·구조 방법은 해당 화면의 실제 버튼 명칭과 가능 조건을 확인한 후 최종 문구를 확정한다.

## 4. 표시와 입력 정책

- 한 번에 한 장만 표시한다. UI 안내는 정해진 순서로 진행한다.
- 상황이 겹치면 동료 전투불능 → NPC 구조 → 전투 → 특수부위 → 층 이동 순으로 선택한다.
- 다음 안내를 열 때 현재 조건을 다시 평가한다. 지나간 상황의 팝업을 뒤늦게 연속 출력하지 않는다.
- 캐릭터 생성, 가방, 인물 상세, 지도, 전리품, 확인창 등 다른 창이 열려 있거나 손가락 제스처가 진행 중이면 안내를 보류한다.
- 안내 중 자동 탐험·휴식·경로 이동·자동 전투의 시간 진행을 막는다. 시뮬레이션 시간과 유예 턴은 감소하지 않아야 한다.
- 안내 종료 후 자동 행동을 즉시 재개하지 않는 방향을 기본안으로 한다. 기존 예약 경로와 세대 번호를 점검해 사용자의 다음 조작으로 안전하게 재개한다.
- 안내 뒤 지도와 버튼은 입력을 받지 않는다. 확인 터치의 release 및 합성 mouse 이벤트가 게임으로 전달되지 않아야 한다.
- 강조할 영역은 실제 컨트롤 좌표를 사용한다. 화면 크기 변경 시 다시 배치한다.
- 320px 폭에서도 글자가 잘리지 않도록 줄바꿈과 필요 시 본문 스크롤을 사용한다. 확인·건너뛰기는 44px 이상이며 항상 보이게 한다.

## 5. 건너뛰기·다시 보기·저장

- UI 안내의 `건너뛰기`: 초기 UI 안내 묶음을 종료한다. 이후 상황 안내는 유지한다.
- 별도 `자동 안내 끄기`: 모든 자동 안내를 끈다. 효과를 명확히 표시한다.
- 메뉴 → `화면 도움말·튜토리얼`: UI 및 상황 항목 목록에서 원하는 설명을 직접 다시 본다. 전체 순서를 강제하지 않는다.
- 메뉴 → `자동 안내 다시 켜기`: 아직 확인하지 않은 상황의 안내를 재개한다.
- 기기별 로컬 설정에 안내 버전, 확인한 ID, 자동 안내 활성 여부를 저장한다. 게임의 결정론적 세이브·명령 로그에는 넣지 않는다.
- 재시작·새 원정에서도 확인한 안내는 반복하지 않는다. 재열람은 확인 이력이나 자동 안내 설정을 바꾸지 않는다.
- 저장 실패 시 현재 실행 중에는 상태를 유지하며 경고만 기록한다. 손상된 설정은 기본값으로 복구한다.
- 브라우저 저장소를 지우거나 다른 기기를 사용하면 안내가 다시 나올 수 있다. 클라우드 동기화는 초기 범위 밖이다.

## 6. 기존 코드 조사와 연결 지점

| 파일·API | 활용 계획 |
|---|---|
| `playtest/party_encounter_sandbox.gd` | 상단·파티·기술·하단 컨트롤 참조, 메뉴 추가, 입력 차단, 자동 진행과 모달 생명주기 연결 |
| `playtest/guild_tutorial_hud.gd` | 기존 길드 의뢰 UI. 원정 안내와 혼용하지 않음 |
| `party_playtest_session.gd`: `party_status`, `party_cards` | 현재 시야와 파티원의 실제 상태 확인 |
| `opening_event_status` | 첫 NPC 상호작용 가능 시점 |
| `ability_binding_item_rows` | 실제 결속 가능한 부위 소지 여부 |
| `floor_transition_assessment` | 다음 층 진입 가능 여부 |
| `exploration_header_status` | 상단 인식 표시의 현재 의미 확인 |
| `graphics_mode_preferences.gd` | 기존 로컬 설정 저장 방식 참고 |

새 구성요소는 안내 내용·발동 조건, 로컬 진행 저장, 표시 오버레이로 책임을 나눈다. 발동 검사는 행동 결과가 UI에 반영되는 지점에서 수행하고, 매 프레임 전체 파티 상태나 인벤토리를 재계산하지 않는다. 전체 refresh뿐 아니라 연속 탐험·전투의 가벼운 refresh 경로도 조사한다.

기존 일반 테스트에서는 자동 안내를 명시적으로 비활성화하거나 임시 설정 경로를 주입한다. 튜토리얼 전용 통합 테스트에서는 실제 발동 경로를 켜서 검증한다.

## 8. 필수 검증

1. 신규 기기 상태에서 던전 준비 후 UI 안내가 한 번 시작된다. 캐릭터 생성 위에는 뜨지 않는다.
2. 확인·초기 안내 건너뛰기·전체 자동 안내 끄기의 효과가 각각 다르며 재실행 후 유지된다.
3. 메뉴에서 임의 항목을 다시 열 수 있고, 재열람이 자동 안내 설정을 바꾸지 않는다.
4. 화면 밖 적, 이야기용 쓰러진 NPC, 바닥에 놓였지만 줍지 않은 부위로 잘못 발동하지 않는다.
5. 상황 안내가 중복되지 않으며, 여러 조건이 겹치면 긴급 상황을 우선한다.
6. 자동 탐험·휴식·예약 경로가 있는 중 안내를 열어도 시간·HP·아이템·유예 턴이 진행되지 않는다.
7. 터치 press/release, 합성 mouse, 마우스, 키보드 입력이 각각 한 번만 동작하고 배경 행동을 실행하지 않는다.
8. 다른 모달과 겹치지 않으며 화면 전환·원정 종료·새 게임에서 오래된 안내가 남지 않는다.
9. 320×640, 390×844, 450×800에서 본문과 확인 버튼에 접근 가능하고 강조 위치가 맞는다.
10. 안내를 열고 닫기만 한 경우 게임 스냅샷과 명령 로그가 바뀌지 않는다. 기존 모바일 HUD·구조·층 이동 검사를 통과한다.

## 9. 현재 산출물

이번 작업은 이 계획서만 남긴다. 작성 도중 시작한 코드 초안은 제거했으며 튜토리얼 기능은 아직 추가하지 않았다. 소음 표시를 포함한 기존 상단 UI는 유지한다.
