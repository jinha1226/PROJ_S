# 9방 던전 추가 계획 — 전술·입구 배치·식량과 개인별 휴식

## 1. 적용 범위와 우선순위

상위 문서: [9방 던전 구현 계획](nine-room-dungeon-implementation.ko.md).

이 문서는 이후 대화에서 정리한 설계를 추가한다. **식량 소모·회복에 관한 이전의 시간 경과 기반 설명과 충돌하면 이 문서를 우선한다.**
문서 작성 시 HEAD는 `2d2e904`이며 9방 구현 작업의 미커밋 코드가 존재한다. 이번 작업에서는 그 코드를 수정·실행·커밋하지 않고 문서만 추가한다.
상위 계획의 턴제 선택 절차는 유지한다. 본 문서로 아군/적 진영별 턴제 전환을 자동 승인하거나 현 혼합 라운드를 삭제하지 않는다.

## 2. 식량·회복 최종 계약

포만도 자원은 없애지 않는다. 목적은 이동에 통행료를 매기는 것이 아니라 **안전한 곳에서의 무제한 휴식을 제한하는 것**이다.
내부 `ration_milli`와 파티 공용 식품을 재사용한다. UI 명칭을 `파티 식량`으로 바꾸는 것은 권장안이며 별도 전체 UI 개편은 필요 없다.

| 상황 | 식량 소모 | 회복 |
|---|---|---|
| 방 안의 비전투 이동·대기 | 없음 | 일반적인 시간 기반 자연회복 없음 |
| 방 사이 이동·재방문 | 없음 | 전환 자체의 회복 없음 |
| 배치·예고 확인·메뉴·현실 시간 대기 | 없음 | 없음 |
| 실제 전투 중 이동·대기 | 없음 | 개인별 소량 자연회복 허용 |
| 전투 도주 처리·추격 | 없음 | 별도 회복 보너스 없음; 전투 회복 규칙만 해당 경계에서 적용 |
| 안전한 곳에서 명시적 휴식 | **휴식 1회당 파티 고정 비용** | 각자의 자동회복량에 휴식 배율을 적용 |
| 음식·물약·회복 능력 사용 | 해당 자원/아이템 규칙 | 해당 효과를 유지; 휴식과 구분 |

방 이동 고정 식량 비용, 탐험 이동마다 소모, 전투 시간 소모는 채택하지 않는다.
식량이 부족하면 휴식할 수 없다. 부족하다는 이유로 전투 중의 이동·대기 회복까지 끄지 않는다.
본 설계의 식량 고갈 효과는 휴식 제한이다. 기존 시간 기반 굶주림 피해·스트레스가 계속 돌아 신규 규칙을 우회하지 않도록 새 ruleset에서 분리한다.

### 실제 전투와 전투방의 구분

- 전투방이라는 방 유형만으로 회복을 허용하지 않는다. 전투가 끝난 빈 방에서 기다리면 회복되지 않는다.
- 방 상태의 실제 교전 여부/활성 encounter를 판정 원본으로 사용한다. 다른 방에 적이 있다는 이유로 안전한 현재 방을 전투 상태로 유지하지 않는다.
- 전투 중 이동·대기로 조금 회복하며 버티는 선택은 허용한다. 적을 남겨 두는 전략을 별도 굶주림/강제 피해로 막는 기능은 이번 범위가 아니다.
- 공격 기회를 포기하는 선택과 실제 적의 위협이 비용이다. 회복 때문에 적 턴을 생략하거나 적 AI를 정지시키지 않는다.
- 전투 중 식사는 기존대로 금지하고 물약 사용은 유지한다. 고기·특수부위 섭취와 변이 슬롯/중복 제한을 삭제하지 않는다.

## 3. 개인별 안전 휴식 계산

전원 최대 HP의 일정 비율 회복, 무조건 완전 회복, 주인공 회복량을 모든 동료에게 복사하는 방식은 사용하지 않는다.

### 공통 원칙

```text
파티 식량 비용 = REST_FOOD_COST        # 참여자별 반복 차감하지 않음

인물 i의 회복량 = 개인 자연회복률(i, 자원) × 휴식 회복 단위
실제 회복량 = min(회복량, 해당 자원의 현재 결손량)
```

개인 자연회복률은 각 인물의 종족/능력치/활성 변이·상태/부상 등 실제 연결된 보정에서 계산한다.
각 보정을 한 번만 적용하며, 없는 회복 효과를 UI 문구만으로 추정해서 더하지 않는다. 신규 변이 회복 효과를 연결한다면 그 효과의 정의와 이벤트 검증까지 같이 연결한다.

| 자원 | 계산 원칙 |
|---|---|
| HP | 개인 HP 자연회복률 × 휴식 단위 × 해당 HP 회복 보정. 부상의 자연회복 저하 적용 |
| MP | 개인 MP 자연회복률 × 휴식 단위 × MP에 명시적으로 연결된 보정. HP 부상 배율을 무조건 복사하지 않음 |
| 피부/근육/뼈 내구도 | 각 인물·부위·조직의 회복률을 별도로 계산. 조직별 속도를 유지하며 HP 회복량을 그대로 조직마다 더하지 않음 |

현재 동일 조직 회복률을 공유하는 인물들은 보정이 같으면 같은 양이 회복될 수 있다. 무작위 개인차를 새로 만들어 차이를 강제하지 않는다.
절단 부위는 일반 휴식으로 재생하지 않는다. 조직 회복이 부상 단계 임계값을 넘으면 기존 골절/깊은 상처/기능 회복 규칙과 전투 수치가 즉시 갱신되어야 한다.

### 수치화·반올림

- `REST_FOOD_COST`, `REST_RECOVERY_UNITS`, `REST_TIME_COST`는 데이터로 분리한다. 이번 대화에서 정확한 숫자는 확정하지 않았다.
- 초기 휴식 배율은 개인의 자연회복 단위를 몇 회 적용할지로 표현한다. HP가 높은 캐릭터에게 자동으로 더 큰 고정 비율 회복을 주지 않는다.
- 낮은 회복률도 반복 휴식에서 영구히 0이 되지 않도록 fixed-point 잔여량/누적 차분을 사용한다.
- 잔여량이 있다면 개인·자원·조직별 권위 상태에 보관하고 저장/로드한다. UI를 닫거나 이동해도 초기화하거나 추가 지급하지 않는다.
- HP/MP/내구도가 상한에 도달하면 남은 결손만 회복하며, 초과분을 저장해 다음 피격 직후 무료 회복시키지 않는다.

## 4. 안전 휴식의 실행 흐름

1. 현재 방의 교전·추격·환경 위험·파티 위치와 휴식 가능 대상을 검사한다.
2. 활동 파티 중 회복 가능한 결손이 하나라도 있고 고정 비용 이상 식량이 있는지 확인한다.
3. 인물별 현재 회복 프로필에서 예상 회복량을 계산해 보여준다. preview는 시간/식량/RNG/회복 잔여량을 변경하지 않는다.
4. 휴식 요청을 commit할 때 파티 식량을 정확히 한 번 차감하고 정해진 휴식 시간을 진행한다.
5. 정상 완료 시 같은 개인 회복 프로필 규칙으로 회복을 적용하고 로그·상태창·초상화를 갱신한다.

안전 판단은 기존 규칙을 재사용하되, `다른 방에 적 존재`와 `현재 방 위험`을 구분한다.
전원이 완전히 회복되어 있거나 일반 휴식으로 고칠 수 없는 절단만 남으면 휴식을 거부하고 식량을 쓰지 않는다.
대상자는 활동 파티의 휴식 가능한 생존 인물이며 예비 NPC/다른 방 NPC에게 공짜 회복을 지급하지 않는다. 쓰러진 동료의 소생은 기존 구조/회복 규칙을 유지하고 이번 변경으로 자동 소생을 추가하지 않는다.

### 중단·롤백 제안

- 사전 검사 실패/중복 클릭/낡은 revision: 무소모, 시간 변화 없음.
- 내부 오류: 식량·시간·회복·이벤트를 함께 롤백한다.
- 휴식 시간이 실제로 진행되다 추격/새 위협으로 중단: 시간과 식량 소비는 유지하고 미완료 휴식의 회복은 지급하지 않는 것을 초기 정책으로 제안한다. 이를 UI에 안내하고 반복 취소로 무소모 시간을 얻지 못하게 한다.
- 진행 중 앱 종료/재개: 같은 휴식 요청을 두 번 차감/회복하지 않는다. 단계와 요청 ID를 저장한다.
- 연속 휴식 버튼은 단발 휴식 요청을 반복할 뿐이다. 매회 필요 회복량·안전·식량을 재검사하고 전원 회복/부족/위협에서 중단한다.

## 5. 전투 자연회복과 이중 지급 방지

- 전투 중 실제로 확정된 MOVE/HOLD가 회복 허용 행동이다. 이동 예고, 배치, 취소된 이동, 실패한 명령은 회복을 지급하지 않는다.
- 현 혼합 라운드에서는 여러 이동 타일을 지나갔다고 타일마다 동일 회복을 지급하지 않는다. 한 인물이 얻을 회복 시간/기회는 그 인물의 라운드 행동 예산 안에서 누적한다.
- 라운드 시간 경계가 100이라면 참여자가 많다고 회복 시간이 300/600으로 불어나지 않는다.
- 이동+공격을 택한 경우와 공격만 한 경우의 회복 자격은 구현 시 명시한다. 초기 제안은 공격/스킬/아이템을 실행한 슬롯에는 대기 회복을 추가하지 않는 것이다. 사용자 확정 내용은 이동·대기 회복 허용이며 모든 공격의 회복까지 확정한 것은 아니다.
- 전투 종료 경계에서 마지막 MOVE/HOLD 회복은 한 번만 판정하고, 다음 비전투 대기로 시간을 넘겨 추가 회복을 얻지 못한다.
- 전투 회복, 기존 안전 자동회복, 명시적 휴식이 같은 시간 경계에서 중복 적용되지 않도록 recovery context를 구분한다.
- 물약, 명시적 회복 변이, 지속 재생 상태는 별도 효과다. 일반 대기 회복 제거를 이유로 해당 아이템/능력 효과까지 삭제하지 않는다. 지속 재생이 의도적으로 무한 회복을 제공하는 변이가 있다면 별도 밸런스 항목으로 보고한다.

## 6. 전투방 입구 배치

사용자 제안: 진입한 입구의 두 칸 이내에서 원하는 대로 초기 배치.

- 첫 전투 진입에서는 기존 대형의 자동 배치를 기본으로 보여주고, 바꾸고 싶은 인물만 조작한다.
- 배치 가능 영역은 입구 기준 지형 이동 거리 2 이내다. 벽을 관통하는 직선 거리로 계산하지 않으며 기존 대각선 규칙을 사용한다.
- 안전하고 점유되지 않은 셀만 후보로 사용한다. 생성 단계에서 초기 3인 파티의 안전 셀 최소 3개를 확보한다. 더 큰 파티를 허용하면 최대 파티원 수와 생성 계약을 함께 수정한다.
- 적 배치/첫 예고/보호 목표를 확인하고 `전투 시작`으로 확정한다. 배치에 식량·회복·행동 시간을 부여하지 않는다.
- 배치 중의 공격 preview는 `배치 중 예고`로 구분하고 현재 가배치에 따라 갱신할 수 있다. 시작 직전 보여준 최종 preview와 실제 시작 계획이 같아야 한다. 시작 버튼을 누른 뒤 숨겨진 재조준으로 공격 대상을 바꾸지 않는다.
- 도주 후 재진입, 추격당한 진입에는 무료 재배치를 주지 않는 것을 초기 정책으로 한다. 실제 입구 대형을 유지한다.
- `initial_deployment_used`는 방/encounter 권위 상태에 저장한다. 재접속이나 왕복으로 초기 배치 권한이 되살아나지 않는다.

## 7. 작은 전장을 위한 적·지형 역할

공격력만 다르게 하지 않고 위험 타일의 형태와 대응 방법이 달라지게 한다. 아래 개별 적 구성은 구현 제안이다.

| 역할 | 초기 공격 | 대응/지형 |
|---|---|---|
| 고블린 전사 | 인접 한 칸 | 비켜서기, 먼저 처치 |
| 고블린 궁수 | 직선 원거리, 첫 충돌 대상에 적중 | 기둥 엄폐, 사선에 적 밀기 |
| 돌진수 | 직선 돌진 후 충돌 지점 정지 | 벽/적 충돌 유도 |
| 주술사 | 예고된 작은 구역 공격 | 범위 이탈, 시전 방해 |
| 방패병 | 정면 방어가 강한 근접 적 | 측후면 접근, 위치 변경 |

먼저 전사+궁수부터 구현하고 이후 한 역할씩 확장한다. 기존 몬스터/이능 정의를 확인해 재사용하며 단순 UI 아이콘만 다른 가짜 공격을 추가하지 않는다.
공격 고정 셀/방향/첫 충돌/밀려난 공격자/벽 차단/아군 오사/보호 대상 충돌을 공통 규칙으로 정의하고 preview와 실제 해결이 같은 함수를 사용해야 한다.
8×8에 모든 역할과 장애물을 한꺼번에 넣지 않는다. 첫 배치부터 피해를 피할 방법이 전혀 없는 조합을 생성 단계와 템플릿 검사에서 걸러낸다.
패턴 소개 방은 한 가지 역할, 이후 방은 배운 역할 두 가지 조합을 우선한다.

## 8. 보호 목표 전투

첫 시도는 **보급 상자 하나를 지키는 선택형 전투**다. NPC 구조나 봉인 장치 방어는 후속 변형으로 둔다.

- 적이 상자를 노리는 공격도 동일하게 예고한다. 보호 대상을 숨겨진 자동 피해로 파괴하지 않는다.
- 모든 관련 적을 처치하거나 정해진 방어 경계를 버티면 보상을 준다. 방어 턴 수와 적 수는 아직 미확정이며 템플릿 데이터로 둔다.
- 상자 파괴는 해당 보상 상실이지 런 즉시 실패가 아니다. 파괴 뒤 전투/퇴각 가능 여부는 기존 방 규칙을 따른다.
- 보호 중 후퇴할 수 있다. 초기 제안은 해당 방어 목표를 실패로 확정하는 것이며, 재입장해 방어 카운터를 초기화해 보상을 반복 얻지 못한다.
- 상자는 `온전함 → 파손 → 파괴` 단계로 읽히게 한다. 내부 내구도/피해 매핑은 별도 설정하고 보이는 단계 및 실제 공격 결과를 일치시킨다.
- 실제 전투 시간 경계에서만 카운터가 증가한다. 캐릭터 수, 이동 칸수, preview, 초기 배치로 방어 턴을 벌지 못한다.
- 동일 경계에서 마지막 적 사망/목표 파괴/방어 완료가 겹칠 때의 우선순위는 `목표 파괴 판정 → 생존 목표의 성공 판정`을 초기값으로 한다.
- 상태 `INACTIVE/ACTIVE/SUCCESS/FAILED`, 목표 ID, 남은 경계 수, 보상 지급 이벤트 ID를 저장한다. 성공 보상/전리품은 정확히 한 번 지급한다.
- 제한된 9방 중 일부 전투방의 encounter 변형으로 배치하며 별도 10번째 방을 추가하지 않는다.

## 9. 현재 코드와 구현 순서

확인한 현재 코드에는 새 합의와 다른 동작이 있다. ‘이미 연결되어 있음’으로 가정하지 않는다.

- `sim/party_recovery_rules.gd`: 현재 STR/INT 기반 HP/MP, 부상의 HP 보정, safe delay/interval을 사용하고 안전 조건/피격으로 회복 누적을 초기화한다. 그대로 호출하면 전투 중 이동·대기 회복 계약과 맞지 않으므로 맥락별 분리가 필요하다.
- `sim/body_penalty_rules.gd`: 현재 `heal_layers`는 피부/근육/뼈에 고정 회복 속도를 적용한다. 개인별 조직 회복 보정을 연결할 읽기 원본을 따로 정의하고 절단 제외·단계 회복은 유지한다.
- `sim/party_ration_rules.gd`, `data/content/hunger_rules.json`: 현재 시간 간격·추가 파티원 소모·굶주림 피해 설정을 전제로 검사한다. drain 값을 0으로 바꾸는 것만으로 끝내지 말고 새 소모 정책과 schema/ruleset 검증을 추가한다.
- `sim/party_encounter_state.gd`: 식량·회복 누적과 새 명시적 휴식 요청/회복 잔여량의 저장 위치를 정한다. 과거 ruleset 재생을 새 정책으로 소급하지 않는다.
- `sim/systems/field_turn_system.gd`, `sim/systems/round_combat_system.gd`, `sim/systems/room_transition_system.gd` (구현 여부 확인): 탐험/전투/도주/방 이동 경계에서 식량 drain과 회복을 각각 한 번만 라우팅한다.
- `playtest/party_playtest_session.gd`, `playtest/party_encounter_sandbox.gd`: 휴식 preview/commit, 실제 교전 상태, 연속 휴식 중단, 각 인물의 회복 표시와 UI 반영.
- `sim/abilities/*`, 소비품 서비스: 회복 변이·물약·고기·식량 이벤트와 새 휴식 정책의 중복/충돌 점검.

### 단계

1. **식량·회복 계약 우선:** 개인 회복 프로필 원본, recovery context, 고정 식량 비용의 단발 휴식, 저장·롤백과 HUD 설명부터 연결한다.
2. **두 방 실험과 입구 배치:** 초기 배치/재진입 제한, 교전 종료 후 대기 회복 차단, 방 왕복 무소모/무회복을 검사한다.
3. **전사+궁수:** 사선·엄폐·오사의 preview/실행 일치를 검증한다.
4. **상자 보호전 1종:** 목표 상태·보상·도주 실패·재방문 저장을 연결한다.
5. 검증 후 적 패턴과 NPC 구조전으로 확장한다. 미확정 수치를 대규모 밸런스 개편으로 묶지 않는다.

## 10. 인수 검사

- 방 안 100회 이동/대기, 방 20회 왕복, 메뉴 장시간 열기: 식량 감소 없음. 비전투 일반 자연회복 없음.
- 실제 전투 중 MOVE/HOLD: 각 개인 회복량에 맞게 회복, 식량 불변. 공격/이동+공격 회복 정책을 별도 명시하고 테스트.
- 다중 이동 경로·여러 동료·preview 반복·취소로 회복이 중복 지급되지 않음.
- 동일 결손 HP/MP를 가진 두 인물에 서로 다른 자연회복률을 부여하고 같은 휴식에서 서로 다른 양 회복을 확인.
- 한쪽의 HP 회복 부상 보정만 바꾸면 그 인물의 HP 회복만 바뀌고 다른 인물/MP에 잘못 전파되지 않음.
- 조직별 회복·골절 해소·깊은 상처 해소·절단 비재생과 상태창 수치 즉시 갱신.
- 식량 비용은 1인/3인, 중복 클릭, 전체 회복 인물 혼합에서도 휴식 한 회당 정확히 한 번. 식량 부족/전원 완치 요청은 무소모.
- 식량 0에서도 전투 MOVE/HOLD 회복은 가능하고 비전투 휴식만 불가. 기존 기아 타이머의 우발적 피해/스트레스 없음.
- 회복 소수 잔여량, 휴식 단계, 식량, encounter 배치 권한, 목표 방어 카운터의 JSON/스냅샷/저널 왕복 일치.
- 입구 2칸 후보가 벽/위험/점유 셀을 포함하지 않고 최소 파티 배치 수를 만족. 초기 가배치 preview와 시작 결과 일치.
- 후퇴/재입장으로 배치·보호 보상·회복을 재발급하지 않음. 상자 파괴와 성공 동시 발생의 판정 순서 고정.
- 실제 모바일에서 개인별 예상 회복과 공용 식량 비용이 한눈에 보이는지 확인. 부상/HP/MP 화면을 다시 열지 않아도 결과 갱신.

## 11. 아직 정해야 할 수치

휴식 식량 비용·휴식 배율/시간, 전투 회복 간격, 조직별 개인 보정 계수, 보호 목표 내구도와 방어 경계 수, 궁수 사거리/피해는 이번 대화에서 정하지 않았다.
