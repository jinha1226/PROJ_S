# NPC 성장 · 공용 가방 · 계획 교체

## 범위

사용자 요청: NPC 레벨/숙련, 공용 가방과 섭취 대상 선택, 공격 지정 시 기존 이동 계획 제거.
추가 질문: 가독성 개선 전에 이미지 생성 목업을 비교할지 검토.
화면의 큰 재배치와 이미지 생성은 아직 하지 않았다. 기능 수정과 화면 디자인 결정을 분리한다.

## 구현

- 동료/NPC에 독립 XP와 근거리·원거리·마법·방어 숙련을 저장한다. 초기 레벨은 1이다.
- 파티의 적 처치 보상은 생존한 활동 동료에게도 동일 XP를 지급한다. 독립 탐험 NPC의 처치는 해당 NPC에게 지급하고 주인공에게 주지 않는다. 같은 사망 사건의 중복 보상을 방지한다.
- 동료 숙련 포인트는 기존 주인공과 같은 레벨 규칙을 사용하고, 안전한 곳에서 동료의 숙련 탭에서 투자한다. 자동 배분 정책은 추가하지 않았다.
- 무기 공격, 방어·회피·막기 수치, 액티브/패시브 변이의 숙련 배수를 해당 행위자의 성장 상태에서 읽는다. 구형 비플레이어 종족은 XP/숙련 구조에만 인간 성장 트리를 사용하고 실제 종족 전투 능력치는 바꾸지 않는다.
- 동료의 상태창에 레벨/경험치, 숙련 탭에 2×2 숙련 카드를 노출한다. 성장/아이템 조작은 저널과 스냅샷 저장에 연결한다.
- 가방은 파티의 미장착 물품을 한 목록으로 표시한다. 용량은 기존 가방 1개 분량을 공유한다. 기존 저장·합류로 초과된 물품은 삭제하지 않고 전부 표시하며 추가 줍기/장비 해제를 제한한다.
- 장비는 캐릭터별로 유지한다. 선택한 동료에게 공용 물품을 장착하고, 포션·식품·특수부위는 대상 선택 후 해당 인물에게 적용한다. 특수부위는 기존 안전/포만감/중복 변이 제한을 유지한다.
- 전투 중 물약은 대상 동료의 라운드 행동으로 예약하며 계획 단계에서는 소모하지 않는다. 고기 식사는 기존대로 전투 밖에서만 가능하다. 감정·독 투척 등 기존 추가 대상 선택은 유지한다.
- 기존 개별 인벤토리 저장 행은 호환용 보관 위치로 유지한다. 사용/장착 시 자동으로 물품을 라우팅하고, 실패 시 원래 위치·개수·상태로 롤백한다. 구형 용량 초과 저장에서 대상의 보관 행까지 가득 찬 경우에는 물품을 먼저 정리해야 할 수 있다.
- 공격/스킬/대기를 지정하면 기존 이동 경로를 지운다. 이동 명령은 명시적으로 이동+행동을 구성할 수 있도록 현재 행동을 유지한다.

## 검증

통과한 headless 검사:

- `tests/party_growth_bag_acceptance.gd`: 동료 성장·포인트·저장/JSON, 동료 물약/고기, 대상 외 변이 불변, 잘못된 대상 무변경, 공용 목록, 동료 장착, 공격 계획 교체.
- `tests/round_combat_ui.gd`: 360×800 / 390×844 입력 연결, 동료 숙련/공용 가방 탭 노출.
- `tests/round_combat_advanced.gd`: 순차 전투·미리보기·저장 회귀. 초기 비플레이어 종족의 성장 복제 오류를 수정한 뒤 재검사 통과.
- `tests/expanded_consumables_acceptance.gd`: 기존 확장 물약/스크롤 효과 회귀 통과.

별도 실행한 `tests/mastery_live_acceptance.gd`는 현재 UI와 맞지 않는 기존 단언에서 완료하지 못했다. 이 테스트는 `주변 적` 문구를 요구하지만 현재 UI는 `전투 중`이고, 삭제된 `StatusCombatSummary` 노드를 직접 참조한다. null 참조 이후 프로세스를 종료했다. 이를 통과로 계산하지 않는다. 현재 UI 노출은 위 라운드 UI 검사로 별도 검증했다.

실물 모바일 시각 검증, 장시간 성능 검증, 새 목업에 맞춘 UI 재설계는 하지 않았다.

## 목업에서 결정할 것

동일한 실제 전투 상황을 두 안으로 비교한다. 현재보다 많은 정보를 추가하지 않는다.

1. 전장 중심: 전장을 크게 쓰고 선택한 인물의 이동/공격을 자세히, 나머지는 간략히 표시.
2. 순서 중심: 얇은 행동 순서 바에서 인물을 선택하면 전장 예고와 연결.

필수 정보는 현재 인물, 예정 행동 순서, 적 위험 타일, 아군 수정 여부, 진행 버튼이다.
실제 모바일 비율·아이소매트릭 투영·기존 스프라이트 크기를 고정하고, 장식보다 작은 크기에서의 판독성을 비교한다.
이미지 모델 목업은 합의용이며 구현 가능성과 터치/스크롤 가독성은 실제 UI에서 별도로 확인한다.
