# 식량·개인별 휴식 구현 기록

범위는 후속 계획의 식량·회복 시스템이다. 입구 배치·궁수·보호 목표는 포함하지 않는다. 기존 혼합 라운드와 소비품·변이의 별도 회복 효과를 유지한다.

## 초기 수치와 실행 계약

사용자가 확정한 밸런스가 아니라 검증을 위한 초기값이다. 휴식 비용은 파티 공용 식량10, 회복 단위6, 경과 시간100이다. 데이터 파일에서 조정한다. 최초 제안10단위는 기본 MP 상한12를 대부분 채워 개인차가 가려지므로6단위로 줄였다. 기존 자연회복의 STR/INT 20당1 증가를 밀리 단위로 계산해 낮은 능력치 구간도 누적한다. HP에만 기존 부상 회복 배율을 적용하며 MP에 복사하지 않는다. 조직은 기존 피부25/근육15/뼈8 속도를 유지한다.

새 런은 별도 회복 ruleset을 기록한다. 기존 저장의 ruleset은 자동 변경하지 않는다. 일반 이동·대기·방 전환은 식량을 소모하거나 안전 자동회복을 지급하지 않는다. 식량0의 시간 기반 기아 피해도 끈다. 실제 전투의 확정 MOVE/HOLD만 개인당 라운드100시간에 한 번 회복한다. 공격·스킬·아이템을 실행하는 계획에는 이동 회복을 추가하지 않는다.

명시적 휴식은 전체 파티에 고정 비용을 한 번 지불한다. 사전 실패·낡은 revision·중복 요청은 무소모다. 내부 실패는 상태와 이벤트를 함께 롤백한다. 실제 경과 중 위협/피해가 생기면 지불한 비용과 시간은 유지하며 휴식 회복은 지급하지 않는다. 단발 휴식은 동기적 원자 트랜잭션이며 저장은 완료/중단된 경계에서 이루어진다. 연속 휴식은 매번 새 요청을 발행한다.

HP/MP의 소수 잔여량은 개인별 권위 상태에 저장하고 상한 도달 시 제거한다. 조직 회복은 현재 정수 단위 원본을 재사용한다. 절단은 회복하지 않으며 조직 임계값과 전투 부상 수치를 즉시 갱신한다. preview는 상태·시간·식량·RNG·잔여량을 바꾸지 않는다.

## 검증 결과

Godot 4.6.2 headless에서 아래 검사를 통과했다. NTFS의 스크립트 로딩 지연을 피하기 위해 기존 검증 프로젝트를 Linux 임시 폴더에 복사하고 현재 구현 파일을 덮어써 실행했다.

- `tests/nine_room_care_acceptance.gd`: 안전 이동·대기100회 무소모·무회복, 식량0 기아 피해 없음, 반복 preview 무변경, 전체 회복·식량 부족·낡은 요청·중복 요청·잘못된 설정의 무소모 거절, 휴식 고정 비용/시간, 개인별 능력치·부상·소수 잔여량, 절단 제외, 실제 전투 HOLD 회복, 권위 상태 감사와 snapshot 복원.
- `tests/nine_room_care_replay.gd`: 실제 이동→전투→퇴각·추격→안전한 방 휴식, 전체 식량 무소모 구간, 휴식 명령 저널의 정확한 저장·재생, 기존 schema1 저장의 이전 식량/회복 정책 보존. 360×800 native UI에서 휴식 확인창을 열어도 상태가 변하지 않고 실제 확인에만 비용이 지급됨을 확인했다.
- `tests/nine_room_transitions.gd`, `tests/nine_room_combat.gd`: 방20회 왕복 무소모 및 기존 방 전환·후퇴·추격 동작.
- 기존 `tests/round_combat_advanced.gd`, `tests/rest_and_pickup_regression.gd`, `tests/nine_room_ui.gd`: 혼합 라운드·오사 경험치, 이전 정책의 휴식·줍기, 모바일 보드 UI 회귀.

실제 휴대폰 터치·웹 내보내기는 이번 검증 범위에 포함하지 않았다. 연속 휴식은 같은 단발 요청을 반복하는 UI 경로이며 회복 완료·식량 부족·위협 또는 중단 시 멈춘다. 초기 수치는 플레이 밸런스 확정치가 아니다.
