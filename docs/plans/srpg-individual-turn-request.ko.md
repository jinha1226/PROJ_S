## 사용자 승인 범위

1. 맵의 기둥을 누구나 기둥으로 알아볼 수 있도록 이미 제작한 기둥·장애물 에셋을 실제 렌더링에 적용한다. 기존 authored 기둥 위치와 충돌을 보존하고 바닥 무늬처럼 보이지 않도록 크기·배치·깊이 정렬을 검증한다. 새 이미지 제작은 필요하지 않다.
2. 적 증원 주기를 완료된 전투 6턴에서 7턴으로 늘린다. 2마리, 활동 적 상한 8, 안전한 외곽 빈 칸, 마지막 적 처치 시 증원 없음은 유지한다.
3. 적 선이동·고정 칸 공격 예고 → 아군 전체 계획 → 일괄 실행 구조를 일반적인 SRPG 개별 행동 순서 구조로 바꾼다. 아군과 적이 같은 행동 순서에 참여하고, 현재 아군의 이동·공격/스킬·대기를 확정하면 해당 캐릭터의 행동을 실행한 뒤 다음 순서로 진행한다. 적도 자기 차례에만 이동·공격한다. 동료는 각자 차례에 조작할 수 있어야 한다. 다른 캐릭터의 미래 계획을 한꺼번에 실행하지 않는다.
4. 기존 `initiative/order`의 검증된 속도 기준과 동률 규칙을 재사용한다. 현재 캐릭터·다음 행동 순서·남은 이동/공격 횟수를 UI에서 확인하게 한다.
5. 이동속도에 따라 이동 범위를 1·2·3칸으로 정한다. 공격속도에 따라 기본 공격 횟수를 정한다. 구체적인 속도 구간·기본값·무기 시간/재장전·부상/상태 효과의 반영은 기존 속도 체계를 읽고 실행 protocol에 명시한다. 공격 횟수 소진·대기·사망·행동 불능·턴 종료가 일관되게 다음 순서로 이어져야 한다. 스킬/아이템을 기본 공격 횟수만큼 무료 반복하는 방식은 피하고 소모 규칙을 기록한다.
6. 증원용 1턴은 전체 행동 순서가 한 바퀴 완료된 전투 라운드로 정의한다. 개별 캐릭터의 행동이나 공격 횟수마다 증원 카운터를 증가시키지 않는다. 배치/관찰/계획 수정은 카운터를 소모하지 않는다. 증원은 도착 라운드에 즉시 공격하지 않는다.

## 실행·평가·종료

실행 전에 구체적인 protocol을 작성·커밋하고, 구현·관련 회귀 검증·실제 모바일 크기 화면 확인·결과 문서·commit까지 수행한다. 현재 Git의 미추적 이미지 import/uid/기타 사용자 파일을 보존한다. 기존 첫층 방당 초기 적 1마리 계약과 HP/피해 공식은 유지한다. 필요하면 저장 형식 호환 처리를 기록하고 기존 저장을 삭제하지 않는다.

검증에는 기둥의 실제 화면 식별성/충돌, 아군·적 혼합 순서, 현재 캐릭터만 행동, 이동속도별 1/2/3칸 경계, 공격속도별 횟수/중복 입력 방지, 사망·턴 건너뛰기, 7라운드 증원 및 전멸 후 증원 없음, 저장 복원/재생, 모바일 입력을 포함한다. 적 예고 방식 전제의 기존 테스트는 새 계약으로 갱신한다. 학습·대규모 밸런스 탐색·후속 실험·추가 정책 변경은 범위 밖이다. 런타임 배포가 기존 실행 흐름에 포함되면 기존 검증된 경로를 따른다.

완료 후 반환 세션에 작업 ID, 완료/중단/검증 실패 상태, 결과 문서 경로와 commit을 간결하게 queue로 보낸다. 결과의 사실·한계·플레이 확인 필요 사항은 문서에 기록한다.
