# 8×8 전장 · 3×3 구역 던전 구현 계획

후속 설계: [전술·입구 배치·식량과 개인별 휴식](nine-room-combat-rest-addendum.ko.md).
식량 소모와 회복의 최신 계약은 후속 문서를 우선한다. 방 이동/전투에 식량을 소모하지 않고, 안전 휴식만 고정 비용을 사용하며 개인 회복량을 반영한다.

## 1. 목적과 인수인계

작업 폴더: `/mnt/d/STARTU/living-world-legacy-integration`

확인한 기준 commit: `e238803`. 구현 세션은 시작할 때 최신 코드와 차이를 확인하고 사용자 변경을 보존한다.
이 문서는 계획이다. 이 문서 작성으로 게임 로직 변경, 새 세션 실행 요청, 배포를 수행하지 않는다.

핵심 경험:

> 플레이어는 하나의 던전을 걸어서 탐험한다. 연결 통로를 넘어가면 화면이 옆방으로 이어지고, 각 방은 한 화면에 들어오는 8×8 전장이 된다. 방 선택 화면은 없다.

전체 재구축을 한 번에 하지 않는다. 연결된 방 두 개로 경계 이동·전투·도주를 검증한 뒤 9개 구역과 기존 콘텐츠를 연결한다.

## 2. 확정 사항과 설계 기본값

### 사용자와 확정한 내용

- 한 층은 3×3으로 배치된 방 9개, 각 방의 논리 격자는 8×8이다.
- 화면에서 다음 방을 선택하지 않는다. 상하좌우 연결 통로로 걸어가면 인접 방으로 자연스럽게 전환된다.
- 오른쪽 출구로 나가면 옆방 왼쪽 입구로 진입하는 등 공간적 대응을 유지한다.
- 모든 방을 전투방으로 채우지 않는다. 전투, 위험 지형/전리품, NPC/휴식, 계단을 배치한다.
- 재방문 시 적 사망, 아이템, 지형 변화 등 해당 방 상태를 유지한다.
- 모든 경계를 개방하지 않고 연결 통로, 막다른 길, 우회로를 만든다.
- 미니맵은 방문한 방과 발견한 연결만 표시한다.
- 전투 중에도 출구를 통해 도주할 수 있으나 방 왕복으로 적 공격을 무료 취소하지 못하게 한다.
- 화면 배치는 승인된 A안의 전장 중심 방향을 따른다. 목업 이미지를 배경으로 붙이는 구현은 하지 않는다.

### 이 계획의 구현 제안값 — 사용자 확정 수치와 구분

아래 수치는 첫 플레이테스트용 기본값이며 설정 파일로 분리한다.

| 항목 | 초기 제안 |
|---|---|
| 시작 방 | 중앙 `(1,1)`, 안전한 방, 통로 2~3개 |
| 방 구성 | 전투 4 / 위험 지형·전리품 2 / 시작·NPC·휴식 2 / 계단 1 |
| 그래프 | 전체 연결 트리 8개 연결에 루프 1~2개 추가; 상하좌우만 연결 |
| 전투방 초기 적 | 보통 2~3마리; 첫 방 실험은 아군 3 대 적 3을 상한으로 시작 |
| 통로 폭 | 1~2타일; 진입측 안전 배치 후보 최소 3칸 |
| 내부 공간 | 통과 가능 타일 최소 40/64; 장식은 가능하면 통행을 막지 않음 |
| 전환 연출 | 약 180~250ms 방향 슬라이드; 연출 시간은 게임 시간과 무관 |
| 전투 이탈 집결 | 출구 중심 체비쇼프 거리 2 이내에 활동 파티원이 모여야 함 |
| 추격 | 출구에서 경로 거리 2 이내의 추격 가능한 적, 최대 2마리 |

`8×8`은 벽/장애물도 포함하는 논리 타일 수다. 외곽 벽의 시각적 두께를 이유로 내부를 무조건 6×6으로 줄이지 않는다. 통로는 안전 배치와 전술적 접근 공간을 확보한다.

## 3. 턴 구조는 구역 구조와 분리한다

현재 구현은 아군/적 혼합 순서, 동료 제안 편집, 전체 계획 진행 방식이다. 최근 대화에서 더 단순한 진영별 턴제를 추천했지만, 사용자가 명시적으로 확정한 것은 이번 방 구조다.

- **필수 범위:** 기존 전투에 구역 경계와 저장/도주 처리를 연결한다.
- **별도 승인 후 진행할 범위:** 아군 자유 선택 → 이동/공격 → 턴 종료 → 적 예고 실행 방식으로 전환하고 동료 계획 편집을 제거한다.
- 방 두 개 실험에서 조작 부담을 비교하고 진영별 턴제 채택 여부를 정한다. 구역 도입을 핑계로 현재 라운드 구현을 먼저 삭제하지 않는다.
- 아래 이탈 규칙은 공통 의미 계약이다. 현재 라운드와 향후 진영별 턴에 맞는 실행 어댑터만 구분한다.

승인된 레이아웃 참고: `docs/mockups/tactical-mobile-v1/a-battlefield-first.png`.
기존 계획 참고: `docs/plans/round-planned-combat-implementation.ko.md`.

## 4. 공간·맵 생성

### 논리 좌표와 저장

첫 버전은 기존 좌표/엔티티/아이템 권위를 보존하기 위해 한 층의 단일 WorldState를 유지하는 방식을 우선한다.

```text
room_coord = (rx, ry), 0 ≤ rx, ry < 3
room_id = ry * 3 + rx
local_cell = (x, y), 0 ≤ x, y < 8
world_cell = room_coord * 8 + local_cell
```

내부 저장 크기는 24×24로 둘 수 있지만 **24×24 전체를 자유롭게 이동하거나 보여주는 월드로 구현하지 않는다.**
구역 membership과 portal만 이동/시야/AI 경계를 결정한다. 물리적으로 인접한 좌표라도 연결 통로가 아니면 넘어갈 수 없다.
방 전환은 월드 생성/삭제가 아니라 활성 구역 변경이며, 이 구조로 방별 객체 복제와 저장 소실을 피한다.

기존 월드 생성 경로가 24×24를 허용하는지 먼저 점검한다. 기존 생성기의 `MIN_SIZE`와 기존 저장 재생성을 무작정 수정하지 말고, 새 ruleset의 별도 생성기를 추가한다.

### 결정론적 생성 순서

1. 층 seed에서 그래프, 방 유형, 지형, 적, 전리품용 별도 seed를 파생한다. 전투 RNG를 소비하지 않는다.
2. 9개 방 모두 도달 가능한 상하좌우 그래프를 만들고 우회로를 추가한다.
3. 시작 방을 고정한 뒤 그래프 최단거리가 먼 방에 계단을 배치한다. 나머지 유형을 할당한다.
4. 연결된 방 쌍마다 양쪽 portal 위치/폭/진입 방향을 함께 생성한다. 짝이 없는 출구는 허용하지 않는다.
5. 출구 사이 길, 파티 진입 영역, 적 배치 금지 영역을 먼저 예약한 뒤 기둥/낮은 벽/물/전리품을 배치한다.
6. 각 방의 필수 출구 간 도달성과 진입 배치 가능성을 검사한다. 실패하면 정해진 횟수만 재시도하고 검증된 단순 템플릿으로 대체한다.

층당 방 구성 합계는 정확히 9개다. 시작 방은 안전 구역 2개 중 하나이며, 계단도 별도 10번째 방으로 추가하지 않는다.
NPC/휴식 역할 방에도 매번 NPC와 모닥불을 모두 생성할 필요는 없다. 배치 개수는 역할 템플릿의 설정으로 관리한다.

## 5. 플레이 흐름과 경계 입력

```text
현재 방 탐험
  → 연결 통로로 이동
  → 이탈 가능 여부·진입 공간 검사
  → 필요한 시간/적 행동 해결
  → 파티·추격 상태와 active_room을 원자적으로 변경
  → 카메라 방향 전환
  → 새 방 탐험 또는 전투
```

- 실제 타일 `(7,y)`의 출구에 접근하면 이동 대상 표시가 옆방 방향으로 이어진다. 별도 ‘다음 방’ 버튼이나 지도 선택 팝업은 없다.
- **출구 셀에 진입하는 정상 이동 요청**을 전환 요청으로 해석한다. 같은 셀을 다시 누르는 추가 확인은 요구하지 않는다.
- 반대 방에서는 짝 출구 바로 안쪽 예약 위치에 배치한다. 등장한 위치가 출구라 해도 자동으로 역전환하지 않는다. 전환은 신규 사용자 이동 의도로만 발생한다.
- 길게 누르기/자동 이동의 남은 입력은 전환 경계에서 취소한다. 터치 한 번이 여러 방을 연속 통과하지 않게 한다.
- 대각선 이동으로 방 모서리를 건너뛰거나 두 방을 한 번에 넘을 수 없다. 방 안의 기존 대각선 허용 규칙은 유지한다.
- 세계 북쪽 출구의 화면 이동 방향은 기존 아이소매트릭 투영으로 변환한다. 논리 상하좌우를 화면 수직/수평과 혼동하지 않는다.
- 적대 구역의 내용을 애니메이션 미리보기로 노출하지 않는다. 새 방 공개는 전환 commit 이후다.

## 6. 파티 진입과 출구 막힘

- 주인공만 포탈에서 이동하고 동료를 어디서든 순간 소환하지 않는다.
- 안전 탐험 중에는 기존 따라오기/집결로 자연스럽게 출구에 모인다. 집결이 필요하면 이동 예고와 짧은 안내로 보여주되 장거리 무시간 끌어오기는 금지한다.
- 전투 이탈은 활동 파티원 전원이 출구의 집결 범위 내에 있고 이동 가능한 경우에만 신청할 수 있다. 멀리 있는 동료, 쓰러진 동료를 자동으로 버리지 않는다.
- 첫 버전에서 동료 유기/들쳐메기 UI는 추가하지 않는다. 이탈 불가 이유를 `동료가 멀리 있습니다`, `이동할 수 없는 동료가 있습니다` 등으로 명확히 표시한다.
- 진입 배치는 주인공 → 파티 순서의 안정적인 순서로, 짝 출구에서 가까운 안전 셀부터 선택한다. 엔티티 ID로 동률을 해소한다.
- 살아 있는 적/동료와 겹치거나 벽/위험 타일에 강제 배치하지 않는다. 적을 지우거나 재배치해서 공간을 만들지도 않는다.
- 진입 공간 부족은 사전 검사로 거부한다. 공간을 확보할 수 없는 경우 원래 방에 머물며 추가 시간/아이템을 소비하지 않는다.
- 단, 전투 중 적 행동을 이미 해결한 뒤 발생한 이탈 실패는 해당 전투 결과를 되돌리지 않는다. 신청 전 거부와 실행 후 실패를 구분한다.

## 7. 시간·도주·추격 계약

### 안전 탐험

출구에 진입하는 한 번의 이동 비용에 방 전환을 포함한다. 기존 지형/부상 기반 이동 시간은 적용하되 `이동 비용 + 별도 전환 비용`으로 이중 과금하지 않는다.
애니메이션이 오래 걸려도 음식·회복·상태 시간이 추가로 흐르지 않는다.

### 전투 중 이탈 — 무료 공격 취소 방지

첫 버전 제안은 **파티 전체의 후퇴 신청**이다. 각자 탈출해 두 방에서 동시에 전투하는 구조는 범위 밖이다.

1. 출구 진입 요청과 집결 검사를 통과하면 `pending_exit`을 기록한다.
2. 그 시점 이후의 아군 미실행 공격/아이템 계획을 취소하고 후퇴 대기로 표시한다. 이미 쓴 자원과 행동은 복구하지 않는다.
3. 현재 적의 미해결 행동 기회를 한 번씩 해결한다. 예고된 공격은 현재 방에서 실제 위치/사거리/생존 조건으로 판정한다. 명중을 강제하지도, 이탈 신청만으로 무효화하지도 않는다.
4. 정해진 전투 경계의 세계 시간·상태 tick을 한 번 진행한다.
5. 파티가 생존·집결·이동 가능 조건을 유지하면 방 전환을 commit한다. 조건이 깨졌다면 후퇴는 실패하며 전투 결과와 시간은 유지한다.

현재 혼합 라운드에서는 이미 행동한 적을 다시 실행하지 않는다. 남아 있는 적 슬롯을 끝내고 현재 라운드의 100단위 시간 경계를 한 번만 처리한다.
향후 진영별 턴제를 채택하면 후퇴 신청이 아군 턴을 마치고 적 턴을 한 번 해결하는 형태로 매핑된다.
모든 적의 행동이 끝난 시점에 신청한 후퇴에 별도 보복 공격을 추가하지 않는다.

### 추격 제안

- 이탈 처리 뒤 출구 근처의 이동 가능한 적 중 추격 AI 상태인 최대 2개체를 안정적으로 선정한다.
- 복제/새로 소환하지 않고 같은 entity ID, HP, 부상, 상태, 전리품 권한을 유지한다.
- 도착 방에 `pending_pursuit`으로 기록하고, 출구에 추격 경고만 표시한다. 숨겨진 적의 이름·정확한 능력은 공개하지 않는다.
- **새 방에서 플레이어가 최소 한 번 대응할 수 있는 행동 기회**가 지난 뒤, 다음 적 행동 경계에 출구의 빈 셀로 들어온다. 등장 그 자체와 첫 공격을 같은 경계에서 처리하지 않는다.
- 진입 셀이 막혀 있으면 추격자는 큐에 대기한다. 파티나 기존 적을 밀어내지 않는다.
- 계속 방을 왕복하더라도 추격 경과·대기 상태를 초기화하지 않는다. 반대 방향 이동 시 같은 적이 양쪽 방에 중복 존재해서는 안 된다.
- 오래된 출발 방의 공격 타일을 도착 방 로컬 좌표로 재사용하지 않는다. 적의 새 공격 예고는 도착 후 다음 적 계획 생성 시 만든다.

이탈/추격 수치와 행동 기회 판정은 설정 및 순수 규칙 함수로 분리한다. 구현 전에 2방 실험 결과로 적절성을 확인한다.

## 8. 시뮬레이션·시야·성능 경계

- 상세 이동/전투 AI, FOV, 타일 렌더링은 현재 방과 대기 추격자만 대상으로 한다.
- 비활성 방의 적은 매 프레임 움직이거나 싸우지 않는다. 부재중 오프스크린 전투는 첫 버전에서 중단한다.
- 시간은 층 전체의 단일 권위다. 방 변경으로 쿨다운·버프·중독을 초기화하지 않는다.
- 비활성 방에서 시간제 효과가 어떻게 만료/누적되는지 별도 표를 작성한다. 원래 absolute expiry를 유지하고, 필요한 누적 피해만 재진입 전 한 번 정산한다. 무한 틱 반복과 중복 사망 보상을 금지한다.
- 독립 NPC는 기존 성격/관계/성장 데이터를 보존하되, 방 밖에서의 상시 타일 단위 이동은 하지 않는다. 구역 간 자율탐험을 다시 연결하는 것은 별도 후속 작업이다.
- 이웃 방이 월드 좌표상 바로 붙어 있어도 시야, 소리 탐지, 경로 탐색, 투사체, 광역기, 피해 숫자, 클릭 검사는 구역 경계를 넘지 않는다. 예외는 명시적인 portal 이동뿐이다.
- 카메라는 현재 8×8 보드를 맞춰 보여준다. 자유 줌아웃으로 9개 방의 적/전리품을 볼 수 없게 한다.
- 방은 경계에서 한 번 갱신한다. 매 이동마다 9개 방 재생성, 매 프레임 전체 층 snapshot/AI/preview는 금지한다.

## 9. 권위 상태·저장·저널

새 ruleset 예: `nine-room-dungeon-v1`. 다음 구조는 구현 명칭 제안이다.

| 상태 | 필수 정보 |
|---|---|
| 층 | schema/ruleset/generator version, floor seed, floor index, 방 그래프, active_room_id |
| 방 | room_id, coord, role, bounds, visited/discovered, arrival candidates, enemy/feature references |
| portal | stable portal_id, 두 room_id, 양쪽 출구/입구, 방향, 통행 조건 |
| 이탈 | 요청 ID, 출발 방, portal_id, actor_id, 단계, expected revision |
| 추격 | entity_id, source/target room, portal_id, 등장 가능한 행동 경계, 아직 미실행인 상태 |
| 파티 | 현재 방, 기존 entity ID/인벤토리/성장/부상/관계의 기존 권위 유지 |

지형·아이템·HP를 방 상태에도 중복 복제하지 않는다. 기존 WorldState를 원본으로 하고 방 구조는 참조/영역 인덱스를 갖는다.

공개 API 제안:

- `room_status()` — 현재 공개 가능한 정보만 반환.
- `assess_room_exit(actor_id, portal_id)` — 비변경 사전 검사.
- `request_room_exit(actor_id, portal_id, expected_revision)` — 기존 이동 입력의 내부 경계 명령.
- `resolve_pending_exit()` — 전투 경계에서 이탈 확정/실패 처리.
- `visible_room_minimap()` — 발견한 구역·연결만 반환.

입력 반복은 요청 ID/revision으로 막는다. 전환 원자적 commit에는 활성 방, 파티 위치/occupancy, 추격 큐, 인지/방문 상태를 함께 포함한다.
저장은 연출 프레임이 아니라 권위 상태를 기록한다. commit 전 앱 종료는 출발 상태, commit 후 종료는 도착 상태에서 재개하고 애니메이션만 생략할 수 있다.
계획 편집 중 이탈, 중독 사망, 포션 사용, 자동 이동과의 저널 replay 순서도 동일해야 한다.

세이브 정책 제안: 신규 런에만 새 ruleset을 적용하고 기존 런은 기존 생성기로 유지한다. 이전 런 데이터가 필요 없다는 과거 발언만으로 저장 파일을 자동 삭제하지 않는다. 하드 리셋을 선택한다면 로드 거부 안내와 새 런 시작을 명시적으로 구현한다.

## 11. 단계별 작업과 완료 조건

### P0 — 구현 전 계약 정리

- 기준 commit, 새 ruleset, 기존 저장 정책, 기존 전투 어댑터를 기록한다.
- 비활성 방 시간제 효과 표와 전환 이벤트 순서를 코드 작성 전에 결과 문서에 명시한다.
- 유지 기능: HP→부상, 휴식 회복, 피부/근육/뼈 표시, NPC 성장, 변이/고기, 미감정 소비품, 공용 가방, 적 오사와 기존 대각선 이동.

### P1 — 두 방 수직 단면

- 8×8 두 방, 짝 출구 하나, 기존 파티/적을 사용한다.
- 네 방향 경계 이동을 별도 fixture로 검사한다.
- 원래 방 상태 유지, 앱 재개, 미니맵, 카메라 전환을 연결한다.
- 현재 전투에서 pending_exit와 추격까지 시험한다. 이 단계에서 사용자에게 조작 부담과 화면 가독성 검토를 요청한다.

### P2 — 9방 생성과 층 진행

- 3×3 연결 그래프/방 배분/입구 예약/계단 접근을 생성한다.
- 처음에는 현재 구현된 1·2층을 사용하고 층 수를 추가하지 않는다.
- 방 재진입은 적·아이템 재생성을 하지 않는다. 최초 층 생성에서만 콘텐츠 seed를 소비한다.
- 기존 몬스터/아이템/변이 콘텐츠를 사용하며 수백 종 신규 밸런스 작업을 섞지 않는다.

### P3 — 기존 게임 UI·자동탐험 통합

- 승인 A안 배치와 기존 아트로 8×8 전장을 실제 모바일에 맞춘다.
- 자동탐험은 처음에는 방 안까지만 수행하고 출구 앞에서 멈춘다. 플레이어가 출구로 이동하면 즉시 전환한다. 방 간 자동 루팅은 후속 작업이다.
- 적 발견 시 기존 안전 정지, 모달 중 입력 차단, 초상화 선택, 소비품 대상 선택을 유지한다.
- 아군/적 진영별 턴제 변경은 별도 승인 후 독립 단계로 수행한다. 미확정 상태에서 새 UI에 `턴 종료`와 기존 `진행`을 동시에 노출하지 않는다.

### P4 — 검증·인수인계

- 아래 필수 검사를 통과하고, 남은 결함과 모바일 확인 범위를 문서화한다.
- 작은 단위로 커밋한다. 사용자에게 구현 결과/테스트/남은 선택을 반환하고, 명시적 요청이 있을 때 main에 푸시한다.
- 결과 문서 권장 경로: `docs/plans/nine-room-dungeon-results.ko.md`.

## 12. 필수 검증 목록

### 결정론·생성

- 최소 100개 seed에서 정확히 9방, 전체 도달 가능, 양방향 portal 대칭, 필수 출구/계단 도달 가능.
- 같은 seed와 ruleset에서 동일 맵·배치·hash. 미니맵/preview 호출이 RNG를 바꾸지 않음.
- 비연결 경계, 외곽, 대각선 모서리로 구역 이탈 불가.

### 상태·시간·도주

- 20회 왕복 후 HP/부상/아이템/사망 적/획득 XP가 되살아나거나 중복되지 않음.
- 한 입력으로 한 번 전환. 자동 이동 잔여 입력과 모바일 더블탭으로 재전환되지 않음.
- 안전 전환 이동 비용 한 번; 전투 이탈 적 잔여 행동 한 번; 이미 행동한 적은 재실행하지 않음.
- 출구에서 공격을 맞아 사망/쓰러짐/집결 실패 시 방 전환 없이 전투 결과 유지.
- 진입칸 부족, 멀리 있는 동료, 쓰러진 동료, 추격 큐 막힘의 실패 이유와 무복제 검증.
- 추격자는 같은 ID로 한 곳에만 존재하고 등장 즉시 공격하지 않음. 왕복으로 대기 시간을 리셋하지 못함.
- commit 직전/직후 저장·로드 및 JSON/저널 재생이 같은 권위 상태를 만듦.
- 방 이동으로 중독·버프·쿨다운·포만감·휴식 회복을 무료 리셋하지 못함.

### 전투·정보 노출

- 이웃 방의 AI/공격/광역기/피해 숫자/아이템명이 현재 방으로 새지 않음.
- 비활성 적이 살아 있어도 현 방 탐험/휴식 판정이 올바름. 현 방 정리만으로 층 전체 보상을 반복 지급하지 않음.
- 계단 진입과 인접 방 전환을 혼동하지 않음. 같은 방 재방문으로 NPC 성장과 변이 획득이 초기화되지 않음.
- 기존 공용 가방·숙련·변이·부상·전투 오사 회귀 검사를 보존한다. 낡은 UI 테스트 실패는 실제 로직 실패와 분리해 보고한다.

### 모바일·성능

- 360×800 / 390×844에서 보드 64칸, 주요 버튼, HP/MP, 로그 3줄이 잘리지 않음.
- 선택선·사거리·적 예고·터치 위치·이동 애니메이션이 같은 아이소매트릭 투영을 사용함.
- 실제 모바일 브라우저에서 출구 진입, 도주, 재진입, 회전/백그라운드 복귀를 검사한다. headless 검사만으로 모바일 완료라고 보고하지 않는다.
- 같은 기기에서 변경 전후 입력 지연/프레임 시간/전환 시간/메모리를 기록한다. 비활성 방 수가 늘어나도 현재 방 이동마다 전체 층 AI나 전체 snapshot이 실행되지 않음을 계측한다.
- 상세 성능 예산은 기준 기기 측정 후 정한다. 측정 없이 ‘최적화 완료’ 또는 고정 FPS 보장을 쓰지 않는다.

## 13. 이번 범위에서 하지 않을 것

- 연속 오픈월드, 방 선택 화면, 모든 층 신규 제작, 정착지 재활성화.
- 현재 게임 전체를 외부 오픈소스 전투 엔진으로 교체.
- 실시간 전투, 두 방 동시 파티 전투, 동료 유기/운반, 오프스크린 대규모 NPC 시뮬레이션.
- 예고 없이 몬스터 재생성, 후퇴 시 무료 HP 회복, 저장 데이터 자동 삭제.
- 이미지 목업의 새 아트를 실제 기존 에셋으로 오인하거나, UI 레이아웃 채택을 아트 교체 승인으로 해석하는 것.
