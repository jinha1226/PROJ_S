## 1. 최종 합의와 구현 목표

**한 라운드의 아군·적 행동 순서와 예정 행동을 한꺼번에 보고, 원하는 아군 행동만 수정한 다음 `[진행]` 한 번으로 순서대로 실행한다.**

- 진영별로 아군 전체가 먼저 행동하는 방식이 아니다. 아군과 적이 섞인 순서로 실행한다.
- 매 아군 차례마다 승인 버튼을 요구하는 방식도 아니다. 정상 상황에서는 라운드당 진행 한 번이다.
- 한 라운드에 참여 캐릭터마다 행동 기회 한 번. 빠르다고 라운드 안에서 두 번 행동하지 않는다.
- 동료 행동은 기존 성격·전술·부상 기반 AI로 자동 작성한다. 유저는 그대로 승인하거나 수정한다.
- 아군과 적은 모두 동일한 **예정 행동**이다. 아군만 유저가 수정할 수 있다.
- 화면에 공개한 예정 행동을 실행 직전에 AI가 다시 고르지 않는다.
- 앞선 이동·공격·밀치기·사망이 뒤 행동에 미칠 영향을 순서대로 예측한다.
- 적의 공격 범위에 다른 적을 밀어 넣으면 그 적도 피해를 받는다.
- 다리 골절은 전투의 이동 가능 칸 감소로 반영한다.
- 같은 던전 화면에서 탐험·전투·도주가 이어진다. 별도 전투 진입 화면이나 순간 탈출 없음.
- 우측 하단의 중복 몬스터 목록은 제거하고, 상단 순서창과 맵 터치로 적 확인 기능을 통합한다.

주인공의 기본 예정 행동은 HOLD(대기). 동료는 AI 행동을 채워 넣는다. 주인공까지 매번 AI가 대신 공격하도록 바꾸는 것은 범위 밖이다. 아무것도 수정하지 않고 진행하면 주인공은 대기하고 동료는 표시된 행동을 수행한다.

### 폐기된 이전 제안

`아군 진영 전체 행동 → 턴 종료 → 적 전체 행동`, `매 아군 차례마다 멈춰 개별 승인`, `동료 예고는 참고용이고 실행 시 재선택`을 구현하지 않는다. 과거 문서/코드의 이런 규칙보다 본 문서가 우선한다.

## 2. 범위와 초기 기본값의 구분

위 1절은 사용자와 합의한 동작이다. 다음 값은 구현을 진행하기 위한 **초기 제안값**이며 밸런스 확정치가 아니다. 구현 세션은 실제 채택한 값을 결과 문서에 기록한다.

| 항목 | 초기 구현안 |
|---|---|
| 한 번의 행동 기회 | 정해진 경로로 이동 후 공격/이능 하나. 이동만/공격만/대기도 가능 |
| 이동력 | 기본 3칸을 출발점으로 데이터화. 종족/장비/부상 보정은 별도 규칙 함수 |
| 팔·다리 부상 | 팔 공격력 감소 유지. 다리는 기존 `move_milli`를 이동 예산으로 변환: `max(1, floor(base_move*1000/move_milli))` |
| 순서 | 라운드 시작 시 initiative 내림차순, 동률은 stable entity ID 오름차순. 라운드 중 편집으로 순서 재정렬 금지 |
| 시간 | 전투 1라운드 = 기본 100 시뮬레이션 시간 단위. 참여자 수와 UI 애니메이션 시간에 비례해 늘리지 않음 |
| 재정렬 | 사망은 슬롯 취소. 속도 상태 변화는 다음 라운드부터 반영 |

현재 코드에는 MOVE/ATTACK/CAST별 `action_speeds`와 개별 행동 비용이 있고, 통일된 initiative 능력치는 없다. 구현 전 기존 종족·무기·버프별 속도 데이터를 조사하고 **initiative / 이동력 / 쿨다운으로 어떻게 매핑하는지** 표를 남겨야 한다. 특정 속도 채널이나 DEX를 근거 없이 전부의 대체값으로 사용하지 않는다. 새로운 속도 밸런스를 대규모로 만드는 것은 범위 밖이다.

이동력 보정과 기존 이동 시간 증가를 중복 적용하지 않는다. 전투의 다리 골절은 이동 예산에만 적용하고, 같은 부상으로 순서도 늦추지 않는다. 탐험의 기존 이동 시간은 유지할 수 있지만 전투 경계에서 시간이 이중 소비되어서는 안 된다. 대각선 코너 이동의 기존 허용 규칙을 보존한다. 물·지형 비용은 새 이동 예산에서 명시적으로 정의하되 기존 HP/부상 공식을 다시 바꾸지 않는다.

## 4. 권위 상태와 API 설계

새 파일명은 제안이며 동등한 분리는 허용한다.

- `sim/round_combat_state.gd`: 저장 가능한 라운드 권위 상태.
- `sim/round_combat_rules.gd`: 참여·순서·이동력·공격 앵커·중단·이탈 규칙.
- `sim/round_plan_service.gd`: AI 계획 생성, 아군 계획 편집과 검증.
- `sim/round_preview_service.gd`: shadow world에서 순차 예측, 결과 DTO/캐시.
- `sim/systems/round_combat_system.gd`: 실행·중단·재개·라운드 종료와 시간 진행.
- `playtest/round_order_bar.gd`: 모바일 행동 순서창.

권위 상태에 최소한 `schema/ruleset`, `round_id`, `phase`, `round_start_time`, `participants`, `order`, `plans`, `plan_revision`, `execution_cursor`, `completed_actor_ids`, `interrupt_reason`, `round_time_committed`를 둔다. phase는 `EXPLORATION / PLANNING / RESOLVING / INTERRUPTED` 등 명확한 enum을 사용한다. `safe_phase=GROUPED` 문자열을 임의로 전투 종료로 해석하지 않는다.

예정 행동 데이터에는 actor ID, 순서, source(AI/USER), 원점, 고정 경로, 목적지, 기술/공격 ID, target 정책, target cell/direction, 필요 비용, 이동 예산을 포함한다. 표시 문구만 저장해서 실행 시 재해석하지 않는다.

세션 API 예시: `round_status()`, `edit_round_plan(actor_id, draft, expected_revision)`, `round_preview()`, `confirm_round(expected_round_id, expected_revision)`, `resume_round(...)`. 동료 선택은 **편집 대상만** 바꾸며 주인공 정체성·시야 소유자·전체 세계 시간을 바꾸지 않는다.

### 경계와 중복 실행 방지

- 한 라운드의 참여자와 순서는 계획 시작 시 고정한다.
- 진행 후에는 입력 편집을 잠그고, 확인한 round/revision에만 실행을 허용한다.
- 빠른 더블탭/재전송/브라우저 복귀에도 동일 슬롯을 두 번 실행하지 않는다.
- 논리 실행과 애니메이션을 분리한다. 애니메이션 프레임 수나 기기 속도가 행동 수를 결정하면 안 된다.
- 환경·지속 효과·허기·쿨다운·회복·NPC 시뮬레이션을 별도 시간 정책으로 연동한다. 라운드당 고정 시간은 성공한 라운드 경계에서 한 번만 소비한다. 슬롯별 tick을 임의로 중복 호출하지 않는다.
- 환경 변화/지속 피해의 처리 순서도 고정하고 공개 가능한 위험은 예측에 포함한다. 멀리 있는 비참여 NPC는 기존 시뮬레이션으로 계속 진행하되 참여자를 다시 행동시키지 않는다.
- 전투 진입/도주 반복으로 무료 행동·쿨다운 초기화·추격 기억 초기화가 발생하지 않도록 경계 시각과 이미 소비한 행동을 기록한다.

## 5. 예정 행동과 순차 예측 계약

### 동일한 계획 모델

아군·적은 같은 예정 행동 자료와 실행기를 사용한다. 동료는 최초 작성만 AI가 담당한다. 아군 계획 편집 이후 **적 AI를 재실행해 카운터 행동을 고르게 하지 않는다.** 표시된 다른 동료의 계획 역시 유저 동의 없이 재선택하지 않는다. 변경된 세계에서 그 고정 계획이 어떤 결과를 내는지만 다시 예측한다.

계획 생성 순서를 안정적으로 고정한다. 최초 적 계획·동료 계획 생성 과정과 유저 수정 이후 결과 재계산을 분리해 순환적인 AI 재계획을 막는다. 성격은 계획 선택에만 반영하며 유저 수정 명령을 몰래 거부/변경하지 않는다.

### 예측과 실전의 일치

- 읽기 전용 snapshot/shadow world에 현재 계획을 **실제 순서대로** 적용해 뒤 행동의 결과를 구한다.
- 앞선 밀치기, 지형 차단, 피격에 의한 이동력 감소, 사망, MP 소모, 행동 불능을 뒤 슬롯에 반영한다.
- 실제 resolver를 재사용하거나 동일한 pure 평가 함수를 공유한다. UI가 HP 피해·부상·넉백 공식을 재구현하지 않는다.
- preview는 실제 world의 RNG, event ID, journal, AI 기억, 아이템, MP를 변경하면 안 된다.
- 명중/막기 등의 확률을 없애는 것은 이번 범위가 아니다. 확정할 수 없는 결과는 확률·범위·조건부 표시를 사용한다. 확정 표시한 결과가 실전과 달라지는 것은 버그다.
- 무관한 UI 조작/preview 새로고침으로 난수 결과를 재추첨할 수 없도록 round/actor/action 의미에 결박된 재현 가능한 난수 정책을 기록한다. 실제 난수 결과를 미리 공개할지와 표시 형식도 명시한다.
- 숨은 적/미탐색 지형을 순서창·경로·예상 피해·preview 오류에서 유출하지 않는다. 전체 권위 world로 계산한 결과를 그대로 사용자 DTO로 내보내지 않는다.

### 공격 대상·밀치기 규칙

적 범위 공격과 일반 타일 공격은 actor ID 추적이 아니라 **명시된 타일/방향에 공격**한다. 점유자가 바뀌면 새 점유자가 피격 후보가 된다. 편에 상관없이 적→적 피해가 발생할 수 있다. 명시적인 추적 기술/단일 개체 기술만 target-ID 정책을 사용하고 UI에서 구별한다.

공격 앵커는 데이터화한다. v1 기본은 월드 타일 고정이며, 공격자가 밀려 범위/사선 조건을 충족하지 못하면 공격을 취소한다. 방향 유지형/원점 추종형 기술을 도입한다면 종류별로 명시하며 무조건 사각형을 공격자에 붙여 옮기지 않는다. 다른 적을 고정 공격 타일에 밀어 넣는 플레이는 v1 필수 검증이다.

`can_attack`의 적대 진영 조건을 전역 제거하지 않는다. **계획된 공격의 실제 피격 대상 판정**에서만 오사를 허용하고, HP 피해 이벤트·킬 귀속·경험치·드롭·적대/인지 갱신의 출처 검증을 함께 맞춘다. 사용자 수정(2026-09-14): 전투 중 적끼리 오사하여 죽은 경우에도 플레이어에게 처치 경험치를 지급한다. 플레이어가 공격을 유도했는지는 조건이 아니다. 밀치기로 적 공격을 유도한 처치도 포함하며, 실제 가해자·사망 이벤트 출처를 보존하고 같은 사망에 경험치를 중복 지급하지 않는다.

### 불가능해진 행동

- 실행 전 사망/기절: 해당 슬롯을 취소하고 사유 표시.
- 고정 경로가 막힘: 마지막 합법 타일에서 이동 중단. 우회로 자동 재탐색 없음.
- 이동 중단 후 공격: 원래 고정 공격이 그 위치에서도 합법일 때만 실행.
- 타일 공격의 원래 적이 죽음: 다른 대상 자동 추적 없음. 해당 타일이 비면 헛공격/취소 중 데이터 정책에 따른 결과 표시.
- 지정 개체 기술의 대상 소멸: 취소. 다른 개체 자동 선택 없음.
- 자원 부족/무기 사용 불가: 취소 또는 부분 이동 후 취소. 비용을 언제 쓰는지 명시하고 부당한 이중 소모 방지.
- 예상한 취소만으로 매번 사용자 확인창을 띄우지는 않는다. 예고 밖 위험에 대한 중단과 구분한다.

## 6. 실행 중 중단·재개와 저장

계획에 없던 새 적 발견, 비공개 위험의 노출 등 중요한 예고 밖 변화가 발생하면 **안전한 행동 경계에서** 중단한다. 경로 이동 중 발견했다면 다음 이동 칸/공격 전에 중단할 수 있도록 슬롯 안의 부분 진행도 기록한다. 단순히 전체 라운드를 먼저 계산한 뒤 애니메이션만 멈추는 구현은 불가하다.

- 이미 실행한 이동·피해·비용은 확정이며 되돌리지 않는다.
- 완료된 캐릭터에게 새 행동 기회를 주지 않는다.
- 미실행 아군 계획만 편집할 수 있다. 공개된 기존 적 계획은 유지한다.
- 새 적은 재개 계획 경계에서 예고를 공개하고 편입한다. 발견 즉시 예고 없는 무료 공격을 넣지 않는다. 편입 슬롯 정책을 데이터/테스트로 고정한다.
- 환경 시각과 라운드 시간 중복 소비 없이 cursor부터 이어 간다.
- 계획 중·중단 중 저장/불러오기가 가능해야 한다. 모바일 백그라운드 전환은 최소한 안전한 논리 경계에서 자동 저장한다.
- 신규 round 상태, 편집 draft, revision, 난수 commitment, cursor를 스냅샷/명령 journal에 포함한다.
- 새 규칙의 ruleset/BALANCE_ID를 부여한다. 예전 진행 데이터 마이그레이션은 요구하지 않지만 파일을 임의 삭제하지 않는다. 최신 새 게임·출발·저장·재생 검증은 필수.

## 7. 탐험·교전·도주

탐험에서는 주인공 이동과 동료 자동 추종을 유지한다. 적/즉각적 위협을 감지하면 자동 이동을 다음 안전 경계에서 멈추고 같은 맵에 순서창과 예정 행동을 표시한다. 내부 round 상태만 전환하며 별도 전투 시작 버튼/화면을 요구하지 않는다.

전투 참여 집합은 현재 파티와 관련 위협을 기준으로 제한한다. 맵 반대편 NPC끼리의 싸움을 전부 라운드 UI에 올리거나 세계 전체 적을 참여시키지 않는다. 적이 사라져 보인다는 이유만으로 참여·추격 기록을 버리지 않는다.

도주도 아군 이동 계획을 작성하고 진행하는 일반 전투다. 적은 예고한 공격을 수행하고 이후 추격/수색 계획을 만든다. 후퇴 버튼은 선택적으로 왔던 길/출구 방향을 안내할 수 있지만 즉시 탈출·순간이동·동료 자동 포기를 수행하지 않는다. 이전 `party_retreat()`의 자동 의사결정 실행과 혼용하지 않는다.

교전 종료는 **파티 전체가 즉각적인 공격/범위 위험에서 벗어나고, 해당 파티를 추격·수색 중인 적도 없을 때**만 허용한다.

- 한 동료가 남아 있거나 추격당하면 유지. 주인공만 안전한 것으로 종료하지 않음.
- 모서리/벽 뒤에 숨었어도 적이 마지막 위치를 조사하는 동안 유지.
- 기존 `HUNTING → SEARCHING → RETURNING`과 수색 만료를 활용. 다른 NPC를 쫓는 적이나 귀환 중인 적까지 무조건 파티의 추격자로 간주하지 않음.
- 숨은 적의 좌표·이름은 종료 판정 때문에 UI에 노출하지 않음. 필요하면 '아직 추격을 떨치지 못했습니다' 수준으로 표시.
- 전원이 쓰러짐/죽음은 탈출 성공이 아니라 기존 패배/구조 규칙을 적용.
- 층 이동/출구 사용으로 남은 동료가 자동 순간이동하거나 전투 상태가 강제 해제되는 우회로도 검사.
- 시간이 진행될 때 수색도 실제로 만료되어야 함. 경계 상태가 고착되어 영원히 탐험 복귀가 불가능해서는 안 됨.

## 8. 모바일 UI/UX

기존 세로 배치를 유지한다.

```text
기존 HUD · 미니맵 · 식량
현재 라운드 순서: 주인공 → 고블린 → 동료 A → 오크 → 동료 B
게임 화면: 선택된 계획의 경로/범위/결과
로그 3줄
파티 초상화
이동 / 공격 / 이능 / 대기 / 진행
```

- 순서창은 한 줄 가로 스크롤. 파티원과 적을 진영 색상+아이콘으로 구분하고 현재 선택/실행/취소 상태를 표시한다.
- 전체 순서를 확인할 수 있어야 한다. 화면에는 다음 5~6칸 정도, 나머지는 가로 스크롤/확장으로 접근하며 몰래 생략하지 않는다.
- 초상화/순서칸 터치로 해당 계획과 예상 행동 시점의 위치를 강조. 선택된 것 외의 범위는 흐리게 해 중첩 난잡함을 줄인다.
- 아군 선택 후 타일·대상·이능 터치는 **계획 편집**. 진행 전 실제 HP/MP/위치/시간 변화 없음.
- 별도 '수정 모드 진입' 버튼은 기본적으로 불필요. 적 선택은 조회만 가능.
- `[진행]`은 전체 라운드 승인. 실행 중 비활성화. 중단 후에는 `[계속 진행]`과 사유를 표시.
- 덮어쓴 동료 계획을 원래 AI 계획으로 되돌리는 작은 버튼은 허용하지만, 적의 새 행동을 재추첨하는 버튼은 금지.
- 중복 몬스터 목록 제거 후에도 적 HP/상태/기술 설명은 맵·순서칸 선택으로 접근 가능해야 함.
- 아이소매트릭 경로·공격 타일 모양을 통일한다. 도착 후 선택 강조가 먼저 이동하거나 스프라이트가 한 칸 밀리는 회귀를 방지한다.
- 작은 화면에서 HUD·로그·초상화·버튼을 가리지 않는다. 최소 360×800, 390×844 세로 화면과 실제 터치 확인.

## 9. 구현 순서와 단계별 완료 조건

각 단계는 코드·테스트·짧은 결과를 커밋한다. 기능을 삭제해서 테스트를 통과시키거나 예고를 단순 장식으로 남기지 않는다.

### A. 규칙과 상태 기반

기준 commit/dirty 변경 확인, initiative·이동·시간 매핑 표 작성. round 상태/계획 DTO/스키마/직렬화와 pure 순서 함수를 구현. 동률 순서·참여자 1회·라운드 경계 테스트 통과.

### B. 계획 작성과 동일 실행기

기존 AI를 어댑터로 감싸 아군·적 계획을 고정. 아군 계획만 편집 가능. 한 캐릭터의 고정 경로+공격/이능 실행, 취소/중단 규칙, 오사와 피해 출처 연결. 이 단계에서 기존 자동 actor 큐가 같은 참여자를 다시 움직이지 못하도록 차단.

### C. 순차 preview

실행기와 같은 규칙으로 shadow simulation을 수행. 앞선 밀치기/사망/장애물/자원 소모를 뒤 슬롯에 반영. 세계 무변경, 난수 안정성, 숨은 정보 보호 검증. 매 프레임 world clone 금지.

### D. 일괄 진행·중단·저장

전체 라운드 confirm, cursor 실행, 중요 변화 자동 정지, 미실행 계획 수정/재개 구현. 한 라운드 시간·환경 처리 1회. 계획/중단 snapshot과 journal replay 일치. 취소된 행동과 시스템 실패 롤백을 구별.

### E. 제품 UI와 탐험·도주

실제 게임 진입 경로에 연결. 순서창/공유 overlay/편집/진행, 중복 적 목록 제거, 안전 추종·교전 전환·파티 전체 추격 해제 연결. 현재 우클릭/터치/초상화/공격 버튼의 즉시 실행 우회 경로를 모두 조사.

### F. 회귀·모바일 검증과 인수인계

아래 필수 시나리오 통과, 프로파일 결과와 알려진 제한 기록. 기본 게임 경로에 실제로 연결했는지 명시. 테스트 장면에서만 동작하는 상태는 완료 아님. 변경 파일·commit·모바일 테스트 방법을 결과 문서에 남긴다.

## 10. 필수 검증 시나리오

1. 3인 파티+적 3명: 한 번 진행으로 표시 순서대로 각 1회, 아군 사이에 적 행동이 실행됨.
2. 동료 AI 기본 계획 그대로 승인 / 동료 하나만 수정 / 나머지 계획·적 계획 불변.
3. 편집·preview 반복만으로 world·MP·HP·journal·RNG 변동 없음. 늦게 도착한 이전 revision confirm 거절.
4. 먼저 적을 처치하면 뒤의 적 공격 취소. 뒤 순서의 동료가 그 공격을 앞질러 막은 것으로 처리되지 않음.
5. 다른 적을 예고 타일로 밀어 넣기 → 적끼리 피해/사망/드롭. 공식·귀속·저장 검증 통과.
6. 공격자 이동/피격 대상 이동/사선 차단/기절/MP 부족에서 계획별 취소·부분 실행이 preview와 일치.
7. 아군 앞 이동이 뒤 경로를 막는 경우 자동 우회/타깃 교체 없음. 예상 취소를 UI에 표시.
8. 다리 골절 전후 이동 예산 감소, 휴식 치료 후 복구, 순서/시간 중복 패널티 없음. 팔 공격력/HP 연동 부상 유지.
9. 실행 중 새 적 발견 → 다음 안전 경계 정지. 완료 슬롯 재실행 없이 수정·재개. 새 적 예고 없는 즉시 공격 없음.
10. 계획 중 저장/불러오기, 중간 이동/중단 저장/복귀, 라운드 후 재생 일치. 진행 더블탭 중복 피해 없음.
11. 시야 밖 적이 순서창·preview·피해 숫자에 새어 나오지 않음. 관련 없는 NPC 싸움이 파티 진행을 잠그지 않음.
12. 모퉁이 도주: 적이 수색 중이면 유지, 수색 만료 후 복귀. 동료 한 명이 남으면 종료 안 됨. 전원 사망은 도주 성공 아님.
13. 층 이동·동료 합류·추격자 사망/기절·교전 재진입에서 참여/시간/무료 행동 오류 없음.
14. 파티 인원이 1명/3명이어도 라운드당 허기·지속 효과·쿨다운 시간이 참여 수만큼 배증하지 않음. 먼 NPC와 참여 NPC 중복 실행 없음.
15. 모든 주요 이능의 액티브·패시브, 물리/속성/밀치기/범위/회복 효과가 새 실행 경로에 연결. 부위 섭취·숙련 UI·아이템 줍기·초상화 HP/MP 회귀 없음.

기존 재사용 검사: `body_penalty_regression.gd`, `hp_derived_injury_regression.gd`, `body_status_scalars_acceptance.gd`, `rest_and_pickup_regression.gd`, `enemy_telegraph_meat_acceptance.gd`, `tactical_overlay_regression.gd`, `solo_start_acceptance.gd`.

알려진 테스트 주의: `monster_all_abilities_acceptance.gd`는 `5853fba` 작업 중 실행에서 포만 상태 특수부위 섭취(`monster_meat_full`)에 실패해 이능 실행 전에 연쇄 실패했다. 안전한 장소·허용 포만감에서 능력을 준비한 뒤 전투 fixture로 들어가도록 최신 규칙에 맞춰 갱신해야 한다. 제품의 포만감/섭취 제한이나 적대 검증을 없애서 우회하지 않는다. 과거 단일 행동 테스트는 새 계약에 맞춰 수정하되 저장·입력·실제 효과 검증 자체를 삭제하지 않는다.

## 11. 성능과 검증 도구

- Godot headless 검사 허용. 필요한 실제 모바일/브라우저 동작도 별도로 검증하며 headless 통과를 모바일 시각 검증으로 보고하지 않는다.
- 계획 생성은 round 시작 시 1회, preview는 편집 revision 변경 시에만. shadow world/경로/overlay 캐시 키에 위치·지형·계획 revision 포함.
- 최초 구현은 전체 라운드 재예측으로 정확성을 확보하되, 수정 후 영향을 받는 suffix 재예측으로 확장 가능한 구조를 유지한다. 매 UI 프레임 전체 맵/이벤트 이력 스캔 금지.
- 고정 seed/맵/파티3+적6 fixture로 계획 생성·편집 preview·논리 실행의 p50/p95, clone 횟수, 메모리/이벤트 증가를 기록. 100라운드 반복 후 시간 증가 추세 확인.
- 초기 목표: 기준 기기를 명시한 편집 preview p95 100ms 이내. 미달이면 병목과 재현 명령을 보고하고 무조건 '최적화 완료'라고 하지 않는다. 캐시 때문에 이전 계획을 실행하는 오류는 성능보다 우선 차단.
- 개발용 전체 테스트를 CI에 무작정 추가하지 않는다. 파싱·핵심 round/replay 검사와 변경 영역 회귀를 우선하며 기존 CI를 파괴하지 않는다.
