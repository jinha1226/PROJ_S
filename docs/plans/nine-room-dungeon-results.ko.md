# 9방 던전 구현 기록

## P0 계약

시작 HEAD는 `d3395e8`이며 계획 기준 `e238803` 이후 계획 문서 커밋만 추가되었다. 기존 추적 파일 변경은 없다. 기존 미추적 Godot import/uid 파일은 보존한다.

새 런은 `nine-room-dungeon-v1` 생성기를 사용한다. 기존 생성기와 MIN_SIZE를 보존하고, 이전 런은 저장에 기록된 생성기와 원래 지도에서 재생한다. 저장 파일은 삭제하지 않는다. 기존 혼합 순서 계획 라운드와 적 오사 경험치 지급을 유지한다.

기존 두 층 단일 WorldState 구조를 재사용한다. 각 층24×24, 두 층을 가로로 배치한48×24 저장 지형에서 방 membership은 층+3×3 방 좌표로 결정한다. 일반 이동·시야·경로·공격은 같은 방 안에서만 허용한다. 방 전환은 명시적 portal 경계만 사용한다. HP·아이템·지형을 방 상태에 복제하지 않는다.

제안값은 별도 설정에 기록한다. 기본 이동 집결 반경2, 추격 경로 거리2/최대2, 전환 연출220ms, 시작 중앙 안전 방, 방 유형4전투/2위험/2안전/1계단이다.

## 비활성 방 시간 효과

| 효과 | 처리 계약 |
|---|---|
| 버프·쿨다운·이능 상태 | 층 공통 absolute expiry 유지. 방 변경으로 시간을 초기화하지 않는다. |
| 독·출혈 등 기존 예약 피해 | 기존 예정 시간을 유지하고 세계 시간 경계의 예약 효과만 정산한다. 비활성 방 상세 AI/공격은 중지한다. 기존 피해·사망·보상 장부로 중복 지급을 차단한다. |
| 환경 불·연기·물 | 기존 공통 환경 cadence를 유지한다. 환경 정산을 AI 기회로 사용하지 않는다. |
| 파티 포만감·회복 | 기존 세계 시간과 안전 판정 사용. 연출은 추가 시간을 소비하지 않는다. |
| 독립 NPC | 기존 데이터 보존. 현재 방 밖의 타일 이동/공격 중지. 구역간 자율 탐험은 후속 범위. |

## 이벤트 순서

사전 검사(집결/이동 가능/진입 공간/revision) → 이탈 요청 → 안전 이동 비용1회 또는 기존 라운드의 미해결 적 슬롯과100시간 경계1회 → 실행 후 생존/집결/공간 재검사 → 파티 위치와 active_room/방문/추격 큐 원자 commit → 공개 UI 전환. 실행 후 후퇴 실패는 적 피해와 시간을 보존한다. 신규 도착 방 계획은 도착 후에만 생성한다. 추격은 최소1번 플레이어 대응 경계 뒤 등장하며 등장과 첫 공격을 분리한다.

## 진행 상태

9방 구조의 구현과 아래 인수 검증을 완료했다. 구현 커밋은 `07eb953`, 원자적 효과 정산·기존 저장 재생·전투 UI 보완 커밋은 `7371ca8`이다. 이후 별도 작업으로 추가된 수작업 방 템플릿 `b30a55d`를 보존하고 현재 HEAD에서 생성 검사를 재실행했다.

사용자의 최종 지시에 따라 이번 완료 범위는 상위 9방 구현이다. [후속 계획](nine-room-combat-rest-addendum.ko.md)의 식량 정책 변경·개인별 명시적 휴식·입구 재배치·궁수·상자 보호전은 아직 구현하지 않았다. 위 P0 식량/회복 정책은 현재 구현의 설명이며 후속 설계의 최종 정책으로 간주하지 않는다.

## 구현 결과

- 층마다 8×8 방 9개, 중앙 안전 방 시작, 전투4/위험2/안전2/계단1, 결정적 연결 그래프와 층 이동을 연결했다. 일반 이동·경로·시야·공격은 현재 방에 제한한다.
- 출구에서 집결·행동 가능·진입 공간·revision을 검사한다. 정상 전환은 시간 비용을 한 번만 지불하고 HP·아이템·적 ID를 유지한다. 실패한 사전 검사는 무소모다.
- 전투 후퇴는 공개된 기존 라운드의 남은 적 기회만 해결한다. 이미 실행한 슬롯을 반복하지 않으며 후퇴 중 사망/집결 실패는 실제 피해와 경과 시간을 보존한다.
- 추격자는 기존 적 ID로 최대2명까지 큐에 보관한다. 첫 대응 경계에는 도착하지 않고 이후 안전 공간을 확보해 도착한다. 도착과 첫 공격은 분리한다.
- 비활성 방의 상세 AI를 중지한다. 소비품/몬스터 독 효과는 재진입 시 경과분을 한 번 정산한다. 기존 예약 출혈과 공통 환경 효과는 원래 세계 시간 cadence를 유지한다.
- 방 방문·출구 발견·전환 요청·추격 큐·효과 정산 시점을 권위 저장 상태에 포함했다. 기존 런의 지도와 필드 저장 재생을 보존한다.
- 고정 8×8 전장, 방 전환 연출, 방문 방 미니맵, 이동/공격/변이/가방/휴식 또는 진행의 기본 버튼5개를 연결했다. 자동 탐험은 방 경계에서 멈춘다.

## 웹 화면과 성능

`7371ca8`의 고정 checkout을 Web release로 export하고 Chromium CDP 터치 이벤트로 16개 검사를 통과했다. 출구 터치 진입·전투 후퇴가 각각100시간만 소비하며, 포커스 복귀·화면 크기 변경·이동 버튼 선택은 추가 턴을 만들지 않았다. [브라우저 결과](nine-room-dungeon-browser.json), [전투 화면](nine-room-dungeon-combat.png), [후퇴 화면](nine-room-dungeon-retreat.png)을 보관한다.

브라우저 기록에는 시작 씬 UID 경고가 있다. 엔진은 텍스트 경로로 정상 로드했으며 기록된 메시지는 이 경고와 위치 설명뿐이다. 실제 휴대폰 검증은 하지 않았고 데스크톱 브라우저의 모바일 화면·터치 에뮬레이션이다. 프레임 p50 33.3ms/p95 50ms는 디버그 관측을 포함한 이 환경의 수치이며 기기 성능 보장이 아니다. 웹 캡처는 이후 추가된 수작업 템플릿 이전의 구현을 대상으로 한다.

[성능 측정 원본](nine-room-dungeon-performance.json): 같은 환경에서 100회 이동/관측 기준 기존 지도 대비 새 지도 입력 p95 8.274→7.070ms, 관측 p95 15.713→8.811ms다. 새 지도 메모리는 57.99→59.20MB였다. 두 경우 모두 반복 중 생성기 호출0회, 비활성 적의 위치 변화0회였다. 롤백용 memento는 유지하며 공개 snapshot을 입력마다 생성하지 않는다.

실기기 모바일 확인과 후속 계획의 신규 전투/휴식 정책은 별도 작업으로 남는다. 현재 원래 9방 기능의 자동 인수 검사에는 미해결 실패가 없다.
