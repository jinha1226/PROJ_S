# 마을 길드·1층 튜토리얼 퀘스트 개발서

- 작성일: 2026-09-10
- 상태: 핵심 구현 완료. 화면 폭별 렌더링·모바일 터치 수동 확인은 남아 있다.
- 목표: 싱글 플레이에서도 마을 길드에 방문하여 짧은 의뢰를 받고, 실제 1층 탐험으로 게임 규칙을 익힌다.
- 범위: 길드 접근·의뢰 UI, 아래 5개 퀘스트, 캠페인당 1회 보상, 진행/저장 테스트.

## 1. 기존 코드와 통합

기존 `playtest/party_encounter_sandbox.gd::_town_deck`에는 GUILD 분류가 있지만 일부 경로에서 `allows_companions()`가 false면 숨기거나 GATE로 바꾼다. 이는 동료 모집 중심의 기존 길드다. `town_life_enabled()`이면 별도 마을 UI 경로를 사용하므로 레거시 길드만 수정해서 완료로 처리하지 않는다.

기존 길드 식별자를 재사용하되 튜토리얼 게시판은 동료 허용 여부와 분리한다. 마을 지도에 길드 진입점을 제공하고 현행/레거시 마을 화면 모두에서 접근을 확인한다. 길드를 열었다고 동료를 자동 영입하거나 싱글 시작 설정을 바꾸지 않는다.

UI는 기존 마을 9-slice 스타일, 24×24 게시판/길드 아이콘을 재사용한다. 지도 클릭→길드→의뢰 목록→상세→수락/보고의 흐름이며 마을 메뉴 조작으로 게임 시간이 흐르지 않는다.

## 2. 퀘스트 목록 — 구현 초안

튜토리얼은 강제 순서가 아니라 권장 순서다. 기본 이동·전투·회복·회수·귀환 규칙을 익히며, 아직 동작하지 않는 이능 흡수나 소재 재제작을 필수 목표로 삼지 않는다.

| ID | 제목 | 배울 규칙 | 완료 조건 | 보상 초안 |
|---|---|---|---|---|
| `GUILD_TUTORIAL_MOVE` | 첫 발걸음 | 터치 이동·8방향·행동하면 시간 진행 | 1층에서 실제 성공 이동 3회, 그중 대각선 1회 | 식량 1개 |
| `GUILD_TUTORIAL_GUARD` | 서두르지 않는 싸움 | 적 접근·대기 방어·공격 | 1층에서 대기 방어 1회와 적에게 유효 공격 1회 | 소액 골드 |
| `GUILD_TUTORIAL_HEAL` | 살아서 돌아올 준비 | 다친 상태의 물약 사용, 회복 후 세계 행동 | 1층에서 본인의 물약으로 HP가 실제 회복된 이벤트 1회 | 사용한 회복 물약 1개 보충 |
| `GUILD_TUTORIAL_LOOT` | 첫 전리품 | 바닥 물품 확인·줍기·용도 확인 | 1층 생성 출처가 있는 전리품 또는 거점 물자 1회 획득 | 소액 골드 |
| `GUILD_TUTORIAL_RETURN` | 원정의 마무리 | 깊이 진행 대신 귀환도 선택, 보상 보고 | 새 1층 전리품을 확보한 원정에서 실제 마을 귀환 | 기본 보급 묶음 |

골드/보급량은 초기 튜닝값으로 별도 기록한다. 상위 소재·추가 이능 슬롯·무제한 경험치를 보상하지 않는다. 각 완료/보고 보상은 캠페인당 1회다.

## 3. 억지 행동과 진행 막힘 방지

- 물약 퀘스트를 위해 자해·함정 밟기를 요구하지 않는다. 자연스러운 부상 후 진행하며 건강하면 다른 의뢰를 먼저 할 수 있다.
- 회복 물약이 없는 신규 플레이어에게는 길드 훈련용 지원 1회를 제안한다. 최초 지원과 완료 보충은 별도 ID로 중복 방지한다. 물약이 남아 있는데 반복 지원을 받아 파밍할 수 없어야 한다.
- 방어 목표는 일부러 공격을 맞는 것을 요구하지 않는다. 공격 성공 목표는 적대 대상만 인정하며 마을 주민 공격으로 채울 수 없다.
- 대각선 이동은 이동 가능한 위치를 안내한다. 막힌 모서리를 누른 실패 입력은 카운트하지 않는다.
- 모든 퀘스트를 깨야 던전 입장이 열리는 구조를 만들지 않는다. 안내 숨기기와 나중에 수행하기를 제공한다.
- 1층에 최소한의 합법적 적/줍기 기회가 존재하도록 테스트 시드를 확보한다. NPC가 전리품을 모두 선점해도 진행이 영구적으로 막히지 않게 한다.
- 이능의 어려운 제거·영구 결속을 튜토리얼 완료 조건으로 강요하지 않는다.

## 4. 상태·이벤트·보상

권장 상태는 AVAILABLE→ACTIVE→COMPLETED→CLAIMED다. 아이템/경험치 지급은 CLAIMED 전이의 원자적 거래로 수행한다. 가방이 가득 차면 거절 또는 명시된 보관함 지급 정책을 적용하고 보상만 잃지 않는다.

- 캠페인 ID와 퀘스트 ID로 최초 지원·수락·보고를 중복 방지한다.
- UI 클릭 횟수가 아니라 성공한 canonical 이벤트로 진행한다. 취소된 공격, 실패한 줍기, 회복 없는 물약 요청은 인정하지 않는다.
- 층 번호는 이벤트 시점의 층을 사용한다. 귀환 후 현재 층 값을 보고 과거 이벤트를 잘못 분류하지 않는다.
- 진행은 캐릭터/캠페인 귀속을 명시하고, 다른 NPC의 행동이 주인공 의뢰를 완료하지 않게 한다.
- 초기안은 수락 후 행동을 인정한다. 수락 이전 행동의 소급 인정은 별도 결정이며 기존 저장에서 임의의 과거 이력을 매 프레임 전수 조사하지 않는다.
- 1·2층 재생성은 퀘스트 수락·완료·지원·보고 기록을 초기화하지 않는다.
- 기존 저장에서는 새 기능 활성화 경계를 두고, 과거 저널을 재생하며 퀘스트 보상을 새로 지급하지 않는다.
- 새 이벤트만 순차 반영하는 인덱스를 사용한다. UI에는 파생 진행 DTO만 전달하고 화면을 열 때 상태를 변경하지 않는다.

## 5. 안내 표현

길드 의뢰에는 목표·현재 진행·보상·간단한 조작 설명을 표시한다. 1층 HUD에는 선택한 의뢰 한 줄만 보여주고, 첫 안내 및 완료 때 짧은 메시지를 출력한다. 매 턴 말풍선을 반복하거나 기존 3줄 전투 로그를 계속 덮지 않는다.

시야/횃불 튜토리얼은 실제 기능 검증 후 후속 추가할 수 있다. 기존 완료 의뢰를 다시 초기화하지 않는다.

## 6. 구현 순서·수용 기준

1. 별도 진행 규칙 모듈과 테스트를 작성하고 canonical 이벤트/저장에 연결한다.
2. 실제 사용 중인 마을 화면에 싱글에서도 접근 가능한 길드와 의뢰 게시판을 연결한다.
3. 1층 목표·진행·보고·지원 및 보상 지급을 검증한다.
4. 모바일 UI와 1·2층 재생성/저장 재생 회귀를 확인한다.

- [x] 싱글에서 마을 길드 진입, 수락·보고·뒤로 가기가 작동한다.
- [x] 5개 목표가 각 실제 행동으로만 증가하며 층/대상/행동 실패 조건을 구분한다.
- [x] 지원/보상은 재수락·중복 탭·마을 왕복·저층 초기화·저장 로드로 복제되지 않는다.
- [ ] 물약 부족·체력 가득 참·가방 가득 참·퀘스트 미수락 상태에서 진행을 막거나 아이템을 잃지 않는다.
- [x] UI 개폐가 시간·연료·스트레스·퀘스트 상태를 변경하지 않는다.
- [ ] 360/390/450px 너비에서 버튼과 설명이 잘리지 않는다.
- [x] 저장/재생 상태와 테스트 명령을 결과 문서로 반환한다. 보상 전후 소유권과 전후 UI 캡처는 수동 검증 항목으로 남아 있다.

현재 마을 진입·세션·HUD 파일은 시야/아이템 작업과 겹친다. 실제 코드 구현은 담당 범위를 조정한 후 진행하고 다른 작업의 미완료 변경을 함께 커밋하지 않는다.
