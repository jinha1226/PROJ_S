## 작업 프롬프트

Living World의 재료·원소·환경 상호작용 시스템을 설계하고 구현해줘.

작업 저장소: `/mnt/d/STARTU/living-world-sim-turn`

목표: 소스 비공개 상업 출시를 전제로, 라이선스 위험을 관리하면서 다양한 환경 현상을 표현한다.
정밀 물리 시뮬레이션이 아니라, 플레이어가 원인과 결과를 이해하고 전술적으로 활용할 수 있는 타일 기반 근사 시뮬레이션이다.

현재 브랜치·HEAD·작업 트리·AGENTS.md를 확인하고 시작하라.
`064f10c`는 이전 작업의 참고 커밋일 뿐, 현재 HEAD라고 가정하지 마라.
기존 사용자 변경과 전투·대형·직접 조작·초상화·8방향 에셋 기능을 보존하라.

### 1. 라이선스 원칙

기본은 자체 구현이다. 위 참고 프로젝트의 이용 범위를 지켜라.

- The Powder Toy, DCSS 등 GPL 프로젝트의 코드를 복사하거나 번역·개작·부분 이식하지 않는다.
- Sandboxels의 코드·소재 정의·반응표를 복사하지 않는다.
- 변수명 변경이나 AI 재작성이 원본 라이선스 의무를 없앤다고 간주하지 않는다.
- 참고할 것은 일반적인 물리 원리와 독립적으로 작성한 요구사항이다.
- 과거에 원본 코드를 검토했다는 이유만으로 위반이라고 단정하지 않되, 독립 구현 여부를 확인하지 않고 “클린룸 구현”이라고 주장하지 않는다.

외부 코드가 꼭 필요한 경우:

- 우선 SS14의 MIT 코드처럼 허용적인 라이선스의 최소 부분만 검토한다.
- 저장소 이름만 믿지 말고 정확한 파일, 고정 commit, 저작권 표시, 파일별 예외, 끌려오는 의존성을 확인한다.
- 재사용 파일과 수정 사항, 원본 URL·commit·라이선스를 기록하고, 필요한 저작권 및 라이선스 고지를 배포물에도 포함한다.
- 코드 라이선스를 이미지·음원·폰트·데이터까지 확대 해석하지 않는다.
- 불명확한 파일은 사용하지 말고 자체 구현으로 대체한다.

현실 물성 데이터:

- 직접 확인한 자료만 사용하고 출처·단위·측정 조건을 기록한다.
- 확인되지 않은 값은 현실 측정값으로 포장하지 말고 게임용 가정값으로 표시한다.
- 외부 데이터베이스를 통째로 복제하지 않는다.
- 데이터 이용 조건이 불명확하면 승인 요청 또는 자체 게임용 값으로 대체한다.

기존 프로젝트의 DCSS 관련 참고·외부 코드 출처도 우선 점검한다.
문서, 라이선스 고지, 관련 commit 및 의심되는 파일을 확인하되, 단순 문자열 검색만으로 “전체 라이선스 문제없음”을 선언하지 않는다.
직접 복사·번역 이식이 의심되면 해당 부분과 근거를 보고하고, 원본 코드를 바탕으로 다시 고쳐 쓰는 방식으로 해결하지 않는다.
범위가 큰 교체는 사용자 승인을 요청한다.

### 2. 구현 전 계획과 현황 점검

먼저 다음을 확인하고 짧은 설계 문서를 작성·커밋하라.

- 현재 환경 tick과 필드 턴 스케줄러
- 타일의 `flammability`, `base_conductivity`, `wetness`, `fire`
- 불 확산·물 소화·전기 전파
- 스킬 피해와 환경 점화 연결 여부
- 방어구·신체 부위·피부·뼈·부상 처리
- 저장·불러오기·시드 재현·이벤트 기록·AI 위험 예측

이미 있는 기능을 중복 구현하지 않는다.
설계 문서에는 구현 순서, 근사 범위, 데이터 구조, 라이선스 출처 관리, 저장 호환성, 검증 시나리오를 포함한다.

### 3. 환경 모델

24×24는 그래픽 규격이다. 픽셀마다 시뮬레이션하지 않는다. 게임 타일 단위로 계산한다.

다음을 구분한다.

**A. 기본 소재**

- 철, 나무, 고무, 돌
- 전기전도성, 열전도성, 열용량에 필요한 값
- 연소 가능 여부·점화 조건·연소열
- 필요한 최소한의 기계적 저항

**B. 표면 물질**

- 물, 기름, 얼음
- 소재와 양을 가진 제한된 층
- 돌 위 기름, 금속 위 물처럼 바탕과 별도로 존재

**C. 대기 상태**

- 단순화한 기체량·온도·연기·수증기·가연성 가스
- 압력은 기체량·온도·유효 부피와 일관되게 계산
- 동일한 양을 여러 상태에 중복 집계하지 않기

**D. 현재 상태**

- 온도, 수분량, 남은 연료량, 연소 여부 등

실제 물성값과 게임용 계산값을 분리한다.
다른 단위의 수치를 그대로 더하지 않는다.
전기전도율처럼 범위 차이가 큰 값은 문서화한 변환을 사용한다.
열전도성과 전기전도성을 혼동하지 않는다.
수치 범위·임계값·속도·피해 배율은 중앙 설정에서 조절한다.

### 4. 지원할 주요 현상

공통 규칙으로 다음을 구현한다.

- 열 전달과 냉각
- 점화·연소·연료 소모·소화
- 증발·응결·결빙·융해
- 연기·수증기·가스 확산과 흐름
- 벽·문·외부 경계를 고려한 압력 변화
- 단순화한 전기 전달과 감쇠
- 폭발의 충격·열·밀쳐냄·파괴

주의:

- 연기를 전부 가연성 가스로 취급하지 않는다.
- 고압이라는 이유만으로 화학 폭발을 발생시키지 않는다.
- 용기 파열·급격한 감압과 가연성 물질의 폭발을 구분한다.
- 열린 장소에 압력이 무한히 쌓이지 않도록 경계 조건을 둔다.
- 얼음은 단순한 파란색 효과가 아니라 물질 상태 변화로 처리한다.
- 소재 조합마다 거대한 if/else 반응표를 만들지 않는다.
- 단순 모델에 꼭 필요한 특수 규칙은 예외임을 문서화하고 제한한다.

정밀 CFD, 개별 연기 입자, 현실 화학 반응 전체, 3D 파괴·유한요소 신체 시뮬레이션은 범위 밖이다.

### 5. 전투와 신체 연결

스킬과 환경은 같은 열·전기·충격 적용 경로를 사용한다.
화염탄이 화염 피해만 주고 환경과 단절되는 문제를 해소한다.

캐릭터는 공격 명중 또는 환경 노출 tick에만 관련 계산을 한다.

처리 흐름:

`피격 부위 → 해당 부위 방어구 → 잔여 에너지/힘 → 기존 피부·연조직·뼈 규칙 → 부상·행동 영향`

- 기존 신체 시스템과 피해 계산을 재사용한다.
- 저항이나 방어구 감소를 두 번 적용하지 않는다.
- 칼 공격에 전도율을 계산하는 식으로 불필요한 속성을 조회하지 않는다.
- 방어구의 부위별 덮임·재질·상태를 반영한다.
- 금속 방어구라는 이유만으로 전기 피해를 일괄 증가시키지 않는다.
- 표면 젖음·절연·단순화한 접촉 조건을 명시한다.
- 기존 시스템에 없는 신체 기능까지 대규모로 새로 만들지 말고, 환경 연결에 필요한 최소 확장과 별도 후속 과제를 구분한다.

### 6. 성능과 결정론

- 프레임 시간과 권위 있는 시뮬레이션 시간을 분리한다.
- 기존 필드 턴이 진행시킨 시간에 맞춰 고정 간격으로 처리한다.
- 변화 중인 타일과 필요한 이웃만 활성 집합으로 갱신한다.
- 화면 밖이라는 이유만으로 환경을 정지시키지 않는다.
- 이전 상태를 읽고 다음 상태에 반영하는 동시 갱신 구조를 사용한다.
- 질량·연료·에너지가 복제되거나 음수가 되지 않도록 한다.
- 열 손실·외부 배출 등 근사적 손실은 명시적인 규칙으로 둔다.
- 작은 차이에 대한 평형 판정과 재활성화 조건을 둔다.
- 전파·연쇄 폭발은 재귀 대신 명시적 큐 등으로 처리한다.
- 벽시계 실행시간에 따라 계산을 임의로 잘라 결과가 달라지게 하지 않는다.
- 동일 시드·명령·설정은 동일 상태와 이벤트를 재현해야 한다.
- 미리보기와 AI 위험 조회는 RNG·시간·상태를 바꾸지 않는다.

성능 목표 수치는 측정 전 단정하지 않는다.
현재 기준 성능과 변경 후 성능을 비교하고 환경·조건을 기록한다.

### 7. 화면과 AI

젖음·기름·가열·연소·얼음·연기·가스 위험을 기존 픽셀 스타일의 간단한 오버레이와 조사 정보로 표현한다.
새로운 대규모 AI 이미지 생성은 필요 없다.

- 연기 농도가 높을 때 시야에 주는 영향을 정의한다.
- 폭발·화재·감전의 원인을 이벤트에서 추적할 수 있게 한다.
- AI가 현재 화재, 전기 전파 가능 경로, 위험한 가스 등을 기존 성격·위험 평가에 반영하도록 연결한다.
- 보이지 않는 환경 상태가 UI나 AI에 부당하게 노출되지 않도록 기존 관측·인지 규칙을 지킨다.

### 8. 검증과 완료 기준

최소한 다음 자동 검사를 만든다.

- 기름 묻은 돌: 기름은 소모되고 돌은 연료처럼 타지 않음
- 젖은 나무: 건조 과정과 점화 지연
- 물/얼음/수증기 변화: 물질량 중복 생성 방지
- 물·금속의 전기 전달, 절연 경계의 차단
- 연기 확산과 벽 차단, 문 개방 후 이동
- 밀폐 공간 가열에 따른 압력 변화
- 감압·파열과 연소 폭발의 구분
- 폭발의 거리·엄폐 감쇠 및 연쇄 폭발 종료
- 서로 다른 소재의 방어구가 만드는 피해 차이
- 방어구·신체 저항 중복 적용 방지
- 저장·불러오기·명령 재실행 일치
- 예측 조회의 비변이성
- 기존 전투·이동·대형·스킬·신체 회귀 검사

성능 시나리오:

- 변화 없는 지도
- 작은 국소 화재
- 넓은 화재와 가스 확산
- 밀집 개체의 환경 노출
- 연쇄 폭발

기존 실제 맵과 100×100 스트레스 맵에서 활성 타일 수·환경 tick 시간·메모리·전체 턴 지연을 측정한다.
가능한 실행 환경만 실제 측정하고, 데스크톱 결과를 모바일 실측으로 표현하지 않는다.

단계별 구현·검증 후 커밋한다.
미완성 기능을 완료로 표시하지 않는다.
기존 저장 호환성에 영향이 있다면 버전 처리와 정책을 명시한다.

최종 보고:

- 구현한 현상과 의도적으로 근사한 부분
- 재사용한 외부 코드·데이터 및 라이선스
- 기존 출처 점검 결과와 남은 불확실성
- 자동 검사와 성능 측정 결과
- 저장 호환성
- commit과 문서 경로
- 남은 문제

원격 푸시·배포는 별도 명시적 요청이 없으면 하지 않는다.
라이선스 적합성에 대한 법률적 보증이나 전체 감사 완료를 주장하지 않는다.
