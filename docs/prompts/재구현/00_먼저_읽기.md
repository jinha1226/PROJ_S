# 재구현 프롬프트 세트 — 먼저 읽기

이 폴더의 프롬프트는 **순서대로 하나씩** 준다. 한 단계가 끝나고 확인 목록이 모두 통과하면 다음 단계로 간다. 모든 단계 프롬프트는 이 문서를 함께 읽는다는 전제로 쓰였다.

## 왜 다시 만드나

지금 게임(`index.html` + `js/`)은 격자 턴제로 시작해 실시간으로 옮기는 중이다. 이동·탐험만 실시간이고, 전투는 옛 턴 루프(`endTurn`을 0.3초마다 부름) 위에서 돈다. 적은 칸 단위로 걷고, 연출 대기열(`TL.wait`)이 전투 코드 약 60곳에 박혀 있다. 혼자를 전제로 짜여 있어 파티(최대 5명)를 얹기 어렵다.

그래서 **전투 코어는 새로 만들고, 전투와 무관한 좋은 부분은 옮겨 온다.** 옮겨 올 것: 데이터 표, 지도 생성, 원소·지형 반응, 장비(DCSS식), 횃불·등잔, 정착지(건설·방·주민), 방문자·등불지기 잇기·결말, 대사, 3D 렌더러(DioramaKit).

## 게임 한 줄

DCSS처럼 혼자 내려가기 시작해, 림월드처럼 마을을 키우고, Eslabong처럼 마을 사람들로 파티를 꾸려 마지막엔 다섯 명이 보스를 친다. 세상은 등불지기가 움직일 때만 움직인다(슈퍼핫). 모바일 세로, 한 손.

2. `docs/설계_실시간_전환.md` — 시간·공간·자동 공격·적 AI 원칙
3. `docs/밸런스_기준.md` — 공식·목표 지표 (수치는 아래 §5가 먼저)
4. `docs/설계_레이드.md` — 파티·역할·명령·레이드
5. `docs/설계_HUD.md`, `docs/설계_아이템_장비.md`, `docs/설계_던전_확장.md`, `docs/설계_정착지_건설.md`, `docs/설계_스토리_정착지.md`, `docs/설계_진행_레벨디자인.md`

문서끼리 부딪히면 번호가 앞선 문서를 따른다. 문서에 없는 결정은 가장 단순한 쪽으로 정하고 **보고서에 적는다.**

## 1. 절대 규칙

- **새 폴더에서 만든다: `next/`** (`next.html` + `next/js/…`). 지금 게임(`index.html`, `js/`)은 교체 단계(08) 전까지 **고치지 않는다.** 옮겨 올 코드는 복사해서 `next/js/`에 둔다(import로 옛 `js/`를 끌어오지 않는다).
- **격자·턴·연출 대기열 없음.** `act()`/`endTurn()`/`TL`/`Anim`/칸 이동/`stepToward` 같은 구조를 새로 만들지 않는다.
- **영혼석 없음.** 영혼석 칸·드롭·스킬·색 배율·색의 반지·오브·공명 브랜드는 만들지 않는다. 역할(직업) 스킬이 그 자리를 대신한다.
- **파티 전제.** 등불지기·파티원·적 모두 같은 `Unit`이다. 조종 주체만 다르다(`player` / `ai`). 처음엔 파티원이 0명이어도 코드는 여러 명을 전제로 짠다.
- **시뮬레이션과 화면을 나눈다.** 시뮬레이션(`next/js/sim/`)은 DOM·THREE를 모른다. Node에서 브라우저 없이 돌고, 같은 씨앗이면 같은 결과가 나온다.
- **화면 스타일은 갈아 끼울 수 있게.** 렌더러는 어댑터 하나로 붙인다(04). 스타일(현재 디오라마 / 로우폴리 / 2D)은 아직 정해지지 않았다.
- 빌드 도구 없음. 브라우저 ES 모듈 + Three.js(CDN importmap). Node 22.

## 2. 시간 (모든 단계 공통)

- 고정 틱 **1/20초**. `world.step()` 한 번 = 한 틱.
- 시간은 **흐를 때만** 흐른다: 조이스틱·이동 키·Space를 누르고 있을 때, 자동 걷기·탐험 중, 스킬 시전 중(시전 시간만큼). 손을 떼면 멈춘다(화면만 0.15초 느려지며 멈춤).
- 멈춘 동안에도 고를 수 있는 것: 노릴 적, 스킬, 소모품, 파티 명령, 장비 창.
- 모든 지속·간격은 **초**로 쓴다. 걸음(0.3초)은 이동 거리에 비례하는 경제(횃불)에만 쓴다.

## 3. 폴더

```
next.html
next/js/
  sim/        규칙. DOM·THREE 금지. world.js(틱·유닛·이벤트), space.js(충돌·길찾기·시야), combat.js, ai/, status.js, elements.js, dungeon/, items.js, gear.js, torch.js, party.js, roles.js
  data/       표만(적·무기·역할·아이템·장비·지형·대사·건설·방문자)
  town/       정착지 규칙(sim과 같은 규칙: DOM·THREE 금지)
  render/     어댑터 + DioramaKit 등 화면
  ui/         HUD·조이스틱·창(DOM)
  app.js      시작·모드 전환·연결
next/tests/   node --test 단위 테스트(sim·town) + playwright 스모크
```

- 파일 하나 400줄 이하. 의존 방향: `data ← sim/town ← (이벤트) → render/ui`, `app.js`가 연결.
- 시뮬레이션은 `world.events`(배열)에 사건을 쌓고, 화면은 매 프레임 그것을 읽어 연출한다. 시뮬레이션이 연출을 기다리지 않는다.

## 4. 문구

`docs/문구_가이드.md`를 따른다. 로그는 일어난 일만, 설명 문구 없음, 시간은 "N초", 조사 얼버무림 금지(조사 함수 `jo()`를 옮겨 쓴다).

## 6. 모든 단계의 끝에 보고할 것

- 만든 파일·옮긴 파일(원본 경로 → 새 경로)
- 확인 목록 결과(통과/실패), 테스트 명령과 출력 요약
- 문서와 다르게 정한 것, 문서에 없어서 정한 것
- 다음 단계로 넘기는 알려진 문제

커밋은 단계마다 하나 이상, main에 바로 한다. 메시지 끝에 공동 작업자 줄을 넣는다(저장소 관례).
