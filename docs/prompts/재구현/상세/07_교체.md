# 07 · 교체

먼저 `00_먼저_읽기.md`를 읽는다. 01~06이 끝나 있어야 한다.

## 목표

`next/`가 옛 게임의 역할을 모두 하게 되면 **새 게임을 본편으로 바꾼다.** 옛 코드는 보관한다. 이 단계에는 새 기능이 없다.

## 할 것

1. **같은 기능 확인표**를 `docs/기록/교체_확인.md`에 만든다: 옛 게임 기능(던전·장비·횃불·정착지 건설·방문자·잇기·결말·도감·설정)마다 새 게임에서 되는지, 테스트 이름.
2. 옛 저장(`torch-meta-v3` 키의 최신 형식)을 새 저장(`torch-next-v1`)으로 옮기는 함수. 영혼석·영혼석 제단·오브·색 반지는 버리고, 장비·주민·건물·기억할 이름들은 옮긴다. 테스트로 확인.
3. 교체:
   - 옛 `index.html`·`js/`·`tests/*.mjs`(옛 것)·`raid-lab.html`·`js/lab/` → `versions/v4/`로 옮긴다(보관, 실행은 가능하게).
   - `next.html` → `index.html`, `next/js/` → `js/`, `next/tests/` → `tests/`. 경로를 고친다.
   - `package.json`의 `test`·`test:all`·`lint`, `.github/workflows/pages.yml`, `tools/fix-imports.mjs`를 새 구조에 맞춘다.
4. 문서:
   - `docs/코드정리_가이드.md`를 새 구조로 다시 쓴다.
   - `README.md`의 구성·테스트 절을 새로 쓴다.
   - 끝난 설계·계획 문서는 `docs/기록/`으로(`계획_실시간_1단계`, `설계_레이드_시제품`, `설계_영혼석_스킬`, 장비 데드셀안·디아블로, `docs/prompts/`의 옛 프롬프트).
   - 각 설계 문서 상태 줄을 새 코드 기준으로 고친다.

## 하지 말 것

- 교체와 함께 새 기능 추가.
- 옛 코드 삭제(보관만).

## 확인

1. `index.html`이 새 게임으로 뜨고 GitHub Pages 배포가 통과한다.
2. `npm run test:all`(새 테스트 전부)과 lint 통과.
3. 옛 저장을 넣고 열면 옮겨진 채로 이어진다.
4. `versions/v4/index.html`로 옛 게임이 열린다.
