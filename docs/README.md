# Slime Automation 문서 인덱스

이 폴더의 문서만으로 첫 번째 모바일 Web 세로 슬라이스를 구현할 수 있어야 한다. 대화 기록이나 외부 메모는 구현 근거로 사용하지 않는다.

## 문서 구성

1. IMPLEMENTATION_GUIDE.md
   - 제품 방향
   - 확정된 게임 규칙
   - 임시 밸런스
   - 기능별 작업 범위
   - 마일스톤과 완료 조건

2. TECHNICAL_SPEC.md
   - 실제 프로젝트와 씬 구조
   - 상태 클래스와 Definition 계약
   - GameSession 명령 API
   - 시스템별 알고리즘
   - 초기 상태와 콘텐츠 ID
   - 저장 스키마와 이벤트 계약

3. TEST_PLAN.md
   - 공통 불변식
   - 기능별 자동 테스트
   - 씬·터치·Web 통합 테스트
   - 마일스톤별 출시 게이트

## 문서 우선순위

문서끼리 충돌하면 다음 순서를 적용한다.

1. IMPLEMENTATION_GUIDE.md의 확정 게임 규칙
2. TECHNICAL_SPEC.md의 구현 계약
3. TEST_PLAN.md의 기대 결과
4. 코드의 기존 동작

코드와 문서가 다르면 코드를 기준으로 문서를 바꾸지 않는다. 먼저 의도된 변경인지 확인한 뒤 코드 또는 문서를 함께 수정한다.

## 변경 규칙

게임 규칙을 변경할 때는 다음 문서를 함께 갱신한다.

- 규칙 또는 밸런스 변경: IMPLEMENTATION_GUIDE.md
- 상태, API, 알고리즘 변경: TECHNICAL_SPEC.md
- 기대 결과 변경: TEST_PLAN.md
- 저장 필드 변경: TECHNICAL_SPEC.md의 schema_version과 마이그레이션 항목
- 마일스톤 범위 변경: 세 문서의 관련 완료 조건

모든 규칙 변경에는 다음을 기록한다.

- 변경 이유
- 기존 저장 데이터 영향
- 필요한 마이그레이션
- 변경되거나 추가되는 테스트
- 현재 마일스톤 범위에 포함되는지 여부

## 구현자가 임의로 결정하면 안 되는 항목

- 숙련도를 재화로 구매하지 않는다.
- 분열은 1마리에서 2마리이며 양쪽의 모든 보유 스킬이 1레벨 감소한다.
- 분열 세대에는 제한이 없고 총수만 서식지로 제한한다.
- 합성은 2마리를 소비하고 스킬 합집합을 가진 1마리를 만든다.
- 합성 결과는 무작위가 아니다.
- 일반 슬라임의 기억 용량은 1, 합성으로 최대 3까지 증가한다.
- 코칭은 작업 사이클당 한 번만 가능하다.
- 자동 작업은 코칭 없이도 계속된다.
- 슬라임은 행동으로 성장하고 시설은 재화로 성장한다.
- 모든 자원 변경은 InventorySystem을 통한다.
- 분열, 합성, 업그레이드는 원자적으로 실행한다.
- 미리보기와 확정은 같은 계산 함수를 사용한다.
- MVP에 운반, 오프라인 진행, 랜덤 특성, 전투를 넣지 않는다.

## 구현 시작 순서

1. IMPLEMENTATION_GUIDE.md의 M0과 M1을 읽는다.
2. TECHNICAL_SPEC.md의 프로젝트 설정, 상태 모델, M0/M1 API를 구현한다.
3. TEST_PLAN.md의 M0/M1 테스트를 먼저 통과시킨다.
4. 임시 도형 View를 연결한다.
5. 모바일 Web에서 M1 합격 기준을 확인한다.
6. M2 이후도 같은 순서로 반복한다.

## 완료의 정의

기능은 화면에서 한 번 작동했다고 완료되지 않는다.

완료 조건:

- 성공 경로 자동 테스트 통과
- 실패 경로 자동 테스트 통과
- 상태 불변식 통과
- 저장·불러오기 왕복 통과
- 터치 입력 중복 없음
- Web export 통과
- 해당 마일스톤의 수동 플레이 기준 통과
