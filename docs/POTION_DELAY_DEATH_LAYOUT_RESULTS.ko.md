# 물약 지연·사망 시 화면 확대 수정 결과

- 날짜: 2026-09-10
- 범위: 두 버그 직접 수정과 회귀 테스트. 길드 구현은 이번 버그 수정 요청에 포함하지 않았다.
- 테스트: `tests/potion_latency_death_layout_regression.gd`

## 1. 물약 처리

`_use_field_potion`에서 사용 전 롤백 캡처의 전체 이력 검증과 사용 후 전체 상태 검증을 실행 중 국소 사후조건 검사로 변경했다. 롤백 사본, 저장/로드의 전체 감사는 유지한다.

회복 이벤트는 다음 행동 단계가 시작되기 전에 발생하므로 그 이벤트 꼬리를 먼저 검증한다. 시간 진행 뒤에는 새 단계의 응답 이벤트부터 검증한다. 서로 다른 step_index의 이벤트를 한 꼬리로 검사해 잘못 거절하지 않도록 경계를 분리했다. 물약의 게임 내 행동 비용과 회복 후 세계 응답 순서는 변경하지 않았다.

동일 레거시 고정 시드의 실제 부상 후 사용 1회 비교:

| 상태 | 물약 함수 경과 시간 | 사용 후 이벤트 수 |
|---|---:|---:|
| 수정 전 | 284,922µs | 95 |
| 수정 후 측정 1 | 86,937µs | 95 |
| 수정 후 측정 2 | 100,031µs | 95 |
| 수정 후 측정 3 | 88,980µs | 95 |

각 수치는 별도 실행의 단회 측정이며 통계적 성능 보장이나 모든 환경의 p95 결과가 아니다. 함수 처리 시간만 측정했으므로 실제 모바일 입력·렌더링 지연 전체를 뜻하지 않는다. 현재 living 모드에서도 물약 승인과 저장 재생을 확인했으며 해당 시나리오는 이벤트 301개에서 약 129~164ms였다(수정 전 동조건 측정 없음).

## 2. 사망 시 지도 확대

현재 living 모드에서 실제 적에게 공격받아 사망했을 때 지도가 `390×518`에서 `390×590`으로 커지는 것을 재현했다. 사망 후 파티 카드 목록이 비어 `party_card_layout_spec(0, …)`가 높이 0을 반환하고, 그 차이 72px를 지도가 차지하는 것이 직접 원인이었다.

- 솔로 제품 화면의 파티 카드 목록이 비어도 기존 72px 영역을 유지한다. 다른 비제품 화면의 빈 목록 동작은 유지한다.
- 종료/완료 시 스킬행의 48px 공간도 유지하고 행동 버튼만 제거한다.
- 지도 투영 계산이 직전 프레임의 스킬행 visible 상태에 의존하지 않도록 솔로 지도에서는 고정 높이를 사용한다.

수정 후 실제 living 모드 사망 전후 모두 지도 크기 `390×518`, 투영 타일 수 `13×19`, 사용자 줌 값이 유지됐다.

## 3. 검증

실행 명령:

```sh
godot --headless --path . --script tests/potion_latency_death_layout_regression.gd
godot --headless --path . --script tests/potion_latency_death_layout_regression.gd -- --living
```

- 레거시 및 living 시드: 실제 이동·적 공격으로 부상, 물약 1회 소비와 양수 회복, 사용 후 전체 감사, 저장/로드·snapshot 동일성 통과.
- 실제 적 공격으로 사망 후 지도 rect·투영 타일·줌 유지 통과.
- 종료/완료 DTO 분기 주입: 360/390/450px 폭에서 비활성 스킬 영역 유지 및 지도 크기/투영 유지 통과.
- 최종 레거시 실행에는 시간 진행 실패 주입을 추가하여 HP·아이템·시간·이벤트·명령 저널의 정확한 롤백과 잘못된 아이템 요청의 무변경을 검증했다.
- living 실행은 실패 주입 테스트 추가 직전 버전으로 통과했다. 실패 주입은 최종 레거시 실행에서 확인했다.
- 테스트는 Godot headless의 실제 Control 레이아웃과 canonical 전투를 사용한다. 종료 완료 분기는 DTO 주입이며, 물리 모바일 기기의 화면 캡처/브라우저 줌 검증은 하지 않았다.

## 4. 동시 작업과 커밋

수정은 기존 시야·아이템 변경을 보존하며 `_use_field_potion`, 스킬행 렌더링, 파티 카드 높이, 지도 투영의 좁은 범위에 적용했다. 작업 도중 다른 세션이 공유 파일을 커밋하여 물약 수정은 `1dee9b1`, 화면 수정은 `adae8a1`에 함께 포함된 것을 확인했다. 해당 커밋을 재작성하거나 되돌리지 않았다.

후속 커밋은 이번 회귀 테스트와 결과 문서만 포함한다. 전체 시야/아이템 구현을 이번 작업의 성과로 보고하지 않으며 푸시는 수행하지 않았다.
