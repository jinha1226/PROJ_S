# 상단 행동 타임라인 구현 결과

2026-09-08. 작업 브랜치 `feat/battle-action-timeline`, 작업 폴더 `living-world-sim-timeline`.
기존 Task 1~3 커밋 위에 Task 4·5 통합과 검증을 진행했다. 커밋·푸시·메인 병합 및 GitHub Actions 변경은 하지 않았다.

## 구현

- DUO 전투에서 상단 HUD와 맵 사이에 48px 줄을 추가했다. 탐험/거점/전리품에서는 숨기며 맵의 가용 높이 계산도 같이 바꿨다.
- 아군 왼쪽, 관측된 적 오른쪽, 중앙 준비 영역이다. 중앙 폭을 24→48px로 늘려 양 진영의 48px 터치 영역이 겹치지 않게 했다.
- 실제 그려진 위치로 터치를 판정한다. 최초 컨테이너 배치와 화면 크기 변경은 새 위치에 바로 맞추며, 세계 상태 변화만 짧게 보간한다.
- 자동전투와 타임라인이 `_battle_presentation_blocked()`를 공유한다. 타임라인 홀드·그룹 목록·기술 선택·기존 드래그/모달 상태에서 자동 행동을 막는다.
- 실제 커밋의 행동 이벤트만 180ms 강조한다(자동전투 간격 320ms보다 짧게). 같은 이벤트나 화면 갱신으로 강조를 다시 시작하지 않고, 강제 이동은 추가 행동으로 세지 않는다. 정보 탭의 800ms 강조와는 별개다.
- 상단 탭은 맵의 인물과 아군 하단 초상화를 800ms 강조한다. 선택 인물/공격 표적/세계시간/기력/저널을 바꾸지 않는다.
- 압축 그룹은 48px 행을 가진 목록으로 연다. 외곽 터치·닫기·취소 키/뒤로 가기로 닫힌다. 전체 화면 입력 차단층과 샌드박스 입력 가드를 함께 써서 맵/드래그로 입력이 새지 않게 했다.
- 스킬 대상 선택 중 상단 탭은 시전이나 그룹 열기로 이어지지 않는다. 바깥으로 놓기·두 번째 손가락·창 포커스 상실은 홀드가 남지 않도록 처리한다.
- 새 월드의 객체 식별자를 세션 조회 캐시 키에 포함해, 카운터가 같은 재시작/불러오기에서 이전 DTO가 재사용되지 않게 했다.

## 시간 표시의 의미와 한계

- 아군 `ready_at`은 코어의 준비 시각이다. 적 `eligible_at`은 기존 actor tick을 고려한 **예상 기회**다. 인지/거리/행동 변경에 따라 결과는 달라질 수 있다.
- 실제 실행 강조는 커밋된 이벤트에서만 나온다. 위치가 중앙에 도착했다고 시뮬레이터를 실행하지 않는다.
- 본 게임은 여러 아군을 묶어 처리한다. 두 아군이 중앙에 함께 준비 상태로 있는 것은 현재 규칙의 결과이며, 가짜 개인 쿨타임으로 숨기지 않았다.
- 독립 행동 게이지, 추가 공격 빈도, 전투 밸런스 조정은 구현하지 않았다. 필요하면 인계 문서 10절의 별도 스케줄러 작업이 필요하다.
- 세션 조회는 최근 최대 64개 이벤트만 확인하고 캐시를 사용한다. 실제 강조는 커밋 결과의 이벤트 ID에서 받으므로 전체 과거 로그를 프레임마다 훑지 않는다.

Godot 4.6.2 headless에서 실행했다. 아래 스크립트는 `godot --headless --path . --script tests/<파일>` 형식으로 실행하며, 종료 코드뿐 아니라 로그의 `SCRIPT ERROR`/`ERROR`/`FAIL`도 확인했다.

통합 검사는 360×640·390×844에서 `Input.parse_input_event()`로 실제 터치 입력 경로를 사용한다. 홀드 중 자동 행동 차단, 그룹 버튼 터치, 바깥 놓기/두 손가락 취소, 기술 대상 모드, 커밋 강조 중복 방지, 전리품에서 숨김, 하단 메뉴 순서 보존을 검사한다. 짧은 강조가 느린 테스트 호스트의 전체 UI 갱신 도중 만료되는 것은 허용하되, 갱신으로 강조 마감 시각이 연장되는 것은 실패 처리한다.

빌드 명령: `godot --headless --path . --export-release Web /tmp/timeline-final-web-06vSmw/index.html`.
독립 시작은 `/tmp`에서 `godot --headless --main-pack /tmp/timeline-final-web-06vSmw/index.pck --quit-after 8`로 확인했다. 이는 웹 브라우저에서의 실제 플레이 검사가 아니라 내보낸 리소스의 독립 로드/시작 검사다.

### 기존 검사와 비교

전체 `run_product_tests.gd` 최초 실행은 182개 중 14개 실패였다. 실패한 14개 메서드를 변경 전 코드에서 각각 다시 실행해 비교했다(변경 전 전체 182개 재실행은 아님).

- 13개는 변경 전에도 동일한 assertion으로 실패했다. 기존 바닥/종족 에셋, 폰트/이전 UI 구성, 성장·명중 규칙 등에 대한 기대값이다. 일부 검사는 기존 null/index 오류와 종료 시 리소스 누수도 동반한다.
- 나머지 1개는 이번 타임라인이 숨겨진 상태에서도 formation/debug 레이아웃의 마지막 자식이 되는 새 회귀였다. 모든 레이아웃에서 `BottomNavigation`이 마지막에 오도록 수정하고 통합 검사에 재발 방지 항목을 넣었다. 기존 `test_each_formation_uses_visible_button_preview_ghosts_and_confirm_to_engaged()`를 단독 재실행하여 WEDGE/LINE/COLUMN 모두 통과했다(`/tmp/timeline-final-formation-v2.log`, 스크립트 오류 없음). 수정 후 전체 182개를 다시 실행한 것은 아니다.
- `party_ui_visual_style_smoke.gd`: 22개 FAIL 줄과 `gauge_spec` null 오류가 변경 전에도 재현되었다. FAIL 목록 diff는 비어 있다.
- `party_ui_layout_smoke.gd`: 26개 실패와 Nil→Dictionary 오류가 변경 전에도 재현되었다. FAIL 목록 diff는 비어 있다.

변경 전 비교 대상은 `living-world-sim-p3`의 기존 UI carry 상태다. 타임라인 베이스 `1e474bb`와 관련 `playtest/`, `sim/`, `tests/` 코드가 같음을 확인했다. 이 작업에서는 해당 폴더의 소스 및 기존 테스트 기대값을 수정하지 않았다. 전체 테스트가 모두 통과한다고 해석하면 안 된다.

### 성능

12회 커밋 표본의 최댓값: 콜드 조회 **4,945µs**, 캐시 조회 **103µs**, 레이아웃 **141µs**. 이 측정은 headless 개발 환경의 소수 표본이며 휴대폰 성능 보장은 아니다. 캐시 조회는 프레임마다 전체 이벤트를 스캔하지 않는다.

주요 로그: `/tmp/timeline-final-integration-v4.log`, `/tmp/timeline-final-acceptance-v3.log`, `/tmp/timeline-final-export.log`, `/tmp/timeline-final-pack.log`. 기존 실패 비교는 `/tmp/timeline-baseline-product.log`, `/tmp/timeline-baseline-visual.log`, `/tmp/timeline-baseline-layout.log`에 남겼다. `/tmp` 로그는 임시 파일이므로 핵심 결과는 이 문서에도 기록했다.

휴대폰 실기의 글자 크기·손가락 조작성은 아직 확인하지 않았다. 헤드리스 포인터 검사와 논리 화면 크기 검사를 실제 기기 플레이테스트로 대체했다고 주장하지 않는다.
