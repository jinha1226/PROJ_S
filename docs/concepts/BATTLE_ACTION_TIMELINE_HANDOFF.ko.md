# 상단 양방향 행동 타임라인 — 구현 인계 계획

작성: 2026-09-08. 상태: **설계만 완료, 타임라인 구현 전**.

작업 저장소: `/mnt/d/STARTU/living-world-sim-p3`.
대상: 인간 2인 파티, 이동은 플레이어가 지정하고 조우 시 자동전투, 필요할 때 수동 기술/공격 표적 지시.

## 1. 사용자 요구와 목표

아군은 왼쪽, 적은 오른쪽에서 중앙을 향해 이동하는 작은 초상화로 표시한다. 중앙은 행동 시점이다. 다음에 누가 행동하는지 읽고 치유·공격 지시에 개입할 수 있어야 한다.

```text
기존 상단 HUD: 층 / 상태       남은 탐험 시간       기존 우측 정보
전투 전용 줄: 아군 ② ①  ──→  [행동]  ←──  적 A B C · +N
게임 맵
기존 하단: 각 인물의 기술 버튼 / 초상화 / 정지·자율
```

이것은 `턴 15` 같은 누적 횟수 표시가 아니다. 행동 가능 시각과 실제 행동을 보여주는 전투 정보다. 상대가 중앙에 가까워도 이동·방어를 할 수 있으므로 **중앙 도착 = 반드시 공격/피해 발생**으로 설명하지 않는다.

## 2. 먼저 알아야 하는 현재 코드의 제약

아래는 문서 작성 시 로컬 코드에서 확인한 사실이다. 기존 시간 관련 기획 문서나 실험실의 구현을 본 게임의 현재 동작으로 간주하지 말 것.

| 코드 | 현재 역할 / 주의점 |
| --- | --- |
| `playtest/autonomous_battle_clock.gd` | 자동전투 표시 간격 0.32초. 세계시간이나 개인 행동 순서를 결정하는 시계가 아니다. |
| `playtest/party_encounter_sandbox.gd::_tick_autonomous_battle` | 자동 판단 → `commit_turn()` 호출. 모달·드래그·기술 대상 선택·일시정지 중 보류한다. |
| `sim/simulator.gd::step_party_turn` | 여러 아군의 행동을 한 단계로 처리하고 각자의 `busy_until`을 설정한다. |
| `sim/simulator.gd::commit_active_skill` | 기술을 먼저 적용하고 다른 준비된 아군의 기본 행동을 처리한다. 다음 정착 경계까지 세계시간을 진행한다. |
| `sim/systems/party_encounter_coordinator.gd::_enemy_batch` | 적의 준비 시각뿐 아니라 actor tick, 인지·거리·행동 가능 여부를 확인한다. 같은 틱의 적들도 묶음 처리될 수 있다. |
| `sim/party_member_state.gd` / `sim/party_encounter_state.gd` | 아군 `busy_until`, 적 `enemy_busy_rows`가 기존 권위 있는 준비 시각이다. |
| `sim/abilities/action_timeline.gd` / `playtest/active_combat_timeline_hud.gd` | 별도 전투 실험실용. 별도 `now/ready`와 비용 표가 있으므로 본 게임에 그대로 연결하면 두 개의 전투 시계가 생긴다. |

중요한 결과:

- 지금은 모든 인물이 완전히 독립된 연속 게이지로 행동하는 구조가 아니다.
- 아군의 비용이 각각 80/120이라도, 한 묶음이 끝난 세계시간이 120이면 UI가 읽을 때 둘 다 이미 준비됐을 수 있다. UI만 추가해서 80짜리 아군이 중간에 한 번 더 행동했다고 표시하면 안 된다.
- 적의 `busy_until=170`이라도 다음 실제 actor tick이 200이면 170에 행동한다고 확정해 표시하면 안 된다.
- 확정된 준비 시각, 현재 계획상 다음 행동 후보, 실제 실행된 행동을 구분해야 한다.

### 구현 범위 결정

**1차 구현은 현재 전투 규칙을 보존하는 ‘행동 준비/실행 타임라인’이다.** 같은 시각 또는 같은 묶음은 함께 표시한다. 독립적으로 행동하지 않는 인물을 보기 좋게 한 명씩 행동하는 것처럼 연출하지 않는다.

사용자가 원하는 완전한 개인별 왕복 게이지를 달성하려면 10절의 스케줄러 작업이 추가로 필요할 수 있다. 구현자는 1차 화면에서 아군이 자주 중앙에 함께 대기하는 현상을 확인하고 보고해야 한다. 이를 가짜 대기 시간으로 숨기거나 UI 작업 중 임의로 전투 규칙을 바꾸지 않는다.

## 3. 모바일 레이아웃

- 기존 상단 HUD 아래에 **전투 중에만 높이 48 논리 px 한 줄**을 추가한다. 탐험 시간·체력 등 기존 정보를 대체하지 않는다.
- 초상화 그림 24~28px, 중앙 표시 20~24px, 글씨 11~12px을 초기값으로 한다. 실제 폰에서 확인 후 조정한다.
- 터치 영역은 최소 48×48px. 그림 크기와 터치 영역은 별개다.
- 맵 위에 덮지 않고 레이아웃에 실제 높이를 반영한다. `_current_grid_view_dimensions()` 등 가용 맵 계산과도 연결한다.
- 탐험·거점·전투 종료/전리품 창에서는 숨기고 공간을 반환한다. 등장/퇴장 시 카메라 점프를 확인한다.
- 아군은 현재 전투에 참여 중인 생존 인물을 모두 표시한다. 기본 2명이며 지원 범위를 넘으면 압축 그룹을 사용한다.
- 적은 **현재 관측 가능하고 전투에 참여한 적 중 가장 이른 후보 최대 3명**만 표시한다. 숨겨진 적은 숫자에도 포함하지 않는다.
- 나머지 관측된 참여 적은 우측 보조 문자 `+N`으로 표시한다. 별도 작은 터치 버튼을 만들지 않는다.
- 동일 종족/동일 에셋도 구분하도록 아군은 번호, 적은 짧은 A/B/C 표식을 붙이고 맵 강조와 일치시킨다. 영구 엔티티 ID를 사용자에게 노출하지 않는다.
- 색만으로 진영을 구분하지 않는다. 좌우 방향·진영 표식도 함께 사용한다.

### 겹침 처리

시간상 가까운 초상화의 터치 영역이 겹치면 한 그룹으로 묶어 대표 초상화와 인원수를 표시한다. 같은 시각의 인물을 옆으로 밀어 다른 시각처럼 보이게 하지 않는다. 그룹을 누르면 구성원을 고르는 작은 목록을 연다(각 행 높이 48px 이상).

그룹 중 준비 시각이 서로 다르면 `근접한 차례`, 실제 같은 실행 묶음이면 `같은 행동 묶음`으로 구분한다. 공간 압축과 전투의 동시 처리를 혼동하지 않는다.

## 4. 시간 → 위치 규칙

### 권위 있는 의미

- `ready_at`: 기존 코어가 가진 다음 행동 가능 시각. 모르면 값 없음으로 처리한다.
- `eligible_at`: 코어의 현재 배치/틱 규칙까지 고려한 가장 이른 실행 후보 시각. 정확히 유도할 수 없으면 값 없음이다.
- `acted_at`: 실제 커밋 이벤트의 세계시간. `event_id`는 같은 시각의 기록 순서를 구분하는 데만 쓴다.
- 준비됐어도 실제 행동이 확정된 것은 아니다. 인지·표적·행동 불능·지침 변경으로 행동이 달라질 수 있다.

### 위치 계산 초안

양쪽을 같은 시간 척도로 그린다. 초기 표시 범위 `H=300` 세계시간 단위는 UI 설정값으로 한 곳에 둔다. 개인마다 자신의 비용을 100%로 정규화하지 않는다. 그러면 80과 160이 똑같이 보인다.

```text
remaining = max(0, ready_at - world_time)
ratio = clamp(remaining / H, 0, 1)
ally_x  = left_center_edge  - ratio * left_rail_length
enemy_x = right_center_edge + ratio * right_rail_length
```

- 중앙은 좁은 ‘준비 영역’으로 잡고 아군/적 표식을 서로 포개지 않게 양쪽 가장자리에 둔다.
- `remaining=0`이면 중앙에 머물며 `준비` 표시. 실행 전에는 외곽으로 재출발하지 않는다.
- `remaining>H`이면 가장 바깥에 표시하고 범위 밖 표식 하나를 붙인다. 과도한 속도 보간이나 숫자 스크롤을 만들지 않는다.
- 행동 후 새 `ready_at`이 현재보다 미래일 때만 그 남은 시간에 해당하는 위치로 돌아간다. 무조건 맨 끝으로 보내지 않는다.
- 현재 묶음 처리상 다음 정착 시점에 이미 준비됐다면 중앙에 남는 것이 올바르다.
- `eligible_at`이 있는 가장 이른 그룹에는 `다음` 표시. 아직 코어와 순서 일치를 검증하지 못한 예측에는 `예상`을 붙인다. 아군 우선/작은 ID 우선 순서를 UI가 새로 만들지 않는다.
- 원시 속도 수치만으로 `ready_at`을 다시 계산하지 않는다. 재료·무기·상태 등 비용 보정은 기존 공용 계산을 사용한다.

## 5. 애니메이션과 실제 전투의 동기화

타임라인은 전투를 구동하는 장치가 아니라 **코어가 준 결과를 보여주는 장치**다.

1. 커밋된 새 상태를 받으면 새 준비 위치를 계산한다. 세계시간이 계단식으로 변하는 것은 정상이다.
2. 두 확정 상태 사이 위치 변화만 최대 0.10초 정도로 부드럽게 표시한다. 이 보간으로 새 행동이나 피해를 발생시키지 않는다.
3. 실제 행동 이벤트가 오면 중앙에 해당 인물/묶음을 짧게 강조하고 맵의 기존 행동 효과와 함께 표시한다. 전체 사건을 한 명씩 재생하느라 전투를 지연시키지 않는다.
4. 빠른 연속 결과가 오면 이전 이동 보간을 최신 상태로 대체한다. 낡은 초상화 이동을 무한 큐에 쌓지 않는다.
5. 표시 초상화가 중앙에 도착했다는 이유로 `commit_turn()`이나 기술 API를 호출하지 않는다.

`autonomous_battle_clock.remaining`은 표시 호출 간격일 뿐이다. 이를 0~100% 개인 행동 게이지로 재활용하지 않는다. 실제 세계시간이 멈췄는데 초상화만 중앙에 도착해 행동 완료처럼 보이는 연출도 금지한다.

### 정지와 수동 개입

- 일시정지·스킬 대상 선택·타겟 드래그·모달 중에는 예상 이동 보간도 멈춘다. 관련 사유는 하나의 공용 presentation-blocked 상태를 참조하도록 정리한다.
- 단, 정지 중 플레이어가 허용된 수동 기술을 실제 커밋했다면 그 확정된 결과에는 즉시 동기화한다. 정지는 새 자동 행동을 막는 것이지 오래된 정보를 유지하는 기능이 아니다.
- 재개 시 이전 지연분을 한꺼번에 처리하지 않는다.
- 사망·전투 이탈·시야 상실 시 표식을 즉시 제거한다. 퇴장 애니메이션 때문에 죽은 적에게 `다음`이 남으면 안 된다.
- 전투 종료는 기존 전리품 창으로 이어진다. 타임라인 완료 연출을 기다리게 하지 않는다.

## 6. 상단 터치 동작

- 초상화 탭: 맵의 해당 인물과 대응하는 하단 초상화를 약 0.8초 강조하고 짧은 이름/준비 상태를 보여준다. 강제 카메라 이동은 MVP에서 하지 않는다.
- 이 탭은 정보 확인이다. 공격 대상 변경·기술 시전·이동·자원 소비를 일으키지 않는다.
- 스킬 대상 선택 중 상단 탭을 시전 확정으로 사용하지 않는다. 이번 버전에서는 상단 탭을 비활성화하고 기존 맵/하단 대상 선택만 유지한다.
- 기존 ‘맵 캐릭터 또는 하단 초상화 → 적 드래그’를 보존한다. 상단 타임라인을 새로운 드래그 시작점으로 확장하지 않는다.
- 영역 안의 터치가 아래 맵으로 관통하지 않아야 한다. 손가락을 누르고 있는 동안 자동전투를 보류하되, 놓으면 원래 정지 상태를 유지/복원한다.
- 2인 이상 압축 그룹 목록은 모달 취급으로 자동전투를 보류한다. 닫기/바깥 터치/뒤로 가기와 모바일 중복 마우스 입력을 검사한다.

## 7. 모듈과 데이터 계약 제안

다음 파일명/API는 **신규 제안**이며 아직 존재하지 않는다. 현재 거대한 샌드박스 파일에 계산·그리기·입력을 모두 추가하지 말 것.

| 제안 모듈 | 책임 |
| --- | --- |
| `playtest/battle_timeline_presenter.gd` | 세션에서 허용한 데이터 → 순수 DTO. 진영, 공개 대상, 준비 시각, 그룹, 다음 후보, 이벤트 연결. |
| `playtest/battle_timeline_bar.gd` | 48px 줄의 그리기, 위치 보간, 겹침 그룹, 탭/선택 신호. 코어 직접 수정 금지. |
| `playtest/party_playtest_session.gd` | `battle_timeline_state()`라는 읽기 전용 창구와 기존 커밋 결과 연결. |
| `playtest/party_encounter_sandbox.gd` | 표시/숨김, HUD 높이, 입력 보류, 맵 강조, 결과 전달만 연결. |

최소 DTO 예시(런타임용, 새 저장 스키마가 아님):

```text
BattleTimelineState
  revision, world_time, phase, visible
  entries[]
    entity_id, side(ALLY/ENEMY), display_name, portrait_key, marker
    ready_at(nullable), eligible_at(nullable)
    status(RECOVERING/READY/UNAVAILABLE)
    group_key, timing_confidence(READINESS_ONLY/EXPECTED)
    is_next_candidate
  hidden_visible_enemy_count
  recent_actions[]
    event_id, actor_id, acted_at, action_kind, batch_key
```

계약:

- `hidden_visible_enemy_count`는 ‘관측됐지만 표시 상한 때문에 생략한 참여 적 수’다. 미발견 적 수가 아니다.
- DTO는 분리된 값으로 반환한다. Node·Callable·world 참조·가변 인물 객체를 넣지 않는다.
- `ready_at`/`eligible_at`이 없다는 것을 임의의 0으로 바꾸지 않는다.
- 최근 행동은 `action.skill`, 일반 `action.move`, `action.melee_attack`, `action.hold` 등 실제 행동의 루트만 사용한다. 밀치기에 의한 강제 이동이나 피해 파생 이벤트를 추가 턴으로 세지 않는다.
- `batch_key`는 실제 실행 경계로 유도한다. 화면 겹침 그룹과 별개로 관리한다.
- 조회로 RNG·이벤트·세계시간·기력·저널·준비 중인 명령을 바꾸지 않는다. `prepare_autonomous_party_turn()`을 단순 그리기 조회 대신 반복 호출하지 않는다.
- 이미 만들어진 계획/결과를 재사용하거나 순수한 조회 경로를 추가한다. 예측을 얻으려고 매 프레임 월드 복제·저장·SHA 계산·롤백 시뮬레이션을 수행하지 않는다.
- DTO 갱신은 커밋/관측/전투 상태 변화 시에만 한다. 프레임마다 하는 일은 작은 그림 위치 보간뿐이다.
- 타임라인을 저장하지 않는다. 불러오기 시 코어에서 재구성하고, 과거 행동 플래시를 다시 재생하지 않는다.

## 8. 구현 순서와 제출물

1. 위 현재 코드 경로와 기존 변경분을 확인한다. 초상화 스킬·드래그·전리품 작업이 미커밋 상태일 수 있으므로 보존한다.
2. 고정 시드 실제 전투에서 시작 시각, 아군 `busy_until`, 적 tick/준비 시각, 행동 이벤트를 작은 표로 기록한다. 비용 80/120 묶음과 적 준비 170/tick 200 같은 경계도 단위 테스트로 명시한다.
3. 읽기 전용 DTO와 순서/그룹 테스트를 먼저 만든다. 아직 확정할 수 없는 예측은 `READINESS_ONLY`로 내려보낸다.
4. 정적인 좌우 타임라인을 붙인다. 360/390px 세로에서 기존 HUD·기술 버튼·맵 터치와 겹치지 않는지 확인한다.
5. 실제 커밋 결과 연결, 짧은 보간, 다음 후보, 정지/재개, 사망/종료 정리를 추가한다.
6. 초상화 탭 강조와 그룹 목록을 추가하고 실제 Input 경로로 터치·마우스 회귀를 검사한다.
7. 아래 인수 검사를 수행하고, 본 게임의 묶음 행동 한계가 화면에서 어떻게 보이는지 보고한다. 필요하면 10절로 넘어갈 별도 변경안을 제시한다.

제출: 코드, 로컬 검사 명령/결과, ‘예상’과 ‘확정’의 구분, 알려진 한계. 요청받지 않은 커밋·푸시·GitHub Actions 변경은 하지 않는다. 이미지 에셋 생성이나 새 대규모 테스트 파이프라인은 필요 없다.

## 9. 인수 기준

- [ ] 실제 게임의 기존 피해·행동 횟수·시간·저장 결과가 타임라인 유무와 동일하다.
- [ ] 아군 왼쪽/적 오른쪽/중앙 행동 표시. 같은 시각과 같은 묶음을 가짜 개인 순서로 바꾸지 않는다.
- [ ] 아군 준비 시각이 정착 시각보다 이르면 중앙 `준비` 상태이지, 가짜 새 쿨타임이 아니다.
- [ ] 적 actor tick보다 이른 시각을 ‘확정 다음 행동’으로 표시하지 않는다.
- [ ] 준비가 가장 이른 인물이 죽거나 시야를 벗어나면 즉시 다음 후보가 바뀐다.
- [ ] 미발견 적·비참여 NPC의 초상화나 인원수가 새어 나오지 않는다.
- [ ] 강제 이동·다중 피해를 여러 턴으로 세지 않는다. 실제 이벤트 하나를 두 번 강조하지 않는다.
- [ ] 일시정지·기술 선택·드래그·그룹 목록·전리품 창에서 자동 시간이 흐르지 않는다.
- [ ] 수동 기술 성공/취소/거절 및 타임라인 탭이 기존 자원/정지 규칙을 깨지 않는다.
- [ ] 360/390px 세로, 적 1/3/6명, 같은 에셋 여러 명, 동시 준비, 사망, 재진입을 검사한다.
- [ ] 모든 클릭 영역이 48px 이상이거나 안전한 그룹으로 합쳐지며, 타임라인 터치가 맵 이동을 유발하지 않는다.
- [ ] 아군/적 수가 고정일 때 전투가 길어져도 프레임당 전체 과거 로그를 훑지 않는다. UI 갱신과 조회 시간을 따로 측정해 보고한다.
- [ ] 기존 `tests/battleheart_mvp_acceptance.gd`, `tests/battle_mobile_loot_acceptance.gd`를 유지하고 필요한 로컬 타임라인 검사를 추가한다.
- [ ] Godot 파싱, Web export, 소스 폴더 밖 배포 PCK 시작을 확인한다. 휴대폰 실기 가독성은 별도 확인이 필요함을 명시한다.

## 10. 후속: 완전한 개인별 행동 게이지가 필요할 때

이는 UI 확장이 아니라 전투 스케줄러/밸런스 변경이다. **1차 UI 작업에 묵시적으로 포함하지 않는다.** 필요성이 확인되면 아래 범위로 별도 승인·구현한다.

- 아군과 적이 공통된 권위 시간축에서 각자의 `next_ready_at`에 행동하도록 한다. 빠른 아군이 느린 동료의 묶음 종료를 기다리지 않고 다시 행동할 수 있어야 한다.
- 같은 시각의 동시 판정/우선순위, 행동 직전 사망, 보호/회복, 표적 재평가를 명시한다. 주인공이나 낮은 ID에게 새 우선권을 주지 않는다.
- 이동·공격·시전 비용을 기존 공용 규칙에서 가져오고, actor tick·환경 사건·배고픔이 빠지거나 이중 진행되지 않게 한다.
- 현재 수동 기술이 다른 아군 행동을 한 번씩 함께 처리하는 계약을 어떻게 바꿀지 먼저 확정한다. 개인 차례 방식이라면 다른 인물에게 무료 추가 행동을 주지 않는다.
- 실험실 `action_timeline.gd`의 별도 HP/시간/비용 표를 본 게임의 두 번째 상태로 복제하지 않는다.
- 저장/구 저널 재현 경계를 버전으로 구분하고, 기존 전투 결과가 달라지는 부분을 명시한다.
- 행동 빈도 변화 자체가 밸런스 변경이므로 고정 조건에서 행동 횟수·받은 피해·전투 소요 세계시간을 비교한다.

이 전환을 마친 뒤에야 ‘각 캐릭터가 중앙에 도착할 때 독립적으로 행동하고 바깥으로 돌아간다’는 최종 개념을 정확하게 구현할 수 있다. 1차 UI를 그 완성판이라고 보고하지 않는다.

## 구현자에게 전달할 요약

이 문서를 먼저 읽고 현재 본 게임의 시간/묶음 처리와 대조하라. 우선 코어를 바꾸지 않는 양방향 행동 준비·실행 타임라인을 별도 모듈로 구현하라. 준비와 실제 실행을 구분하고, 같은 묶음·관측 제한·정지·저장·성능·기존 드래그/기술/전리품 회귀를 지켜라. 실제 개인별 게이지를 위해 필요한 코어 전환은 별도 범위로 보고하라.
