# 작은 거점과 원정 — 첫 개발 계획

## 방향

던전의 물자를 안전하게 가져와 작은 거점을 개선하고, 개선된 준비 여건으로 다음 원정에 나간다. 전투는 기존 2인 자동전투와 간헐적 지휘를 유지한다. 마을에서 기다리거나 접속을 유지해서 자원을 얻는 구조는 만들지 않는다.

림월드에서는 주민의 상태·관계와 재료를 이용한 건설·제작이 거점 운영에 함께 작용한다([공식 소개](https://rimworldgame.com/)). 여기서는 그 연결을 참고하되, 자유 건설·농사·생산망·거점 습격을 한꺼번에 구현하지 않는다.

## 첫 수직 구현 범위

1. 던전에서 목재·석재·약초를 수집한다. 수집 지점은 화면에서 찾을 수 있어야 하고, 실제 위치와 행동 시간을 요구한다.
2. 원정 중 휴대 물자와 거점 보관 물자를 분리한다. 안전한 귀환을 완료해야 보관 물자로 전환된다.
3. 창고·숙소·치료실 세 시설을 고정 배치한다. 물자를 지불해 1~3단계로 개선하며 현재 효과·다음 효과·비용을 표시한다.
4. 효과는 운반·휴식·치료에 실제로 적용한다. 장식용 레벨만 올리지 않는다. 세부 수치와 효과는 구현 규칙 및 검증 결과를 기준으로 별도 기록한다.
5. 기존 치료·장비·상점·원정 출발은 계속 접근 가능해야 한다.

첫 버전은 현재 두 인물의 상태를 거점에서도 표시한다. 주민 네 명과 출전 두 명의 교대 편성은 다음 단계다. 새로운 주인공 사망 규칙, 자동 재영입, 별도 주민 복제 데이터는 이번에 도입하지 않는다.

## 첫 튜닝안

구현팀과 합의한 초기 값이며 확정 밸런스가 아니다. 시작 보관 물자는 목재 4·석재 2·약초 2로, 시작 물자만으로는 개선할 수 없다.

| 시설 | 1 / 2 / 3단계 효과 | 2단계 비용 (목재/석재/약초) | 3단계 비용 |
| --- | --- | --- | --- |
| 창고 | 원정 운반 한도 8 / 12 / 18 | 8 / 5 / 0 | 14 / 10 / 0 |
| 숙소 | 기존 휴식의 긴장 회복 300 / 450 / 650 | 6 / 3 / 2 | 12 / 8 / 5 |
| 치료실 | 기존 치료비 25 / 20 / 15금화, 회복 물약 판매 재고 4 / 5 / 6 | 4 / 4 / 6 | 8 / 8 / 12 |

층마다 유한 수집 지점 9곳을 배치한다. 목재·석재 지점은 각각 3개씩 3단위, 약초 지점은 3개씩 2단위로 총 24단위다. 한 번에 전부 운반할 수 없으며, 원정·층·지점 식별자로 수집 잔량을 추적한다. 운반 한도 때문에 일부만 수집하면 나머지는 지점에 남긴다.

보관 물자만 목재 2금화·석재 3금화·약초 4금화에 교환할 수 있다. 시설 개선과 당장의 치료/소모품 사이에 선택을 만들고, 유한한 시작 금화가 소진되어도 원정으로 운영비를 마련할 수 있게 한다. 귀환 자체로 무료 금화를 지급하지 않는다.

시작 재고를 고려하면 첫 개선에 필요한 추가 물자는 창고 7단위, 숙소 3단위, 치료실 6단위다. 모두 초기 운반 한도 안에 들어가지만 실제 접근 거리·전투·치료 지출을 포함한 첫 개선 소요 시간은 플레이테스트로 확인해야 한다.

## 시간과 귀환

- 마을에서는 시간을 멈춘 채 준비하고 시설을 개선한다. 메뉴 열기·새로고침·저장 불러오기로 보상을 얻지 않는다.
- 원정의 물자 지점은 결정적으로 생성하고 원정 내에서 재수집할 수 없게 한다. 다음 원정의 갱신 기준을 저장·재현한다.
- 기존 던전 폐쇄 귀환을 유지한다. 빠른 시제품 검증을 위해 입구나 활성화한 귀환 지점의 안전한 수동 귀환도 지원한다. 전투 중 어디서나 누르는 즉시 탈출로 만들지 않는다.
- 귀환 정산은 원정당 한 번만 실행한다. 수집·입고·시설 지출은 명령 기록과 저장 복원에서 동일해야 한다.

## 모바일 화면

작은 고정 시설 구역, 물자 요약, 주민 요약을 중심으로 구성한다. 화면을 실시간으로 돌아다니는 주민 AI는 아직 필수가 아니다. 거점 미리보기에서는 다음 개선 목표를 확인할 수 있지만, 던전 안에서 건설·치료를 실행할 수는 없다.

360~390px 세로 화면에서 최소 48px 터치 표적을 확보하고 긴 정보는 세로 스크롤한다. 휴대/보관 물자를 분명히 구분하고, 개선 불가 시 부족한 재료나 최대 단계 같은 이유를 보여준다.

## 구조와 담당

- 기획·범위 조정·통합 검증: 메인 에이전트.
- 자원·시설 규칙 및 세션/저장 연결: Sol medium `base_core`.
- 모듈형 거점 화면과 수집/귀환 입력: Sol medium `base_ui`.
- 독립 수집·정산·저장 인수 검사: Luna max `base_acceptance`.

기존 큰 세션/화면 파일에는 진입점과 이벤트 연결만 추가하고, 자원·시설 계산과 화면 구성을 별도 모듈로 분리한다. 동일 인물 ID를 유지한다. 기존 저장은 삭제하거나 조용히 초기화하지 않는다.

첫 구현의 모듈은 다음과 같다.

- `sim/base_progression_rules.gd`: 물자 잔량·시설 비용·단계별 효과 계산.
- `sim/base_resource_cache_rules.gd`: 층별 고정 수집 지점 생성.
- `playtest/base_progression_service.gd`: 수집·귀환·개선·교환 명령과 기존 세션 연결.
- `playtest/base_progress_panel.gd`: 거점 관리와 원정 중 미리보기에 공용으로 쓰는 화면.

수집 지점은 첫 버전에서 기존 물자 표식을 재사용한다. 자유 배치형 거점 지도나 주민이 걸어 다니는 생활 화면은 아직 포함하지 않는다.

## 완료 기준

- 직접 이동하여 물자를 수집하고 귀환해 시설 하나를 개선한 뒤 다시 출발할 수 있다.
- 먼 거리 수집, 같은 지점 중복 수집, 운반 한도 초과, 던전 안에서 개선, 부족한 물자 지출, 최대 단계 초과를 거절한다.
- 귀환과 화면 재진입으로 물자가 중복 입고되지 않는다.
- 개선 효과가 다음 수집·휴식·치료에 실제 반영된다.
- 수집 도중과 개선 이후 저장·복원 결과가 동일하다. 기존 원정/파티 저장도 확인한다.
- 두 인물의 이동·자동전투·귀환 흐름이 유지되고 내보낸 Web 패키지가 실행된다.

## 첫 구현 검증 기록 (2026-09-08)

- 거점 규칙 검사 7개 통과: 유한 수집·운반 한도·중복 정산 방지·교환·단계별 실제 치료/휴식·저장 복원·수집 중 원정 종료 정산.
- 독립 인수 검사 4개 통과: 직접 이동과 수집, 원거리/용량 제한, 귀환 → 창고 2단계 → 교환 → 재출발 → 저장 재현, 이전 시나리오 복원.
- 기존 원정 검사 13개 통과. 두 명 자동전투 후 탐험 복귀 검사도 통과.
- 거점 UI 검사 통과: 360×640 및 390×640, 미리보기 → 귀환 → 거점 → 시설 이용 → 재출발, 최소 터치 높이와 수집 표식의 시야 제한.
- Web 내보내기 및 소스 폴더 밖에서 내보낸 PCK 실행 통과. 실제 휴대전화 브라우저에서의 조작감과 성장 속도는 추가 플레이테스트 대상이다.

로컬 검사는 이번 기능 확인용이며 GitHub Actions에 무거운 시뮬레이션 검사를 추가하지 않았다. 기존 전체 `party_ui_layout_smoke.gd`는 현재 기본 DUO를 SOLO로 기대하는 등 이전 흐름과 맞지 않아 별도로 정비가 필요하다. 위 기록은 해당 전체 UI 검사가 통과했다는 의미가 아니다.

## 후속 단계

1. 주민 네 명과 두 명 출전 편성.
2. 잔류 주민의 원정 시간 단위 휴식·치료 활동.
3. 구조·지원 기억을 이용한 대화·감사·마찰 사건.
4. 재미가 확인된 뒤 시설 확장과 제한적인 제작.

위 후속 항목은 첫 구현의 완료 범위가 아니다. 기초 성장 곡선은 첫 개선까지 걸리는 원정 수, 빈손 귀환 비율, 치료 비용과 수집량을 관찰한 뒤 조정한다.
