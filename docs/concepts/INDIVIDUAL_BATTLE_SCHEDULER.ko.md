# 개별 행동 자동전투 / 기술 예약

2026-09-08. 기존 상단 타임라인의 배치 결과 표시 방식 대신, 실제 개별 행동 시각을 표시·실행한다. `BATTLE_ACTION_TIMELINE_REPORT.ko.md`의 배치 처리 한계는 이전 구현 기록이다.

## 플레이 규칙

- DUO 전투는 기본 자동 진행. 각 인물의 `busy_until`을 다음 행동 시각으로 사용한다.
- 아군과 적이 같은 전투 시계를 사용한다. 중앙 도달 시 해당 인물만 행동하고, 자신의 다음 행동 시각을 갱신한다. 아군 파티 전체를 기다리거나 가장 느린 인물의 시간으로 세계를 건너뛰지 않는다.
- 무기 공격 시간, 이동 지형 비용, 기술별 비용(현재 화염탄/치유 120 등)을 기존 규칙에서 재사용한다. 이번 작업에서 임의의 민첩 계수나 새 밸런스 수치는 추가하지 않는다.
- 기본 속도는 세계시간 100당 0.5초. 렌더링 속도 설정과 게임 내 행동 비용은 분리한다.
- 스킬은 인물당 하나 예약. 새 예약은 기존 예약을 교체하고, 예약된 버튼을 다시 누르면 취소한다. 예약·취소 자체는 세계시간과 기력을 소비하지 않는다.
- 다음 행동 시 사거리·시야·생존·기력 등을 다시 검사한다. 실패하면 예약을 지우고 같은 행동 기회에 기존 AI 기본행동을 실행하며, 기력은 소모하지 않는다.
- 평소 기본행동 AI를 사용하고, 스킬은 플레이어 예약으로만 사용한다. 지정 공격 표적은 기존 드래그 지침을 유지한다.
- 일시정지 및 대상 선택/모달/드래그 중에는 연속 시계와 HUD 모두 멈춘다. 재개 시 남은 시간을 보존한다. 대상 선택을 끝내면 선택 전에 수동 일시정지 상태였는지도 보존한다.

## 실행 구조

| 모듈 | 책임 |
| --- | --- |
| `sim/systems/individual_battle_scheduler.gd` | 다음 사건 선택, 한 인물의 AI/기술 실행, 환경·상태 틱, 트랜잭션·실패 복원 |
| `playtest/individual_battle_session.gd` | 예약/취소, 다음 사건 조회 캐시, 커밋과 저널 리플레이 |
| `playtest/autonomous_battle_clock.gd` | 연속 표현 시계, 일시정지 시 진행량 보존 |
| `playtest/battle_timeline_bar.gd` | 같은 시계에서 계산하는 위치; 결과 도착 후 0.1초 보간하던 방식은 DUO에서 사용하지 않음 |
| `playtest/party_encounter_sandbox.gd` | 자동 진행, 기존 조작 연결, 전투 중 UI 노드를 재생성하지 않는 갱신 |

스케줄러는 인물의 준비 시각과 기존 환경/상태 틱 중 가장 이른 사건으로만 세계시간을 이동한다. 같은 시각의 환경/상태 틱을 먼저 처리하고, 이후 동일 시각 인물은 entity ID 순으로 개별 재평가한다. 같은 시각이라고 두 아군을 함께 계획하거나 합산 공격하지 않는다. 동시 준비 표시는 가능하지만 독립된 행동이다.

정상 진행은 기존 rollback memento와 새 이벤트 꼬리 검사로 보호한다. 저장/불러오기에서는 기존 전체 월드 감사와 저널 재실행을 유지한다. 프레임마다 월드 스냅샷을 생성하거나 전체 저널을 검사하지 않는다.

모든 상태·환경 틱과 배고픔 처리는 유지한다. actor tick에서는 적 AI를 중복 실행하지 않는다. 피해/치유/밀치기 효과는 기존 공용 판정을 재사용하며, 승리 시 재집결·기력 회복·전리품으로 이어진다.

## 저장 호환

새 저널 종류는 `individual_step`, `reserve_skill`, `cancel_reserved_skill`이다. 실행 시각/인물을 검증하고, 예약은 저널 재실행으로 복원한다. 예약용 별도 월드 스키마는 만들지 않는다.

기존 `party_turn`·`active_skill` 저널은 이전 배치 API로 재실행한다. 따라서 기존 저장의 행동 결과를 새 스케줄러로 다시 해석하지 않는다. 새 전투 UI에서만 개별 실행/예약 API를 사용한다.

## 성능·표현 범위

- 전투 중 초상화와 기술 버튼을 유지하고 HP/기력/예약 표시만 갱신한다.
- 같은 프레임에서 최대 16건, 경과 8ms를 넘으면 다음 프레임으로 양보한다. **개별 한 건 자체가 8ms를 넘지 않는다는 보장은 아니다.** 미처리 준비 사건이 있으면 표시 시계를 그 시각에 붙들어 HUD만 먼저 지나가지 않게 한다.
- 백그라운드 복귀의 큰 delta는 제한해 한 번에 전투 전체가 끝나는 현상을 막는다.
- 표시 시계의 프레임 내 소수 진행량은 저장하지 않는다. 불러오면 마지막 확정 세계시간부터 표시를 다시 시작한다. 실제 다음 행동 시각과 예약은 보존한다.
- 좁은 HUD에서 인접한 초상화의 압축 표시는 유지한다. 같은 준비 시각과 실제 배치 실행은 구분한다.

## 검증

Godot 4.6.2 headless에서 확인했다.

- `tests/individual_battle_acceptance.gd`: 통과. 실제 생성 맵에서 인물 행동 48회(서로 다른 5명), 환경/상태 시점 11회, 패배 종료까지 전체 월드 감사 및 저장 재실행 확인. 예약/취소/재예약, 실행 시 1회 기력 소모, 쿨다운 중 선택, 예약 복원, 수동 정지, UI 노드 유지, 표시 시계 일치를 포함한다.
- 위 표본의 커밋 처리 중앙값 9,252µs, 최댓값 65,987µs. 이 수치는 전체 렌더링 프레임 시간이 아니며, **모바일 60fps를 보장하지 않는다.** 개별 사건의 비용이 큰 구간은 실제 기기에서 추가 프로파일링할 여지가 있다.
- `tests/battleheart_mvp_acceptance.gd`: 7개 케이스 통과. 기존 즉시 시전 API의 피해·치유·밀치기·기력·구 저장 호환은 그대로 검사한다. UI의 이중 확정 검사는 즉시 실행 대신 단일 무료 예약을 기대하도록 변경했다.
- `tests/battle_timeline_integration.gd`: 모바일 터치/모달/강조 통합 검사 통과. 해당 파일의 구 배치 표본 성능 기록은 호환성 검사이며 개별 스케줄러 측정치로 쓰지 않는다.
- `tests/run_battle_timeline_presenter_tests.gd`: 10개 통과.
- `tests/individual_battle_loot_acceptance.gd`: 통과. 실제 구 저장의 전투를 개별 스케줄러로 이어서 승리→자동 재집결→360×640 전리품 선택→저장 재실행까지 확인했다.

별도의 난이도 수치 변경은 하지 않았다. 개별 실행으로 판정 순서가 달라져 기존 배치 전투와 승패가 달라질 수 있다. 헤드리스 모바일 논리 해상도 및 입력 검사와 실제 휴대폰 프레임 성능은 구분한다.
