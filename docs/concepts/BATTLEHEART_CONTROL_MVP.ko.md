# 개별 지휘 + 수동 액티브 전투 MVP

2026-09-08. 기준 커밋 `3ae72d8`. 거점에서 출발하는 인간 2인 파티에 적용한다. 배틀하트에서 참고할 부분은 자동 기본 전투에 플레이어가 개입하는 조작 구조이며, 전체 게임이나 외형을 복제하지 않는다.

후속 HUD 작업: [상단 양방향 행동 타임라인 구현 인계 계획](BATTLE_ACTION_TIMELINE_HANDOFF.ko.md). 설계 문서이며 타임라인 기능은 아직 구현하지 않았다.

## 이번 플레이 목표

평소 이동·평타·자동 판단은 기존 흐름을 유지한다. 전투 중 한 인물을 선택해 지속 지침을 바꾸거나, 필요한 순간에 그 인물의 액티브 기술을 한 번 사용한다. 액티브는 AI가 자동 사용하지 않는다. 성격과 감정은 평상시 자동 판단에 계속 영향을 준다.

### 시작 구성

| 인물 | 기술 세트 ID | 수동 액티브 |
| --- | --- | --- |
| 주인공 | VANGUARD_V1 | 강타, 밀치기 |
| 첫 동료 | SUPPORT_V1 | 화염탄, 응급 치유 |

세트 ID와 현재 기력은 인물의 저장 상태다. 세트별 기술 정의는 버전이 있는 공용 데이터에서 읽는다. 인물 ID·이름·종족으로 기술을 고정하지 않는다. 영입 후보도 선택된 세트를 가지며, 거점에서 세트를 교체하는 기능은 이번 범위가 아니다.

모두 인간이며 기존 개인 재능을 유지한다. 재능은 강점을 주고, 특정 재능을 갖지 않았다는 이유로 마법·치유 사용을 막지 않는다.

## 조작 규칙

1. 각 초상화 바로 위에 그 인물의 두 기술을 고정 표시한다. 초상화에는 체력과 현재 기력을 표시한다. 인물 선택 드롭다운을 거치지 않고 바로 시전자를 정한다.
2. 기술을 누르면 자동전투를 잠시 정지하고 대상 선택 모드로 들어간다. 시전자와 기술 이름, 대상 조건, 취소 버튼을 표시한다.
3. 적 기술은 적, 치유는 아군을 지정한다. 자기 치유도 허용한다. 벽·사거리·행동 불능·기력 부족은 거절 이유를 보여준다.
4. 유효한 대상에 한 번 확정하면 정상 행동 시간과 기력을 정확히 한 번 소비한다. 취소·미리보기·거절은 월드와 자원을 바꾸지 않는다.
5. 완료나 취소 후에는 진입 전 일시정지 상태로 복귀한다. 원래 수동 정지 중이었다면 계속 정지한다.

맵의 아군 또는 초상화에서 적으로 드래그하면 해당 인물의 공격 대상을 지정한다. 드래그 중 선과 표적 링을 표시하고 자동전투를 보류한다. 빈 곳에 놓거나 두 번째 손가락이 닿으면 취소한다. 우측 작은 버튼은 정지/재개, 자율(선택 인물의 표적 해제)이며 기술 대상 선택 중에는 취소로 바뀐다. 초상화 짧은 탭은 인물 정보, 맵의 아군 짧은 탭은 선택이다.

기존 `후퇴`, `공격 중지`, `자리 지키기` 및 전체 파티 명령 API는 호환용으로 유지하지만 기본 화면의 메뉴에서는 뺀다. 개별 지침과 일회성 기술 명령을 저장에서도 구분한다.

바쁜 인물의 수동 기술은 이번 버전에서 예약하지 않는다. 버튼이나 실행 판정에서 준비 중임을 알리고, 실패 시 기력과 시간이 그대로여야 한다. 전투 종료·시전자 사망·화면 전환 시 대상 선택 상태가 남지 않도록 정리한다. 인물 정보창의 기존 접근과 긴 터치 동작을 보존한다.

## 전투 규칙

### 전투 후 선택 회수

승리 후 자동 재집결이 끝나면 전리품 창을 자동으로 연다. 왼쪽에는 내 가방(20칸), 오른쪽에는 방금 끝난 전장의 바닥 아이템을 표시한다. 오른쪽 아이템을 누르면 그 하나만 가방으로 옮긴다. 회수는 추가 행동 시간 없이 처리하며 가방이 가득 차면 거절한다. 선택하지 않은 물건은 바닥에 남는다. 닫은 창은 탐험 화면의 `전리품` 상호작용으로 다시 연다. 이동 중 자동줍기와 전투 중 전체 수거는 없다.

전리품은 별도 복제 보상 목록이 아니라 해당 전투 사망 지점의 실제 ground item을 읽는다. 다음 전투·이탈·층/거점 전환 후에는 지난 전장의 원격 회수가 끝난다. 저장에는 `battle_loot` 개별 선택을 기록해 옛 이동/아이템 저널 의미를 바꾸지 않는다. 이번 MVP에서 가방 쪽 탭은 아이템 이름 확인이며, 같은 창에서 버리기/장비 비교·교체는 추가하지 않는다.

### 시간과 자원

- 자동전투 표시 간격은 0.7초에서 0.32초로 단축한다. 프레임당 최대 한 단계만 처리하며 기존 공격 속도, 행동 시간, 피해·기력 규칙은 바꾸지 않는다. 입력 중·모달·기술 대상 선택·정지 상태에서는 진행하지 않는다.
- 최대 기력 12. 초기 비용은 강타 3, 밀치기 3, 화염탄 3, 응급 치유 4.
- 초기 행동 시간은 강타/밀치기 100, 화염탄/치유 120을 목표로 한다. 기존 스케줄러와 동일한 시간 단위이며 무료 추가 행동을 주지 않는다.
- 한 전투 단계에서 수동 기술을 먼저 적용한 뒤, 나머지 행동 가능한 파티원의 기본 행동을 바뀐 위치·HP에서 다시 판단해 각각 한 번 실행한다. 시전자의 평타는 중복 실행하지 않는다. 적·환경 시간은 이 행동들 중 가장 긴 시간만큼 한 번만 진행한다. 밀치기나 처치 전의 오래된 표적 정보를 재사용하지 않는다.
- 기력은 확인된 승리/재집결과 거점 귀환 경계에서 회복한다. 단순 이탈이나 잠시 적이 보이지 않는 상황, UI 새로고침, 저장/불러오기로 회복하지 않는다.
- 응급 치유는 실제로 적용된 물리·화염·전격 HP 피해의 50%를 회복 가능량으로 적립하고, 이후 물약 등으로 회복한 양은 차감한다. 현재 잃은 HP를 넘지 않으며 굶주림은 적립 대상이 아니다. 절단 복구·부활·거점 치료를 대체하지 않는다. 회복 가능량 기본값 0인 실험실 DTO를 그대로 붙여 치유가 항상 실패하는 상태로 두지 않는다.
- 밀치기는 벽·다른 점유자·맵 밖·막힌 대각 모서리를 통과하지 않는다. 위치 변경은 점유 인덱스와 전투 이력에 함께 반영한다.
- 피해·내성·방어·신체 손상은 기존 공용 전투 경로를 사용한다. 실험실의 별도 HP/몸 상태를 본 게임의 두 번째 권위로 가져오지 않는다.
- 기술 판정은 상태를 읽기만 한다. 실제 실행에서 조건을 다시 확인하고 명령·기력·피해·행동 시간·저장을 한 트랜잭션으로 처리한다.
- 시전자 이름 → 기술 → 대상 → 결과를 짧게 표시해 자동전투 중에도 개입 결과를 읽을 수 있게 한다.

## 모듈과 작업 분담

- 전투/저장 담당(Sol medium): 명령 및 인물 상태 버전, 기술 세트, 액티브 실행 서비스, 개별 지침 조회, 기존 공용 전투 연결.
- 모바일 UI 담당(Sol medium): 별도 작은 전투 조작 패널, 시전자/기술/대상 선택 상태, 일시정지 복귀, 기존 화면 연결. 세션이나 기력을 직접 변경하지 않는다.
- 독립 검증 담당(Luna max): 실제 API/포인터 검증과 구 저장 테스트. 구현 파일을 수정하지 않는다.
- 주 에이전트: 범위/계약 결정, 코드 리뷰, 교차 통합, 결과 검증 및 문서 정리.

UI와 코어 경계는 `active_skill_rows`, `active_skill_assessment`, `use_active_skill`, `actor_command_assessment`, `issue_actor_command`, `actor_command_status` 세션 메서드다. 상세 구현은 별도 모듈에 두고 세션/샌드박스 파일에는 연결만 추가한다.

저장 호환 비용을 줄이기 위해 일반 명령 `HOLD/MOVE/MELEE`는 기존 4개 키를 그대로 유지하고, `SKILL` 명령만 필수 `skill_id`를 포함한 5개 키를 쓰는 엄격한 구분 형식을 우선한다. 임의로 두 형식을 모두 허용하는 것이 아니라 명령 종류별 정확한 키 집합을 검증한다. 인물의 기력/세트 필드는 별도의 상태 스키마 버전으로 이전한다.

## 완료 검사

- 주인공과 동료 각각 유효한 기술을 쓰며 실제 피해/치유/위치/기력/행동 시간이 일치한다.
- 잘못된 진영·벽·범위·기력·바쁜 상태는 거절되고 미리보기/취소/중복 터치는 추가 비용이 없다.
- 한 인물의 지침이 다른 인물에게 전파되지 않는다. 자동 평타·이동은 계속 동작한다.
- 이탈/재접촉으로 기력이 충전되지 않는다. 정상 회복 경계는 중복 적용되지 않는다.
- 구버전 저장 복원과 기술 사용 후 저장/재현이 통과한다. 신규 형식의 필수 필드 누락은 구형 호환으로 오인하지 않는다.
- 360/390px 세로 화면에서 인물→기술→대상, 취소, 원래 일시정지 복귀를 확인한다. 48px 이상 조작부를 쓰고 지도를 가리는 상시 대형 패널은 추가하지 않는다.
- Godot 파싱 및 Web 내보내기/독립 패키지 시작을 확인한다. 무거운 테스트를 GitHub Actions에 추가하지 않는다.

보호막, AI 액티브 선택, 자유 기술 편성, 드래그 이동 명령, 광역/지점 지정 기술, 전투 밸런스 전체 재조정은 이번 범위가 아니다. 기본 네 기술이 실제로 재미있는지 플레이한 뒤 확대한다.

## 구현 및 검증 기록

- 기술 세트, 순수 판정, 저장 검증, 모바일 조작 패널은 각각 별도 파일로 분리했다. 세션 API가 권위 있는 시뮬레이터 실행을 연결한다.
- 정상 이동·평타의 기존 4키 명령은 유지하며 액티브는 별도 저널 명령으로 재현한다. 인물 상태는 스키마 23이다.
- 실제 이전 빌드 `3ae72d8`에서 만든 스키마 22 거점/전투 저장 모두 새 코드로 불러오기에 성공했다. 작은 전투 저장은 `tests/fixtures/battleheart_schema22_combat.json`에 보존했다.
- 기존 인간·재능 검사 0 실패, 자동전투 검사 0 실패, 거점 건설 규칙 3/3 통과.
- `tests/battleheart_mvp_acceptance.gd` 최종 7개 케이스 통과: 실제 기술/치유/저장, 거절·미리보기 순수성, 개별 지침, 이탈 시 기력 보존, 밀치기와 단일 파티 단계, 모바일 조작, 구 저장 이전.
- 360/390px의 논리·물리 좌표를 일치시킨 헤드리스 화면에서 실제 Input 경로의 터치로 기술 선택/취소를 확인했다. 원래 일시정지 상태 복귀와 중복 확정 방지도 검사했다.
- 밀치기로 발생한 강제 이동은 일반 보행과 구분해 원인 기술·도착 칸·이벤트 시간을 검증한다. 밀치기 후 동료 기본 행동 1회, 단일 시간 진행, 저장 복원 검사를 통과했다.
- Web 내보내기, 소스 디렉터리 밖에서 배포 PCK 단독 시작, 같은 PCK로 액티브 실행 후 저장/불러오기 통과.
- 테스트는 로컬 실행용이다. GitHub Actions에 새 시뮬레이션 작업을 추가하지 않았다. 실제 휴대폰의 시각적 가독성 평가는 별도 플레이테스트가 필요하다.

### 초상화 스킬 / 드래그 / 전리품 개편 검증

- 기존 7개 액티브·저장 호환 검사를 새 초상화 UI에 맞춰 재실행해 통과했다.
