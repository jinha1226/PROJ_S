# 모바일 전투·줍기·횃불 수정

기준 commit: `fe0211e`. 외부 코드/라이브러리를 추가하지 않고 기존 전투·아이템·시간 authority를 유지한다.

## 원인과 변경

- **몬스터 줄서기:** 이동 자체는 이미 8방향이다. `forecast_enemy_action`이 목표 쪽 한 칸만 검사하고 막히면 HOLD를 반환하던 것이 병목이다. 직접 접근이 막히면 목표 주변의 빈 공격 칸을 여러 목적지로 놓고 기존 경로 탐색기를 호출한다. 우회는 최대 12걸음으로 제한하며, 인접 공격·점유·지형 모서리·동시 이동 예약 규칙은 유지한다. 완전히 막힌 통로에서는 여전히 기다린다. 별도의 전지적 팀 전략이나 장거리 추적 엔진을 만든 것은 아니다.
- **아이템 타일 도착 지연 / 줍기 비활성:** 도착 콜백이 최대 6회의 아이템 액션(각 100시간 및 NPC/환경 처리)을 한 번에 수행했다. 도착은 이동만 하고 아이템을 남긴다. [줍기] 한 번은 바닥 아이템 한 항목(묶음이면 그 묶음), 100시간만 사용한다. 버튼 활성 여부는 상세 아이템 DTO 생성 대신 개수만 읽는다. 버튼 설명과 기존 회귀 검사의 UX 계약도 이에 맞췄다.
- **횃불 조회 비용:** 상태를 읽을 때마다 점화 이벤트까지 전체 사건을 역순 검색하던 부분을 world별 파생 인덱스로 바꿨다. 새 사건만 읽고, 사건 절단/교체 시 재구성한다. 장착 횃불은 이미 찾은 아이템 참조를 사용해 소유자 전체 재검색도 피한다. 연료는 여전히 현재 world time으로 계산하며 인덱스를 저장 데이터에 넣지 않는다.
- **횃불 표시 정확성:** 종이인형 장비 모양 캐시와 연료/점화 상태를 분리했다. 아이템 revision이 같아도 연료 소진·점화·소화는 현재 상태를 표시한다.
- **상태창 / 초상화:** 기존 전투 요약을 공격력·방어력·회피율·블록율로 명시하고, 현재 사용하는 커스텀 초상화에도 같은 DTO로 두 줄을 표시한다. 주인공뿐 아니라 동료도 자신의 수치를 받는다. 기존 HUD → 게임 → 로그 → 초상화 → 버튼 순서는 그대로이고, 초상화 높이만 72→84px로 늘렸다. 회피 수치는 상대 명중률을 감소시키는 값이며 무조건적인 최종 회피 확률이 아니다. 블록은 기존 `parry_milli`(명중한 공격에 대한 막기 확률)를 표시하며 새로운 확률 공식을 만들지 않는다.

## 검증 기록

- 새 `mobile_combat_loot_torch_acceptance.gd`: 고립된 열린 방에서 3마리가 서로 다른 인접 칸에 도달, 대각선 이동, 점유/모서리 규칙, 한 칸 통로의 대기, 결정성 검증. 실제 아이템 authority/기존 UI로 도착 시 숨은 턴 없음, 버튼 줍기, 상태창/초상화 값 일치 검증. 기존 횃불 점화·연료·소화·저장 재현 검사도 호출한다.
- 기존 `legacy_shell_engine_acceptance.gd`: PASS. 실제 UI와 새 전투 엔진, 배치 순서, 저장 재현 검사.
- 적 전술 matrix: 8개 seed, 80턴, 253개 적 행동 중 HOLD 5회. setup/거절/잘못된 world/복원 실패/claim 불일치 모두 0. 8개 전투 모두 종료. 전체 적 전술 묶음에는 기존 인지 검사 2개 실패가 있어 기준 commit과 분리 확인한다.
- 횃불 조회 microbenchmark: 사건 10,001개에서 100회 조회, 역순 검색 약 427–652ms, 준비된 인덱스 약 0.10–0.14ms. 합성 이벤트 조회만 비교한 것이며 게임 전체 배속 수치가 아니다.
- `torch_travel_performance_probe.gd`: 실제 390×844 UI/headless, 각각 6번의 성공한 왕복 이동. 꺼짐/켜짐 입력 콜백 평균 약 23.8/26.6ms, `grid.draw_world` 약 11.14/11.25ms 표본. 두 world 검증 모두 통과하고 켜짐 측정 종료까지 실제 횃불이 유지됨을 확인했다. 서로 다른 점화/소화 턴 이력과 실행 잡음이 있으며 모바일 브라우저의 GPU/프레임 성능을 대신하지 않는다.
- X11 소프트웨어 렌더링으로 390×844 화면 캡처를 확인했다. 전투 수치 두 줄과 이름이 초상화 안에 들어가고 기존 화면 순서를 유지한다.
- 상태창 캡처에서는 기존 `StatusCombatSummary` 노드가 있어도 clipped/autowrap 라벨의 표시 높이가 사라지는 문제를 추가 확인했다. 전투 칸은 네 개의 짧은 명시적 줄로 바꾸고 실제 창을 연 뒤 가시성·최소 표시 높이를 검사한다.

- 최종 새 acceptance: 두 바닥 아이템 중 버튼 한 번에 하나만 감소/100시간 사용, 두 번째 누름으로 나머지 획득 및 비활성 확인까지 PASS.
- `run_party_enemy_tactics_tests.gd`: 12개 중 10개 통과, 인지 검사 2개 실패. 별도 `fe0211e` worktree에서 아래 두 메서드를 재실행해 **동일한 assertion 실패**를 확인했다. 이번 수정의 신규 실패는 아니며 인지 모델/과거 fixture 정합성은 이번 범위에서 바꾸지 않았다.
  - `test_los_contest_is_monotonic_and_six_states_are_reachable`: 반복 시야의 ALERT 도달, SUSPICIOUS/ALERT 전환 사건 기대 실패.
  - `test_distant_monsters_do_not_join_combat_and_visible_dto_never_leaks_to_memory`: 먼 적 forecast의 사유, 특정 근처 적의 관측 DTO 존재 기대 실패.
- Web release export 종료 코드 0. 별도 `/tmp` 경로에서 내보낸 `index.pck`를 `--main-pack ... --quit-after 5`로 기동, 스크립트 오류 없이 종료 코드 0.
- 기존 `rest_and_pickup_regression.gd`: 현 변경에서는 `fixture wins one fight` 1개 실패. 수정 전 `fe0211e`에서는 같은 전투 fixture 실패와 휴식 관련 3개 실패(총 4개)를 확인했다. 과거 ENGAGED 전환을 기대하는 장기 매크로 검사는 완전 통과로 보고하지 않는다. 새 실제 버튼/단일 턴 검사를 별도로 사용하며 기존 검사도 삭제하지 않는다.

모바일의 끊김이 완전히 해결되었다고 판정하지 않는다. 모바일에서는 새 원정에서 적 세 마리 접근, 아이템 타일 도착 후 [줍기], 횃불 켜기/끄기 후 같은 길 왕복, 초상화·상태창 수치를 확인한다.
