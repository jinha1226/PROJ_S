# 시야·기억·광원 최적화 protocol

- 작업 ID: `VISION-LIGHT-OPT-001`
- 기준 commit: `22245e0`
- 사용자 관측: 광원과 방향 시야 적용 뒤 이동·줌에서 끊김이 생겼고, 줌아웃 시 캐릭터 시야 밖의 광원이 실시간으로 보이는 것은 플레이 규칙과 모순된다.

## 표시 규칙

- `VISIBLE`: 현재 지형, 액터, 아이템, 횃불·모닥불의 실시간 광원과 제한된 불꽃 애니메이션을 표시한다.
- `MEMORY`: 발견했던 지형과 정적 횃불·모닥불 표식만 저채도·낮은 밝기로 표시한다. 광원 pool, 주변 밝힘, 실시간 깜빡임은 표시하지 않는다.
- `UNSEEN`: 지형과 모든 표식을 표시하지 않는다.
- 줌아웃은 화면에 포함되는 기억 지형만 늘리며 현재 캐릭터가 얻는 실시간 정보 범위를 늘리지 않는다.

## 시야 규칙

- 기본 후방·주변 시야를 1셀에서 2셀로 늘린다.
- 이동은 이동 방향, 근접 공격과 대상 기술은 대상 방향으로 권위 `party.facing`을 갱신한다.
- 방향 갱신과 같은 턴의 관측부터 새 FOV를 사용한다.

## 성능 변경

- 매 redraw마다 `화면 셀 × 광원 × Bresenham LOS`를 반복하지 않는다.
- 관측 projection cache를 재구축할 때만 각 `VISIBLE` 광원의 셀별 도달 여부를 계산해 저장한다.
- 조명 pool과 방사형 암흑 mesh는 셀별 광원 후보 cache를 읽고 거리 감쇠만 계산한다.
- 광원 pool 밝기는 고정하고 불꽃 glyph만 느리게 깜빡여 전체 조명 mesh의 애니메이션 재계산을 막는다.

## 검증

- MEMORY 지형·횃불·모닥불은 희미하고 정적이며 주변을 밝히지 않아야 한다.
- VISIBLE 광원은 부드러운 거리 감쇠와 벽 차단을 유지하고 UNSEEN을 노출하지 않아야 한다.
- 후방 2셀과 이동·공격 시 방향 FOV 갱신을 확인한다.
- 반복 조명 조회 중 LOS 계산 횟수가 증가하지 않고 기존 필드 턴·시작 회귀를 통과해야 한다.
