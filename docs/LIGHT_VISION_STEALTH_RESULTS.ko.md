# 조명·종족별 시야 단계 0~1 구현 결과

실험 ID: `LIGHT-VISION-001`
기준 commit: `41d0c87`

## 구현 내용

- `sim/vision_profile_registry.gd`에 공통 프로필, 종족 프로필, 몬스터 유형 덮어쓰기를 추가했다. 미등록 종족·유형은 기본 프로필로 되돌아가고 개발 경고를 남긴다.
- `sim/vision_rules.gd`에 거리·조도·방향·식별 강도·LOS를 반환하는 순수 관찰 질의를 추가했다. 밝은 환경은 전방위, 어두운 환경은 전방 각도와 주변 범위를 사용한다.
- 벽, 닫힌 문, 밀도 높은 연기는 공통 cardinal LOS 검사로 가린다. 출발·도착 칸 자체는 검사에서 제외한다.
- 파티 시야, 적 분대 인지, 필드 턴 시야, 표시용 FOV가 같은 `VisionRules` 질의를 사용하도록 연결했다. 파티 감지 반경과 태그 보너스는 기존 권위 상태로 유지하고, 조명·방향·종족 프로필만 공통 질의에서 계산한다.
- `VISION_TEST_LIGHTING_V1` 고정 조명 시나리오를 추가했다. 실제 횃불 아이템·연료·준비 UI·어둠 스트레스는 구현하지 않았다.
- `PartyPlaytestSession.vision_debug_observation()`을 개발용 진단 출력으로 추가했다. 이 출력은 동일한 관찰 질의를 호출하며 RNG·시간·이벤트·저장 상태를 변경하지 않고, 액터나 숨은 객체의 상세 데이터를 포함하지 않는다.
- 기존 저장 wire에는 새 필드를 추가하지 않았다. 방향은 기존 `PartyEncounterState.facing`을 사용하고, 적 방향은 최신 이동 이벤트에서 재현한다.

## 검증 결과

`godot --headless --path . --script res://tests/run_environment_regression_tests.gd` 실행 결과:

- 총 68개 테스트, 실패 0개
- 프로필 상속·fallback, 밝은 전방위/어두운 전방·주변, 밝은 대상, 벽·닫힌 문·연기, 표시 FOV 일치, 세이브 후 개발 진단 출력 재현을 포함한다.

추가로 다음 관련 회귀 묶음도 통과했다.

- `run_party_ai_tests.gd`: 파티 공통 인지 및 분대 blackboard 8개
- `run_phase4_tests.gd`: 파티 encounter·필드 턴·세이브 회귀 24개

참고로 별도 `run_party_enemy_awareness_tests.gd`에는 기준 코드부터 유지된 생성 맵 거리 가정 불일치가 남아 있다. 현재 생성된 첫 적은 주인공과 14칸 떨어져 있어 테스트 주석의 “5칸 직선” 조건을 만족하지 않으며, 이 단계에서는 맵 생성·인지 상태 머신을 범위 밖에서 변경하지 않았다.

기존 저장 wire와 동적 횃불 상태는 이번 단계의 범위 밖이다. 다음 단계에서 횃불 광원 변경을 도입할 때에는 `lighting`을 저장·이벤트 계약에 편입하고, 이 단계의 고정 조명 테스트를 동적 광원 replay 테스트로 확장해야 한다.
