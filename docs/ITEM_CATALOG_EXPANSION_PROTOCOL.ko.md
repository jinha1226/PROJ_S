- 기준 commit: `2b5fa8d`
- 범위: 무기·방어구·포션·식량·마석·제작 재료의 실제 정의, 공용 메타데이터, 기존 사용·장착·거래 경로 연결

## 구현 범위

이번 배치는 현재 구현된 1·2층과 다음 3·4층 준비에 필요한 T1/T2 아이템을 대상으로 한다. 기존 저장 ID와 인스턴스 소유권을 유지하며 `POTION_UNSPECIFIED`, placeholder 정의는 마이그레이션용으로 보존한다.

| 분류 | 이번 목표 |
|---|---|
| 무기 | 현행 7개 전투 형태를 유지하고 T2 재질 변형을 추가한다. 새 변형은 기존 무기 피해·시간·사거리·신체 피해 계약을 사용한다. |
| 방어구 | 천·가죽·사슬·판금 갑옷과 목재·철 방패를 장착 가능하게 등록한다. 환경 피해 보호도 같은 정의 ID로 연결한다. |
| 포션 | 소형·표준·상급 회복 물약의 회복량을 아이템별로 분리한다. 소비·회복·저널 재생은 기존 원자적 사용 경로를 유지한다. |
| 식량 | 건빵·배급 식량·말린 고기의 영양량을 아이템별로 분리하고, 기아 시스템이 결정적으로 한 개를 선택해 소비한다. |
| 마석 | 마석 조각·마석·정제 마석을 환금품으로 등록하고 등급별 매입가를 한 권위에서 읽는다. |
| 재료 | 철·강철·목재 계열과 가죽·천·갑각·점액·약초를 등록한다. 실제 제작식이나 드롭이 없는 재료는 활성 출현표에 넣지 않는다. |

## 데이터 계약

`items.json`은 장착·소비·저장에 필요한 아이템 정의의 단일 권위를 유지한다. 별도 `item_catalog.json`은 정의 ID를 참조해 다음 콘텐츠 메타데이터만 소유한다.

- `family`: `WEAPON`, `ARMOR`, `POTION`, `FOOD`, `MAGIC_STONE`, `MATERIAL`
- `tier`: 0~3. 레거시·도구는 0, 저층은 1, 중층은 2다.
- `min_depth`: 새로 생성 가능한 최소 깊이
- `buy_price`, `sell_price`: 0이면 해당 거래 방향 비활성
- `effect_kind`, `effect_power`: `NONE`, `HEAL`, `NUTRITION`만 이번 배치에서 허용

아이템 정의와 카탈로그 행은 ID로 교차 검증한다. 회복량·영양량·매입가를 UI나 세션 상수에 다시 복제하지 않는다.

## 원자성·저장 규칙

- 장비 변형은 새 정의 ID를 가지며 인스턴스 ID·희귀도·접사·소유자·장착 슬롯은 재제작에서 보존한다.
- 포션과 식량은 효과 적용이 실패하면 수량·시간·이벤트를 전부 복원한다.
- 같은 스택은 기존 stack key와 한도를 사용한다.
- 마석 판매는 실제 보유 스택 전체를 한 번만 제거하고 골드 이벤트를 한 번 기록한다.
- 카탈로그 조회, 상점 목록, 미리보기는 세계 상태와 시간을 바꾸지 않는다.
- 새 아이템을 과거 사망·상자 이벤트에 소급 생성하지 않는다.

## 검증

1. 모든 JSON과 아이템·무기·카탈로그 교차 참조 검증
2. 여섯 분류의 활성 정의와 ID·티어·깊이·거래·효과 계약 검사
3. 무기·방어구 장착 및 저장 복원
4. 서로 다른 회복량과 영양량, 가득 찬 체력·식량 게이지의 비소비 검사
5. 세 등급 마석 판매와 저널 재생
6. 재료 부족 재제작 거절의 소유권·revision·이벤트 원자성

T3 무기·방어구 수치, 독·해독·기력 포션, 요리 버프, 재료별 전체 제작 트리와 드롭 확률은 실제 3층 이상 및 상태 효과가 연결될 때 확장한다.
