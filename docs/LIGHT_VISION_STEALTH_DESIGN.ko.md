# 조명·종족별 시야 단계 0~1 설계

실험 ID: `LIGHT-VISION-001`

기준 commit: `41d0c87`

## 범위

이번 단계는 공통 시야 계약과 고정 조명 테스트 장면까지만 구현한다. 횃불 아이템·연료·원정 준비 UI·어둠 스트레스·시야 토글 UI는 후속 단계로 남긴다.

## 데이터 계약

`sim/vision_profile_registry.gd`가 공통 기본값, 종족 기본값, 몬스터 유형 덮어쓰기 순서로 다음 정수 필드를 해석한다.

- `base_sight_range`: 밝은 환경의 최대 거리
- `dark_vision_milli`: 어둠에서 유지되는 시야 비율
- `dark_front_angle`: 어둠에서의 전방 유효 각도
- `peripheral_range`: 전방 밖에서 가까이 감지할 수 있는 거리
- `detection_sensitivity_milli`: 식별 강도에 쓰는 민감도
- `darkness_stress_resistance_milli`: 후속 스트레스 단계가 사용할 저항값

미등록 종족·유형은 공통 기본값을 사용하고 개발 경고를 남긴다. 범위와 각도는 registry 검증으로 제한한다.

## 판정 계약

`sim/vision_rules.gd`가 관찰자·대상 위치, 방향, 프로필, 조명 설정을 받아 거리, LOS, 관찰자/대상 조도, 방향 제한, 식별 강도를 함께 반환한다. 밝음(`>=700`)은 전방위로 처리하고, 어둠에서는 프로필의 전방 각도와 주변 범위를 적용한다. 밝은 대상은 방향 불이익을 완화하지만 최대 거리 제한은 유지한다.

벽·닫힌 문·연기는 기존 지형/연기 규칙과 같은 cardinal ray 검사로 처리한다. 출발·도착 타일은 가림 검사에서 제외한다.

파티 FOV, 적 인지, 표시용 FOV는 같은 `VisionRules` 질의를 사용한다. 파티 방향은 `PartyEncounterState.facing`을 사용하고, 적 방향은 최신 `action.move`의 이동 방향을 이벤트에서 역방향으로 찾아 복원한다. 새 저장 필드는 추가하지 않는다.

고정 조명 설정은 시나리오별 순수 입력으로만 제공한다. `VISION_TEST_LIGHTING_V1`은 어두운 기본 조도와 하나의 고정 광원을 가진 검증 장면이다. 실제 동적 횃불은 이 단계에서 만들지 않는다.

## 검증 계획

- 프로필 상속과 미등록 fallback
- 밝은 곳 전방위와 어두운 곳 전방/주변 차이
- 밝은 대상의 방향 완화 및 최대 거리 유지
- 종족·몬스터 유형 차이
- 벽·닫힌 문·연기 가림
- 파티/적/표시 FOV가 같은 결과를 내는지
- 방향과 동일 seed 질의의 결정론
- 기존 body, movement, awareness, field-turn 회귀

판정은 pure 함수이며 캐시나 화면 갱신이 RNG·시간·이벤트를 변경하지 않는다.
