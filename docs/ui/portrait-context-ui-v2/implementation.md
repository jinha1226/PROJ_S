# 전투·탐험 하단 UI 및 개별 SRPG 턴 구현

2026-09-15 개별 턴 전환을 반영했다. 상세 검증은 `docs/plans/srpg-individual-turn-results.ko.md`를 참조한다.

## UI

- 기존 아이소메트릭 보드, 타일과 카메라·줌 코드는 변경하지 않았다.
- 상단은 층/방 또는 배치 안내·증원까지 남은 턴, 식량, 메뉴로 축소했다. 전투 중 행동 순서 막대를 표시한다. 배치 단계와 탐험에서는 숨긴다. 소형 미니맵은 숨겼으며 전체 지도는 메뉴에 남겼다.
- 로그는 기존 3줄 영역을 유지한다. 기존 서술 로그가 비어 있으면 실제 이동·피해·증원 이벤트를 최근 3줄로 표시한다.
- 전투/배치 중에는 선택 파티원 초상화와 HP·MP, 액티브 슬롯 2개, 배치 완료/행동 실행/턴 종료 버튼을 표시한다.
- 전투가 없으면 최대 3명의 초상화와 HP·MP를 나란히 표시한다. 방 역할이 아니라 실제 라운드 활성 상태를 기준으로 바뀐다.
- 초상화를 누르면 기존 상태·숙련·변이·아이템 창을 연다. 전투 중 다른 파티원은 보드에서 선택한다.
- 스킬이 없는 칸은 빈 슬롯으로 표시한다. 여러 액티브를 보유하면 스킬 버튼을 길게 눌러 다음 두 개로 넘긴다. 표시된 스킬을 누르면 기존 대상/범위 선택 흐름을 사용한다.
- 현재 차례의 캐릭터만 이동·공격·스킬을 지정한다. 기본 공격은 적을 눌러 지정한다. 직접 지정한 이동 뒤 공격/스킬은 그 이동을 보존하지만, AI가 제안한 이동은 새 공격 지시로 교체한다.
- 휴식·줍기·계단/상호작용·자동탐험·대기는 상단 메뉴로 접근한다. 전투 중 휴식 메뉴는 비활성화한다.

## 턴 구조

1. 최초 진입 위치 주변 2칸 안에서 무시간 배치를 확정한다. 배치 중 적은 이동하거나 공격하지 않는다.
2. 아군과 적을 기존 initiative 내림차순, 동률은 ID 오름차순으로 섞어 정렬한다. 현재 아군만 행동을 지정할 수 있다.
3. 이동 범위는 이동속도와 부상·이동 지연에 따라 1~3칸이다. 기본은 2칸이다. 이동 비용은 한 캐릭터의 차례 안에서 공유하며, 이동만 실행하면 같은 차례에서 공격을 이어갈 수 있다. 가능한 이동 칸을 파란색으로 표시한다.
4. 기본 공격은 공격속도와 무기의 공격+재장전 시간에 따라 1~3회다. 한 번씩 대상과 행동을 지정해 실행하며 남은 공격 횟수가 있으면 같은 차례를 유지한다. 마지막 공격을 소모하면 다음 순서로 넘어간다. 스킬·아이템·빈 대기는 차례를 마친다.
5. 적은 자기 차례에 최신 위치에서 이동·공격을 결정한다. 미래의 고정 칸 공격 예고와 적 선이동은 제거했다. 적의 사거리·장애물 시선 차단·범위 공격 특성은 유지한다. 진행은 다음 조작 가능한 아군 앞에서 멈춘다. 라운드 첫 캐릭터가 적이면 '적 턴 진행'으로 적 차례를 처리한다.
6. 전체 순서가 끝나면 기존 100시간 경계·회복·상태 처리를 한 번 적용한다. 사망/행동 불능 캐릭터는 건너뛴다. 이동·추가 공격마다 경계 시간이나 증원 카운터가 증가하지 않는다.

상단 순서 막대에서 현재 차례와 다음 캐릭터를 확인하고, 그 아래에서 남은 이동 칸과 공격 횟수를 확인한다. 오래된 revision의 확인 요청은 거부하고 이동·공격 소모 원장을 저장하므로 중복 입력이나 저장 복원으로 예산이 환불되지 않는다.

## 증원 설정

설정 파일: `data/content/stage_counterplay.json`

- 시험 기본값: 완료된 전투 **7라운드마다 2마리**.
- 현재 방의 미처리 적이 있을 때만 증원한다. 마지막 적을 제한 턴에 처치해도 증원하지 않는다.
- 최대 활동 적 8마리. 안전한 외곽 빈 칸을 사용하고 파티 바로 옆에는 소환하지 않는다. 공간이 없거나 상한에 닿으면 미룬다.
- 도착한 증원은 해당 턴에 기습 공격하지 않는다. 다음 라운드의 행동 순서에 참여한다.
- 방별 턴과 증원 횟수는 저장하며 방/층 전환 시 유지한다. 배치, 관찰, 계획 수정, 비전투 이동/대기는 증원 턴을 소모하지 않는다.
- 기존 HP·피해·부상 공식은 변경하지 않았다. 7라운드/2마리가 적절한지는 모바일 실제 플레이 후 조정해야 한다.

## 검증

- `stage_counterplay_acceptance.gd`: 무시간 배치, 적 선이동 없음, 혼합 initiative, 관찰 불변성, 개별 입력 재생, 이동/공격 속도 경계와 예산 소모, 중복 revision, 차례 중 저장 복원, 7라운드 증원 및 전멸 후 증원 없음.
- `srpg_party_turns_acceptance.gd`: 실제 NPC 모집 후 두 아군의 개별 차례와 재생, 차례 밖 입력 거부, 적이 아군 사이/맨 앞에 오는 순서.
- `stage_context_ui_acceptance.gd`: 실제 360px 뷰포트 터치, 배치·이동·턴 종료, 이동 범위·기둥 차단, 순서 막대·남은 예산, 중복 입력/화면 내 버튼 검증.
- `first_floor_solo_roster.gd`: 첫층 전투방당 초기 적 1마리와 기존 기둥 좌표·충돌 유지.
- `round_combat_scenarios.gd`: 기존 비방 전투 실험용 일괄 계획 경로 회귀.

실기기 브라우저에서 전체 층 클리어·난이도 검증을 완료했다는 의미는 아니다. 과거 3마리 초기 배치나 고정 칸 예고를 전제로 하는 모든 테스트를 이식한 것은 아니다.

## 저장과 이미지

새 전투 상태 형식에 맞춰 생성 버전을 7로 올렸다. 이동 원장 외에 공격 소모 원장을 저장한다. 이전 저장 파일은 삭제하지 않지만 이번 버전은 새 게임으로 시작한다.

`runtime.png`는 실제 Godot 네이티브 360×800 화면이다. 목업 캐릭터나 타일 이미지를 런타임 에셋으로 대체하지는 않았다.
