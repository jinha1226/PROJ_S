# a788c30 계열 화면의 전투·이동 엔진 교체

## 기준과 의도

사용자가 지정한 UI 기준은 `a788c30`이다. 실제 작업은 `39ec270`에서 분리한 `feat/legacy-shell-new-core`이며, 그 사이의 횃불 HUD·시야·입력 수정은 보존했다. 기존 `party_encounter_sandbox.tscn`과 `PartyPlaytestSession`을 사용한다. 간이 던전의 UI를 비슷하게 꾸미는 방식은 중단했다.

- 기본 주소: 기존 게임 화면 + 공통 전투·이동 엔진.
- `?demo=rebuilt` / `--rebuilt-demo`: 별도 재구축 데모. 제품 메뉴에서는 노출하지 않는다.
- `?prototype=combat`: 작은 전투 실험 장면.
- `?legacy=1`: 더 이상 화면 전환에 필요하지 않으며 기본 게임으로 열린다.

기존 상단 HUD(미니맵·식량·횃불), 게임 화면, 3줄 사건 로그, 파티 초상화, 기술/행동 버튼 순서다. 기술 행은 초상화 아래로 이동했다. 횃불 미장착도 `횃불 없음`으로 표시하고, 연료가 있을 때는 행동 시간 100 기준의 약 턴 수를 표시한다.

## 실행 경로

기존 UI 입력 → 기존 Session의 명령 검증 → 새 공통 엔진 → 기존 WorldState의 결과 반영 → 기존 UI 관찰 자료 갱신.

새 던전 World를 옆에서 동시에 실행하거나, 두 World의 HP를 동기화하지 않는다. 장비·종족·성격·이능·신체·상태 이상·식량·횃불·사회적 사건·마을·저장은 기존 WorldState가 관리한다.

### 전투

- `sim/systems/field_actor_queue.gd`: 새 실행부의 최소 힙 구조를 실제 캠페인의 행동 시각에 연결했다. 매 행동마다 전체 전투원을 다시 훑던 후보 선택 루프를 제거했다.
- 플레이어 다음 입력 시각 이전의 NPC/동료만 처리한다. 같은 시각에는 ID 순서를 사용하며 환경 tick은 기존의 경계 시각 계약을 따른다.
- 보통 행동은 해당 actor만 다시 등록한다. 환경 tick이나 구성원 수 변경은 큐를 다시 만든다. 죽거나 행동 불가능해진 actor는 꺼낼 때 제외한다.
- `sim/turn_engine.gd`: 명중/회피, 갑옷/관통, 최소 피해, 명중 후 방어 판정의 공통 계산부. 실제 캠페인의 무기 공격·비무장 공격·동료/적 공격과 재구축 데모가 함께 호출한다.
- 기존 무기/종족/이능 수치를 입력으로 사용한다. 이벤트 생성, 신체 손상, 사망·드롭, 상태 이상, 원자적 실패 복원은 캠페인 연결부가 담당한다. 기존 이벤트를 우회해 HP만 수정하지 않는다.
- 처리 결과의 `turn_engine: turn-engine-v2`, `queue_builds`로 실제 명령 경로를 확인할 수 있다.

### 이동과 자동이동

- 일반 `WeightedPathfinder`와 재구축 데모의 경로 탐색을 같은 정수 인덱스/배열 기반 A*로 연결했다.
- 기존 Session에 별도로 있던 탐험용 단일/다중 목적지 탐색도 새 엔진으로 교체했다. 목적지 터치·접근·자동이동이 옛 탐색 루프로 빠지지 않는다.
- 위험 경로는 매 노드마다 전체 후보 정렬 및 경로 배열 복사를 하던 구현을 없애고, 최소 힙과 부모 포인터를 사용한다.
- 위험도 우선순위와 우회 걸음 수 제한을 유지한다. 위험 경로의 상태는 `(셀, 걸음 수)`로 구분해, 더 안전하지만 길어진 경로가 제한 내의 짧은 경로를 제거하지 않도록 한다.
- 기존 발견한 지형, 보이는 위험만 참조하는 정책, 대각선 한쪽 모서리 허용/양쪽 차단, 점유 검사, 물 이동 비용을 유지한다.

## 검증

Godot 4.6.2:

- `turn_engine_acceptance.gd`: 가중 경로, 다중 목적지, 결정적 동률 처리, 모서리 규칙, 위험 경로의 걸음 제한, 명중/방어 경계.
- `legacy_shell_engine_acceptance.gd`: 기본 씬, 실제 Session의 새 엔진 호출, 이동, HUD 자원/로그/초상화 순서, 입력 없는 시간 정지, 저장 재현.
- `field_turn_acceptance.gd`: 실제 이동·공격·기술, 실패 원자성, 환경 실패 rollback, 저장 정확한 재현, 마을 출발.
- `field_turn_ui_acceptance.gd`: 실제 UI 명령, 지도/초상화 동료 선택, 대기·명령의 정확한 시간 소모.
- `solo_start_acceptance.gd`: 종족 선택/마을/출발/파티/저장 흐름.
- `straight_path_regression.gd`: 직선 경로.
- 기존 `test_party_playtest_session.gd`의 3개 위험 경로 검사: 안전 우회, 긴 물 우회, 시야 밖 위험 정보 비노출.
- `rebuilt_runtime_acceptance.gd`, `rebuilt_equipment_acceptance.gd`: 공통 코어를 쓰는 데모 쪽 회귀 검사.
- Web 릴리스 내보내기. X11/OpenGL의 360·450px 실제 렌더링에서 기존 던전·마을 화면 확인.

모바일 실기기 장시간 자동탐험 성능의 보증은 아니다. 경로 자료구조와 행동 후보 선택의 중복을 제거했지만, 기존 환경·사회적 사건·저장 검증 비용까지 없앤 것은 아니다.

## 범위 구분

이번 요청은 지정된 기존 게임의 전투·이동 기반 교체다. 기존 장비/종족/이능/성장 데이터는 유지한다. 별도 데모에 추가했던 4계열 포인트 성장과 축약 장비 목록을 기존 데이터 위에 덮어쓰지는 않았다. 해당 성장 정책까지 제품에 통합하려면 기존 성장 저장·보상·UI와 일관되게 별도 이식해야 한다.

DCSS/Pixel Dungeon 원본을 그대로 복사한 포트는 아니다. 앞서 참고해 독립 구현한 행동 시간·최소 힙·경로/시야 구조를 공통 엔진으로 추출해 실제 기존 게임에 연결한 것이다.

중단한 간이 UI 수정은 원래 작업 폴더의 `archive/interrupted-rebuilt-ui-layout`에 보관하며, 이 작업 브랜치와 배포 대상에는 포함하지 않는다.
