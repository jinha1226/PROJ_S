# Living World — 조명·종족별 시야·은신·횃불 구현 개발서

- 작성일: 2026-09-10
- 기준 코드: `6618551a9ebf5107b123d9ad31273d564bb39b7a`
- 상태: 구현 인계용 설계. 이 문서 작성 자체는 기능 구현 완료를 뜻하지 않는다.
- 목적: 다른 개발 세션이 기존 턴제 구조를 유지하면서 단계적으로 구현하고 검증할 수 있게 한다.

## 1. 목표와 확정 요구사항

밝은 곳에서는 편하게 탐험하고, 어두운 곳에서는 방향·빛·종족 특성을 이용해 위험을 판단하고 숨을 수 있게 한다. 정밀 광학 시뮬레이션은 필요 없다.

1. 밝은 곳은 전방위로 잘 보이고, 어두운 곳에서만 바라보는 방향의 중요성이 커진다.
2. 플레이어·동료·NPC·몬스터는 공통 시각 판정을 사용한다. AI만 벽 너머 플레이어 위치를 아는 예외를 만들지 않는다.
3. 기본 시야는 종족별로 다르게 두고, 같은 종족에서도 몬스터 유형별 차이를 줄 수 있게 한다.
4. 관찰 가능한 적의 시야를 표시하여 어둠·엄폐·후방 접근을 이용하는 플레이를 지원한다.
5. 원정 준비물에 식량·포션·횃불을 두고, 그림 중심의 준비 UI를 제공한다.
6. 횃불은 실제 시야와 발각에 영향을 주며, 게임 시간이 흐를 때 연료를 소비한다.
7. 매우 어두운 곳에 오래 머무르면 스트레스가 증가한다. 잠깐 지나가는 어둠에는 즉시 벌점을 주지 않는다.
8. 기존 단일 필드 턴제, 8방향 이동, 싱글 시작, 아이템·휴식·저장 기능을 유지한다. 전투 모드나 실시간 전투를 재도입하지 않는다.

거리·각도·연료 시간·스트레스 수치는 아직 밸런스 확정 사항이 아니다. 아래 데이터 항목과 행동 원칙을 구현 계약으로 삼고, 초기 수치는 별도 설정으로 관리한다.

## 2. 현재 구조와 통합 지점

기준 코드에서 확인된 내용:

- `sim/party_perception_registry.gd`: 파티 기본 탐지 반경과 시야 태그 보너스로 거리를 계산한다. 현재 종족별 조명·방향 프로필은 이 계산에 없다.
- `sim/enemy_perception_registry.gd`: 고블린·코볼트의 거리·지각 프로필과 정수 기반 의심 증가 계산, 지형·연기 기반 시선 검사가 있다.
- 현재 적 프로필 검증은 키 목록을 엄격하게 확인한다. 필드 추가 시 레지스트리 검증과 기존 테스트도 함께 수정해야 한다.

구현 전 다음 통합 후보의 실제 호출 흐름을 확인한다. 파일별 수정이 전부 필수라는 뜻은 아니다.

| 영역 | 통합 후보 | 원칙 |
|---|---|---|

| 저장·재현 | `playtest/party_playtest_session.gd`와 기존 replay 경로 | 새 규칙 버전·마이그레이션 경계 명시 |

새 모듈이 필요하면 조명 계산과 시각 프로필 해석 정도로 책임을 나눈다. 화면, AI, 전투에서 각자 다른 시야 공식을 만들지 않는다.

## 3. 종족·몬스터별 시각 프로필

### 3.1 데이터 우선순위

`공통 기본값 → 종족 기본값 → 몬스터/개체 유형 덮어쓰기 → 개체의 일시적 효과`

- 덮어쓰지 않은 필드는 상위 값을 상속한다.
- 종족과 몬스터 유형은 별도 식별자로 취급한다. 같은 종족의 정찰병과 중장병이 다른 시야를 가질 수 있다.
- 모든 기존 종족·몬스터 유형의 프로필 또는 명시적 기본값 적용을 검사한다.
- 미등록 식별자는 안전한 공통 기본값을 쓰고 개발용 경고를 남긴다. 누락 때문에 시야가 0이 되거나 무한대가 되면 안 된다.
- 효과 적용 순서, 중첩, 상한·하한, 종료 시 복원 규칙을 결정론적으로 정의한다.

| 제안 필드 | 의미 |
|---|---|
| `base_sight_range` | 밝은 환경에서의 기본 최대 시각 거리 |
| `dark_vision` | 저조도에서 거리·방향 불이익을 완화하는 능력 |
| `dark_front_angle` | 어두울 때 전방 유효 시야각 |
| `peripheral_range` | 어두울 때 측후방의 최소 주변 인지 범위 |
| `detection_sensitivity` | 희미한 대상을 인식하거나 의심을 쌓는 민감도 |
| `darkness_stress_resistance` | 어둠 노출로 인한 스트레스 저항 |

필드명은 제안이며 기존 명명 규칙에 맞춰도 된다. 구현 시 거리 단위, 각도 단위, 정규화 범위, 조합 순서와 유효성 검증을 데이터 계약에 명시한다.

### 3.2 차별화 방향

- 인간형: 균형형 기준 프로필.
- 장거리 시각 종족: 밝은 곳에서 먼 대상을 잘 본다.
- 지하 적응 종족: 어두울 때 시야 손실이 작다.
- 감시형 몬스터: 넓은 주변 시야 또는 높은 탐지 민감도.
- 추격형 포식자: 강한 전방 탐지, 상대적으로 약한 후방 인지.
- 시각이 약한 동굴 생물: 짧은 시야. 청각 등 별도 감각은 후속 기능으로 분리한다.

이는 설정 방향 예시이지 특정 종족에 대한 확정 배정이 아니다. 실제 게임 종족 목록에 맞춘 초기 표를 개발 결과에 포함한다.

**야간 시력과 어둠 공포는 독립이다.** 어둠을 잘 보지만 두려워하거나, 잘 보지 못해도 스트레스를 받지 않는 개체가 가능해야 한다. 밝은 곳에서도 종족별 기본 거리 차이는 유지한다.

## 4. 공통 조명·시야 규칙

### 4.1 판정 흐름

1. 관찰자의 최종 시각 프로필과 현재 위치·8방향 바라봄을 얻는다.
2. 최대 거리 밖의 후보를 제외한다.
3. 벽·닫힌 문·기존 연기 규칙에 따른 시선 가림을 검사한다.
4. 관찰자 위치와 대상 타일의 조도를 함께 사용해 거리·방향별 식별 강도를 계산한다.
5. 시각 정보와 실제 발각/의심 상태를 구분하여 반환한다. AI·플레이어 화면·시야 오버레이가 이 결과를 공유한다.

밝기 변화에 따른 거리·방향 불이익은 완만하게 보간한다. 고정된 세 단계 경계에서 타일 하나 차이로 시야가 급격히 뒤집히지 않게 한다. 재현성이 필요하므로 정수 또는 고정소수점 표현을 우선 검토한다.

| 환경 | 기대하는 체감 |
|---|---|
| 밝음 | 기본 거리 안에서 전방위로 잘 보임. 방향 불이익은 거의 없음 |
| 어스름 | 전방은 선명하고 측후방은 어느 정도 제한 |
| 깊은 어둠 | 전방 중심으로 보이며 가까운 주변만 제한적으로 인지 |

- 어두운 곳에 선 관찰자도 시선과 거리 조건을 만족하면 밝게 비친 대상을 볼 수 있어야 한다. 관찰자 타일 밝기만으로 시야 전체를 잘라내지 않는다.
- 동시에 밝은 대상이 있다는 이유로 최대 거리나 모든 후방 제한을 무시하지 않는다. 대상 조도가 방향 제한을 얼마나 완화하는지도 공통 설정에 둔다.
- 인접 주변 인지는 벽 너머 탐지가 아니다. 존재 감지와 정확한 개체 식별을 나누면 UI도 구별해야 한다.
- 대각선 모서리와 닫힌 문의 가림 정책을 명시하고 공통 검사에 적용한다.
- 이미 탐험한 지형은 어둡게 기억할 수 있지만, 보이지 않는 적의 현재 위치나 방향은 갱신하지 않는다.
- 이동·공격 시 바라봄을 갱신한다. 방향만 돌리는 입력이 있다면 기존 행동 시간 체계에 비용을 연결하여 무료 회전으로 어둠 제약을 무력화하지 않게 한다. 구체적 비용은 플레이 테스트 후 결정한다.
- 방향 상태는 에셋 유무와 독립적으로 저장한다. 특정 개체의 8방향 그림이 부족해도 시야 규칙을 누락하지 않는다.

## 5. 적 시야 표시와 은신

- 선택한 적의 시야 표시 또는 표시 토글을 제공한다. 현재 관찰 가능한 적만 대상으로 한다.
- 강한 탐지 영역은 옅은 붉은색, 약한 영역은 더 흐리게 표시한다. 지형과 이동·공격 예고선의 가독성을 해치지 않는다.
- 밝은 곳의 적 시야를 무조건 부채꼴로 그리지 않는다. 실제 전방위 시각 결과를 표시한다.
- 오버레이는 실제 공통 질의를 재사용한다. 의심 누적·대상 은신 등 조건이 있으면 표시를 '탐지 가능 영역'으로 설명하고 즉시 발각 보장으로 오인시키지 않는다.
- 숨은 적, 탐험하지 않은 지형, 보이지 않는 적의 방향을 오버레이로 유출하지 않는다.
- 시야 표시를 켜고 끄는 동작은 턴·의심·연료·스트레스에 영향을 주지 않는다.

인지 흐름은 기존 시스템에 맞춰 `미인지 → 의심 → 추적 → 마지막 목격 위치 조사/수색`에 해당하는 동작을 구현한다. 시야를 잃으면 마지막 목격 위치까지만 추적하고, 플레이어의 현재 좌표를 계속 참조하지 않는다. 재발견하면 관측 정보를 갱신한다.

별도의 필수 은신 모드를 만들지 않는다. 어둠, 벽, 적의 뒤쪽을 이용하면 자연스럽게 숨을 수 있게 한다. 소음 시스템이 이미 있다면 주의 방향과 연동하되, 없으면 이번 구현에서 정밀 청각 시뮬레이션까지 확장하지 않는다.

## 6. 횃불 아이템

### 6.1 상태와 시간

- 소지·보조 손 장착·점화 상태를 구분한다.
- 장착 후 점화/소화가 가능하며 기존 장비 슬롯 충돌 규칙을 따른다. 방패·양손 무기와의 충돌을 우회하지 않는다.
- 실제 게임 경과 시간에 비례해 켜진 횃불의 연료만 소비한다. 입력 대기·메뉴·애니메이션은 시간을 흐르게 하지 않는다.
- 장착 해제 시 기본 정책은 소화로 두고, 자동 재점화하지 않는다. 떨어뜨린 횃불을 동적 광원으로 유지하는 기능은 후속 범위로 둔다.
- 미사용 횃불은 묶을 수 있지만, 사용 중인 횃불의 남은 연료는 개별 상태로 보존한다. 스택 전체가 함께 소모되면 안 된다.
- 연료 소진 시 광원이 사라지고 중요한 알림을 한 번 남긴다. 첫 버전은 다음 횃불 자동 교체·점화를 하지 않는다.
- 점화·소화·장착의 행동 비용은 기존 아이템 행동 규칙을 따르고 문서화한다.

### 6.2 시뮬레이션과 표현

- 횃불은 주변 실제 조도를 올린다. 사용자의 시야를 돕지만 적에게도 사용자를 더 잘 보이게 한다.
- 벽과 닫힌 문이 빛을 가린다. 단순한 화면 원형 밝기 효과만 넣고 AI 판정은 그대로 두면 안 된다.
- 손에 든 횃불, 작은 불꽃, 주변 밝기, 연료 게이지로 상태를 표현한다.
- 불꽃의 장식적 깜박임은 프레임 애니메이션으로만 처리한다. 매 프레임 탐지 결과를 바꾸거나 시야 캐시를 무효화하지 않는다.
- 첫 버전의 횃불은 조명용이다. 근처 기름·나무에 자동으로 불을 붙이는 환경 시뮬레이션 연동은 별도 승인 범위로 둔다.

## 7. 원정 준비물 그래픽 UI

식량·포션·횃불의 세 카드로 구성한다. 각 카드에는 아이콘, 이름, `챙김 / 보유` 수량, 빼기·더하기 조작을 둔다.

- 식량: 빵·말린 고기 묶음, 포션: 붉은 병, 횃불: 천을 감은 나무 횃불 등 식별 쉬운 그림.
- 실제 24×24 원본 아이콘을 정수 배율·nearest-neighbor로 표시한다.
- 기존 다크판타지 9-slice 슬롯과 버튼 스타일을 사용한다. 아이콘이 작아도 터치 영역은 기존 공통 최소 크기를 유지한다.
- 소량의 겹친 아이콘으로 준비물 더미를 표현한다. 수량만큼 노드를 생성하지 않는다.
- 선택하면 용도 설명을 제공하고, 추가 시 가방으로 들어가는 짧은 연출을 줄 수 있다. 연출은 게임 시간을 진행하지 않는다.
- 횃불 등 준비물 부족은 경고하되 출발을 막지 않는다. 횃불 없이 숨는 선택도 허용한다.
- 실제 인벤토리·창고·출발 로직을 단일 원장으로 삼는다. UI 전용 수량을 별도 진실로 만들지 않는다.
- 편집 중 수량은 예약값인지 즉시 이동인지 하나로 정한다. 취소·출발 실패·저장/재로드 시 중복 지급이나 아이템 유실이 없어야 한다.

새 그림이 필요하면 프로젝트 원본과 스타일에 맞춘 자체 제작 자산을 사용한다. 외부 게임의 그림·코드를 그대로 가져오지 않는다. 외부 자료 사용 시 출처와 이용 조건을 별도로 기록하고, 유료 서비스 연결은 사용자 승인 없이 진행하지 않는다.

## 8. 장시간 어둠 노출과 스트레스

노출은 개체가 서 있는 타일의 조도와 경과 시간으로 계산한다. 시야가 좁다는 이유나 화면이 어둡다는 이유만으로 증가시키지 않는다.

1. 매우 어두운 환경에서 개체별 노출 시간을 누적한다.
2. 유예 시간을 넘으면 서서히 스트레스를 증가시킨다.
3. 밝은 곳에 나오면 어둠으로 인한 추가 증가를 멈춘다.
4. 누적 노출은 빛에서 점진적으로 감소시킨다. 밝은 타일 한 번 밟기로 유예 시간이 완전히 초기화되지 않게 한다.
5. 이미 오른 스트레스는 기존 회복·성격 시스템에 맡긴다. 횃불 점화로 즉시 회복시키지 않는다.

설정 항목: 깊은 어둠 기준, 유예 시간, 노출 증가·감소율, 스트레스 증가율·상한, 종족 및 성격 보정.

- 빠른 개체가 행동을 많이 한다는 이유로 더 빨리 스트레스를 받지 않게 경과 시간을 사용한다.
- 조작 캐릭터 전환으로 노출 상태가 초기화되지 않게 개체별로 보존한다.
- 스트레스가 있는 개체에만 적용한다. 야행성·무감정 몬스터까지 인간과 동일하게 적용하지 않는다.
- 야간 시력은 시각 판정, 어둠 저항은 스트레스 판정에 독립적으로 작용한다.
- 어둠으로 인한 스트레스 시작·밝은 곳 복귀 같은 의미 있는 전환만 로그에 남긴다. 매 시간 단위마다 로그를 쌓지 않는다.

## 9. 성능·저장·재현성 계약

### 9.1 성능

- 매 프레임 또는 매 개체마다 던전 전체 타일을 순회하지 않는다.
- 정적 조명과 지형 가림은 캐시하고, 동적 광원은 활성 광원 및 영향 범위 중심으로 계산한다.
- 광원 이동·점화·소화·소진, 문/지형/시선 차단 연기 변화, 층 이동, 로드·롤백에서 필요한 캐시만 무효화한다.
- 시야 캐시 키에 위치·방향·프로필/효과 변경과 관련 조명·가림 버전을 포함한다. 단순 시간 키만으로 전체를 다시 계산하지 않는다.
- 화면 연출은 렌더링, 연료·노출·인지 갱신은 기존 시뮬레이션 시간 경계에서 수행한다.
- 기존 환경 동적 타일 인덱스와 지형 캐시를 재사용한다. 물가·미니맵 성능 개선을 되돌리지 않는다.
- 매 시간 펄스에 전체 이벤트 이력 검증을 재도입하지 않는다. 실행 중 국소 사후조건과 저장/로드 경계의 전체 검증을 구분한다.

### 9.2 저장과 규칙 버전

- 방향, 켜진 횃불·잔여 연료, 어둠 노출, 마지막 목격 정보 등 미래 결과에 영향을 주는 상태를 저장·재현한다.
- 파생 조명/시야 캐시는 저장된 정답으로 신뢰하지 말고 재구성한다.
- 같은 시간에 소진·이동·인지가 겹칠 때 이벤트 순서를 명시한다. 미리보기나 UI 갱신에서 난수를 다시 뽑지 않는다.
- 과거 저널에 새 시야 공식을 무조건 적용하면 기존 전투·이동 재생이 달라질 수 있다. 기존 규칙으로 과거를 재생한 뒤 새 규칙으로 전환하는 명시적 버전 경계 또는 마이그레이션 이벤트를 설계한다.
- 기존 저장을 지원하지 못하는 경우 조용히 변형하지 말고, 구현 전에 제한과 대안을 보고한다.
- 기준 커밋의 순차 전투 이벤트 경계 검증, 포션 회복 순서 호환성, 휴식 국소 검증을 유지한다.

성능 보고는 같은 시드·행동 기록·환경을 사용한다. 초기 로딩과 워밍업을 분리하고 턴 처리, 입력 대기, 물가, 다수 광원, 시야 표시/미니맵 토글의 중앙값·p95·최악값을 전후 비교한다. 절대 FPS를 근거 없이 보장하지 않는다.

## 10. 단계별 구현과 검토 지점

전체 기능을 한 번에 섞지 않는다. 기본 인계는 **1차 구현 후 플레이 감각 검토**까지로 제한하고, 다음 단계는 별도 진행 요청을 받는다.

| 단계 | 결과물 | 완료 기준 |
|---|---|---|
| 0. 조사·계약 | 호출 흐름, 프로필 스키마, 규칙 버전·캐시 정책 | 기존 시스템과 중복되지 않는 설계 및 테스트 계획 기록 |
| 1. 공통 시야 기반 | 조명·방향 질의, 종족/몬스터 프로필, 개발용 시야 표시와 고정 조명 테스트 장면 | 밝음/어둠·종족 차이·벽 가림·표시와 판정 일치 검증 |
| 검토 지점 | 재현 시드/행동과 화면 캡처 제출 | 여기서 멈추고 시야 거리·불편함·표현 검토 요청 |
| 2. 적 인지·은신 | 의심/추적/마지막 목격 연결, 사용자용 적 시야 토글 | 시야 상실 후 현재 플레이어 위치 추적 금지 |
| 3. 횃불 | 장비·점화·연료·동적 조명·손과 게이지 표현 | 양방향 탐지 영향과 시간/소유권 검증 |
| 4. 원정 준비 UI | 식량·포션·횃불 카드 및 실제 재고 연동 | 작은 화면 터치·취소·출발 실패 검증 |
| 5. 어둠 스트레스 | 개체별 노출·유예·저항·전환 로그 | 시간 기반 누적과 빛에서 증가 중지 검증 |
| 6. 통합 검증 | 저장/재생·성능·기존 기능 회귀 보고 | 알려진 실패 없이 검증 결과와 한계 제출 |

저장·성능·테스트는 마지막 단계까지 미루지 않고 각 단계에서 수행한다. 1차 단계의 적 오버레이는 개발용 검증 도구이며, 의심 상태를 포함한 최종 은신 UI 완성을 뜻하지 않는다.

## 11. 수용 테스트 체크리스트

### 공통 시각 및 종족 차이

- [ ] 같은 장면에서 밝을 때 전방위, 어두울 때 방향 중심으로 바뀐다. 플레이어와 몬스터 모두 동일 원리로 동작한다.
- [ ] 같은 조도에서 종족별 기본 거리·야간 시력 차이가 확인된다. 밝은 곳에서도 기본 거리 차이는 남는다.
- [ ] 몬스터 유형 값이 종족 값을 덮고, 미지정 항목은 상속된다. 임시 효과 종료 시 정상 복원된다.
- [ ] 어두운 관찰자가 밝게 비친 대상을 거리·시선·방향 정책에 맞게 볼 수 있다.
- [ ] 벽·닫힌 문·대각선 모서리·연기 정책이 일관되며 문 열기/연기 변화 후 캐시가 갱신된다.
- [ ] 인접 인지가 벽 너머 개체를 유출하지 않는다. 탐험 기억에 숨은 적의 실시간 위치가 나타나지 않는다.
- [ ] 이동·공격·방향 전환·저장/로드 후 8방향과 판정이 일치한다.

### 적 인지·표시

- [ ] 표시 영역과 실제 공통 시각 질의가 일치한다. 표시 토글은 월드 상태·난수·시간을 바꾸지 않는다.
- [ ] 관찰 불가능한 적의 위치·방향·시야가 표시되지 않는다.
- [ ] 적은 시야를 잃은 후 마지막 목격 위치를 조사하며, 플레이어의 새 좌표를 몰래 사용하지 않는다.
- [ ] 재발견 시 정상 추적하고, 밝은 곳의 표시도 실제 시야와 일치한다.

### 횃불·준비물

- [ ] 횃불의 빛이 사용자 시야와 적의 탐지 양쪽에 영향을 준다.
- [ ] 연료는 켜진 횃불 하나에서 경과 시간만큼 감소한다. 메뉴·입력 대기·불꽃 애니메이션에서는 감소하지 않는다.
- [ ] 부분 사용 횃불의 연료, 미사용 스택, 보조 손 충돌, 해제 시 소화, 소진 알림이 정상이다.
- [ ] 준비 수량 변경·취소·출발 실패·저장/로드에서 아이템 복제나 유실이 없다.
- [ ] 횃불이 없어도 경고 후 출발할 수 있다. 작은 화면에서 수량과 연료·아이콘이 읽히고 버튼을 누를 수 있다.

### 스트레스·재현·회귀

- [ ] 짧은 어둠 통과는 유예되고, 장시간 깊은 어둠 노출은 스트레스를 올린다.
- [ ] 빛에서는 추가 증가가 멈추지만 기존 스트레스는 즉시 회복되지 않는다.
- [ ] 밝고 어두운 타일을 오가는 행동으로 유예를 무한 초기화할 수 없다.
- [ ] 같은 경과 시간에는 행동 속도·클릭 수와 무관한 노출이 적용된다. 캐릭터 전환으로 초기화되지 않는다.
- [ ] 야간 시력과 어둠 스트레스 저항을 독립적으로 바꾼 테스트가 통과한다.
- [ ] 저장/재생 후 방향·연료·노출·인지 상태가 동일하고, 기존 저장의 규칙 전환 정책이 검증된다.
- [ ] 포션, 충분한 시간의 연속 휴식, 8방향 이동, 전투 후 저장/회복, 물가·미니맵 성능 회귀 테스트가 통과한다.
- [ ] 같은 시드·행동 기록의 성능 비교와 프로파일 자료를 제출한다.

## 12. 개발 세션에 전달할 실행 요청

아래를 작업 요청으로 사용한다. 모델/세션 선택과 실제 전달은 사용자가 한다.

> Living World 프로젝트에서 이 개발서를 기준으로 단계 0~1만 우선 구현해줘. 현재 작업 트리와 기존 변경을 보존하고, 기준 코드 이후 변경이 있다면 실제 통합 기준 커밋을 기록해줘. 먼저 기존 perception·시간·저장 흐름을 확인하고 데이터 계약과 검증 계획을 문서로 남겨 커밋한 뒤, 공통 조명/방향 시야와 종족 기본값·몬스터 유형 덮어쓰기를 구현해줘. 고정 조명 테스트 장면과 실제 판정을 재사용하는 개발용 시야 표시를 제공해줘. 새 전투 모드, 정밀 광학/청각 시뮬레이션, 외부 게임 코드·에셋 복사는 하지 마. 기존 저장 재현성과 성능 개선을 보존하고, 프로필 상속·밝기/방향·벽 가림·표시 일치·저장 테스트를 수행해줘. 변경 파일, 테스트 명령과 결과, 재현 시드/행동, 화면 캡처, 초기 튜닝값, 알려진 한계와 커밋을 반환해줘. 단계 1 완료 후 검토를 위해 멈추고, 횃불·준비물 UI·스트레스 등 이후 단계는 자동 진행하지 마. 사용자가 별도로 요청하지 않으면 푸시하지 마.

각 후속 단계도 같은 방식으로 코드·테스트·결과 문서를 커밋하고 반환한다. 통과하지 않은 테스트나 미구현 범위를 완료로 표시하지 않는다.
