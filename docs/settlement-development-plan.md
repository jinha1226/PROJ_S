## 2. 목표와 종료 범위

마왕에게 점령된 세계의 외진 피난처에서 초보 모험가가 시작한다. 탐험으로 구한 주민과 자원이 피난처를 성장시키고, 시설이 다음 원정을 지원한다. 연속 오픈월드 대신 기존 지역 선택 및 던전 1·2층을 유지한다.

첫 완성의 필수 흐름:

**주민 구조 → 거점 잔류 → 청사진 배치 → 자재 운반 → 건설 → 생산/휴식 → 원정 준비**

플레이어는 건설 위치·생산 주문·주민별 작업 우선순위만 정한다. 주민은 유효한 작업을 골라 실제 거점 지도에서 이동하고 수행한다. 단순 타이머에 장식용 NPC만 붙이는 것으로 완료 처리하지 않는다.

이번 범위에 넣지 않는다:

- 전투·던전 이동·시야 엔진 재교체, 신규 전투 숙련 축.
- 자유 벽/방 설계, 전력·배관·온도, 농업·계절·번식, 습격·외교·다중 정착지.
- 모든 주민의 던전 밖 생활을 매 프레임 정밀 시뮬레이션하는 전역 엔진.
- 새로운 아트 제작, RimWorld UI·에셋 복제, 기존 저장 전체 초기화.

## 3. 외부 코드 및 라이선스 원칙

이 계획은 외부 구현을 번역·개작하는 계획이 아니라 기능 명세에서 출발하는 독립 구현이다. 법률적 무위험을 보증하는 문서는 아니다.

1. GPL/AGPL 코드 및 라이선스 불명 코드를 새 시스템에 복사·번역·AI 재작성하여 반입하지 않는다. 이름 변경·언어 변환을 라이선스 회피 수단으로 취급하지 않는다.
2. 작업 큐, 자재 예약, 운반, 우선순위 같은 일반적인 기능을 우리 데이터와 이벤트 모델로 직접 설계한다. 외부 소스의 구체적 함수 구조를 옮기는 방식은 피한다.
3. 외부 코드가 꼭 필요하면 MIT/BSD/Apache-2.0 등 조건을 파일·버전 단위로 확인한다. 허용적 라이선스도 무조건 무고지는 아니다. 의존성과 에셋은 따로 확인한다.
4. 반입 시 `docs/third-party-code-register.md`에 URL, 고정 commit, 원본 경로, 반입 경로, 라이선스, 변경 내역을 기록하고 필요한 고지 파일을 배포물에 포함한다. 반입하지 않았다면 결과 문서에 그렇게 명시한다.
5. 기존 전투 코드 전체의 라이선스 적합성은 이 문서에서 보증하지 않는다. 기존 반입 정황을 발견하면 기록하고 별도 감사 대상으로 보고한다.

참고 링크는 기능·라이선스 검토용이며 코드 반입 승인이 아니다:

- [Godot Colony Sim Tutorial](https://github.com/davisbrandon02/colony-sim-tutorial): Godot 예제 후보. 실제 반입 전 해당 revision의 LICENSE와 개별 파일을 확인한다.

## 5. 최소 상태와 불변 조건

새 이름은 제안이며 기존 명명 규칙에 맞춰 조정 가능하다.

- `SettlementJob`: 안정적 job ID, 종류, 상태, 대상 시설/청사진, 담당 주민, 우선순위, 생성 순서, 작업량, 의존 작업, 대기 이유.
- `ResidentWorkState`: 주민 ID, 거점 타일, 현재 job ID, 이동 경로 및 경로 revision, 작업별 우선순위, 재평가 시점.
- `MaterialReservation`: 예약 ID, job ID, 자원 종류/수량, 현재 위치(창고/운반 중/현장), 담당 주민.
- `FacilitySlotReservation`: 건설 접근 칸 또는 생산/휴식 슬롯의 소유 작업.
- `SettlementState`: simulation tick, 작업/주민/예약 인덱스와 revision. 저장 가능한 정규 상태와 재생성 가능한 캐시를 구분한다.

작업 상태: `QUEUED → RESERVED → MOVING → WORKING → COMPLETED`. 자재·인력·경로 부족은 `BLOCKED`와 이유를 유지하고, 취소는 `CANCELLED`로 닫는다. 건설은 운반 작업 완료 전 WORKING으로 넘어갈 수 없다.

필수 불변 조건:

- 주민당 수행 작업 최대 하나. 같은 작업을 중복 수행하거나 원정과 거점 작업을 겸하지 않는다.
- 가용 자원 = 창고 보유량 − 창고 예약량. 예약만으로 물리 재고를 두 번 차감하지 않는다.
- 물리 자재는 창고/운반/현장 중 정확히 한 곳에 존재한다. 완공·생산 완료 시에만 이번 MVP의 투입량을 소비한다.
- 미완성 작업 취소 시 미소비 자재는 회수 대상이 된다. 현장/운반 자재는 반환 운반 후 창고 가용량으로 복귀하며 즉시 복제 환불하지 않는다. 반복 취소/완료 명령은 중복 지급하지 않는다.
- 주민 사망·행동 불능·원정 편입 시 작업과 예약을 안전하게 해제한다. 운반 자재는 마지막 유효 거점 위치에 회수 가능한 상태로 남긴다.
- 청사진도 공간을 예약한다. 중첩과 입구·시설 접근 차단은 기존 배치 규칙으로 거부한다.
- 실패한 명령은 자원·예약·저널을 부분 변경한 채 남기지 않는다. 저장/재생에서 같은 상태를 복원한다.

## 6. 주민 선택과 시간 정책

### 주민 작업

- 최초 대상: 살아 있고 행동 가능한 실제 거점 잔류 주민. 세계의 미가입 NPC는 작업자로 사용하지 않는다.
- 혼자 시작할 때도 거점에 있는 주인공을 명시적으로 작업 가능하게 하되 원정 출발 시 작업을 해제한다.
- UI 우선순위는 운반/건설/생산별 `끄기·낮음·보통·높음`. 휴식은 별도 필요 행동이며 전부 끄더라도 무한 노동시키지 않는다.
- 선택 순서: 수행 가능성 → 필수 휴식 → 사용자 우선순위 → 대기 시간·거리·적성/성격 보정 → 안정적 ID 동률 해소.
- 기존 personality profile 및 신체/회복 상태의 실제 의미를 확인하고 최소 보정만 연결한다. 없는 허기/피로 수치를 이미 있는 것처럼 사용하거나 새로운 성격 체계를 중복 생성하지 않는다.
- 실행 담당은 실제 사용 필드, 정규화 범위, 가중치를 protocol에 기록한다. 성격은 사용자가 높게 지정한 일을 항상 무시하게 만드는 강한 배수로 시작하지 않는다.
- 진행 중 작업은 매 tick 교체하지 않는다. 완료·무효화·필수 휴식 시점에 재평가하고 BLOCKED 작업은 관련 변경 때 다시 평가한다.

### 시계: MVP 제안 정책

- 거점 화면: 기존 0.5초 간격을 초기값으로 사용하는 고정 논리 tick. 화면 애니메이션과 분리한다.
- 원정 중: 성공적으로 확정된 플레이어 행동 한 번당 거점 논리 tick 한 번. 실패 입력·UI 열기·몬스터별 내부 하위 행동은 추가 tick을 만들지 않는다. 거점 잔류 주민만 진행한다.
- 앱 백그라운드/종료 중: 진행하지 않으며 복귀 시 현실 시간만큼 일괄 따라잡지 않는다. 원정 귀환 때 이미 진행한 시간을 다시 계산하지 않는다.
- 원정에서의 거점 진행은 위치·작업의 논리 갱신만 하고 거점 렌더 노드를 만들지 않는다.
- 위 두 입력은 같은 결정적 `advance` 경로를 사용한다. 저널/재생에 tick 경계가 남아야 하며, UI 프레임 시간이나 비결정적 난수가 결과를 바꾸면 안 된다.

## 7. 단계별 구현 순서와 완료 기준

### S0 — 기준 확보와 구현 protocol

- 관련 기존 테스트를 실행하여 기준 통과/실패를 기록하고, 변경 전 성능 표본을 남긴다.
- `docs/settlement-development-protocol.md`에 실제 상태 소유권, 이벤트/저널 확장, 시계 연결 지점, 자원 이동 계약과 검증 명령을 먼저 기록·커밋한다.
- 기존 저장의 레거시 단일 작업 처리 방식을 정한다. 새 스키마로 변환하거나 레거시 경로에서 끝내되 기존 미완성 작업을 무음 삭제하지 않는다.

### S1 — 다중 작업과 예약

- 전역 단일 작업을 주민별 작업과 큐로 확장한다. 기존 버튼도 동일 명령 경로를 사용하도록 어댑터를 둔다.
- 예약/취소/완료/주민 이탈을 구현한다. 처음에는 기존 시설·자원만 사용한다.
- 완료 기준: 주민 둘이 서로 다른 작업 수행 가능, 한 작업/자재 중복 획득 불가, 자원 부족 작업이 대기 이유를 갖고 유지, 저장/재생 일치.

### S2 — 운반과 실제 거점 이동

- 창고 출고 → 운반 → 현장 인도 → 건설 의존성을 구현한다. 동일 자원은 묶음 단위로 옮겨 아이템 개체 수를 불필요하게 늘리지 않는다.
- 거점의 기존 타일·통로 규칙으로 경로를 계산한다. 경로 막힘은 안정적인 BLOCKED 상태와 재시도로 처리한다.
- 완료 기준: 지도상의 주민 위치와 자재 위치가 정규 상태와 일치, 운반 전 완공 불가, 취소/주민 이탈 후 다른 주민이 자재 회수 가능.

### S3 — 생산·휴식·성격 및 원정 연결

- 건설한 진료소에서 기존 물약 주문·생산·수령을 연결한다. 숙소 휴식은 기존 효과를 재사용한다.
- 사용자 우선순위와 최소 성격/신체 보정을 연결한다. 생산 주문은 유한 횟수로 시작하여 무한 자동 생산을 넣지 않는다.
- 원정 편입/잔류, 원정 중 tick, 귀환을 연결한다.
- 완료 기준: 구조한 주민이 거점에 남아 일을 하고, 원정 중 작업이 진행되며, 결과물이 귀환 후 정확히 한 번 수령된다. 편입된 동료는 거점에서 동시에 일하지 않는다.

### S4 — 모바일 UI와 통합 검증

- 기존 피난처 지도·픽셀 폰트·공통 캐릭터 창을 유지한다. 새 데스크톱 관리 화면으로 메인 레이아웃을 교체하지 않는다.
- 지도에서 시설 선택 → 청사진 미리보기 → 비용/가능 여부 → 확정·취소. 작은 타일은 확대 상태에서도 정확히 선택된다.
- 주민 카드: 현재 작업, 상태/대기 이유, 작업 우선순위. 작업 목록: 진행량과 취소. 자재 표시는 총량과 예약량을 구분한다.
- 진행 중에는 바뀐 카드/게이지만 갱신한다. 모달·스크롤·드래그 중 전체 화면 재생성을 피한다.
- 360×640, 390×844에서 터치·스크롤·팝업·닫기 확인. 기능이 없는 버튼이나 설명만 있는 작업은 완료로 치지 않는다.

## 8. 성능 계약과 검증

성능 수치는 보장값이 아니라 초기 목표이며 실제 환경과 함께 보고한다.

- 전체 이벤트 재스캔·전체 월드 검증·모든 주민 경로 계산을 매 프레임 하지 않는다. 이벤트 인덱스/dirty revision으로 필요한 상태만 갱신한다.
- 불변 검사와 자원 거래는 명령 경계에, 전체 감사는 저장/복원·수용 테스트에 둔다. 검증 삭제로 속도를 맞추지 않는다.
- 주민 작업 선택은 유휴/변경 시, 경로 재탐색은 목표·통행 상태 변경 시 수행한다. 이벤트는 의미 있는 논리 변화 단위이며 시각 보간 좌표를 기록하지 않는다.
- 동일 seed·환경에서 주민 1/4/12명, 작업 0/8/32개, 10,000 논리 tick을 측정한다. tick p50/p95/max, 메모리, 이벤트 수, 경로 탐색 횟수, UI 재구축 횟수를 남긴다.
- 초기 목표: 12명/32작업의 거점 논리 tick p95 5ms 이하(개발 환경); 동일 부하 초반/후반 p95 증가 20% 이내. 미달 시 숨기지 말고 병목과 남은 작업을 기록한다.
- 기존 자동탐험·이동 성능도 같은 조건으로 전후 비교한다. 모바일 체감 검증은 별도로 필요하며 데스크톱 통과만으로 모바일 최적화 완료라고 보고하지 않는다.

핵심 수용 시나리오:

1. 첫 피난처 시작 → 구조 → 귀환 → 주민 둘의 서로 다른 작업 → 건설 → 물약 생산·수령.
2. 자재 부족 → 보급 → 재개; 두 작업이 같은 재고를 경쟁해도 음수/복제 없음.
3. 예약/운반/현장 인도/작업 중 각각 취소, 사망·원정 편입; 회수 후 자원 보존과 중복 환불 없음.
4. 길 막힘과 시설 접근 불가 → 이유 표시 → 장애 해소 후 재개, 왕복 진동 없음.
5. 각 작업 단계에서 저장/로드·정확한 저널 재생; 원정 중 진행과 귀환 중복 tick 없음.
6. UI를 열고 닫거나 오래 플레이해도 tick·이벤트가 이중 발생하지 않음.

기존 회귀 테스트 후보:

- `tests/frontier_campaign_acceptance.gd`
- `tests/base_work_acceptance.gd` (단일 작업 가정은 새 명세에 맞게 명시적으로 갱신)
- `tests/base_settlement_build_acceptance.gd`
- `tests/base_production_acceptance.gd`, `tests/base_rest_acceptance.gd`
- `tests/character_views_acceptance.gd`

신규 예약/자원 보존 단위 테스트와 위 통합 수용 테스트를 추가한다. 모든 테스트를 CI에 무차별 추가하지 말고 빠른 핵심 회귀와 수동 성능/모바일 점검을 구분한다. Godot 종료 코드뿐 아니라 `SCRIPT ERROR`/`FAIL`도 검사한다.
