# Model B 구현 계약

기준: legacy `d685c33`, 설계 `c08e338`, DCSS 분석 기준 `2bd8e06e6e5614a6f4917c1c24e04a8922319476`.

사용자 지시: 동료 관계, 신체 손상, 몬스터 능력 흡수를 유지하고 나머지를 Model B로 교체한다. 기존 저장·legacy 경로는 보존하며 새 기본 런은 별도 버전 저장을 사용한다.

- 새 기본 경로 `game/crawl`: 입력 기반 시간제 턴, 8층 branch graph, 두 rune→orb→귀환, 영구 죽음.
- 공유 코드 재사용: LOS/대각선 판정, A*·추적, 맵 생성, BodyState/Injury/Function, HEXACO/Memory/Emotion/Relationship model, 19개 몬스터 능력 정의, 기존 타일·폰트·캐릭터 자산.
- 3종족, 10훈련축(목표 자동훈련), 24적 역할, 12주문, 3신 계약. 장비는 지연/방어/회피/저항/브랜드/주문 부담을 교환한다.
- 자동 탐색·휴식은 위험과 새 발견에서 중지. 전투·소모품·분기·장비·신앙 선택은 수동.
- 식량·횃불 수명·마을·4축 포인트 성장·반복 전투 자동화는 새 런에서 제외. 재생 흡수 능력의 식량 비용은 MP로 이관.
- 관계 유지 검증: 도움, 피해, 복수, 명령 충돌, 감정/기억의 보존과 실제 동료 행동 영향.
- 신체 유지 검증: 조직/사지/혈액 저장, 기능 손상이 이동·장비·공격에 영향, 일반 회복이 사지 재생하지 않음.
- 흡수 유지 검증: 정수 드롭/습득→레벨 제한 6결속→능동·수동 선택, 19효과 연결, 저장.

검증: headless script compile, seed별 맵 연결, branch round trip, 전투/주문/저항/환경/신앙, 세 보존 시스템, save deterministic continuation/invalid input, UI smoke. 기존 공유 코드의 관련 acceptance도 실행한다. 배포·원격 push는 범위 밖.

구현 모델은 DCSS C++ 복사가 아닌 기존 Godot 엔진 위의 독립 규칙이다. 런 시간과 밸런스는 플레이테스트 전 목표치이며 실측 주장하지 않는다.
