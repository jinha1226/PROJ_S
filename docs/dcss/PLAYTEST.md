# Model B 플레이테스트

이번 버전은 Model B 단독 프로토타입이다. 신체 손상·성격 동료·몬스터 흡수 이능은 붙이지 않는다. 신앙의 수호령과 주문 소환수는 감정/관계가 없는 전술 소환수다.

## 실행

Windows: `build/model-b-windows/ModelB.exe`. `ModelB.pck`는 같은 폴더에 둔다. 개발 실행은 Godot 4.6.2에서 `project.godot` → F5. 웹 빌드는 `build/model-b`에서 HTTP 서버를 시작해 브라우저로 연다. 기본 세로 해상도 450×800, 360×800도 검사했다.

## 한 판의 목표

D1 → D2(3개 제단) → D3(분기). 습지 M1/M2와 화로 F1/F2를 원하는 순서로 탐색해 두 룬을 얻는다. D3에서 심장부 Z로 들어가 오브를 얻고, D3→D2→D1 지상 출구로 돌아온다. 돌아올 때 추격자가 추가된다. 이미 방문한 층의 적·전리품·지형·발견 상태는 유지된다. 죽으면 새 탐험을 시작한다.

## 조작

- 인접 칸 터치: 이동. 무기 사거리 안의 적 터치: 공격. 멀리 있는 알려진 칸: 안전 경로 이동.
- 적을 길게 누르기(PC 우클릭): HP·행동 역할·저항·상태와 주문 선택.
- 주문 버튼→대상 칸. 폭발/안개/부채꼴은 첫 터치로 범위를 표시하고 같은 칸 재터치로 확정한다. 아군도 피해를 받는다.
- 계단 `>`/`<`, 제단 `A`, 룬 `R`, 오브 `O`, 보물 `$` 위에서 **사용/계단**. 제단 계약은 **신앙** 창에서 선택한다.
- **탐색**: 적·새 물건/특수 지점·위험에서 중지. **휴식**: 안전할 때 HP/MP 회복. 상태 이상 중 자동 휴식 불가.
- **가방**: 장비 교체(시간 소모), 회복/가속/이동/안개/마도구. 활·지팡이는 양손으로 방패 효과를 받지 않는다.
- **성장/주문**: 최대 2훈련 목표를 선택하면 XP가 자동 배분된다. 발견한 주문 중 6개까지 준비한다. 안전할 때 변경한다.
- PC: WASD/방향키, Space/마침표 대기. 대각선은 칸을 클릭한다.

## 비교해 볼 선택

1. 인간의 무기/마법 혼합, 드워프의 중갑, 엘프의 마법을 비교한다.
2. 큰 피해·느린 도끼와 빠른 단검, 2칸 창, 6칸 활 사이에서 위치와 행동 시간을 비교한다.
3. 습지의 독·물·전기와 화로의 화염·장갑에 맞춰 반지·브랜드·주문·분기 순서를 바꿔 본다.
4. 혼란→기습, 독 안개→점화, 소환수 길막→원거리, 안개→후퇴, 방어구→주문 실패율의 상호작용을 확인한다.
5. 전투의 맹세(주문 금지), 결속(무기 교체 시 파괴), 수호(최대 HP 희생)를 비교한다. 파기에는 징벌이 따른다.

## 저장과 피드백

행동 뒤 자동 저장하고 앱 중단 시 저장한다. 저장은 `user://model_b_run_v1.json`, 직전 파일은 `.bak`; 기존 legacy 저장을 읽거나 덮어쓰지 않는다. 손상된 저장은 자동 덮어쓰기를 막는다. 테스트 도중 종료·재시작해 위치/장비/적 상태가 이어지는지 확인할 수 있다.

이번 테스트에서 알고 싶은 것은 런 시간 목표 달성 여부, 반복 조작의 피로도, 위험 판독, 장비/훈련/신앙 선택의 실제 차이다. 45–75분은 설계 목표이며 아직 사람 플레이로 측정하지 않았다. 원작 DCSS 수치와 승률을 재현한 버전은 아니다. 장비/주문/몬스터 수치는 첫 밸런스이며 조정 대상이다.

## GitHub Actions로 테스트

워크플로 이름: **Model B tests and playable builds**. 이 파일이 포함된 branch를 push하거나 PR을 만들면 관련 경로 변경 시 자동 검사한다. 기본 branch에 workflow가 등록된 뒤에는 Actions → 해당 workflow → Run workflow에서 branch를 골라 실행할 수도 있다. feature branch에서 최초 도입할 때는 push trigger를 사용한다.

성공한 실행의 Artifacts에서 `model-b-windows-<commit>`을 받아 압축 해제 후 `ModelB.exe`를 실행한다. 웹 artifact는 HTTP 서버에 올려 테스트한다. `model-b-test-logs-<commit>`은 실패 시에도 가능한 로그를 남긴다. 이 workflow는 GitHub Pages에 배포하지 않는다. Ubuntu에서 Windows 파일을 export하고 같은 pack을 Godot로 검사하지만 Windows OS의 실제 실행까지 검증하는 것은 아니다.
