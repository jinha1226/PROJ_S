# 종족 선택 터치 회귀 확인

기준 커밋: `07ca2ee`. 사용자가 Godot 실행을 허용한 뒤 Godot 4.6.2 headless로 조사했다.

## 관측한 증상

- 선택 함수를 직접 호출하면 정상적으로 선택창이 닫히고 던전으로 진입했다.
- 실제 `_ready` 경로로 UI를 만든 뒤 Viewport에 마우스 누름·뗌을 보내도 진입했다.
- 같은 버튼 좌표에 `InputEventScreenTouch` 누름·뗌을 보내면 오류 출력 없이 선택창이 남았다. 수정 전 회귀 테스트 종료 코드는 1이었다.
- 기존 선택창은 Button의 마우스 기반 동작에 의존하고 별도의 터치 처리가 없었다. 게임의 전역 터치 처리도 종족 선택창을 일괄 차단하지 않았다. 브라우저의 마우스 에뮬레이션 전달 방식에 의존하지 않도록 변경했다.
- 이번 테스트는 네이티브 터치 패킷 경로의 실패를 확인한 것이다. 특정 모바일 브라우저에서 어느 이벤트가 누락됐는지, 어느 이전 커밋부터 증상이 생겼는지까지 확정한 것은 아니다.

## 수정

전체 종족을 검사하자 별개의 초기화 실패도 확인됐다. 드워프의 기본 민첩은 3인데 모든 종족에게 민첩 4가 필요한 단검을 강제 장착했다. 초기 바닥 장비 생성 시 `item_requirements_not_met`가 반환되어 원정 초기화가 중단됐다. 재능에 따라 민첩이 보정될 수 있어 실행 조건에 따라 증상이 달라질 수 있다.

시작 시 종족·재능을 반영한 실제 능력치로 지급 무기의 조건을 검사하고 처음으로 장착 가능한 무기를 선택하도록 변경했다. 기본 단검이 가능하면 유지하고, 불가능하면 철퇴 등 기존 지급 무기를 사용한다. 물품을 삭제하거나 능력치·장착 조건을 완화하지 않는다.

- 종족 선택창이 열리면 게임 입력 처리에 앞서 선택창 전용 터치 처리기로 전달한다.
- 같은 버튼에서 짧게 누르고 뗄 때 한 번만 선택한다. 드래그, 취소, 두 번째 손가락, 바깥 터치는 선택하지 않는다.
- 터치 직후 합성 마우스 이벤트는 억제한다. 일반 마우스·키보드 GUI 경로는 유지한다.
- 선택창을 열 때 위치를 즉시 계산한다. 실패 시 오류 사유를 선택창 내부에 표시한다.
- 기존 solo_start 테스트는 선택창에서 이미 출발한 뒤 두 번째 출발을 요구하던 오래된 기대값을 현재 흐름에 맞췄다.

- 각 종족 시작 장비 조건 및 전체 월드 상태 유효성

- 중복 release·합성 마우스 이벤트의 중복 명령 방지
- 일반 마우스 선택 및 진입 후 턴 명령 수락
