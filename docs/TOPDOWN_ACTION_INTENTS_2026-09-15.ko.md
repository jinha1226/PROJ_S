# 탑뷰 적·동료 행동 예상 표시

기준 commit: `52c184f`. 사용자 요청: 적·동료 NPC의 이동 경로와 공격 대상을 간결하게 표시하고 푸시. 이 환경에서 Godot 실행 금지.

## 적용

- 기존 동료 결정 함수와 적의 실제 전투 선택기가 반환하는 현재 상태의 예상 행동을 사용한다. 별도 AI·시간 진행·저장 상태 변경은 없다.
- 필드 턴에서도 적 예상을 연결한다. 동료가 없는 플레이에서도 적 표시를 제공한다. 인지 상태가 ALERT/HUNTING인 조우한 적을 기존 선택기가 제한한다.
- 동료 청록 `#59d5e8`, 적 주황 `#ffa45b`. 이동은 가는 곡선 점선과 빈 도착 원, 공격은 실선과 대상 칸 가장자리의 방향 삼각형이다. 어두운 외곽선을 사용한다.
- 선택/터치 강조 중에는 연결선을 표시한다. 이동·공격 종류, 출발/도착, 표적/스킬이 바뀌면 1.2초 동안 표시한다. 매 UI 갱신의 대기시간 변화만으로 타이머를 연장하지 않는다.
- 평소에는 공격 대상의 방향 삼각형만 유지한다. HOLD와 치유 MEND는 공격 표식으로 그리지 않는다. 이동은 다음 행동의 목적지까지만 표시한다.
- 원점과 목적지 모두 기존 시야 필터를 통과해야 표시한다. 플레이어 입력 후 상황에 따라 실제 결정은 바뀔 수 있는 예상이며 확정 공격 예약을 새로 만들지 않았다.
- 연속 탐험에서도 매 갱신에 표시를 갱신한다. 기존 터치 행동은 유지하고 터치 강조를 통해 해당 배우의 선을 잠시 표시한다.

## 검증

- Godot 실행, 엔진 import, 런타임 테스트, 화면 캡처는 수행하지 않았다(사용자 지시).
- gdtoolkit 4.5 파서: `party_grid_view.gd` 전체 및 나머지 두 파일의 변경 함수 4개 문법 검사 통과.
- session 전체 파일은 기존 세미콜론 뒤 for 구문을 외부 파서가 처리하지 못한다. 변경 전 HEAD에서도 동일한 한계를 확인하여 변경 함수 단위로 검사했다. 이 검사는 Godot 타입 검사나 실제 렌더링 검증을 대체하지 않는다.
- `git diff --check` 통과. 기존 전투 선택기 연결, 표시 DTO 소비자, 표시 만료 및 관찰 시야 조건을 코드 검토했다.
- 후속 런타임 확인 항목: 적이 주인공/동료로 표적을 바꾸는 경우, 동료 이동→공격 전환, 단독 파티, 여러 적의 표시 중첩, 확대/축소, 이동 중 갱신, 선택 해제 후 1.2초 만료.
