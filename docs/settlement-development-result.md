## 구현한 흐름

실제 피난처 시작 → 생존자 구조·동행 → 귀환·주민 잔류 → 청사진 주문 → 창고 자재 예약 → 주민 이동·출고 → 현장 운반·인도 → 건설 → 원정에서 약초 확보·귀환 → 물약 생산·정확히 한 번 수령을 수용 테스트로 확인했다.

- S0: protocol 선행 commit 및 기준 실패 기록. 기준 commit을 `/tmp/settlement-baseline` 독립 worktree에 체크아웃하여 기존 실패와 이동 표본도 재현했다.
- S1: 주민별 안정적 작업 ID, 다중 큐, 자재·접근 칸·생산/휴식 시설 슬롯 예약, 취소/이탈 처리. 주민 두 명의 서로 다른 작업을 동시 검증했다.
- S2: 주민 거점 타일/경로와 STORAGE/CARRIED/SITE/RECOVERY/CONSUMED 자재 위치를 정규 이벤트 상태로 기록한다. 실제 지도는 이 좌표를 읽고 자재 묶음 표시를 그린다. 운반 전 건설·생산을 시작하지 않는다.
- S3: 기존 진료소 물약 완료/수령과 숙소 감정·스트레스 회복 효과를 사용한다. 유한 주문, 주민별 운반/건설/생산 우선순위, 필수 휴식, 원정 잔류/편입과 시간 행동 연결을 구현했다.
- S4: 기존 지도/픽셀 폰트/인물 창을 유지한다. 작업 목록/취소, 주민 카드/우선순위, 물리 창고량·예약량·운반/현장량·가용량을 표시한다. tick은 기존 카드/게이지/지도 상태만 갱신하며 완료 후 전체 갱신은 모달/배치/터치 종료까지 미룬다.

새 조리대·작업대·농업·습격·자유 벽/방·오픈월드·새 아트는 이번 구현에 포함하지 않았다. 전투·던전 이동 엔진은 교체하지 않았다.

## 시간·자재·호환성 계약

거점 창이 활성일 때 0.5초 고정 논리 tick이다. 백그라운드/종료 중 진행·복귀 catch-up은 없다. 원정에서 성공한 시간 행동당 1 tick이며 실패 입력과 중첩 하위 행동은 추가 tick을 만들지 않는다. 자원 채집/아이템 행동의 상위 transaction에 포함된다. 시간 소모가 없는 확정 주민 상호작용도 한 번 진행한다. 시간 제한 자동 귀환을 발생시킨 마지막 행동도 1 tick을 남기되 돌아온 주인공을 그 원정 tick의 거점 작업자로 사용하지 않는다. 수동 귀환은 catch-up을 만들지 않는다.

물리 재고를 예약 시 소비하지 않는다. 창고 가용량은 미소비 예약 전체를 제외하고, 물리 창고량은 운반/현장에 있는 묶음을 제외한다. 소비는 건설/생산 완료 때 한 번만 발생한다. 창고 예약 취소는 즉시 해제하지만 운반/현장 취소는 실제 반환 운반 후 가용량에 복귀한다. 사망·행동 불능·원정 편입은 작업자를 해제하며 들고 있던 자재를 마지막 유효 타일의 회수 대상으로 남긴다. 개인 휴식의 대상 주민이 이탈하면 대기/진행 중 휴식 주문을 취소하고 예약 골드를 한 번 해제한다. 판매도 예약을 제외한 가용량을 검사한다.

새 `version=2` 작업 명령을 저널에 기록한다. 레거시 단일 작업 명령은 기존 서비스로 재생한다. 미완성 레거시 작업을 완료/취소한 뒤 새 큐를 시작하며 무음 삭제하지 않는다. 레거시 미완성 작업 저장/복원 → 완료 → 새 주문 → 정확한 저장 재생까지 별도로 통과했다.

정규 상태는 `base.settlement_work_changed`의 변경 필드 patch와 논리 tick이다. world metadata의 증분 인덱스·자원/시설/회사원/골드 캐시는 저장하지 않으며 이벤트 suffix 변경/rollback/world 교체 시 다시 만든다. 순수 시각 좌표 보간이나 UI 프레임 시간을 저널에 넣지 않는다.

주민 선택은 유휴/작업 무효화/필수 휴식 때 수행한다. 작업/공급/우선순위/통행/주민 위치 변화 revision이 없으면 BLOCKED 작업을 매 tick 다시 탐색하지 않는다. 운반에도 접근 칸을 예약하여 주민들이 같은 출고/인도 칸으로 수렴하는 반복 경로 계산을 방지했다.

## 실제 성격·신체 필드

HEXACO `personality_profile.value("C")`를 0~1000 범위로 사용한다. 레거시 4-facet profile에는 conscientiousness가 없어서 실제 존재하는 `composure`를 사용하고, 값이 없으면 중립 500이다. 생산/건설 점수 보정은 `int(value/100)`, 운반은 `10-int(value/100)`으로 0~10이다. 사용자 우선순위 단계는 100,000, 대기는 최대 10,000, 거리는 맨해튼 거리 감점이므로 이 작은 성격 보정이 사용자 높은 우선순위를 뒤집지 않는다. 동률은 안정적 작업 ID로 정한다.

신체는 기존 ACTIVE·status_rows·recovery_lock_until 및 `can_act`를 작업 가능성 조건으로 사용한다. 새 허기/피로 변수를 만들지 않았다. 기존 stress 또는 FEAR/ANGER/SADNESS/GUILT intensity가 600 이상이면 노동을 중단하고 기존 비용/숙소 효과로 필수 휴식을 주문한다. 골드 부족이면 이유를 표시하고 노동을 계속하지 않는다. 노동 우선순위를 모두 꺼도 이 휴식은 동작한다.

## 사용자 플레이 순서

1. 새 게임에서 종족을 고르면 피난처에서 시작한다. 숲길로 출발하여 생존자에게 식량을 나누고 동행을 수락한다. 입구에서 피난처 귀환한다.
2. 주민을 원정에 편성하거나 거점에 남긴다. 거점 관리의 주민 카드 아래에서 운반·건설·생산을 끄기/낮음/보통/높음으로 설정한다. 주인공도 피난처에 있을 때 작업한다.
3. 지도 아래 **건설** → 진료소 → 지도의 빈 땅 → 비용/배치 가능 여부 → **확정**. 자원이 모자라면 주문을 남겨 보급 후 진행한다. 주민이 창고로 이동하고 재료를 운반한 뒤 건설하는 것을 확인한다.
4. 진료소를 선택해 회복 물약 **1개 제조**를 주문한다. 초기 진료소 건설은 starter 약초도 사용하므로 숲길에서 약초를 더 확보해 귀환해야 한다. 완성 후 **가방으로 1개**를 누른다. 주문+완성품 한도는 6이다.
5. 숙소에서 주민 휴식을 주문하거나 필수 휴식 자동 전환을 확인한다. 노동을 모두 꺼도 필수 휴식은 유지하며 골드 부족이면 대기한다. 작업 취소 시 운반/현장 자재는 회수될 때까지 가용량에 즉시 더해지지 않는다.

## 외부 코드·남은 검증

외부 코드/에셋을 반입하지 않았고 GPL 번역·개작도 수행하지 않았다. 기존 거점·전투·자원·UI 경로를 확장했다. 따라서 이번 변경으로 추가되는 제3자 고지 파일은 없다. 기존 저장소 전체의 라이선스 감사를 수행한 결과는 아니다.

물리 모바일/브라우저 체감·장기 메모리와 저장 크기·기준에서도 실패하는 네 레거시 fixture의 별도 정비는 남은 검증/유지보수 사항이다. 농업·습격·다중 정착지는 자동으로 확장하지 않았다.
