# 이동 끊김·자동이동 개선

## 원인과 수정

- 공유 시야 조회가 시야 밖 먼 몬스터에도 프로필·조명·LOS를 반복 계산했다. 등록된 프로필의 조명 배율 상한과 주변 시야 상한에 근거해 불가능한 거리를 먼저 제외한다. 가까운 대상의 실제 시야 판정은 그대로다.
- 적 초상화 갱신이 이미 계산한 파티 상태를 버리고 다시 계산했다. 현재 갱신의 상태 DTO를 전달해 재사용한다. 프레임 간 캐시로 오래된 적 위치를 노출하는 방식이 아니다.
- 싱글플레이에서도 빈 동료 예상 행동을 만들려고 전술 보드를 생성했다. 행동 가능한 동료가 없으면 즉시 빈 결과를 반환한다.
- 기존 자동이동은 110ms였지만 등속 보간 판별은 180ms 이상에서만 켜져 매 칸 감속했다. 명시적 연속 이동 플래그를 도입해 자동이동은 짧은 간격에서도 등속으로 연결한다. 수동 이동의 완만한 보간과 기존 긴 이동 호환은 보존한다.
- 자동 탐험/지정 경로의 실제 시간 간격과 캐릭터·카메라 이동 시간을 110ms → 90ms로 맞췄다. 시뮬레이션의 턴 비용이나 이동 스탯을 바꾸지 않는다. 한 호출당 한 번의 이동, 위험·적 발견 정지, 터치 유지 중 정지 규칙은 유지한다.

## 측정

Godot 4.6.2 headless, 390px, seed 44/20260828, 기존 `waterside_performance_probe.gd`의 좌우 이동 6회. 별도 복사본에서 이능 마무리 코드와 이번 최적화를 비교했다. 동시 작업 중인 아이템 확장은 이 A/B 측정에 포함하지 않았다.

| 조건 | 변경 전 | 최종 변경 후 | 감소 |
|---|---:|---:|---:|
| 마른 바닥 6회 | 661.9ms | 375.9ms | 약 43% |
| 물 주변 6회 | 725.8ms | 410.5ms | 약 43% |
| 적 표시 갱신 평균, 마른 바닥 | 7.06ms | 0.013ms | 중복 상태 계산 제거 |
| UI 관측 평균, 마른 바닥 | 10.95ms | 5.16ms | 거리 밖 시야 계산 제거 |

이 수치는 처리와 테스트 프레임 대기를 포함한 wall time이며 GPU 프레임 시간/FPS가 아니다. 단일 개발 환경 측정으로 모바일 Web에서 60fps나 끊김 완전 해소를 보장하지 않는다. 물 환경 계산 자체는 이 표본에서 평균 0.3ms 정도로 주된 비용이 아니었다.

## 검증

- `run_party_auto_explore_tests.gd`: 9개 통과. 숨겨진 적·위험 정보 비노출, 적 발견/체력/취소 정지, 호출당 한 번 이동, 저장 재현.
- `travel_smoothness_acceptance.gd`: 짧은 자동이동 등속 샘플, 기존 수동 보간, 싱글 동료 예상 빈 결과, 전체 맵 위치의 원래 시야 predicate와 결과 비교, 기존 종족·조명 시야 회귀와 카메라/캐릭터 보간 회귀.
- `ability_binding_gameplay_acceptance.gd`: 자연 이동 → 실제 전투 → 전체 저장 재현 통합 회귀.
- CI에 이동·시야·보간 회귀를 연결했다. 실제 모바일 브라우저 렌더링/입력 체감 측정은 별도다.
- 다른 세션의 아이템 통합 `c1ea608` 위에서도 `travel_smoothness_acceptance.gd`를 다시 실행해 통과했다.
