# 코드 정리 가이드

작성일: 2026-09-29 · 대상: `dungeon.html`(4,240줄, 한 파일) → `index.html` + `js/` 모듈
적용: 2026-09-29 PROJ_S에 반영 완료(§11). 원본은 `versions/v3.html`.

사람과 AI 모두 이 문서를 기준으로 코드를 나누고, 이후 기능을 추가할 때도 이 규칙을 지킨다.

## 1. 왜 나누나

- 파일 하나가 4,000줄을 넘어서 AI가 한 번에 읽기 어렵고, 한 곳을 고치면 다른 곳이 깨지기 시작한다.
- 기능을 추가할 때 **관련 파일 3~4개만** 보여주면 되게 만든다.
- 밸런스 조정은 `data/`만, 연출은 `render/`만 고치면 되게 만든다.
- 정착지와 던전이 3D 체계(`DioramaKit`)를 공유하는 지금 구조를 유지한다.

## 2. 기본 원칙

1. **동작은 한 줄도 바꾸지 않는다.** 정리는 옮기기만 한다. 버그를 발견해도 정리 중에는 고치지 않고 `TODO(정리 후)` 주석으로 남긴다.
2. **빌드 도구 없이 브라우저 ES 모듈**(`<script type="module">`, `import`/`export`)만 쓴다. Three.js는 지금처럼 importmap + CDN.
3. **파일 하나는 400줄 이하**를 목표로 한다. 넘으면 역할별로 다시 나눈다.
4. **의존 방향은 한쪽으로만** 흐른다(§4).
5. **한 번에 한 모듈씩** 옮기고, 옮길 때마다 직접 한 판 해서 확인한다(§7).

큰 객체(`View`, `UI`, `Town`)는 기본 파일에 상태와 핵심 메서드를 두고, 나머지 메서드는 `Object.assign(객체, { … })`로 다른 파일에서 붙인다. `main.js`가 그 파일들을 `import './ui/input.js'`처럼 불러 붙인다.

## 4. 의존 규칙

```
data ← util        core ← flow ← ui / town
  ↑                  │emit        ↑
  └──── render ──────┘ (ports) ───┘
```

| 모듈 | 불러와도 되는 것 | 불러오면 안 되는 것 |
| --- | --- | --- |
| `util/` | 없음 | 전부 |
| `data/` | 다른 `data/` | 나머지 |
| `core/` | `data/`, `util/`, 다른 `core/` | `render/`, `ui/`, `town/`, `flow.js`, THREE |
| `render/` | `data/`, `util/`, `core/state.js`(읽기), THREE, 같은 `render/` | `ui/`, `town/`, `flow.js` — 필요하면 `ports`로 |
| `flow.js` | 전부 | — |
| `ui/`, `town/` | 전부(상태는 core 함수로만 바꾼다) | — |

- **core → 화면은 사건으로만.** `emit(type, data, delay)` → `TL` → 듣는 쪽. `core/state.js`는 `setListener(fn)`만 제공하고 `main.js`가 `setListener((type, data) => View.on(type, data))`로 잇는다.
- **순서가 필요한 전환은 `flow.js`.** 던전 진입·귀환·층 이동은 "정착지 치우기 → HUD 바꾸기 → 층 그리기"처럼 순서대로 불러야 해서 사건 하나로 못 바꾼다. 그래서 core가 아니라 `flow.js`에 둔다.
- **render → ui/town/flow는 `ports`로.** `render/ports.js`의 `ports.UI`, `ports.Town`, `ports.Anim`을 `main.js`가 채운다. render 파일은 ui/town을 import하지 않는다.
- **core 안의 순환 import는 허용한다.** 영혼석·원소 연쇄(`damage` → 초록 발동 → `weaponHit` → `damage`, 불 → 독 폭발 → 기름 폭발 → 불)는 본래 서로를 부른다. 대신 **최상위에서 다른 모듈 함수를 부르지 않는다**(함수 안에서만 부른다). 그러면 브라우저 ES 모듈에서 안전하다.
- 다른 모듈의 `let`은 바꿀 수 없다(import는 읽기 전용). 바꿔야 하면 그 모듈에 setter를 둔다(`setR`, `resetMeta`, `setListener`).

## 5. 상태

- 게임 상태는 **`G` 하나**(던전 한 판)와 **`meta` 하나**(정착지·저장)뿐이다. 모듈 안에 다른 전역 변수를 두지 않는다.
- `G`는 `core/state.js`에서 `export const G`로 만들고, 다른 모듈은 `import { G }`로 쓴다. 새 판은 `G`를 새로 만들지 않고 `Object.assign`/필드 초기화로 갈아 끼운다(참조 유지).
- 저장은 `meta`만 `localStorage`에 한다(`saveMeta`). 저장 형식에 `version` 필드를 둔다.
- render의 캐시(`_texCache`, 메시 등)는 render 모듈 안에만 둔다. `G`에 넣지 않는다.

## 6. 이름과 스타일

- 파일 이름은 소문자와 하이픈(`entity-view.js`).
- 내보내는 것만 `export`. 표 상수는 대문자(`WEAPONS`), 함수는 동사로 시작(`applyFire`).
- 한국어 문구(로그, 버튼, 설명)는 지금처럼 코드 안에 둔다. 나중에 필요하면 `data/text.js`로 모은다.
- 주석은 **왜** 그런지만 쓴다. 지금 코드의 주석은 그대로 옮긴다.

## 7. 옮기는 순서

한 단계마다 로컬 서버로 열어 한 판(1층 이상, 영혼석 발동·원소 반응·소모품 사용·정착지 귀환 한 번씩) 해보고 다음으로 간다.

1. `index.html` 만들기: `dungeon.html`의 HTML·CSS·importmap을 옮기고, `<script type="module" src="js/main.js">` 하나만 둔다. 이 단계에서는 `main.js`에 게임 스크립트 전체를 그대로 붙여 넣어 **한 파일 모듈**로 동작 확인.
2. `render/diorama.js`: `DioramaKit` 블록을 옮기고 `window.DioramaKit` + `diorama-ready` 이벤트 대신 `export`로 바꾼다.
3. `util/`, `data/`: 함수 없는 표부터 옮긴다. 가장 쉽고 가장 자주 고칠 곳이다.
4. `core/state.js`: `G`, `Game`, `TL`, `emit`, `log`, `setListener`.
5. `core/` 나머지: `elements` → `combat` → `stones` → `items` → `skills` → `ai` → `mapgen` → `fov` → `run` → `meta` 순서.
6. `render/`: `dolls` → `entity-view` → `fx` → `sfx` → `view`.
7. `ui/`, `town/`.
8. `main.js`에 남은 것이 시작과 연결뿐인지 확인. 원본 `dungeon.html`과 같은 씨앗으로 같은 첫 층이 나오는지 비교.

## 8. 확인 방법

- **실행:** 저장소 루트에서 `python3 -m http.server 8000` → 브라우저 `http://localhost:8000`. (모듈은 파일 더블클릭 `file://`로는 안 열린다.) 폰 확인은 GitHub Pages로.
- **씨앗 고정:** 주소에 `?seed=123`을 붙이면 판마다 그 씨앗을 쓴다(`util/rng.js`의 `seedOr`). 없으면 예전처럼 시각으로 정한다.
- **정리 전후 비교:** `node tools/equivalence.mjs versions/v3.html index.html` — 두 페이지에 같은 `Math.random`·`Date.now`를 넣고 같은 각본(정착지 → 원정 → 전투 300여 턴 → 보스층 → 귀환 → 영혼석 24종 아레나)을 돌려 32개 시점의 상태 JSON을 비교한다. 원본에는 `?seed=`가 없어서 이 방식으로 비교한다. 규칙 코드의 `Math.random`은 판 시작 씨앗에만 쓰이므로 이렇게 고정하면 결정적이다.
- **스모크:** `npm test` (CI와 같음).
- **import:** 파일을 옮기거나 함수를 새로 쓰면 `npm run fix-imports` — 빠진 import를 채우고 안 쓰는 것을 지우며, 없는 export를 import하거나 §4 규칙을 어기면 알린다. CI는 `npm run lint`로 검사만 한다.
- **콘솔 오류 0:** 한 판 하는 동안 브라우저 콘솔에 빨간 오류가 없어야 한다.
- **자동 확인 페이지(선택):** `test.html`에서 `core/`만 불러와 화면 없이 규칙을 검사한다. 예: 젖은 적에게 번개 → 이웃 젖은 적도 피해, 기름 위 불 → 폭발, 영혼석 연쇄 3단계 → 슬로모션 이벤트 발생. core가 화면을 모르면 이런 검사가 가능하다.

## 11. 적용 결과 (2026-09-29)

- `index.html`(243줄: 틀·CSS·importmap) + `js/` 49개 파일, 합계 4,510줄. **가장 긴 파일 277줄**(`render/view.js`), 400줄 넘는 파일 없음.
- 옮기기는 사람 손 대신 JS 파서(acorn)로 최상위 선언을 파일로 나누고 import/export를 자동으로 만들었다. 함수 본문은 그대로다.
- 본문을 바꾼 곳(동작 같음):
  - `emit`: `View.on` 직접 호출 → `setListener`로 연결된 듣는 쪽 호출.
  - `R = mulberry32(…)` → `setR(mulberry32(seedOr(…)))` (import한 `let`은 바꿀 수 없어서 + `?seed=`).
  - 타이틀의 "처음부터": `META = null` → `resetMeta()`.
  - render 안의 `UI.`/`Town.`/`Anim.` → `ports.UI.` 등.
