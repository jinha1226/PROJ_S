# 조합형 이능 개발 가이드

- 작성일: 2026-09-15
- 상태: 후속 이능 설계와 구현에 적용할 기준 문서. 이 문서 자체는 콘텐츠 구현 완료를 뜻하지 않는다.
- 범위: 파티 전투, 장비, 원소·환경 시뮬레이션과 결합되는 이능의 분류, 데이터 계약, 실행 순서, 조합 규칙과 검증 기준.
- 연계 문서: [이능 획득·결속·성장 개발서](ABILITY_BINDING_DEVELOPMENT_PLAN.ko.md), [기존 16종 연결 결과](ABILITY_CONNECTION_RESULTS.ko.md), [재료·원소·환경 시뮬레이션](ENVIRONMENT_SIMULATION_DESIGN.ko.md).

## 1. 목표

이능은 미리 정해진 직업 세트를 재현하기 위한 목록이 아니다. 캐릭터가 장비와 이능을 선택한 결과로 공격 방식, 원소 운용, 파티 역할과 자원 순환이 만들어져야 한다. 냉기를 쓰는 쌍수 전투원, 독과 시체를 이용하는 소환사, 동료의 공격을 대신 받는 방패 사용자는 이 구조를 검증하는 예시일 뿐 고정 직업이나 필수 빌드가 아니다.

새 이능은 다음 질문에 답할 수 있어야 한다.

1. 어떤 행동 또는 사건에 붙는가?
2. 무엇을 전달하거나 변화시키는가?
3. 어떤 모양과 범위로 전달되는가?
4. 어떤 장비·상태·타일 조건에서 작동하는가?
5. 파티와 적의 행동 선택에 어떤 영향을 주는가?
6. 다른 이능과 결합했을 때 공통 규칙만으로 결과를 계산할 수 있는가?

특정 이능 안에 열, 전도, 점화, 상태 전파 같은 계산을 다시 만들지 않는다. 이능은 공용 전투·환경 시스템에 명시적인 효과를 전달하고, 실제 결과는 해당 시스템이 결정한다.

## 2. 설계 원칙

### 2.1 직업 대신 직교하는 조합 축을 사용한다

모든 이능을 하나의 역할로만 분류하지 않는다. 한 이능은 행동, 속성, 형태, 반응, 전술 축의 태그를 함께 가질 수 있다. 캐릭터의 빌드는 여러 이능과 장비가 공유하는 태그 및 전투 중 생성된 상태에서 나온다.

예를 들어 `무기 적중`, `냉각`, `다중 타격`, `낮은 온도 소비`는 서로 독립된 기능이다. 이들이 함께 장착될 때 냉기 연타 빌드가 되지만, `냉각`은 투사체·방벽·함정·소환 공격에도 재사용할 수 있어야 한다.

### 2.2 조합 가능한 공통 부품과 저작형 이능을 함께 사용한다

플레이어가 임의의 부품으로 이름 없는 기술을 제작하게 만들 필요는 없다. 개별 이능은 이름, 설명, 획득 출처와 고유한 판단 가치를 가진 저작 콘텐츠로 유지한다. 내부 실행은 공통 효과 부품과 태그로 구성한다.

이 방식은 다음을 동시에 만족한다.

- 플레이어에게는 이해 가능한 이능 하나로 보인다.
- 구현은 같은 원소·범위·상태·위협 규칙을 재사용한다.
- 새 이능이 기존 이능과 별도 예외 코드 없이 반응한다.
- 가능한 모든 조합을 수작업으로 열거하지 않아도 된다.

### 2.3 조합에는 이득과 제약이 함께 있어야 한다

태그가 일치한다는 이유만으로 피해 배율만 계속 곱하지 않는다. 강한 조합은 시간, 위치, 장비, 자원, 상태 축적 또는 위험 증가 중 하나 이상의 대가를 가진다. 예를 들어 다중 타격은 상태를 빨리 쌓지만 방어가 낮아지거나 위협을 더 만들 수 있고, 넓은 전도는 적뿐 아니라 젖은 아군과 사용자를 위험하게 할 수 있다.

### 2.4 결과는 현재 화면과 로그에서 설명 가능해야 한다

이능 설명에는 발동 조건, 소비값, 전달 대상, 주요 결과를 표시한다. 전술 이능으로 적의 목표가 바뀌면 기존 적 행동 예상선도 즉시 바뀌어야 한다. 원소 연쇄 결과는 원인 사건을 유지하여 피해·상태·환경 변화가 어떤 이능에서 시작됐는지 추적할 수 있어야 한다.

## 3. 다섯 가지 분류 축

### 3.1 행동 `ACTION`

캐릭터가 직접 선택할 수 있는 새로운 동사를 제공한다.

| 태그 | 의미 |
|---|---|
| `STRIKE` | 무기 또는 신체로 대상을 공격한다. |
| `PROJECTILE` | 사거리와 시야를 가진 투사체를 보낸다. |
| `MOVE_ATTACK` | 이동과 공격을 하나의 행동으로 실행한다. |
| `WARD` | 타일 또는 개체에 지속 방어 효과를 만든다. |
| `SUMMON` | 독립 행동 주체나 고정 구조물을 만든다. |
| `REPOSITION` | 밀기, 당기기, 자리 교환 등 위치를 바꾼다. |
| `INTERACT` | 시체, 문, 표면, 기체, 아이템 등 전장 객체를 사용한다. |

행동 이능은 대상, 사거리, 시야 요구, 행동 시간과 비용을 반드시 정의한다. 이동과 공격을 포함하는 복합 행동도 전체가 하나의 권위 있는 행동으로 확정·롤백되어야 한다.

### 3.2 속성 `PAYLOAD`

행동이나 사건이 세계에 전달하는 내용이다.

| 영역 | 공용 시스템에 전달할 값 |
|---|---|
| 물리 | 피해, 충격, 밀침, 구조물 파괴 요청 |
| 열·화염 | 온도 상승, 점화 요청, 연소 가능한 표면 생성 |
| 냉기 | 온도 하강, 결빙 가능한 상태 생성 |
| 물 | 표면 물과 젖음 증가 |
| 전기 | 지정 타일 방전. 전파는 현재 전도도가 결정 |
| 대기 | 연기, 증기, 일반 기체, 가연성 기체 생성 |
| 생물 | 독, 출혈, 회복, 재생 등 개체 상태 변화 |
| 죽음 | 시체 생성·소비, 사망 사건 또는 소환 자원 변화 |
| 인지 | 은폐, 감지, 시야·청각 또는 관심 변화 |

모든 속성을 동등한 의미의 원소로 취급하지 않는다. 현재 열·냉기·물·전기·연소·폭발·표면·기체는 타일 환경 시뮬레이션에 속한다. 독과 산성은 현재 개체 상태 또는 직접 피해에 가깝다. 시체와 소환은 개체 수명주기이며, 위협은 AI 선택 상태다. UI와 데이터도 이 차이를 보존한다.

### 3.3 형태 `DELIVERY`

효과가 공간과 대상에 전달되는 방법이다.

| 태그 | 의미 |
|---|---|
| `SELF` / `SINGLE` | 자신 또는 단일 대상 |
| `LINE` / `PIERCE` | 직선 경로와 관통 |
| `CONE` | 방향성 부채꼴 |
| `BURST` / `NOVA` | 지정점 또는 사용자 주변 범위 |
| `CHAIN` | 조건을 만족하는 다음 대상으로 전파 |
| `TRAIL` | 이동 경로에 타일 효과를 남김 |
| `AURA` | 사용자 주변에서 지속 판정 |
| `ZONE` | 지정 타일 범위에 지속 효과 |

형태는 효과 자체를 다시 구현하지 않는다. 예를 들어 `CHAIN + ELECTRIC`은 각 대상을 직접 순회하여 고정 피해를 주는 별도 기술이 아니라 최초 방전 위치와 출력을 환경 시스템에 전달한다. 실제 전파 경로는 물, 금속, 고무와 현재 젖음에 따라 결정된다.

### 3.4 반응 `TRIGGER`

선택 행동이 아닌 사건에 붙어 이능을 발동한다.

| 태그 | 발동 시점 |
|---|---|
| `ON_HIT` | 사용자의 공격이 실제 적중한 뒤 |
| `ON_HURT` | 사용자가 실제 피해를 받은 뒤 |
| `ON_BLOCK` | 방어 또는 보호막이 피해를 줄인 뒤 |
| `ON_MOVE` | 이동이 확정된 뒤 |
| `ON_KILL` | 사용자의 원인 계보에 속한 처치 뒤 |
| `ON_DEATH` | 장착자 또는 지정 소환체의 사망 뒤 |
| `ON_STATUS` | 특정 상태가 부여·소비·해제된 뒤 |
| `PERIODIC` | 권위 있는 세계 시간 경계에서 |

반응은 미리보기나 화면 갱신에서 발동하지 않는다. 같은 사건에서 동일 반응은 기본적으로 한 번만 실행한다. 파생 사건이 같은 반응을 다시 부를 수 있는지는 이능별 예외가 아니라 공통 재귀 정책으로 제한한다.

### 3.5 전술 `TACTIC`

파티원과 적의 목표, 위치 관계와 피해 책임을 바꾼다.

| 태그 | 의미 |
|---|---|
| `THREAT_GAIN` / `THREAT_LOSS` | 적이 공격 대상으로 고려하는 우선도를 바꿈 |
| `GUARD_ALLY` | 지정 동료 주변을 유지하고 공격을 가로막음 |
| `INTERCEPT` | 조건을 만족하면 이동 또는 피해 대체 반응 실행 |
| `COVER` | 사선이나 접근로를 차단하여 뒤의 동료를 보호 |
| `FOCUS` | 파티가 같은 적을 우선 평가하도록 함 |
| `OVERWATCH` | 지정 범위에 들어온 적에게 반응 |
| `SHARE_DAMAGE` | 피해 일부를 다른 개체와 분담 |
| `DISENGAGE` | 자신의 관심을 낮추거나 안전한 위치로 이탈 |

전술 태그는 캐릭터 직업을 정하지 않는다. 방패가 없어도 마법 장벽으로 호위할 수 있고, 소환수가 위협을 끌거나 원거리 사용자가 엄호할 수 있다. 장비 조건이 있는 이능만 해당 장비를 요구한다.

## 4. 조건과 자원

조합은 다음 조건을 공통 문법으로 표현한다.

- 장비: 무기 종류, 쌍수, 방패, 양손, 원거리, 맨손, 방어구 무게.
- 개체: HP 구간, 방어·보호막, 독·출혈 등 상태, 최근 이동·피격·처치.
- 타일: 표면, 젖음, 온도, 불, 소재, 기체, 통행 가능 여부.
- 공간: 거리, 방향, 인접 파티원, 사선, 엄폐, 경로.
- 전술: 현재 공격 대상, 관심 단계, 호위 대상, 집중 표적.
- 자원: 행동 시간, MP, HP, 전하, 시체, 소환 한도, 아이템.

조건은 실행 시점의 권위 상태에서 다시 검사한다. 미리보기는 같은 평가 함수를 사용하지만 상태, RNG, 시간, 사건 ID를 소비하지 않는다. 조건이 사라지면 효과를 임의의 다른 대상으로 옮기지 않고 명시된 실패 또는 대체 행동 규칙을 따른다.

## 5. 권장 데이터 계약

아래는 개념적 형태다. 실제 키와 저장 버전은 구현 protocol에서 현재 registry 계약에 맞춰 확정한다.

```gdscript
{
  "ability_id": "...",
  "name": "...",
  "category_tags": ["ACTION", "PAYLOAD", "DELIVERY"],
  "action_tags": ["STRIKE"],
  "payload_tags": ["COLD"],
  "delivery_tags": ["SINGLE"],
  "trigger": "ACTIVE",
  "target": "ENEMY",
  "range": 1,
  "time_cost": 100,
  "resource_costs": {"mp": 2},
  "requirements": {
    "equipment_tags_all": ["MELEE"],
    "target_status_any": [],
    "tile_state_all": []
  },
  "effects": [
    {"effect_id": "WEAPON_ATTACK"},
    {"effect_id": "APPLY_COLD", "amount": 120}
  ],
  "reaction_policy": {
    "once_per_root_action": true,
    "allows_derived_trigger": false
  },
  "ai_hints": ["DAMAGE", "CONTROL"],
  "ui_tags": ["근접", "냉기"]
}
```

정의에는 자유 형식 스크립트 이름을 무제한으로 넣지 않는다. 효과 ID, 조건 ID와 형태 ID는 중앙 registry가 검증하며 알 수 없는 값은 콘텐츠 로드 단계에서 거절한다. 수치는 데이터에 두되 판정식은 공용 시스템에 둔다.

## 6. 실행 순서

하나의 이능 행동은 다음 순서로 처리한다.

1. 사용자 또는 AI가 행동과 대상을 선택한다.
2. 장비, 자원, 거리, 시야, 타일과 대상 조건을 평가한다.
3. 행동 비용과 입력을 하나의 확정 요청으로 고정한다.
4. 기본 행동을 실행하고 적중, 이동, 방어, 상태와 환경 impulse 사건을 생성한다.
5. 형태가 허용한 대상과 타일에 공용 효과를 전달한다.
6. 환경 시스템이 열, 상변화, 연소, 전도, 기체와 폭발을 정산한다.
7. 발생한 사건을 기준으로 반응 이능을 정렬해 실행한다.
8. 위협과 파티 전술 상태를 갱신하고 적·동료의 다음 행동을 다시 예측한다.
9. 최종 상태와 원인 계보를 저장·재생 가능한 사건으로 남긴다.

같은 시각의 순서는 stable actor ID, ability ID와 effect index 등 명시적인 정렬 기준을 사용한다. Dictionary 순회 순서나 프레임 시간에 결과를 맡기지 않는다.

## 7. 원소·환경 연결 규칙

이능은 현재 환경 API가 이해하는 impulse를 생성한다.

- 열은 `apply_heat` 또는 점화 요청을 사용한다. 젖음, 연료, 가연성과 기존 불 상태가 성공 여부를 결정한다.
- 냉기는 `apply_cold`를 사용한다. 물·얼음·증기의 상변화는 환경 tick이 처리한다.
- 물은 `apply_water`로 표면 물과 젖음을 바꾼다.
- 전기는 `discharge`의 시작점과 세기를 전달한다. 전도 경로와 거리 감쇠는 현재 타일 상태가 결정한다.
- 폭발은 `explode`에 종류와 세기를 전달한다. 충격, 밀침, 열과 구조물 파괴는 공용 폭발 규칙이 처리한다.
- 연기, 증기와 가연성 기체는 공용 대기량으로 생성한다. 확산과 배출은 환경 tick을 따른다.

이능 설명은 직접 보장하는 결과와 환경에 따라 달라지는 결과를 구분한다. 예를 들어 전기 이능은 “젖은 타일을 따라 전도될 수 있음”이라고 표시하고, 고정된 대상 수를 약속하지 않는다.

## 8. 위협과 파티 전술 연결

위협은 숨은 피해 배율이나 단일 도발 상태로만 구현하지 않는다. 적의 현재 행동 선택에 사용하는 입력 중 하나로 관리한다.

권장 관측 단계는 다음과 같다.

- `INTEREST`: 공격 대상 후보로 평가 중.
- `PURSUIT`: 현재 이동 목표.
- `ATTACK`: 다음 행동이 해당 대상에 대한 공격.

피해, 방해, 회복, 보호와 일부 이능은 위협을 증감할 수 있다. 최종 대상은 거리, 접근 가능성, 인지 여부, 몬스터 성향과 전술 상태를 함께 평가하여 선택한다. 도발도 접근 불가능한 적이나 고유 목표가 있는 적을 무조건 조종하지 않는다.

공격 대상이 결정되면 기존 주황색 적 예상선에 즉시 반영한다. 동료의 호위·엄호·집중 결정은 청록색 예상선에 반영한다. UI는 계산 근거가 아니라 권위 상태에서 만든 현재 예상의 투영이다.

## 9. 조합 예시와 사용 원칙

다음은 시스템 완성도를 확인하기 위한 조합 예시이며 별도 직업 정의가 아니다.

- 무기 적중 행동 + 냉기 payload + 다중 타격 delivery + 낮은 온도 상태 소비.
- 투사체 행동 + 독 상태 + 처치 반응 + 인접 전파 delivery.
- 소환 행동 + 시체 소비 + 사망 반응 + 독 또는 대기 payload.
- 방벽 행동 + 위협 증가 + 호위 전술 + 방어 성공 반응.
- 전기 payload + 연쇄 delivery + 젖은 타일 조건 + 피격 방출 반응.
- 이동 공격 + 열 payload + 경로 흔적 + 가연성 표면 점화.

새 조합을 검토할 때는 특정 예시가 가능한지만 보지 않는다. 같은 구성 요소를 다른 행동·장비·파티 역할에서도 재사용할 수 있는지 확인한다.

## 10. 기존 이능의 분류와 이전 방향

기존 결속 이능을 즉시 삭제하거나 저장 ID를 바꾸지 않는다. 우선 메타데이터 태그와 공용 효과 부품으로 분류한 뒤 결과가 동일한지 확인한다.

| 기존 이능군 | 우선 분류 |
|---|---|
| 화염샘, 서리실, 독니 | 속성 및 상태 부여 |
| 돌 파편, 사냥꾼의 도약 | 행동 및 전달 형태 |
| 축전 기관, 부식성 혈액 | 피격 반응 |
| 포식 신경, 흡혈 기관 | 조건부 적중·피해 변환 |
| 질긴 가죽, 갑각, 암석 골격 | 방어와 장비·피해 조건 |
| 그림자막, 반향 감각, 심층안 | 인지와 탐색 조건 |
| 재생 조직 | 주기 반응과 회복 |

현재 액티브/패시브 이중 모드는 유지할 수 있다. 다만 새 구조에서 한 이능의 두 모드가 같은 태그와 효과 부품을 공유하는지 검토한다. 단지 이름만 같은 서로 무관한 두 효과로 만들지 않는다.

## 11. 구현 우선순위

### 단계 A: 공통 분류와 실행 기반

1. 기존 이능에 행동·속성·형태·반응·전술 태그를 추가한다.
2. 중앙 registry가 태그, 조건, 비용, 효과 목록을 검증하게 한다.
3. 공용 effect executor가 기존 피해·상태·환경 API를 호출하게 한다.
4. root action과 파생 사건에 출처·깊이·발동 이능을 기록한다.
5. 기존 16종의 결과와 저장 재생이 변하지 않는지 확인한다.

### 단계 B: 조합을 여는 범용 기능

완성형 직업 묶음보다 현재 부족한 공통 부품부터 구현한다.

- 형태: 다중 타격, 관통, 연쇄, 범위, 경로 흔적.
- 반응: 방어 시, 처치 시, 이동 시, 상태 소비 시.
- 전술: 위협 증감, 호위, 엄호, 집중, 피해 분담.
- 개체 수명주기: 제한된 소환, 시체 조회와 소비.
- 조건: 장비 태그, 타일 상태, 대상 상태, 파티 위치 관계.

### 단계 C: 콘텐츠 확장

각 신규 이능은 최소 두 가지 이상의 기존 행동·속성·역할과 유효하게 결합해야 한다. 하나의 사전 정의된 빌드에서만 작동하는 이능은 고유 보상 등 명확한 이유가 있을 때만 허용한다.

## 12. 밸런스 가드레일

- 피해 증폭은 합산·곱연산 순서를 중앙 규칙으로 고정한다.
- 한 행동에서 동일 반응 이능은 기본 한 번만 발동한다.
- 파생 피해는 기본적으로 또 다른 `ON_HIT`·`ON_KILL` 연쇄의 root가 되지 않는다.
- 소환수, 분열체와 구조물은 공통 활성 개체 상한에 포함한다.
- 행동 시간 감소에는 최솟값을 둔다. 무한 행동 순환을 허용하지 않는다.
- 보호막, 피해 분담과 가로막기의 적용 순서를 고정한다.
- 시체와 상태를 소비하는 효과는 성공 시에만 자원을 제거한다.
- 아군 피해와 환경 피해는 별도 면역을 기본 제공하지 않는다.
- 강제 이동은 통행, 점유, 모서리와 맵 경계를 기존 이동 규칙으로 검사한다.
- AI는 플레이어에게 공개되지 않은 타일·대상 상태를 조합 판단에 사용하지 않는다.

## 13. UI 기준

이능 상세에는 다음 정보를 같은 순서로 표시한다.

1. 발동 방식과 행동 시간.
2. 대상과 전달 형태.
3. 직접 효과와 비용.
4. 발동 조건과 소비되는 상태.
5. 환경에 따라 달라질 수 있는 반응.
6. 위협 증가·감소 또는 파티 전술 영향.

`근접`, `냉기`, `적중 시`, `연쇄`, `호위` 같은 짧은 태그를 검색·비교에 사용한다. 태그만 보고 정확한 수치를 추측하게 하지 않으며 본문 설명도 함께 제공한다. 현재 이능 결속 6칸과 액티브/패시브 모드 선택은 별도 합의가 있기 전까지 유지한다.

## 14. 완료 판정과 검증

조합형 이능 기반은 다음 조건을 모두 만족해야 완료로 본다.

- 기존 이능 ID, 획득물, 결속 슬롯과 저장 데이터의 호환 정책이 문서화되어 있다.
- 모든 이능 정의가 중앙 schema 검증을 통과한다.
- 동일한 초기 snapshot과 명령열은 동일한 사건 순서와 최종 snapshot을 만든다.
- preview와 UI 조회는 RNG, 시간, 자원, 상태와 사건 ID를 바꾸지 않는다.
- 실패한 행동은 비용, 시체, 상태, 타일과 위협을 부분 소비하지 않는다.
- 열·냉기·물·전기는 별도 이능 계산이 아니라 공용 환경 시스템으로 실행된다.
- 피해와 회복은 기존 HP·신체 경로를 우회하지 않는다.
- 반응 재귀, 다중 타격, 전도, 폭발과 소환 상한이 유한함을 검증한다.
- 위협 변화 후 적 공격 대상 예상선과 실제 다음 선택이 같은 상태를 기준으로 한다.
- 동료의 호위·엄호·집중 예상과 실제 행동의 차이는 상황 변화로 설명할 수 있다.
- 장비, 원소, 상태, 형태와 전술 축을 각각 바꾼 조합 행렬 검사를 둔다.
- 단독 캐릭터에서도 전술 이능 부재로 턴 진행이나 UI가 실패하지 않는다.
- 실제 모바일 화면에서 태그, 대상선, 환경 표식이 겹칠 때 가독성을 별도로 확인한다.

개별 콘텐츠의 수치 균형과 재미 평가는 기반 구현의 정확성 검증과 분리한다. 첫 구현은 가능한 빌드 수를 세는 대신, 공통 부품이 여러 문맥에서 같은 규칙으로 작동하고 결과를 설명할 수 있는지를 판정한다.
