# 완성형 이능 제작·획득·결속 — 구현 인수인계

- 작성일: 2026-09-15
- 상태: 사용자와 합의한 방향을 정리한 구현 요구사항. 구현 완료 보고서가 아니다.
- 대상: 후속 구현 담당자(Claude 포함).
- 연계: [조합형 이능 개발 가이드](ABILITY_COMPOSITION_DEVELOPMENT_GUIDE.ko.md), [획득·결속·성장 개발서](ABILITY_BINDING_DEVELOPMENT_PLAN.ko.md), [기존 연결 결과](ABILITY_CONNECTION_RESULTS.ko.md), [환경 시뮬레이션](ENVIRONMENT_SIMULATION_DESIGN.ko.md).
- 우선순위: 이 문서의 확정 사항은 이전 문서의 액티브/패시브 모드 선택 설명보다 우선한다. 그 밖의 기존 계약은 명시적으로 변경한 항목만 바꾼다.

## 1. 확정된 핵심

**개발자가 공통 효과를 조합해 이름 있는 완성 이능을 제작한다. 플레이어는 완성 이능을 획득하고, 캐릭터의 결속 슬롯에 넣어 사용한다.**

1. 플레이어가 냉기·연타·관통 같은 부품을 각각 모아 스킬을 조립하는 시스템은 이번 방향에서 채택하지 않는다.
2. 결속 슬롯에는 개별 부품이 아니라 완성 이능 하나가 들어간다. 최대 6칸이다.
3. **이능 하나는 패시브 효과와 액티브 기술을 모두 제공한다. 하나를 선택하는 모드가 아니다.**
4. 결속하면 패시브가 적용되고 해당 액티브도 사용 가능해진다. 액티브 사용은 비용·대상·장비 등 정상 조건을 따른다. 패시브가 무조건 매 턴 발동한다는 뜻은 아니다.
5. 같은 슬롯을 패시브와 액티브가 공유한다. 두 칸을 차지하지 않는다. 여섯 이능을 결속하면 여섯 패시브와 여섯 액티브를 사용할 수 있는 구조다.
6. 몬스터 종류가 적더라도 서로 다른 부위가 서로 다른 완성 이능의 획득 출처가 될 수 있다.
7. 능력의 다양성은 실제 전투·환경 기능에 근거해야 한다. 부위 이름에 맞추려고 구현되지 않은 효과를 임의로 붙이지 않는다.
8. 빌드의 조합은 결속한 여러 이능, 장비, 전장 상태의 상호작용에서 나온다.

### 플레이 흐름

`몬스터 부위 등 획득물 발견 → 줍기·보관 → 패시브/액티브 확인 → 해당 캐릭터에게 결속 → 패시브 적용 + 액티브 사용 가능`

줍기와 결속은 별도 동작이다. 바닥 아이템을 줍는 것만으로 자동 결속하지 않는다.

## 2. 여기서 ‘조합’의 의미

| 주체 | 하는 일 |
|---|---|
| 개발자 | 공통 행동·효과·전달 형태·조건·반응을 조합하여 완성 이능 정의를 작성 |
| 플레이어 | 획득한 완성 이능 중 무엇을 결속하고 어떤 장비와 함께 쓸지 선택 |
| 전투 시스템 | 같은 피해·상태·이동·환경 규칙으로 이능 사이의 상호작용을 계산 |

예를 들어 냉각을 부여하는 이능과 적을 밀치는 이능을 함께 결속하면 접근을 늦추고 거리를 벌리는 운용이 가능하다. 물을 만드는 이능과 전기 이능은 젖음·전도 규칙을 통해 연결될 수 있다. 이는 **상호작용의 방향을 설명하는 예시**이며 신규 이능 이름·수치·구현 완료를 뜻하지 않는다.

공통 효과를 재사용하는 것과 무작위로 효과를 붙여 콘텐츠를 자동 생성하는 것은 다르다. 런타임 무작위 이능 생성, 등급별 랜덤 옵션, 모든 조합의 자동 허용은 합의되지 않았다.

## 3. 몬스터 부위와 획득물

### 확정된 방향

- 하나의 몬스터 종에서 여러 부위 기반 이능을 설계할 수 있다. 고블린 귀와 고블린 눈처럼 출처를 구분할 수 있다.
- 각 획득물은 플레이어에게 완성 이능과 연결된 물건으로 보인다. ‘귀 + 냉기 + 연타’를 조립해야 사용할 수 있는 파편 체계로 만들지 않는다.
- 부위의 기능, 몬스터의 기존 행동, 제공하는 이능 사이에 설명 가능한 관계가 있어야 한다.
- 모든 몬스터의 모든 부위에 이능을 채울 필요는 없다. 해당 종의 특징과 구현된 기능에 맞는 부위를 선정한다.

### 저작 순서

1. 현재 전투 시스템에서 실제 사용할 수 있는 효과를 찾는다.
2. 그 효과가 만드는 플레이 선택과 제약을 정한다.
3. 같은 원리로 연결되는 패시브와 액티브를 작성한다.
4. 그 이능에 어울리는 몬스터와 부위를 선정한다.
5. 획득물·이능·몬스터 출처의 ID 연결을 기록한다.

‘귀니까 소리를 추적한다’, ‘눈이니까 약점을 간파한다’고 먼저 이름 붙인 뒤, 청각·약점 판정 시스템이 존재한다고 가정하면 안 된다.

### 아직 결정되지 않은 사항

- 부위별 드롭 확률, 한 몬스터가 한 번에 주는 부위 수, 희귀도.
- 부위 파괴·절단·해체와 드롭을 연결할지 여부.
- 동일 부위의 개체별 변이, 부위별 등급, 랜덤 옵션.
- 기존 정수 획득물을 물리적인 부위 아이템으로 전부 교체할지 여부.

이 항목들은 기존 드롭 동작을 보존하면서 별도 제안으로 남긴다. 부위 기반 출처가 가능하다는 합의만으로 신규 해체 시스템이나 확률 정책까지 구현하지 않는다.

## 4. 패시브와 액티브 설계 기준

### 하나의 이능으로 읽혀야 한다

둘은 같은 기관·원리·전투 성향을 공유해야 한다. 패시브는 방어인데 액티브는 출처와 관련 없는 소환처럼 이름만 묶인 구성을 피한다.

다음 관계를 사용할 수 있다. 반드시 한 유형으로 통일할 필요는 없다.

- **상시 특성 + 능동 행동:** 특정 공격이나 이동의 특성을 바꾸고, 액티브로 같은 특성을 의도적으로 사용.
- **축적 + 소비:** 패시브로 자원을 축적하고 액티브로 소비. 축적 경로·상한·소멸 조건이 있어야 한다.
- **조건부 반응 + 직접 사용:** 조건을 만족하면 작은 효과가 발생하고 액티브로 같은 계열의 효과를 원하는 시점에 사용.

‘축적 후 소비’ 구조라도 다른 이능이 만든 공통 상태·자원과 결합할 수 있는지 검토한다. 개별 이능 전용 자원을 무작정 늘리지 않는다.

### 동시 사용에 따른 밸런스

- 패시브와 액티브를 함께 제공하는 총효용을 기준으로 수치를 평가한다. 기존 선택형 모드의 수치를 단순 합쳐 적정하다고 간주하지 않는다.
- 액티브 자신의 적중·피격·상태 사건이 같은 이능의 패시브를 발동시키는지 명시한다.
- 다중 타격의 반응 횟수, 파생 피해의 재발동, 처치 귀속은 공통 반응 규칙을 따른다.
- 위력 외에 행동 시간, 자원, 위치, 장비, 준비 조건, 환경 위험으로 제약을 만든다.
- 사용자가 승인하지 않은 새 수치나 발동 횟수를 기존 계약인 것처럼 작성하지 않는다.

## 5. 실제 전투와의 연결

콘텐츠를 대량으로 작성하기 전에 다음 표를 **실제 파일·함수 및 검증 근거**로 채운다.

| 기능 | 코드 경로/함수 | 현재 판정·UI | 상태 | 추가 작업 |
|---|---|---|---|---|
| 피해·회복 | 조사 후 기입 | HP·신체 처리 경로 | 지원/부분/미지원 | 필요 작업 |
| 이동·강제 이동 | 조사 후 기입 | 경로·점유·행동 비용 | 지원/부분/미지원 | 필요 작업 |
| 상태 부여·소비 | 조사 후 기입 | 발동·지속·해제 | 지원/부분/미지원 | 필요 작업 |
| 열·냉기·물·전기 | 조사 후 기입 | 환경 impulse와 정산 | 지원/부분/미지원 | 필요 작업 |
| 반응·주기 효과 | 조사 후 기입 | 사건·세계 시간 | 지원/부분/미지원 | 필요 작업 |
| 소환·시체 | 조사 후 기입 | 생성·상한·수명·소비 | 지원/부분/미지원 | 필요 작업 |
| 파티 전술 | 조사 후 기입 | 기존 명령·AI·표적 예상 | 지원/부분/미지원 | 필요 작업 |

‘문서에 쓰여 있음’은 구현 근거가 아니다. 부분 지원은 가능한 범위와 빠진 부분을 함께 기록한다. 미지원 기능이 필요한 이능은 후보로 두고, 먼저 지원 기능으로 초기 콘텐츠를 구성한다.

### 파티 전투 문맥

- 동료 획득·장비·성장과 전술 기능은 이미 존재한다. 새 이능을 위해 같은 시스템을 다시 만들지 않는다.
- 주인공이 탱커면 동료가 뒤에서 공격하고, 주인공이 원거리면 동료가 앞에서 싸우는 등 역할은 조합에 따라 달라진다.
- 고정 직업이나 주인공 탱커/동료 탱커 전제를 두지 않는다.
- 적을 붙잡기, 거리 벌리기, 접근로 제어 같은 실제 효과로 협동이 생기게 한다. 단지 동료가 있다는 이유로 피해 배율을 붙이는 식의 시너지는 피한다.
- 동료용 액티브는 기존 AI가 대상·비용·위험을 평가할 수 있어야 한다. UI에 버튼만 추가한 상태를 동료 사용 지원 완료로 보고하지 않는다.

## 6. 이능 한 개의 저작 양식

다음은 작성 항목이며 최종 저장 schema가 아니다. 기존 registry와 호환되게 구현자가 구체화한다.

| 항목 | 작성 내용 |
|---|---|
| 식별 | canonical 이능 ID, 이름, 획득물 ID |
| 출처 | 몬스터 종, 부위, 해당 출처가 자연스러운 이유 |
| 핵심 역할 | 이 이능 때문에 달라지는 플레이 선택 한 문장 |
| 패시브 | 발동 사건/조건, 효과, 대상, 횟수/상한, 비용 |
| 액티브 | 행동, 대상, 사거리·시야, 형태, 효과, 시간·자원 비용 |
| 공유 원리 | 패시브와 액티브가 같은 이능인 이유 |
| 내부 구성 | 공통 효과 ID, 조건 ID, 실행 경로, 원인 사건 |
| 조합 | 다른 이능·장비·환경과의 유효한 상호작용 최소 두 문맥 |
| 제약 | 실패 조건, 위험, 소비·환불, 연쇄 한도 |
| 동료 AI | 사용 조건, 대상 선택, 불필요한 사용 방지 |
| 표시 | 설명, 태그, 직접 보장 효과와 환경 의존 효과, 발동 피드백 |
| 검증 | 단독·동시 효과, 거절 무소비, 저장 재생 등 |

앞선 대화의 ‘서리 발톱’, ‘고블린 귀의 소리 추적’ 등은 아이디어였으며 확정 콘텐츠 목록이 아니다. 이 이름이나 효과를 의무적으로 구현하지 않는다.

## 7. 기존 코드와 저장 호환

우선 확인할 진입점:

- `data/content/monster_abilities.json`: 몬스터와 이능·획득물 연결. 현재 `IMPLEMENTED_DUAL_MODE` 같은 상태값이 있으므로 의미를 점검한다.
- `sim/abilities/ability_binding_rules.gd`: 결속 상한·중복·미리보기.
- `sim/abilities/monster_ability_definitions.gd`: 기존 이능 정의.
- `sim/abilities/monster_ability_runtime.gd`: 액티브 평가·실행과 패시브 조회.
- `sim/abilities/monster_passive_service.gd`: 패시브 사건 처리. 기존 모드 변경 사건을 참조하는 경로가 있다.
- `playtest/party_playtest_session.gd`: 사용자 명령·저장·재생·이능 UI의 연결 경계.

위 목록은 진입점 확인 결과이며 전체 구현 감사 완료를 뜻하지 않는다. 추가 참조는 코드에서 추적한다.

### 필수 변경

1. 결속 ID 하나에서 패시브 적용과 액티브 사용 가능 여부를 함께 파생시킨다.
2. 액티브/패시브 선택 UI를 제거하고 두 효과를 함께 설명한다.
3. 현재 런타임뿐 아니라 AI, 설명, 결속 미리보기, 저장·로드, 재생, 테스트의 모드 전제를 함께 바꾼다.
4. 기존 모드 데이터가 있는 저장의 이전 정책을 먼저 문서화한다. 기존 이벤트의 의미를 조용히 바꿔 과거 재생을 깨뜨리지 않는다.
5. 이능 ID, 획득물, 사용자 소유 이능을 보존한다. 동일 이능을 두 개로 복제해 동시 사용을 흉내 내지 않는다.

### 이번 작업으로 바꾸지 않을 정책

- 기존 레벨별 결속 한도 `min(레벨, 6)`와 동일 canonical 이능의 중복 방지.
- 현재 숙련 체계. 근접/원거리/방어/마법을 기본 동작이나 6계통으로 교체하는 논의는 최종 채택되지 않았다.
- 제거·재결속 비용, 획득물 회수, 영구 소실 정책. 무료 교체나 영구 결속을 새로 확정하지 않는다.

제거 정책은 기존 코드의 제한을 보존한다. 패시브/액티브 동시 제공과 공통 효과 연결은 이 정책의 추가 결정 없이 진행할 수 있다.

## 8. 권장 구현 순서와 완료 기준

1. 기능 지원 표와 기존 모드 의존 경로를 조사한다.
2. 이능 하나가 두 효과를 제공하는 결속 계약·이전 정책·반응 규칙을 기록한다.
3. 기존 이능을 동시 제공 구조로 연결하고 UI·AI·저장 경계를 검증한다.
4. 지원 기능으로 신규 이능 후보를 작성한다. 후보별 출처·제약·공통 효과 경로를 명시한다.
5. 처음부터 수량을 크게 늘리기보다 다른 전투 문맥에서 작동하는 소수의 이능으로 검증하고 콘텐츠를 확장한다. 신규 이능 수와 드롭 확률은 별도 결정 항목이다.

완료 판정:

- 한 이능 결속으로 패시브와 액티브가 함께 작동하고 슬롯은 한 칸만 사용한다.
- 패시브를 얻기 위해 액티브를 포기하거나 반대로 선택하는 UI·런타임 경로가 없다.
- 주인공과 동료 모두 동일 결속 계약을 사용한다.
- 신규 효과는 실제 공통 전투·환경 경로에 연결되어 있으며, 미지원 효과를 설명만으로 약속하지 않는다.
- 미리보기/UI 조회는 상태·RNG·시간·사건 ID를 바꾸지 않는다.
- 실패한 결속·사용·소비는 아이템·자원·상태를 부분 소모하지 않는다.
- 반응 연쇄·다중 타격·소환은 공통 상한으로 유한하게 끝난다.
- 기존 저장과 신규 저장의 처리 정책을 검증하고, 같은 버전에서 동일 명령열의 재생이 일치한다.
- 관련 기존 테스트를 변경된 계약에 맞추고 실행 결과·제한을 결과 문서에 남긴다.
- 변경 코드·검증·결과를 커밋한다. 이번 문서 작성은 자동 구현·푸시·배포 요청이 아니다.
