# 4계열 숙련·포인트 성장 계획

- 작성일: 2026-09-11
- 상태: 사용자 합의 방향을 정리한 설계 문서. 구현 완료나 밸런스 검증 결과가 아니다.
- 작업 범위: 계획 작성만. 현재 게임의 8개 숙련·집중 경험치 배분·계산식은 이번 문서 작업으로 변경하지 않는다.
- 적용 대상: 재구축 실행부. 기존 캠페인 진행 데이터 이전은 목표에서 제외한다.

## 1. 목적과 설계 우선순위

모바일에서 처음에는 쉽게 조작하고, 익숙해지면 종족·장비·이능·환경의 조합을
깊게 활용할 수 있게 한다. 숙련은 독립된 액티브 스킬 트리가 아니라 투자한
전투 방향에 무게를 주는 성장축이다. 좋은 장비를 발견했을 때 같은 계열 안에서는
쉽게 활용하고, 다른 계열로 전환할 때는 투자에 따른 선택 비용이 남도록 한다.

본 문서의 4계열 포인트 숙련을 우선한다. 과거 문서의 “몬스터 이능은 액티브로
만들지 않는다”와 재구축 버전의 8계열 자동 경험치 숙련은 새 목표의 근거로
사용하지 않는다. 이외의 기존 설계 전체를 폐기하거나 승인한 것으로 해석하지 않는다.

## 2. 합의한 성장 구조

| 요소 | 역할 |
|---|---|
| 종족 | 신체·기본 특성·장단점 |
| 능력치 | 전투 및 자원 계산의 기초값 |
| 아이템 | 전투 도구·공격 형태·장비 효과 |
| 몬스터 이능 | 획득·결속하는 패시브와 액티브 |
| 숙련 | 관련 전투 행동·이능 성능에 적용하는 투자형 배수 |

- 별도 독립 스킬 트리를 추가하지 않는다.
- 이능은 몬스터에서 얻는 획득물을 보관한 뒤 명시적으로 흡수·결속하는 방향이다.
- 기존 이능 계약의 액티브·패시브 공용 슬롯, 동일 이능 중복 금지,
  캐릭터 레벨에 따른 최대 6칸은 유지한다. 숙련 투자로 슬롯이 늘어나지 않는다.
- 숙련 투자만으로 이능이나 속성 마법이 자동 습득되지는 않는다.
- 이능 제거·회수 비용은 본 문서에서 확정하지 않는다.

## 3. 숙련 목록

| 표시 이름 | 신규 ID 제안 | 적용 대상 |
|---|---|---|
| 근접 | MELEE | 검·도끼·둔기·창·맨손, 물리 근접형 액티브 |
| 원거리 | RANGED | 활·쇠뇌·투척, 물리 원거리형 액티브 |
| 마법 | MAGIC | 마법형 액티브의 지정된 주효과 |
| 방어 | DEFENSE | 갑옷·방패·회피 등 방어 계산의 지정된 항목 |

- 정확한 영구 ID는 기존 JSON 참조 충돌 검사 후 확정한다. 기존 ID를 다른 의미로 재사용하지 않는다.
- 회피는 방어에 포함한다. 은신 숙련은 만들지 않는다.
- 은신 행동 자체를 금지하는 것은 아니다. 필요하면 시야·소음·지형·장비·이능에서 다룬다.
- 화염·냉기·전격 등 속성마다 숙련을 만들지 않는다.
- 투사체라는 이유만으로 원거리를 적용하지 않는다. 예를 들어 화염탄은 마법,
  물리 돌진은 근접이다. 속성은 별도로 적 저항·환경·종족·이능과 상호작용한다.
- 혼합 이능도 숙련 하나를 주 계열로 지정하며 근접×마법 같은 배수 중첩은 하지 않는다.
- 주인공과 동료는 같은 숙련 계산 규칙을 사용한다. 동료 포인트 조작/자동 배분 UI 정책은 별도 확정한다.

## 4. 포인트 획득과 투자

합의 방향은 **캐릭터 레벨업 때 숙련 포인트를 받고 4계열 중 선택해 투자**하는 것이다.
기준안은 레벨업마다 1점이다. 처치 경험치는 캐릭터 레벨 성장에 사용하며,
개별 숙련에 처치 경험치를 자동/집중 배분하는 현재 재구축 방식은 교체한다.

- 이름은 “숙련 포인트”로 통일하여 액티브·패시브 이능과 구별한다.
- 공격·명중·피격·회피 성공 횟수로 숙련을 올리지 않는다.
- 대기, 시체 공격, 약한 적에게 일부러 맞기 같은 행동에 숙련 성장 보상을 주지 않는다.
- 투자 전 현재 효과와 투자 후 효과를 보여주고 명시적으로 확정한다.
- 시작 레벨의 지급량, 캐릭터 최고 레벨, 계열별 최대 투자량과 점당 비용은 미정이다.
- 초반 체감과 후반 전문화를 함께 확보하되 구체적인 성장 곡선은 검증 후 확정한다.
- 재분배 장소·비용·허용 횟수는 미정이다. 무료 상시 재분배나 영구 투자 잠금을
  이번 합의로 간주하지 않는다. 정책 확정 전에는 자동 초기화/환급을 구현하지 않는다.

## 5. 배수 계산 계약

### 5.1 공격·액티브 주효과

방향을 설명하는 개념식:

```text
기초 효과량 = 능력/무기 기본값 + 확정된 능력치·장비 보정
숙련 적용량 = 기초 효과량 × 해당 계열 숙련 배수
최종 결과 = 대상 방어·속성 저항 등 공용 해결 규칙 적용
```

이는 계산 경계의 제안이며 정확한 능력치·장비 공식, 관통/저항 처리 순서와
반올림 규칙까지 확정한 수식은 아니다. 구현 전에 공용 피해 규칙에서 확정한다.

- 전역 “전투력”을 올린 다음 이능에도 다시 곱하는 이중 적용을 금지한다.
- 하나의 주효과에 숙련 배수는 정확히 한 번 적용한다.
- 기본 피해·직접 회복량·보호량 등 어떤 값에 적용하는지는 이능별로 명시한다.
- 명중, 공격 속도, MP 비용, 재사용 대기, 발동률, 지속시간, 범위, 타격 수,
  추가 행동까지 같은 숙련 배수로 일괄 증폭하지 않는다.
- 현재 임시 구현의 피해·명중·공격 속도 숙련 보너스를 새 배수 위에 그대로
  남기지 않는다. 새 계약에서 명시적으로 승인한 보정만 유지한다.
- 다단 공격은 타격마다 배수를 거듭 누적하지 않는다. 원본 행동의 총 효과
  예산과 각 타격 배분을 정의한다.
- 이미 숙련 보정된 피해의 일정 비율로 생기는 추가 피해·흡혈·반사에는
  숙련을 다시 곱하지 않는다. 원본 효과와 파생 효과의 관계를 보존한다.

### 5.2 패시브와 발동 연쇄

- 모든 패시브가 마법 숙련을 받는 것은 아니다.
- 직접 피해·회복·보호량이 있는 패시브만 정의별로 계열/보정 대상을 검토한다.
- 조건 변경·면역·이동 방식 등 규칙형 패시브는 자동 수치 증폭하지 않는다.
- 원본 행동당 추가 발동 상한 2회와 파생 효과의 재귀 발동 금지라는 기존 안전장치를
  기본으로 유지한다. 정확한 발동 대상과 처리 우선순위는 공용 이벤트 계약에 명시한다.

### 5.3 방어

- 방어는 공격의 역수 같은 단순 공식으로 확정하지 않는다.
- 피해 감소·방패 방어·회피는 서로 다른 방어 경로이므로, 방어 숙련이 모든 경로를
  동시에 크게 증폭하지 않도록 장비별 적용 항목을 지정한다.
- 피해 감소에 상한을 두고, 회피·방패 확률도 무적에 도달하지 않도록 별도 제한을 검토한다.
- 피해 감소 상한 수치, 중복 방어의 결합 방식, 최소 피해 정책은 미정이다.
- 직접 이동해 공격 범위를 벗어나는 회피는 플레이어 판단이다.
  이를 숙련 확률 판정으로 대체하지 않는다.

## 6. 모바일 UI/UX

다음은 구현 시 사용할 화면 설계 제안이다.

- 장비와 숙련을 별도 탭으로 구분한다. 이능 결속 화면과는 역할을 분리한다.
- 숙련 화면에는 남은 포인트와 4계열을 한 번에 보여준다. 목록 선택 드롭다운은 없앤다.
- 각 계열은 투자량, 현재 배수/효과, 1점 투자 후 변화, 적용되는 보유 장비·이능을 보여준다.
- 미투자 상태에서도 기본 행동은 가능하다. 포인트를 찍기 전까지 플레이를 막지 않는다.
- 레벨업은 짧은 알림과 포인트 표시로 전달하고 강제 팝업을 피한다.
- 미리보기/취소로 포인트가 소비되지 않는다. 최종 확정은 중복 터치에도 한 번만 처리한다.
- 일상 화면에서는 “화염탄 피해 증가”처럼 짧게 설명하고, 상세에서는 계산 근거를 볼 수 있게 한다.
- 실제 성장 방식은 포인트이므로 개별 숙련 경험치 게이지를 표시하지 않는다.
- 동료 선택, 전투 중 투자 허용 여부, 투자 시 턴 소비 여부는 구현 전에 결정한다.

## 7. 데이터와 실행부 정리

이 절은 구현 계획이며 이번 문서 작업에서 실행하지 않는다.

1. 기존 숙련 JSON, 무기/종족/성장/이능 참조를 조사해 4계열 참조 계약을 만든다.
2. 캐릭터별 레벨·획득 포인트·미사용 포인트·계열별 투자량을 정본 상태로 정의한다.
3. 이능/무기에 주 숙련 계열과 보정 대상 필드를 명시한다. 미지원 정의는 조용히
   임의 분류하지 말고 검증 오류 또는 명시적 미적용으로 처리한다.
4. 공용 계산 경계를 만들어 플레이어·동료·적, 일반 공격·액티브·패시브에서 재사용한다.
5. 재구축 코드의 8계열 XP/집중 훈련/중복 보정과 UI를 대체하고 연결되지 않은 버튼을 없앤다.
6. 수치는 콘텐츠 JSON 한 곳에서 관리한다. 새 실행부 코드 상수에 별도 테이블을 복제하지 않는다.
7. 저장에는 영구 ID와 투자 상태를 기록하고 파생 배수는 로드/변경 시 계산한다.
   스키마를 구분하고 잘못된 포인트·음수·초과 투자·알 수 없는 ID를 거절한다.

기존 캠페인 진행을 이전할 필요는 없지만 기존 저장 파일을 무단 삭제해도 된다는 뜻은 아니다.
새 저장 버전/새 게임 안내를 제공하고, 자동 숙련 환산은 별도 필요가 확인되지 않으면 만들지 않는다.

## 9. 검증과 완료 기준

### 규칙 검증

- 레벨업 중복 처리/저장 재개로 포인트가 복제되지 않는다.
- 투자·취소·부족 포인트·상한·중복 터치·저장 왕복에서 포인트 총량이 보존된다.
- 근접·원거리·마법·방어 매핑, 혼합 속성, 패시브 미적용이 정의대로 동작한다.
- 일반 공격과 이능의 배수가 한 번만 적용되고 파생 피해에서 재증폭되지 않는다.
- 투자 증가가 예기치 않은 효과 감소를 만들지 않으며 방어 상한을 넘지 않는다.
- 장비/종족/신체 손상·이능 변경 시 캐시가 갱신되고 전체 상태를 매 프레임 재계산하지 않는다.

### 밸런스 검증

- 같은 레벨·포인트·장비 획득 예산으로 근접/원거리/마법 및 공격/방어 투자 조합을 비교한다.
- 단일 적/집단/원거리 적/좁은 통로/개활지/속성 지형에서 여러 seed와 행동 정책을 사용한다.
- 승률, 소요 행동 시간, 자원·소모품 사용, 부상 누적, 피격량을 함께 기록한다.
- 극단 투자·복합 이능·최대 방어·흡혈/반사 연쇄에서 무한 회복·무적·행동 봉쇄를 검사한다.
- 미숙련의 좋은 장비로 전환할 가치와 기존 전문 장비를 유지할 가치가 모두 있는지 비교한다.
- 수치 목표와 허용 범위는 실험 전에 정한다. 자동 전투 결과만으로 재미나 모바일 UX를 판정하지 않는다.

### 사용자 경험 및 인계

- 360/390/450px에서 4계열·포인트·변화량을 읽고 터치할 수 있다.
- 실제 모바일에서 별도 공략 없이 투자 대상을 이해하고 취소/확정할 수 있는지 확인한다.
- 실기기 입력 지연/자동이동/전투 성능을 별도로 측정한다.
- “계산 코드만 있음”, “UI 연결”, “전투 연결”, “밸런스 검증”을 구분해서 보고한다.
- 원거리·마법이 빠진 상태를 4계열 시스템 전체 완료라고 보고하지 않는다.
- 구현·검증은 별도 요청 후 진행하고, 코드/결과를 커밋한다. 별도 요청 없이 푸시하지 않는다.
