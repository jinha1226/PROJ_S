# 솔로 1층 탐험 · 유물 회수 구현 결과

작성일: 2026-09-22 · 계획: [solo-floor1-relic-plan.md](solo-floor1-relic-plan.md)

## 적용 범위

| 단계 | 파일 | 결과 |
| --- | --- | --- |
| 1. 솔로 실행 | `expedition/main.gd` | 기본 세션과 패배 후 재시작 모두 `Session.new(seed, true, false, true)`(주인공 1명). 초상화 하나·이능 두 칸·공용 소모품 한 줄을 기존 하단 높이 안에 배치. 동료가 없으면 `전술` 대신 `원정` 버튼. |
| 2. 원정 수명주기 | `expedition/session.gd` | `objective` / `snapshot` / `result` 데이터, `finish_expedition(reason)` 단일 정산기(출정당 1회), `return_home()`, `abandon()`, `refit()`(무료 재정비). 연속 층에서 `retreat()`는 항상 거부. |
| 3. 유물 배치 | `expedition/expedition_objective.gd`, `continuous_floor.gd` | 입구 기준 8방향·모서리 규칙 BFS. 기존 심부 출구 칸을 우선 후보, 대체 후보는 경로 거리 상위 20%에서 시드로 선택, 최종 대체는 가장 먼 도달 칸. `exit` feature 제거, 기존 `relic` 랜드마크는 `altar`로 분리. |
| 4. 획득·반납 | `expedition_objective.gd`, `main.gd` | 팝업 무료, `Objective.pickup`만 상태를 바꾸며 행동 1회 소비. 입구 인접·안전 시 확인창 → `return_home()`. 보너스 100은 정산기에서 1회. |
| 5. 지도·이동 | `continuous_floor.gd`, `map_view.gd`, `board.gd`, `map_icons.gd` | 발견 시 `PORTAL` 마커 추가, 회수 시 마커 제거 후 epoch 변경으로 미니맵 1회 재구성. 자동 이동은 `objective.state` 변화 시 정지. 보드에 유물 전용 아이콘. |
| 6. 실패·정비 | `session.gd` | 패배·포기는 스냅샷(육체·기억·성격은 `to_dict`/`from_dict`로 직렬화) 복원. 결과 카드 + `정비하기`. |
| 7. 솔로 밸런스 | `continuous_floor.gd`, `tests/solo_balance.gd` | 솔로일 때 적 체력 45%(20~32 클램프). 스크립트 봇 8시드 전부 완주. |

## 계획 대비 변경·확인 사항

- 임무 유물은 동료 모드 연속 층에도 동일하게 적용된다(층 목표가 하나로 통일). 동료 시스템·보스 테스트는 그대로 두었고, `tests/character_ui.gd`만 기본 세션이 솔로가 되어 동료 세션을 직접 만들도록 고쳤다.
- 심부 출구 feature는 삭제했다. 원본 위치는 유물의 우선 후보로만 쓰인다. 100개 시드 모두에서 출구 칸이 채택되었고(입구에서 경로 거리 ≥ 40), 대체 경로는 테스트 가능하도록 남겨 두었다.
- `Body.heal`은 혈액·충격만 회복하고 부위 손상은 남긴다. 물약 설명을 이에 맞게 고쳤고, 무료 재정비·유료 요양 로그도 같은 문구를 쓴다.
- 결과 카드가 보이는 동안 보드 자리표시자는 숨긴다(세로 화면에서 하단 버튼이 밀려나는 문제).
- 패배 처리 순서: `end_round`에서 파티 전멸 시 원소 처리 전에 정산하고, `enemy_attack_turn`은 BATTLE이 아니면 즉시 반환한다. 스냅샷 복원으로 살아난 주인공이 같은 라운드의 남은 적 차례에 다시 맞지 않게 하기 위함이다.
- 부모 프로젝트 재사용: `playtest/frontier_campaign.gd`의 상태별 목표 문구 방식과 `party_playtest_session.gd`의 rollback 패턴을 참고했으나, `sim.world` 계약에 묶여 있어 파일은 복사하지 않았다.

## 솔로 밸런스 측정 (`tests/solo_balance.gd`)

봇 규칙: 최단 경로로 유물까지 이동, 보이는 적은 `auto_attack`, 안전할 때 물약·붕대로 회복, 회수 후 입구로 복귀.

| 조정 | 결과 (12시드) |
| --- | --- |
| 원본 체력(오크 70 등) | 12/12 패배. 두 번째 무리(근접+궁수)에서 라운드당 13 피해를 받아 물약 5개를 다 쓰고도 사망. |
| 체력 50% | 12/12 패배. 오크 35는 세 번 쳐야 하고 궁수 접근 중 사망. |
| 체력 45%, 20~32 클램프 | 8/8 완주. 행동 약 230, 회복 5개 전부 사용, 종료 체력 22/59, 식량 27→16, 밝기 90→68, 횃불 미사용. |

봇은 방어·밀쳐내기·지형을 쓰지 않으므로 실제 플레이 여유는 이보다 크다. 행동 230회는 목표 시간 10~15분 범위로 추정하며, 스트레스가 200까지 오르는 점과 회복 아이템 전량 소모는 실기 플레이 뒤 조정 대상이다.

## 실기 확인이 남은 항목

- 모바일 실기에서 목표 칩·유물 팝업·결과 카드의 터치 감각과 문구 이해도.
- 귀환길 반복 이동의 지루함, 샛길(조사물·제단)을 택할 이유.
- 스트레스 누적 속도와 무료 재정비 수치(체력 60%·스트레스 60).


## 1인 루프 검토 후 보완 (2026-09-22)

- 솔로 정비 화면의 출정 버튼 옆과 원정 창에서 유료 요양에 접근하도록 연결했다. 자금 20, 체력 +20, 스트레스 -40이라는 기존 비용·효과를 유지한다.
- 무료 정비의 체력 하한을 60%에서 80%로 올렸다. 스트레스 상한 60, 부위 손상 유지 규칙은 동일하다.
- 솔로 연속 층의 행동력은 항상 1이므로 붕괴의 불이익을 스트레스 150 이상일 때 받는 피해 +1로 정했다. 스트레스 양의 누적량은 기존 계산 결과의 절반(올림)으로 낮추고, 상태창에 효과를 안내한다. 기존 동료·방 모드에는 적용하지 않는다.
- 원정 창에 ‘입구까지 이동’을 추가했다. 기존 발견 지형 경로 탐색과 이동 중단 규칙을 사용하며, 순간 이동과 자동 정산은 하지 않는다. 입구에 인접한 상태에서는 귀환 확인창을 연다.
- `solo_recovery.gd`에 실제 요양 버튼, 잔액 차감, 무료 정비, 붕괴 전후 피해, 안정제 효과, 동료 모드 비적용, 입구 이동·귀환 확인, 적 발견 시 이동 차단, 모바일 세로 배치 검증을 추가했다.
- `solo_balance.gd`는 안전할 때 스트레스 125 이상이면 안정제를 사용하고, 새 캐릭터 8시드 외에 동일 캐릭터 4회 연속 출정을 검사한다.

### 보완 후 측정

첫 출정 8시드 모두 성공: 행동 232~234, 종료 체력 18~22, 식량 16, 밝기 68, 회복품 5개 사용.

| 연속 출정 | 출정 전 정비 | 결과 | 종료 체력 | 종료 스트레스 | 안정제 사용 | 누적 자금 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 신규 캐릭터 | 성공 | 22 | 110 | 0 | 100 |
| 2 | 무료 정비 | 성공 | 13 | 115 | 2 | 200 |
| 3 | 무료 정비 + 요양 1회 | 성공 | 24 | 104 | 1 | 280 |
| 4 | 무료 정비 + 요양 1회 | 성공 | 28 | 104 | 1 | 360 |

연속 출정은 시드 0의 동일 캐릭터를 유지했다. 전투·회복·이동은 공개 행동 API를 사용하며 적 제거, 순간 이동, 자금 주입은 하지 않았다. 목표 위치를 미리 아는 봇이므로 초행 탐색 시간이나 모바일 실기 조작감은 이 결과로 보장하지 않는다. 자원 소모율은 이번 보완에서 변경하지 않았다.

검증: 18개 테스트 스위트 통과(솔로 기능·회복·밸런스 및 기존 통합·동료·보스 회귀 포함). 웹 내보내기 성공.
