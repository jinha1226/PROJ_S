# 이능 결속 구현 프로토콜

- 구현일: 2026-09-10
- 대상 계획서: `docs/ABILITY_BINDING_DEVELOPMENT_PLAN.ko.md`
- 구현 범위: 캐릭터별 이능 결속 상태, 슬롯 한도, 중복 차단, 이능 획득물 소비, 저장 wire, 이벤트·journal 검증, 상세 UI

## 정책 가정

계획서의 핵심 미정 항목 중 이번 구현에서는 권장 흐름에 따라 **흡수=결속**으로 해석한다. 이능 획득물을 보관하는 것과 결속하는 것은 분리하고, 결속 확정 시에만 아이템을 소비한다.

제거 후 소멸·회수·재아이템화 및 비용은 계획서에서 미정이므로 구현하지 않는다. 제거 API와 UI는 정책 미정 사유를 반환하거나 잠금 상태를 유지하며, 확인 없이 기존 결속을 삭제하지 않는다.

## 수치 계약

- 최대 결속 슬롯: 6
- 캐릭터 레벨 `L`의 개방 슬롯: `min(L, 6)`
- 검증 레벨: 1, 2, 5, 6, 7 → 1, 2, 5, 6, 6
- 액티브·패시브는 같은 결속 배열을 공유한다.
- 액티브 전투 버튼 노출은 기존 `skill_loadout_id` 정책과 분리하며, 결속만으로 모든 버튼을 자동 노출하지 않는다.

## 실행 순서

1. `AbilityBindingRules`가 canonical ID, 효과 미리보기, 슬롯 한도와 결속 배열을 검증한다.
2. 대상 캐릭터의 안전 상태와 보관 아이템을 확인한다.
3. 아이템이 이능 획득물인지 확인하고 canonical 이능 ID로 변환한다.
4. 중복 및 열린 슬롯을 확인한다. 거절 시 아이템·이벤트·journal을 변경하지 않는다.
5. 결속 확정 시 복제 inventory에서 아이템을 소비하고 캐릭터 배열을 갱신한다.
6. `party.ability_bound` 이벤트와 `ability/BIND` journal을 함께 기록한다.
7. 전체 world audit가 실패하면 snapshot으로 원자적 rollback한다.

## 저장·무결성

- party schema v25에서 `bound_ability_ids`를 저장한다.
- v24 저장은 빈 결속 배열로 마이그레이션하며 이능을 추론하거나 자동 장착하지 않는다.
- 결속 ID는 canonical·정렬·중복 없음·최대 6개여야 한다.
- 결속 이벤트는 actor=target, 능력·아이템·slot 전이와 최종 캐릭터 projection을 검증한다.
- 결속된 획득물 instance는 결속 후 owner가 없어야 한다. 제거가 잠겨 있으므로 현재는 소비 후 복구되지 않는다.

## 종료 범위

이번 단계는 결속 영속화와 획득물 거래까지다. 패시브 수치 registry, 결속된 액티브를 전투 버튼에 노출하는 별도 loadout 정책, 제거 비용·회수 정책은 다음 설계 결정 후 별도 작업으로 남긴다.
