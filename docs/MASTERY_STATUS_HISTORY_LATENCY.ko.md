# 숙련·상태창 갱신과 누적 기록 지연 수정

기준: `3612e7b`. 2026-09-12, Godot 4.6.2 headless / Linux PC.

## 원인과 변경

- 숙련 계산 자체에는 3레벨 잠금이 없다. 3레벨은 누적 250 XP, 미사용 2점이다.
  기존에는 적이 보이거나 안전 단계가 아니면 버튼을 설명 없이 비활성화했다.
  열린 패널은 자기 투자와 탭 선택 외에는 갱신되지 않았다. 변경 사유를 표시하고,
  상태 변화 시 열린 숙련 UI도 갱신한다. 전투 중 투자 금지와 레벨당 1점 규칙은 유지했다.
  사용자 당시 저장 파일은 없으므로 당시 원인을 단일 조건으로 확정하지 않는다.
- 장비 조작 후 아이템 목록만 갱신하고 상태 상세 DTO는 다시 채우지 않았다.
  열린 상세창은 world/시간/이벤트 수/파티·아이템 revision/XP·숙련 변경에 따라
  전투 수치와 성장 정보를 갱신한다. 탭·확인창을 다시 열지 않으며 변화 없는 프레임은 건너뛴다.
- `PartySurvivalRules.control_id`가 현재 조작 캐릭터를 묻는 매 호출마다 전체 이벤트를
  역순 검색했다. 이 조회는 시야·아이템·경로에서 반복되어 기록량에 비례한 큰 지연을 만들었다.
  파티 명령, 진형, 접촉 경고, 사망 흔적, 사기, 캠페인 초기화 여부도 증분 인덱스로 조회한다.
  과거 특정 이벤트 경계의 검증은 기존 재구성 경로를 유지한다.
- AUTO의 계획용 관찰에서는 동료 표시 위치·아이템 상세·혈흔 장식을 만들지 않는다.
  화면 관찰은 보이는 바닥 아이템만 상세 DTO로 변환한다. 가려진 지형 메모리와
  위험 회피, 적 발견 정지, 이동·전투 규칙은 유지한다.
- 인덱스는 저장되지 않는 파생 데이터다. 이벤트 추가분만 처리하며 기록 축소·마지막
  이벤트 교체·새 world에서는 재구축한다. 기록을 삭제하거나 저장 검증을 끄지 않았다.

## 재현 가능한 측정

`godot --headless --path . --script tests/history_latency_probe.gd`

고정된 DUO 필드 관찰 fixture에 무효과 이벤트를 추가하여 기록량만 분리했다.
각 단계 워밍업 후 관찰 context + AUTO fog snapshot 쌍을 10회 측정했다.
패딩한 world는 유효 저장 파일이 아니며 그 위에서 실제 턴을 실행하지 않는다.

| 이벤트 수 | 수정 전 평균 | 수정 후 평균 |
|---|---:|---:|
| 5 | 12.250 ms | 13.871 ms |
| 10,000 | 785.469 ms | 12.293 ms |
| 50,000 | 3,696.129 ms | 12.582 ms |

숫자는 전체 프레임/FPS가 아닌 특정 읽기 경로 비용이다. 모바일 GPU 렌더링이나
NPC가 오랫동안 실제로 만든 다양한 기록을 모두 대체하는 검사는 아니다.

## 기능 검증

- `tests/mastery_live_acceptance.gd`: 3레벨 2점, 안전 시 즉시 배분, 위협 시 이유 표시,
  다음 레벨업 없이 안전 복귀 후 활성화, 열린 상태창 장비 공격력 갱신,

  기록 87개, 첫 16회 34.211 ms / 마지막 16회 33.985 ms, 상태 검증 및 저장 재생 일치.
