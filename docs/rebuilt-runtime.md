> 최신 구현: [4계열 숙련 내부 시스템·UI 결과](PROFICIENCY_FOUR_AXIS_RESULTS.ko.md).
> 아래 8계열 숙련과 이전 저장 스키마 설명은 과거 구현 이력이다.

> 후속 설계: [4계열 숙련·포인트 성장 계획](PROFICIENCY_FOUR_AXIS_PLAN.ko.md).

> 후속 계획 작성만으로 게임 코드가 교체되지는 않는다.

## 범위

기본 진입점을 `game/rebuilt/game.tscn`으로 교체했다. 기존 캠페인의 매 턴 실행 경로를 우회하는 독립 게임 상태이며, 기존 코드와 저장 파일은 삭제하지 않았다.

- 기본 주소: 새 던전 실행부
- `?legacy=1` 또는 네이티브 `--legacy-game`: 기존 게임
- `?prototype=combat`: 이전 전투 실험 화면
- 새 저장: `user://rebuilt_dungeon_v1.json`, 임시 파일과 `.bak` 사용

구현 범위는 64×64 던전, 이동/전투/즉시 사망, 적 추적과 성격 기반 후퇴, 6칸 시야와 지형 기억, 횃불/고정 광원, 자동탐험, 회복약/금화, 층 이동, 상태창, 저장/복구다. 한쪽 벽 모서리의 대각선 이동은 허용하고 양쪽이 벽인 틈은 막는다.

**기존 게임과 기능 동등한 완성품은 아니다.** 마을, 동료 관계/명령 규칙 전체, 기존 장비/능력 전체는 아직 이식하지 않았다. 동료 1명의 추종/대기/전투와 상세 부위 손상을 연결했고, 장비·숙련도는 아래 독립 규칙으로 추가했다. 기존 캠페인 진행 데이터 이전은 사용자 요청에 따라 목표에서 제외한다.

## 장비·숙련도

DCSS의 장비 속성/행동 시간 및 경험치 배분형 숙련도라는 설계 개념을 참고했다. 원본 C++ 코드나 수치 테이블을 복사/번역하지 않았다. 참고 위치는 [item-prop.cc](https://github.com/crawl/crawl/blob/master/crawl-ref/source/item-prop.cc), [skills.cc](https://github.com/crawl/crawl/blob/master/crawl-ref/source/skills.cc)이며 DCSS와 동일한 전투 모델/밸런스를 주장하지 않는다.

- 하단 **장비·숙련**에서 장착과 훈련 대상을 선택한다. 변경에는 100 행동 시간이 들고 적도 행동하므로 안전한 곳에서 사용한다.
- 시작 장비 선택지: 단검/손도끼/철퇴/창/맨손, 천옷/가죽 갑옷, 방패 없음. 사슬 갑옷/소형 방패는 던전 바닥에서 획득한다. 중복 장비는 금화로 전환한다.
- 단검은 빠르고, 손도끼는 높은 피해 대신 낮은 명중과 긴 공격 시간, 철퇴/창은 일부 보호 관통을 제공한다. 창은 이번 버전에서 인접 공격만 지원한다. 부상 계산에 실제 선택 무기 정의를 전달하여 절단/타격 등의 형태도 일치시킨다.
- 갑옷은 보호력과 부담을, 방패는 별도의 방어 확률과 부담을 갖는다. 갑옷/방패 숙련도가 부담을 줄인다. 회피 숙련도는 상대 명중 확률을 낮춘다.
- 팔 기능과 양손 무기 규칙을 검사해 장착을 거부하거나 전투 중 맨손으로 대체한다. 사용할 수 없는 방패는 방어 효과를 주지 않는다. 보관 장비 자체를 삭제하지는 않는다.
- 검술/도끼/둔기/창술/맨손/갑옷/회피/방패 중 하나에 처치 경험치 배분. 살아 있는 파티원에게 적 한 명당 `20 + 층×5` 지급. 플레이어 훈련 대상은 변경 가능, 동료는 기본 검술 훈련. 대기/공격 반복/시체에는 경험치 없음.
- 레벨은 `20 × 레벨²` 누적 경험치 기준, 최대 20. 무기 숙련은 피해·명중을 높이고 공격 시간을 줄이되 무기별 최저 시간을 유지한다. 수치는 이 프로젝트의 독립 초기 밸런스다.
- 명중과 방패 판정은 세계 seed/저장되는 타격 순번을 사용하는 별도 해시 경로다. 빗나가거나 막힌 공격도 시간이 소비되지만 HP/상처는 발생하지 않는다. 재로드로 다음 판정을 바꿀 수 없다.
- 장비/팔 기능/숙련도/공격력이 바뀔 때만 전투 수치를 재계산한다. 단순 상처 갱신만으로 장비 규칙을 재계산하지 않는다. 기존 무기 레지스트리 규칙 자체는 수정하지 않고 새 실행부의 계산 계층에 국한했다.
- 저장 schema 3: 장착 슬롯/보관 목록/경험치/훈련 선택 포함. 이전 재구축 저장은 기본 장비로 초기화하되 기존 캠페인 데이터 이전을 구현한 것은 아니다.
- 미포함: 사용형 기술/마법, 마법 브랜드/랜덤 유물, 원거리 탄약/사거리 전투, 장비 강화, 동료 장비 관리 UI. 기존 게임 전체의 장비 목록을 옮긴 것은 아니다.

검증: `tests/rebuilt_equipment_acceptance.gd`에서 장착/실패 원자성/장비별 수치/숙련 성장/최저 시간/처치 중복 보상 차단/방패/부상 제약/정확한 저장 왕복/잘못된 저장 거부/명중 실패/재로드 판정 유지/획득을 검사한다. 기존 던전 및 동료·신체 회귀 검사도 함께 실행한다. 성능 측정은 실제 렌더링/실기기 검증과 구분한다.

세 회귀 검사 PASS 및 웹 빌드 확인. Chromium 390×844 터치 에뮬레이션에서 장비 창/목록/손도끼 선택/장착을 확인했으며, 표시값이 단검 피해 10·명중 90%·시간 114에서 손도끼 피해 14·명중 78%·시간 144로 바뀌고 세계 시간 100이 소비되었다. 실제 휴대폰에서의 프레임 지연은 미검증이다. 장비 연결 후 로컬 밀집 100명 테스트의 한 실행은 중앙값 13.2ms, p95 21.1ms였다. 아래 초기 버전의 더 낮은 수치를 현재 성능으로 해석하지 않는다.

## 동료·신체 손상 연결

- 새 게임에 동료 1명 배치. 기존 재구축 저장에서 동료가 없으면 하단 **동료 → 합류**로 추가한다. 기존 캠페인 동료 명단을 가져오는 기능은 아니다.
- 동료는 플레이어를 따라오고 인접한 적을 공격한다. 대기 명령에서는 이동하지 않되 인접 전투는 수행한다. 벽 너머의 적을 선택하지 않는다.
- 플레이어가 동료 칸으로 이동하면 공격하지 않고 자리를 교환한다. 적도 가까운 동료를 공격할 수 있다.
- 동료 창에서 HP/성격/신체 상태를 확인하고 추종·대기를 전환한다. 인접한 살아 있는 동료에게 공유 회복약을 사용할 수 있다.
- 기존 `BodyState`, `BodyInjurySystem`, `BodyCombatRules`, `BodyFunctionRules`, 무기 정의를 `body_bridge.gd`로 연결했다. 모든 전투원의 타격이 머리/몸통/양팔/양다리 및 피부/연부조직/뼈 손상, 상처, 혈액, 충격을 갱신한다.
- 사용 가능한 다리가 2/1/0개이면 이동 비용 100/160/250%, 팔이 2/1/0개이면 공격력 100/75/35%. 두 팔 기능 상실 시 신체 타격 무기로 전환한다. 이 수치 조정은 새 실행부의 정책이며 기존 게임 밸런스 전체 이식은 아니다.
- 회복약은 HP/혈액/충격을 회복하지만 부위 기능 상실·절단·상처 이력을 초기화하지 않는다. 지속 출혈 틱, 수술/재생 치료, 관계/신뢰도, 복잡한 동료 자율 판단은 이번 범위에 포함하지 않았다.
- 피부 질김/뼈 강도는 신체의 실제 저항 임계값, 혈액은 실제 혈액량/용량이다. 각 부위의 조직 표시는 세 층 중 최저 무결성이다. HP와 혈액은 서로 다른 값이며 HP 또는 혈액이 0이면 즉시 사망한다.
- 저장 스키마는 2로 갱신하되 파일명은 유지한다. 이전 재구축 v1 저장은 HP/진행을 보존하고 새 신체를 초기화한다(당시 존재하지 않던 부상 이력을 추정하지 않는다). v2에서는 신체/동료 명령/결정적 타격 순번을 왕복 저장한다. 층 이동 때 동료의 생사와 부상을 유지한다.

추가 검증: `godot --headless --path . --script tests/rebuilt_party_body_acceptance.gd` 통과. 추종/대기/자리 교환, 피아 구분, 동료 공격·피격·즉시 사망, 실제 부상 생성, 팔다리 기능 페널티, 회복약, 저장 정확한 왕복/결정적 재개/v1 마이그레이션/손상된 저장 거부, 층 이동 지속성을 검사한다.

Web 릴리스 빌드 통과. 390×844 Chromium 터치 에뮬레이션에서 이전 v1 저장 불러오기 → 동료 창 → 합류 → 새로고침 → 동료 HP 60/60, 혈액 976/976 및 부위 상태 유지/표시를 확인했다. 이 과정에서 발견한 상태창 포맷 인수 누락은 수정하고 회귀 검사에 추가했다.

기존 실행부 회귀 테스트도 통과했다. 신체 계산 연결 후 같은 100명 적 테스트의 로컬 중앙값은 약 6.8ms(p95 11.5ms)로, 아래 초기 실행부 수치보다 증가했다. 실제 공격 대상만 부상 처리하며 전체 신체를 매 프레임 계산하지 않는다. 동료 목록도 적마다 전체 탐색하지 않고 행동 묶음당 한 번 수집한다. 모바일 실기기 프레임 시간은 별도 검증 대상이다.

## 구조

- `world.gd`: 단일 정본 상태와 행동 처리. 입력이 없으면 시뮬레이션을 돌리지 않는다.
- `min_heap.gd`: 절대 행동 시각 기반 스케줄러와 경로 우선순위 큐.
- `navigation.gd`: 플레이어 경로는 배열 기반 A*, 적 추적은 목표별 공유 거리장. 거리장은 최대 8개, 14칸 범위이며 동적 점유는 다음 이동 시 검사한다.
- `board.gd`: 화면 주변 타일만 그리기, 타일 자료 캐시, 120ms 이동 보간. 애니메이션이 끝나면 프레임 처리를 중단한다.
- `game.gd`: 입력/UI/자동이동 타이머/지연 저장. 기존 이벤트 저널과 저장 경로를 공유하지 않는다.

시야는 플레이어 위치가 바뀔 때 갱신한다. 고정 광원은 층 생성/복구 때 미리 계산한다. 그리기 중 광원 LOS 계산이나 전체 게임 상태 복제는 없다. 시야 밖 적은 그리지 않고 기억한 지형과 광원만 어둡게 표시한다.

기존 지도 생성기, 타일/캐릭터 자산, HEXACO 자료, 공통 이동/시야 기하 규칙은 재사용했다.

DCSS 전투 전체를 이식했다는 의미도 아니다.

## 검증

명령: `godot --headless --path . --script tests/rebuilt_runtime_acceptance.gd`

통과 항목: 실제 맵 초기화, 대각선 모서리 규칙, 실패 행동 원자성, 물 이동 비용, 시야 캐시, 반경, 즉시 사망과 점유 해제, JSON 정확한 왕복과 결정적 재개, 잘못된 저장 거부, 물 경로, 100명 적 처리, 자동탐험.

로컬 Godot 4.6.2 headless 측정:

| 작업 | 중앙값 | p95 |
|---|---:|---:|
| 물 10칸 목적지 경로, 50회 | 1.063ms | 1.211ms |
| 100명 적 배치에서 대기, 30회 | 0.652ms | 0.790ms |

공유 거리장 적용 전 새 실행부의 적별 A* 버전은 같은 종류의 밀집 테스트에서 중앙값 약 339ms였다. 이는 개발 중 새 실행부 간 비교이지 기존 게임 전체와의 대조 벤치마크가 아니다. 표 수치는 렌더링/저장/모바일 브라우저를 포함하지 않으며, 정지한 플레이어와 캐시 재사용에 유리한 조건이다. 실기기 이동 중 프레임 지연의 보증으로 해석하지 않는다.

Web 릴리스 내보내기 성공. Chromium의 390×844 터치 에뮬레이션에서 화면과 터치 이동 확인. 새로고침 후 위치, 시간 200, 횃불 연료 19800이 유지되고 저장 복구 메시지가 표시됨을 확인했다. 실제 휴대폰에서의 장시간 자동탐험/발열/프레임 시간은 추가 검증 대상이다.
